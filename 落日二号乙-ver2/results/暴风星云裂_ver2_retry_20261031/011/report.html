F-1 011.php 登录接口 username 参数直接拼接 SQL 导致 SQL 注入（可绕过认证）

critical sql_injection / CWE-89 · 置信度 0.9 · candidate / llm_inferred

位置：011.php:5-13

011.php 第 3 行判断 $_GET['Login'] 存在后，第 5 行直接读取 $_GET['username'] 到 $user，未做任何转义或参数化；第 8-9 行对 password 做了 md5() 处理，但 username 完全未处理；第 12 行将 $user 直接拼接进 SELECT 语句，第 13 行通过 mysqli_query 执行。攻击者可在 username 中注入 SQL 片段，构造恒真条件绕过登录校验（第 15 行 mysqli_num_rows == 1 即视为登录成功），也可通过报错回显（第 13 行 die 输出 mysqli_error）进行报错注入读取数据库内容。

影响：未认证攻击者可直接绕过登录进入受保护区域，并通过报错注入读取数据库中的用户、密码哈希等敏感数据，可能导致全库数据泄露。

CVE/CWE 论证：CWE-89 SQL 注入。外部 GET 参数 username 未经转义直接拼接进 SQL 并由 mysqli_query 执行，链路在单文件内闭合，无需认证即可触发，属典型高危 SQL 注入。

修复建议：使用 mysqli 预处理语句（prepare/bind_param）绑定 username 与 password；对输入做类型与长度校验；关闭错误信息回显，避免 die(mysqli_error) 泄露数据库结构。
