F-1 014.php 修改密码功能 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.68 · candidate / rule_verified+llm

位置：014.php:59-61

攻击者通过修改密码表单提交的 password_conf 参数（014.php:51 读取）进入 $pass_new，随后在 014.php:60 被直接拼接进 UPDATE 语句：$insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . dvwaCurrentUser() . "';";，并在 014.php:61 交给 mysqli_query 执行。代码未对 $pass_new 做 mysqli_real_escape_string 转义、未使用预处理/参数化查询，也未做类型或字符白名单校验，因此单引号可闭合字符串字面量，注入任意 SQL 片段（如通过 WHERE 条件恒真或子查询改变更新范围）。此外 014.php:61 在查询失败时通过 die() 输出 mysqli_error，构成基于报错的注入回显通道。

影响：数据库写入被篡改：攻击者可改写 users 表中任意用户（包括 admin）的 password 字段，实现账户接管/越权登录；结合报错回显可枚举库表结构，进一步读取或破坏数据。属于持久化数据完整性破坏与认证绕过。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：该逻辑位于修改密码的 HTTP 处理路径，password_conf 来自请求参数，无需本地访问；无需认证即可构造请求（若该页面本身要求登录，则攻击者只需一个低权限账户即可横向篡改他人口令）；利用链闭合：source（014.php:51 password_conf）→ 字符串拼接（014.php:60）→ mysqli_query 执行（014.php:61），中间无有效净化，且错误信息回显（014.php:61 die 分支）为注入结果提供反馈。

修复建议：改用预处理语句与参数绑定：$stmt = mysqli_prepare($link, 'UPDATE `users` SET password = ? WHERE user = ?'); mysqli_stmt_bind_param($stmt, 'ss', $pass_new, dvwaCurrentUser()); mysqli_stmt_execute($stmt);。同时对密码做长度/字符白名单校验，使用 password_hash() 存储口令哈希而非明文；关闭向用户回显的数据库错误信息（记录到服务端日志），并遵循最小权限原则，使应用数据库账户仅具备必要表的 UPDATE 权限。
