F-1 015.php 修改密码功能 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：015.php:67-69

攻击者通过修改密码表单提交的 password_conf 参数（015.php:52 读取）进入 $pass_new，随后在 015.php:68 被直接拼接进 UPDATE 语句：$insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . dvwaCurrentUser() . "';";，并在 015.php:69 交由 mysqli_query 执行。代码中未见 mysqli_real_escape_string、预处理语句或类型校验，单引号可闭合字符串字面量，从而改写 SET 子句或注入额外 SQL 片段；错误信息还会通过 die(mysqli_error(...)) 回显，便于构造报错型注入。

影响：可越权修改任意用户（含 admin）口令，进而登录后台；结合报错回显可读取数据库结构，进一步可拖取 users 表中的用户名与口令散列，造成数据泄露与账户接管。

CVE/CWE 论证：CWE-89：外部可控参数 password_conf 未经参数化即拼入 SQL 并执行，属典型二次拼接型注入；该页面为 DVWA 的公开功能端点，无需认证即可访问（或仅需低权限会话），利用链 source→拼接→mysqli_query 闭合，外部可达。

修复建议：改用预处理语句：$stmt = $db->prepare("UPDATE users SET password = ? WHERE user = ?"); $stmt->bind_param('ss', $pass_new, dvwaCurrentUser()); 并对输入做长度与字符白名单校验；关闭错误详情回显，改为记录日志；数据库账户遵循最小权限，仅授予必要表的 UPDATE 权限。

F-2 DVWA 密码修改功能 CAPTCHA 校验可被绕过（step=2 直接提交 passed_captcha=true）

high auth_bypass / CWE-287 · 置信度 0.87 · candidate / llm_inferred

位置：015.php:46-69

015.php 的密码修改流程分为两步：step=1 时调用 recaptcha_check_answer 校验 CAPTCHA，通过后渲染一个隐藏表单，其中包含 step=2、password_new、password_conf、passed_captcha=true。step=2 分支（第 46-81 行）仅检查 $_POST['passed_captcha'] 是否为真（第 55 行），完全不重新校验 CAPTCHA，也不校验该值是否由服务端签发。攻击者可直接构造 step=2 请求并携带 passed_captcha=true，跳过 CAPTCHA 校验，直接进入密码更新逻辑（第 62-69 行），将当前登录用户的密码改为任意值。这使 CAPTCHA 这一反自动化/防暴力破解机制完全失效，可被脚本化批量利用。

影响：CAPTCHA 防护完全失效，攻击者可脚本化批量修改密码/进行自动化操作，绕过反自动化机制。

CVE/CWE 论证：CWE-804（Guessable CAPTCHA）/CWE-602（Client-Side Enforcement of Server-Side Security）。外部可达、仅需低权限登录，链闭合：客户端可控 passed_captcha 直接绕过服务端 CAPTCHA 校验。

修复建议：在 step=2 分支重新校验 CAPTCHA，或将 CAPTCHA 通过结果存入服务端 session 并在 step=2 读取 session 值而非信任客户端 passed_captcha。
