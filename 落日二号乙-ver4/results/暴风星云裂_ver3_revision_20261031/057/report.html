F-1 057.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：057.php:17-19

攻击者通过 HTTP 请求向留言板提交评论/姓名，输入在 057.php:5 附近被读取为 $message 与 $name（候选标注 source 为 query `mtxMessage`，即请求参数 mtxMessage 对应的留言内容）。这两个变量未经任何转义或参数化，直接在 057.php:18 被拼接进 SQL 字符串：$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";，随后在 057.php:19 交给 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行。由于变量被包裹在单引号内且未调用 mysqli_real_escape_string / 预处理语句，攻击者只需在提交内容中放入单引号即可闭合字符串字面量，再追加任意 SQL 片段（如通过 name 字段构造 '),('... 或利用注释符截断），从而改变 INSERT 语句语义。校验无效的原因：代码路径中不存在白名单、类型校验、长度限制或转义处理，唯一“处理”是把原始值直接做字符串插值。最终危险操作是 057.php:19 的 mysqli_query 执行被篡改的 SQL；此外该行在失败时通过 die() 回显 mysqli_error，会把数据库错误信息（表名、列名、语法片段）返回给攻击者，为盲注/报错注入提供反馈通道。

影响：数据库写入被任意控制：可向 guestbook 表插入伪造/恶意记录，或通过子查询、堆叠/联合技巧读取其他表数据（如用户凭据），造成数据泄露与数据完整性破坏；错误回显进一步降低利用门槛。若数据库账户权限过高，还可能扩展到其他表的篡改。属于典型的存储型 SQL 注入，影响所有可访问该留言提交端点的未认证用户。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：注入点位于 PHP 页面 057.php 的请求参数处理路径，任何能访问该页面的远程用户均可提交；无需认证，代码中未见任何会话/权限校验；利用链闭合：外部输入 → $message/$name（057.php:5 附近）→ 字符串拼接 $query（057.php:18）→ mysqli_query 执行（057.php:19），中间无净化函数，链路完整。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：1) 改用预处理语句与参数绑定：$stmt = mysqli_prepare($link, "INSERT INTO guestbook (comment, name) VALUES (?, ?)"); mysqli_stmt_bind_param($stmt, 'ss', $message, $name); mysqli_stmt_execute($stmt);，彻底消除拼接。2) 若短期无法改造，至少对 $message/$name 使用 mysqli_real_escape_string 并配合严格白名单（长度、字符集）。3) 关闭错误回显：生产环境不要 die(mysqli_error(...))，改为记录日志并返回通用错误页。4) 数据库账户遵循最小权限，仅授予 guestbook 表的 INSERT 权限。
