F-1 022.php 修改密码处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.8 · candidate / rule_verified+llm

位置：022.php:42-44

攻击者通过修改密码表单提交 password_new 参数（022.php:25 读取），该值在 022.php:38 仅经过 mysqli_real_escape_string 转义后于 022.php:39 被 md5() 处理，随后在 022.php:43 被直接拼接进 UPDATE 语句：$insert = "UPDATE `users` SET password = '" . $pass_new . "' WHERE user = '" . $current_user . "';";，最终在 022.php:44 由 mysqli_query 执行。由于 md5() 在转义之后执行，转义产生的反斜杠会被 md5 哈希吞掉，转义对最终进入 SQL 的字符串不再生效，等于校验被绕过；同时语句未使用参数化查询，$current_user 也直接拼接。因此攻击者可构造使 md5 输出可控或利用拼接结构改变 SQL 语义的输入，实现注入。

影响：可篡改 users 表中任意用户（含 admin）的密码记录，导致账户接管；进一步可借助 UPDATE 语句的注入点读取数据库内容或破坏数据完整性，属于数据库层面的越权写入与数据泄露。

CVE/CWE 论证：CWE-89：外部可控输入（HTTP POST 参数 password_new）未经参数化即拼入 SQL 并在 022.php:44 执行；该脚本为 DVWA 的 Web 端点，远程无需认证即可访问（会话内即可提交），利用链 source→拼接→mysqli_query 闭合。注意：转义在 md5 之前执行导致净化失效，是本条成立的关键。

修复建议：改用预处理语句与参数绑定（mysqli_prepare + bind_param），彻底避免字符串拼接；若必须哈希口令，应在参数化写入前完成哈希，且不要依赖 mysqli_real_escape_string 作为唯一防线；对 $current_user 同样使用绑定参数；限制数据库账户对 users 表的写权限至最小集合。

F-3 022.php 使用 MD5 处理口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.75 · candidate / rule_verified+llm

位置：022.php:38-39

022.php:39 执行 $pass_new = md5( $pass_new );，将用户新口令以无盐 MD5 单轮哈希后写入数据库（022.php:43-44 的 UPDATE）。MD5 属于已破解的快速哈希算法，且此处未见盐值或迭代（如 password_hash/PBKDF2/bcrypt/argon2），口令存储强度不足。注意：该弱点类型应为 weak_hash（CWE-328），而非 weak_crypto（CWE-327，后者指 DES/ECB 等加密算法缺陷）。

影响：一旦数据库泄露，攻击者可用彩虹表/GPU 暴力快速还原用户明文口令，进而横向登录其他系统（口令复用场景）；无盐设计还使相同口令产生相同哈希，便于批量识别。

CVE/CWE 论证：CWE-328：源码原文证据为 022.php:39 的 md5( $pass_new )，用于口令这一安全用途；属实现型弱点，无需 HTTP 污点链即可成立。外部可达性：该逻辑在修改密码流程中由任意已访问该页面的用户触发。

修复建议：改用 PHP 内置 password_hash()（PASSWORD_DEFAULT/bcrypt 或 argon2id）生成带盐慢哈希，校验使用 password_verify()；迁移期可对旧 MD5 值在用户下次登录时透明重哈希；禁止在 SQL 拼接前以 md5 作为“净化”手段。
