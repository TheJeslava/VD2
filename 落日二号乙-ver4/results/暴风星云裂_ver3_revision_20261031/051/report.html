F-1 051.php 开放重定向候选（CWE-601）：header 重定向目标为固定字符串，污点未到达汇点

medium open_redirect / CWE-601 · 置信度 0.4 · candidate / rule_verified+llm

位置：051.php:7-9

证据显示 051.php:5 从 query 参数 `default` 读取外部输入，051.php:7-9 的代码为：先注释「Do not allow script tags」，再用 `stripos($default, "<script") !== false` 判断输入是否包含 `<script`，命中时执行 `header("location: ?default=English")`。关键事实是：该 header 的 Location 值是硬编码字符串 `?default=English`，其中不含变量 `$default`，因此外部输入并未进入重定向目标。攻击者可控的 `default` 只影响「是否触发该分支」这一布尔判断，无法改变跳转目的地，也无法注入 CRLF（值中无用户数据）。因此候选 exploit_chain 第 2 步所称「污点进入 open_redirect 汇点」与给出的代码片段不符：片段中不存在把 `$default` 拼进 Location 的语句。按当前 code_pack 可见范围，该候选不构成开放重定向；若 051.php 其他行（未在片段中给出）存在 `header("location: " . $default)` 之类的拼接，则需另行取证，本片段不足以支撑。

影响：按现有证据：无开放重定向影响。若强行按候选结论推断，最坏情形也仅是把用户重定向到站内固定地址 `?default=English`，不构成跨站跳转、不泄露凭据、不导致钓鱼落地页劫持。当前证据下影响为「无」（证据不足支撑 CWE-601 的实际影响）。

CVE/CWE 论证：不满足 CWE-601 的构成要件：开放重定向要求攻击者可控数据进入 Location/Refresh 等跳转目标。此处 Location 为常量 `?default=English`，`$default` 仅参与 `stripos` 判断，未参与响应头构造，污点链在 051.php:8 处被「仅用于比较」切断，未闭合到 051.php:9 的 header 值。外部可达性成立（query 参数无需认证即可访问），但可达不等于可利用；利用链不闭合，故不应授予 CVE/CWE-601 归类。

修复建议：1) 若后续确认存在动态跳转，应改为白名单映射：仅接受预定义键（如 `en`/`zh`），用映射表取固定 URL，禁止直接把参数拼入 Location；2) 对跳转目标做规范化与同源校验（解析后校验 scheme/host 属于本站），拒绝 `//evil.com`、`https://`、`\\`、含 CR/LF 的值；3) 输出前过滤 `\r\n` 防响应头注入；4) 当前代码建议保留 `<script` 检查的同时，明确注释该 header 为固定回退值，避免审计误判；5) 若确无动态跳转需求，可关闭该候选。
