F-1 021.php 未过滤的 POST 参数 include 导致路径穿越/任意文件包含（CWE-22）

high path_traversal / CWE-22 · 置信度 0.4 · candidate / rule_verified+llm

攻击者通过 HTTP POST 提交参数 include（021.php:14 `if (isset ($_POST['include']))`），该值在 021.php:16 被直接拼接进 `$page['body']` 的内联表达式 `" . $_POST['include'] . 影响：任意文件读取（泄露配置文件、凭据、源码），在拼接结果被 include/require 消费时可升级为本地文件包含，配合可写文件可导致代码执行；同时可造成敏感路径探测。

修复建议：不要将用户输入直接拼接为文件路径或包含目标：使用固定白名单映射（如 `$pages = ['home'=>'home.php', ...]`）按 key 取文件；若必须接受路径，先 `basename()` 去目录成分，再用 `realpath()` 规范化并校验结果前缀位于允许目录内；禁止对用户输入使用 include/require，改用模板引擎的受限渲染。

F-2 021.php 中 POST 参数 include 未转义直接拼接进页面导致反射型 XSS（CSP nonce 可绕过）

medium xss / CWE-79 · 置信度 0.9 · candidate / llm_inferred

位置：021.php:14-18

021.php 第 14-18 行读取 $_POST['include']，未做任何 HTML 实体编码（无 htmlspecialchars/htmlentities），直接字符串拼接进 $page['body']，随后该 body 被输出到响应页面。攻击者提交含 <script> 的 include 参数即可在受害者浏览器执行任意脚本。第 3-5 行设置的 CSP 使用固定 nonce 'TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA='（源码第 10 行注释即给出可直接使用的示例 <script nonce=...>alert(1)</script>），且 script-src 含 'unsafe-inline'，因此 CSP 无法阻止注入脚本执行；第 8 行还显式关闭 X-XSS-Protection。属于反射型 XSS，可窃取会话/发起敏感操作。

影响：反射型 XSS，可在受害者浏览器上下文执行任意 JS，窃取 Cookie/会话、伪造请求、钓鱼。

CVE/CWE 论证：CWE-79。外部 POST 参数直达 HTML 输出，无编码，无需认证，链闭合；CSP 因固定 nonce 与 unsafe-inline 失效。

修复建议：对 $_POST['include'] 使用 htmlspecialchars($v, ENT_QUOTES, 'UTF-8') 输出；移除 'unsafe-inline'，nonce 每次请求随机生成；恢复 X-XSS-Protection。

F-3 021.php CSP 策略同时启用 unsafe-inline 与固定 nonce，削弱脚本来源限制（CWE-693）

medium csp / CWE-693 · 置信度 0.72 · candidate / rule_verified+llm

位置：021.php:2-3

021.php:3 设置 `Content-Security-Policy: script-src 'self' 'unsafe-inline' 'nonce-TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA=';`。该策略同时允许 `'unsafe-inline'` 与一个硬编码、可预测的 nonce。按 CSP 规范，当存在 nonce 时 `'unsafe-inline'` 会被忽略，但 nonce 值固定写在源码中（base64 解码为可读字符串），任何能读取源码或猜测该值的攻击者都可为其注入的 `<script nonce=...>` 打上合法标记，从而绕过 script-src 限制。此外策略缺少 `object-src 'none'`、`base-uri`、`default-src` 等加固项。

影响：CSP 作为 XSS 纵深防御被削弱：一旦存在 HTML 注入点（如本文件 include 参数拼接输出），攻击者可复用固定 nonce 执行内联脚本，导致会话劫持、凭据窃取、页面篡改。

CVE/CWE 论证：CWE-693 保护机制失效。属配置/实现型弱点，无需污点链即可成立；证据为 021.php:3 的策略字符串原文（含 `'unsafe-inline'` 与硬编码 nonce）。外部可达性取决于是否存在注入点，本文件 021.php:16 的拼接输出提供了潜在注入面。

修复建议：移除 `'unsafe-inline'`；nonce 必须每次响应随机生成（如 `base64_encode(random_bytes(16))`）且不可硬编码；补充 `default-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'`；对输出做上下文编码，不依赖 CSP 作为唯一防线。
