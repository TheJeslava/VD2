F-1 044.php 不安全文件上传（CWE-434）：上传文件被直接 move_uploaded_file 落盘，缺少类型/扩展名校验

critical file_upload / CWE-434 · 置信度 0.78 · candidate / rule_verified+llm

位置：044.php:7-9

攻击者通过 HTTP 文件上传字段 `uploaded` 提交任意文件（044.php:9 的 `$_FILES['uploaded']['tmp_name']`）。代码在 044.php:9 直接调用 `move_uploaded_file($_FILES['uploaded']['tmp_name'], $target_path)` 将临时文件移动到目标路径，输入中给出的片段（044.php:7-9）未出现任何扩展名白名单、MIME 校验、`getimagesize()` 内容校验或文件名规范化逻辑，因此校验无效（缺失）。最终危险操作是文件写入（落盘到 `$target_path`）。需要说明的证据缺口：`$target_path` 的赋值语句不在 code_pack 片段内，其是否包含上传目录、是否由用户可控文件名拼接无法从现有证据确认；若 `$target_path` 位于 Web 可访问目录且保留原始扩展名，则可上传 .php 等可执行脚本。

影响：若上传目录可被 Web 服务器解析（如 Apache 对 .php 的处理），攻击者可上传 webshell 并获得远程代码执行（RCE），进而读取/篡改应用数据、横向移动；即使不可执行，也可造成任意文件落盘、磁盘占用、覆盖同名文件等文件写入影响。具体影响取决于 `$target_path` 的目录与命名策略（证据不足，未在片段中给出）。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部可达性：上传入口为 HTTP multipart 请求的 `uploaded` 字段，无需认证即可触达（片段中未见任何鉴权/会话校验）。利用链闭合：`$_FILES['uploaded']['tmp_name']` → `move_uploaded_file(..., $target_path)` 直接落盘，中间无白名单/内容校验，构成 source→sink 完整链路。证据等级为 llm_inferred：`$target_path` 定义与目录可执行性未在 code_pack 中体现，故不宣称已动态验证。

修复建议：1) 使用扩展名白名单（如仅 jpg/png/gif/pdf）并同时校验 MIME 与文件头（`finfo_file`/`getimagesize`）；2) 上传文件名由服务端随机生成（UUID），不采用客户端 `name`，避免路径穿越与覆盖；3) 上传目录置于 Web 根之外，或配置 Web 服务器禁止该目录执行脚本（`php_flag engine off` / 去除 Handler）；4) 限制文件大小与数量，落盘权限最小化（非 Web 用户可写可执行）；5) 对 `$target_path` 做规范化并校验其位于允许的上传根目录内。

F-2 DVWA 044.php 无限制文件上传导致任意 PHP 文件写入 web 目录（RCE）

high file_upload / CWE-434 · 置信度 0.85 · candidate / llm_inferred

位置：044.php:3-16

044.php 在收到 POST 参数 Upload 时，直接取 $_FILES['uploaded']['name'] 经 basename() 处理后拼接到 DVWA_WEB_PAGE_TO_ROOT."hackable/uploads/" 目录，并调用 move_uploaded_file() 落盘。代码未校验扩展名、MIME、文件内容，也未做白名单或重命名，攻击者可上传 .php 文件到 web 可访问目录，随后直接请求该文件即可在服务器执行任意 PHP 代码，形成远程代码执行。

影响：攻击者可在服务器写入并执行任意 PHP 代码，完全控制 Web 应用与主机（RCE）。

CVE/CWE 论证：CWE-434 无限制文件上传。外部可直接通过 HTTP multipart 请求触发，链闭合：上传文件名/内容 → move_uploaded_file 落盘到 web 目录 → 直接请求执行。

修复建议：使用扩展名白名单（如仅 jpg/png/gif）、校验 MIME 与文件魔数、随机重命名文件、将上传目录置于 web 根之外或禁用该目录 PHP 执行（php_flag engine off）。
