F-1 客户端使用 MD5 生成令牌（CWE-328 弱哈希，非 CWE-327 弱加密）

medium weak_crypto / CWE-327 · 置信度 0.55 · candidate / rule_verified+llm

位置：032.php:17-18

证据位于 032.php 第 17-18 行：第 17 行从页面元素 phrase 读取用户输入 `var phrase = document.getElementById("phrase").value;`，第 18 行将其经 rot13 变换后送入 md5 计算并写入隐藏/表单字段 `document.getElementById("token").value = md5(rot13(phrase));`。攻击者输入点即页面中 id 为 phrase 的输入框（客户端可控），数据流为 phrase → rot13(phrase) → md5(...) → token 字段值。校验无效的原因在于：rot13 只是可逆的字符替换，不引入任何密钥或随机性；MD5 已被证明存在碰撞攻击且计算极快，且整个令牌生成完全在浏览器端 JavaScript 中完成，算法与变换对攻击者完全可见，因此该“令牌”不具备不可预测性与抗伪造性。需要说明的是，该弱点本质是弱哈希（CWE-328），而非 DES/ECB 类弱加密算法（CWE-327），标题中的 CWE-327 归类应修正。此外，输入仅给出 032.php 第 17-19 行片段，token 字段在服务端如何被消费（是否用于 CSRF 校验、会话绑定或一次性凭证）在 code_pack 中不可见，因此“可伪造令牌导致绕过”的最终汇点属于推断，证据不足。

影响：若该 token 被服务端用作安全令牌（如 CSRF token、表单防重放令牌或隐藏状态凭证），攻击者可在本地复现同一算法（rot13 + MD5）离线批量生成合法 token，从而伪造请求、绕过 CSRF 防护或重放表单，造成越权操作或业务数据篡改。若 token 仅用于非安全用途（如展示用摘要），则实际影响降级为信息暴露（可预测摘要）。由于服务端消费逻辑未在证据中给出，具体影响等级需结合后端校验代码确认。

CVE/CWE 论证：对应 CWE-328（Use of Weak Hash）：MD5 用于生成安全相关令牌，属不可逆哈希的强度不足问题，不应归为 CWE-327（Use of a Broken or Risky Cryptographic Algorithm，指 DES/RC4/ECB 等加密算法/模式）。外部可达性：该逻辑位于 032.php 返回的页面脚本中，任何能访问该页面的用户（无需认证即可加载页面）都能触发并观察算法；利用链闭合度：输入（phrase）→ 变换（rot13）→ 弱哈希（md5）→ 输出（token 字段）在客户端完整闭合，但“token 被服务端信任”这一环在给定证据中缺失，故不宣称完整可利用链，仅确认弱点成立。

修复建议：1) 不要在客户端生成任何安全令牌；令牌必须由服务端使用密码学安全随机源生成（如 Java 的 SecureRandom、PHP 的 random_bytes、Node 的 crypto.randomBytes）。2) 若必须对用户输入做完整性保护，改用带密钥的 HMAC-SHA-256（服务端持有密钥），而非裸 MD5。3) 令牌应绑定会话并设置有效期与一次性使用语义，服务端校验时使用常量时间比较。4) 移除 rot13 这类可逆混淆，它不提供任何安全性。5) 若历史数据已用 MD5，迁移时对存量令牌做失效处理而非兼容。
