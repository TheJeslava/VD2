F-1 008.php 日志写入 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.68 · candidate / rule_verified+llm

位置：008.php:79-81

攻击者通过 HTTP 请求的 query 参数 `user_id`（008.php:19 读取）控制 `$id`，该值被赋给 `$current_user_id` 后直接以字符串拼接方式嵌入 INSERT 语句 `$log_query`（008.php:79-80），未做整型转换、未使用 mysqli_real_escape_string、也未使用预处理语句，最终在 008.php:81 通过 `mysqli_query($GLOBALS["___mysqli_ston"], $log_query)` 执行。由于 `{$current_user_id}` 位于 VALUES 列表的数值位置，攻击者提交如 `1),(1,1,'x')-- -` 之类的值即可闭合元组并注入任意 SQL 片段，校验完全失效。

影响：可向 bac_log 表写入任意数据（日志伪造/审计污染），并可通过 UNION/子查询读取 users 等表内容，造成数据库数据泄露；若数据库账号权限过高，还可进一步读写文件或篡改业务数据。

CVE/CWE 论证：CWE-89：外部可控的 query 参数 `user_id` 未经参数化直接拼接到 SQL 语句并在 008.php:81 执行，攻击者无需认证即可通过 HTTP 触发，利用链（source 008.php:19 → $current_user_id → $log_query → mysqli_query 008.php:81）闭合。

修复建议：改用预处理语句（mysqli_prepare + bind_param），对 user_id 强制 `(int)` 转换或 filter_var(FILTER_VALIDATE_INT) 校验；ip_address 使用参数绑定而非字符串拼接；数据库账号遵循最小权限，禁用 FILE 权限。

F-4 DVWA BAC 页面通过可篡改的 user_id Cookie 实现越权访问任意用户资料

high idor / CWE-639 · 置信度 0.88 · candidate / llm_inferred

位置：008.php:30-45

008.php 第 15 行从 $_GET['user_id'] 读取目标用户 ID，第 16 行仅用 /^\d+$/ 校验为纯数字，第 19 行 intval 后进入业务逻辑。第 30-33 行的访问控制完全依赖客户端 Cookie $_COOKIE['user_id']：只要 Cookie 中的 user_id 与请求参数 user_id 相等（$id == $cookie_id），即视为“本人”并放行。Cookie 由攻击者完全可控，因此攻击者只需把 Cookie user_id 与查询参数 user_id 设为同一个任意受害者 ID，即可绕过归属校验，读取任意用户的 first_name、last_name、avatar 等资料。服务端从未将请求中的 user_id 与当前登录会话（dvwaCurrentUser() 查出的 $current_user_id）比对，属于典型的水平越权（IDOR）。

影响：任意已认证（甚至仅需能访问该页面）的攻击者可读取其他用户的姓名、头像等个人资料，造成水平越权与隐私泄露；结合第 7 行 dvwaCurrentUser() 可知服务端本可拿到真实当前用户 ID 却未用于校验。

CVE/CWE 论证：CWE-639 授权绕过（IDOR）。外部可通过 HTTP 直接触发，无需高权限，仅需可控 Cookie；链闭合：source(Cookie/参数)→格式校验→Cookie 相等判定→SQL 查询→回显。

修复建议：服务端应使用会话中已认证的 $current_user_id（第 10 行）与请求的 $id 比对，禁止信任客户端 Cookie 做归属判断；对敏感资料查询强制 WHERE user_id = 当前会话用户。

F-5 008.php 用户资料字段未编码直接输出导致存储型 XSS

medium xss / CWE-79 · 置信度 0.52 · candidate / llm_inferred

位置：008.php:40-47

第 40-47 行将数据库返回的 $row['first_name']、$row['last_name']、$row['avatar'] 直接拼接进 HTML 字符串并输出，未调用 htmlspecialchars/htmlentities 编码。若攻击者能控制自己资料中的这些字段（如通过资料编辑功能写入含脚本的 avatar 或姓名），则当其他用户（含管理员）查看该资料页时脚本在其浏览器执行，构成存储型 XSS。

影响：存储型 XSS，可在受害者（含管理员）浏览器执行任意脚本，窃取会话或发起敏感操作。

CVE/CWE 论证：CWE-79。外部可达，输出点未编码；但写入点（资料编辑）不在 CODE PACK 内，链的 source 端依赖外部功能，故置信度中等。

修复建议：输出前对所有用户数据使用 htmlspecialchars($v, ENT_QUOTES, 'UTF-8') 编码；对 avatar 等 URL 字段做协议白名单校验。
