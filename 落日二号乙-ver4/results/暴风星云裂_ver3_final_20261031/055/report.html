F-1 055.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.7 · candidate / rule_verified+llm

位置：055.php:17-19

攻击者通过 HTTP 请求向留言板提交留言内容（源码中对应变量 $message，候选标注的 source 为 query `mtxMessage`，即 055.php:5 处从请求读取的留言字段），该值未经任何转义或参数化处理，在 055.php:18 被直接拼接进 SQL 字符串：$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";，随后在 055.php:19 交由 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行。由于 $message 被包裹在单引号内且未调用 mysqli_real_escape_string 等转义函数、也未使用预处理语句，攻击者可闭合单引号并注入任意 SQL 片段（如通过 comment 字段构造 ' , (SELECT ...))-- - 之类的载荷），使原本的 INSERT 语义被改写。校验无效的原因：代码路径中不存在白名单、类型校验或参数绑定，仅依赖字符串拼接；同时 055.php:19 的 or die(...) 会把 mysqli_error 内容回显到页面，为报错型注入提供了反馈通道。最终危险操作是数据库写入/查询执行，攻击者可借此读取或篡改 guestbook 及其他可访问表的数据。

影响：数据库层面的数据泄露与篡改：攻击者可利用报错回显与 UNION/子查询读取任意可访问表（如用户凭据、其他业务数据），并可向 guestbook 注入伪造记录或通过堆叠/子查询修改数据；在数据库账户权限过高时可能进一步读写文件或影响其他库。属于未授权远程可利用的 critical 级注入。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：注入点位于留言提交处理逻辑，任何能访问该页面的远程用户均可提交 POST/GET 参数触发，无需认证；利用链闭合：外部输入 $message（055.php:5）→ 字符串拼接 $query（055.php:18）→ mysqli_query 执行（055.php:19），中间无净化函数，且错误信息回显（or die + mysqli_error）增强了可利用性。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：1) 改用预处理语句与参数绑定：$stmt = mysqli_prepare($link, "INSERT INTO guestbook (comment, name) VALUES (?, ?)"); mysqli_stmt_bind_param($stmt, 'ss', $message, $name); mysqli_stmt_execute($stmt);；2) 若必须拼接，至少对 $message/$name 使用 mysqli_real_escape_string 并强制字符集；3) 关闭生产环境的数据库错误回显，将 mysqli_error 写入服务端日志而非响应体；4) 对留言长度与字符集做白名单校验；5) 数据库账户遵循最小权限，仅授予 guestbook 表的 INSERT 权限。
