F-1 021.php 中 POST 参数 include 未编码直接拼接进页面导致反射型 XSS（CSP nonce 硬编码可绕过）

medium xss / CWE-79 · 置信度 0.85 · candidate / llm_inferred

位置：021.php:14-18

021.php 第 14-18 行读取 $_POST['include']，未经任何 HTML 实体编码或过滤，直接字符串拼接进 $page['body']，随后该变量被输出到页面（本文件为 DVWA CSP 练习页，body 由外层模板渲染）。同时第 3 行 CSP 使用硬编码固定 nonce 'TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA='，且第 8 行显式发送 X-XSS-Protection: 0 关闭浏览器 XSS 过滤。攻击者可提交带该固定 nonce 的 <script> 标签，既绕过 CSP 又执行任意 JS，形成反射型 XSS。

影响：攻击者可构造链接诱导受害者提交表单，在目标域执行任意 JS，窃取会话或执行敏感操作；CSP 因固定 nonce 形同虚设。

CVE/CWE 论证：CWE-79 反射型 XSS；外部无需认证即可通过 POST 触发，污点链在 021.php 内闭合（source 第 14 行 → 拼接第 15-17 行 → 输出 body），CSP 绕过由第 3 行硬编码 nonce 与第 8 行关闭 XSS 过滤共同支撑。

修复建议：对 $_POST['include'] 使用 htmlspecialchars($v, ENT_QUOTES, 'UTF-8') 输出；CSP nonce 每次请求随机生成（random_bytes）而非硬编码；移除 X-XSS-Protection: 0。

F-2 021.php 中 CSP 策略同时启用 'unsafe-inline' 与固定 nonce，削弱脚本来源限制（CWE-693）

medium csp / CWE-693 · 置信度 0.55 · candidate / rule_verified+llm

位置：021.php:2-3

证据来自 021.php 第 3 行：$headerCSP = "Content-Security-Policy: script-src 'self' 'unsafe-inline' 'nonce-TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA=';"。该策略在 script-src 中同时声明 'self'、'unsafe-inline' 和一个硬编码的 nonce 值（base64 解码为 "Never going to give you up"）。攻击者输入点：任何能向页面注入 HTML 的入口（如反射型参数、存储型内容、第三方脚本或同源上传/JSONP 端点）——本 code_pack 仅给出 021.php 第 2-4 行，未提供具体 getParameter/getHeader 等取值语句，因此具体注入参数名证据不足。经过的变量/函数：注入内容进入响应 HTML 后由浏览器按第 3 行下发的 CSP 解析。校验为何无效：'unsafe-inline' 使内联 <script> 与事件处理器（onerror/onload 等）无需 nonce 即可执行，nonce 白名单形同虚设；同时 nonce 为源码中硬编码常量，任何能读取该文件或从历史响应中获取该值的攻击者都可复用同一 nonce 构造 <script nonce=...>，nonce 的“每次响应随机”安全前提被破坏。最终危险操作：浏览器执行攻击者控制的脚本，CSP 未能阻断。

影响：CSP 作为纵深防御失效：一旦存在任意 HTML 注入点（反射/存储型 XSS、富文本、第三方组件），攻击者脚本可在受害者浏览器上下文执行，导致会话 Cookie/令牌窃取、以受害者身份发起操作（CSRF 绕过同源策略防护）、页面内容篡改与钓鱼。注意：本 finding 本身是配置型弱点，不直接构成 XSS；实际脚本执行仍需一个独立的注入入口，该入口在本 code_pack 中未提供。

CVE/CWE 论证：CWE-693（Protection Mechanism Failure）：安全机制（CSP script-src）被配置为不生效。外部可达性：021.php 为 Web 可访问脚本，第 3 行策略随响应头下发，任何访问者均无需认证即可获得该策略。利用链闭合度：配置缺陷部分闭合（策略文本已确认），但“攻击者脚本注入点”这一环在给定 code_pack 中缺失，故不能宣称完整可利用链；置信度按此下调。

修复建议：1) 从 script-src 中移除 'unsafe-inline'，改用 nonce 或 hash 白名单；2) nonce 必须每次响应由 CSPRNG 生成（如 random_bytes(16) 后 base64），禁止硬编码常量，且不得在日志/错误页回显；3) 若必须兼容旧代码，使用 'strict-dynamic' 配合 nonce，并保留 'self' 作为回退；4) 增加 object-src 'none'、base-uri 'self'、frame-ancestors 限制；5) 通过响应头统一注入 CSP（避免模板拼接），并对所有输出点做上下文相关编码，从根上消除 HTML 注入入口。
