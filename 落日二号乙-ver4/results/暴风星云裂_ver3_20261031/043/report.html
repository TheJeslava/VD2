critical file_upload / CWE-434 · 置信度 0.68 · candidate / rule_verified+llm

位置：043.php:18-20

攻击者通过 HTTP 文件上传字段 `uploaded` 提交文件（043.php:12 读取上传内容，临时文件路径进入 `$uploaded_tmp`）。代码随后在 043.php:20 调用 `move_uploaded_file( $uploaded_tmp, $target_path )` 将临时文件移动到 `$target_path`。从给出的片段看，在读取上传内容（043.php:12）与移动文件（043.php:20）之间，没有出现对文件扩展名、MIME 类型、文件内容或目标路径的白名单校验，也没有对 `$target_path` 做规范化/目录限制，因此上传文件的原始名称/类型可直接影响落盘位置与落盘文件名。校验无效的原因：不存在任何 allowlist 或内容检查，`move_uploaded_file` 只保证文件来自本次上传，不保证其类型安全。最终到达的危险操作是文件写入（落盘到 Web 可访问目录时可被解析执行）。

影响：任意文件上传：攻击者可上传 .php/.phtml 等可执行脚本到 Web 根目录下，通过访问上传后的 URL 触发服务端执行，导致远程代码执行（RCE）；即使不可执行，也可造成任意文件写入、覆盖已有文件、磁盘占满，或上传恶意 HTML/JS 用于钓鱼与存储型 XSS。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部可达性：上传入口为 HTTP multipart 请求的 `uploaded` 字段，无需认证即可访问 043.php。利用链闭合：请求 → `$uploaded_tmp`（043.php:12）→ `move_uploaded_file($uploaded_tmp, $target_path)`（043.php:20）→ 文件落盘。缺少扩展名/类型白名单与目标路径约束，攻击者可直接控制落盘文件，链路上无有效净化点。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：1) 对上传文件使用扩展名白名单（如仅 jpg/png/pdf），并结合 finfo/getimagesize 校验真实 MIME 与文件头，不信任客户端 Content-Type；2) 由服务端生成随机文件名，禁止使用客户端原始文件名拼接路径；3) 将上传目录置于 Web 根之外，或配置该目录禁止脚本执行（如 php-fpm/nginx 关闭 PHP handler）；4) 对 `$target_path` 做 realpath 规范化并校验其前缀必须位于允许的上传目录内，防止路径穿越；5) 限制文件大小与数量，上传后重命名并设置最小权限（0644、非可执行）；6) 对上传内容做病毒/恶意脚本扫描。
