F-1 023.php 口令更新语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：023.php:15-17

攻击者通过 HTTP GET 参数 password_new（023.php:5 `$pass_new = $_GET['password_new'];`）提交输入。该值在 023.php:11 仅经过 mysqli_real_escape_string 转义，随后在 023.php:12 被 md5() 处理，最终在 023.php:16 被直接拼接进 SQL 语句：`$insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . $current_user . "';";`，并在 023.php:17 交由 mysqli_query 执行。校验无效的原因：mysqli_real_escape_string 只对引号等字符做转义，无法阻止注入语义；且 md5() 会把输入规约为 32 位十六进制串，因此 password_new 实际无法携带可用的注入载荷——真正未参数化、可被外部影响的是 023.php:16 中拼接的 $current_user（来自 dvwaCurrentUser()，023.php:15）。若该用户名可被攻击者影响（例如注册/改名接口或会话中的用户名可控），则引号闭合后即可注入任意 SQL。当前证据仅覆盖 023.php，dvwaCurrentUser() 的实现不在 code_pack 内，无法确认其可控性，故该注入点的外部可达性证据不足。

影响：若 $current_user 可控，攻击者可闭合 023.php:16 的字符串字面量，改写 UPDATE 语句（例如修改任意用户口令、追加条件或子查询），导致越权修改账户口令、数据库内容篡改；023.php:17 的 die(mysqli_error(...)) 还会把数据库错误信息回显到页面，造成数据库结构/版本等信息泄露。若仅 password_new 可控，则因 md5() 归一化，实际可利用性很低。

CVE/CWE 论证：CWE-89：SQL 命令中特殊元素未正确中和。外部可达性：入口为 HTTP GET（023.php:5-6），无需额外权限即可提交请求；但利用链闭合依赖 $current_user 的外部可控性，该函数实现不在 code_pack 中，属证据不足环节。因此本条按 llm_inferred 记录，不宣称已闭合的 RCE/越权链。

修复建议：1) 将 023.php:16-17 改为预处理语句：`$stmt = $mysqli->prepare('UPDATE users SET password = ? WHERE user = ?'); $stmt->bind_param('ss', $pass_new, $current_user); $stmt->execute();`，彻底消除字符串拼接；2) 不要用 md5 处理口令，改用 password_hash()/password_verify()（PASSWORD_DEFAULT 或 Argon2id）；3) 移除 023.php:17 中把 mysqli_error 直接输出到页面的逻辑，改为记录服务端日志并返回通用错误；4) 对 $current_user 做来源校验（仅允许当前会话绑定的用户），避免其被外部输入影响。

F-2 DVWA 密码修改接口（023.php）缺少 CSRF token，可被跨站强制修改当前用户密码

high csrf / CWE-352 · 置信度 0.85 · candidate / llm_inferred

位置：023.php:3-17

023.php 在 `isset($_GET['Change'])` 成立时直接读取 `password_new`/`password_conf` 并执行 `UPDATE users SET password=...`，整个流程没有任何 CSRF token、Referer 校验或原密码确认。攻击者只需诱导已登录受害者访问一个自动提交的页面（GET 请求即可，甚至可用 <img> 标签），即可把受害者密码改为攻击者已知的值，随后用新密码登录接管账户。由于该接口使用 GET 且无 token，属于典型的认证后 CSRF（CWE-352）。

F-3 023.php 使用 MD5 存储口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.8 · candidate / rule_verified+llm

位置：023.php:11-12

023.php:12 `$pass_new = md5( $pass_new );` 对口令使用 MD5 做单向摘要后写入 users 表（023.php:16-17）。MD5 属于已被攻破的快速哈希：无盐、计算极快，可被 GPU/彩虹表大规模预计算与暴力破解；且同一口令产生固定摘要，便于离线比对。此处保护对象是用户登录口令，属安全用途，因此归类为 weak_hash（CWE-328），而非 weak_crypto（CWE-327）。该弱点为配置/实现型，不依赖 HTTP 污点链，证据即 023.php:12 的算法调用原文。

影响：数据库一旦泄露（备份泄露、SQL 注入拖库、运维越权读取），攻击者可用彩虹表或 GPU 暴力在很短时间内还原大量用户明文口令；由于用户常跨站复用口令，可进一步导致账户接管与横向渗透。

CVE/CWE 论证：CWE-328：使用已被攻破的密码学算法。外部可达性：口令修改入口 023.php:5-6 为 HTTP GET，无需认证即可触达该哈希逻辑（在 DVWA 低安全级别下）；利用链为「口令明文 → md5() → 入库 → 库泄露后离线破解」，无需在线交互即可完成，属闭合的实现型弱点。

修复建议：1) 用 `password_hash($pass_new, PASSWORD_DEFAULT)`（bcrypt/Argon2id）替换 023.php:12 的 md5()，校验时用 password_verify()；2) 为历史 MD5 记录做迁移：用户下次登录成功后用新算法重算并覆盖；3) 增加每用户随机盐（password_hash 已内置）；4) 强制口令复杂度与长度下限，降低离线破解成功率。

F-5 023.php 口令修改接口缺少 CSRF 防护（CWE-352）

medium csrf / CWE-352 · 置信度 0.65 · candidate / rule_verified+llm

位置：023.php:4-5

023.php:4-6 通过 GET 读取 password_new 与 password_conf，并在 023.php:16-17 直接执行 UPDATE users SET password 的状态变更操作。整个流程未见 CSRF token、Origin/Referer 校验，也未要求重新输入旧口令；状态变更使用 GET 方法，可被 `<img src="...">` 等跨站资源请求触发。校验无效的原因：服务端仅依赖浏览器自动携带的会话凭据判断身份，攻击者页面可让受害浏览器在已登录状态下发起该请求。注意：当前 code_pack 仅含 023.php，无法确认会话 Cookie 是否设置 SameSite、也无法确认是否存在上游统一 CSRF 过滤器，故该结论为基于本文件的推断。

影响：攻击者诱导已登录受害者访问恶意页面，即可在受害者不知情下把其账户口令改为攻击者指定值，随后用新口令登录接管账户；若受害者具备高权限，可进一步扩大至后台管理操作。

CVE/CWE 论证：CWE-352：跨站请求伪造。外部可达性：023.php:5-6 为 GET 入口，无需攻击者持有凭据，仅需受害者已登录并访问攻击者页面；利用链为「恶意页面 → 受害者浏览器携带会话 → GET 触发 023.php:16-17 的 UPDATE」，链路在本文件内闭合。缺口：SameSite 属性与全局 CSRF 过滤器不在 code_pack 中，无法排除。

修复建议：1) 将口令修改改为 POST，并在表单中携带一次性 CSRF token，服务端在 023.php 处理前校验 token 与会话绑定；2) 校验 Origin/Referer 与站点同源；3) 会话 Cookie 设置 SameSite=Lax 或 Strict、Secure、HttpOnly；4) 修改口令前要求输入旧口令做二次确认；5) 修改成功后使旧会话失效并重新认证。
