F-2 021.php 中 POST 参数 include 未编码直接拼入页面 body 导致反射型 XSS（CSP nonce 硬编码可绕过）

medium xss / CWE-79 · 置信度 0.88 · candidate / llm_inferred

位置：021.php:14-18

021.php 第 14-18 行读取 $_POST['include']，未经 htmlspecialchars 等任何编码，直接字符串拼接进 $page['body']；第 19-25 行把 $page['body'] 与表单一起输出到响应体。攻击者提交含 <script> 的 include 值即可在受害者浏览器执行任意脚本。同时第 3 行 CSP 使用硬编码 nonce 'TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA='（base64 解码为 'Never going to give you up'），且第 10 行注释已直接给出可用的 nonce 值，攻击者可在注入的 <script nonce="..."> 中复用该 nonce 通过 CSP；第 8 行还显式设置 X-XSS-Protection: 0 关闭浏览器 XSS 过滤。

影响：反射型 XSS：可在受害者浏览器上下文执行任意 JS，窃取会话 Cookie/令牌、伪造请求执行敏感操作、钓鱼。CSP 因硬编码 nonce 失效，X-XSS-Protection 被显式关闭，防护形同虚设。

CVE/CWE 论证：CWE-79。外部可达（POST 参数直接进入响应体），无需认证，链完整闭合；CSP nonce 硬编码（CWE-330 相关）使防护可绕过。属 DVWA 类教学靶场 CSP 绕过场景，真实部署中可被赏金平台接收为反射型 XSS。

修复建议：对 $_POST['include'] 使用 htmlspecialchars($v, ENT_QUOTES, 'UTF-8') 输出；CSP nonce 每次请求随机生成（random_bytes）而非硬编码；移除 X-XSS-Protection: 0；对输入做白名单校验。

F-3 021.php 硬编码 CSP 同时启用 unsafe-inline 与固定 nonce（CWE-693）

medium csp / CWE-693 · 置信度 0.6 · candidate / rule_verified+llm

位置：021.php:2-3

021.php:3 定义 $headerCSP = "Content-Security-Policy: script-src 'self' 'unsafe-inline' 'nonce-TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA=';"。该策略同时包含 'unsafe-inline' 与一个硬编码、可预测的 nonce。'unsafe-inline' 会使内联脚本无需 nonce 即可执行，从而大幅削弱 CSP 对 XSS 的缓解作用；固定 nonce 写在源码中，任何能读到源码或猜到该常量的人都能构造带该 nonce 的脚本标签。此外该 CSP 未包含 default-src、object-src 等兜底指令。输入片段仅覆盖 021.php:2-3，未给出该 header 实际被 header() 输出的代码，也未给出页面中内联脚本的注入点，因此“可被利用执行任意脚本”的完整链路在本证据范围内未闭合。

影响：CSP 对内联脚本注入的防护基本失效：一旦页面存在任何 HTML/JS 注入点（例如同文件 021.php:16 将 $_POST['include'] 拼入 body），注入的内联脚本可绕过 CSP 执行，导致会话劫持、页面篡改或钓鱼。当前证据不足以证明存在可直接利用的注入点。

CVE/CWE 论证：CWE-693（防护机制失效）。外部可达性：CSP 随 021.php 响应下发，任何访问者均可获得。利用链：响应头下发弱 CSP（021.php:3）→ 页面存在注入点（未在片段中确认）→ 内联脚本执行。因缺少注入点与 header 输出代码，链条未闭合。

修复建议：移除 'unsafe-inline'，改用基于 nonce 或 hash 的严格策略；nonce 必须每次请求随机生成（如 random_bytes + base64），不得硬编码在源码中；补充 default-src 'self'、object-src 'none'、base-uri 'self' 等指令；同时修复 021.php:16 的输入拼接问题，避免依赖 CSP 作为唯一防线。
