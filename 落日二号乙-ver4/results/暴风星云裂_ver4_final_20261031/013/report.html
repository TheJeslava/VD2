F-1 013.php 修改密码处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：013.php:29-31

攻击者通过修改密码表单提交新口令，输入在 013.php:8 被读取为 `password_new`，随后在 013.php:26 仅经过 `mysqli_real_escape_string()` 转义，在 013.php:27 被 `md5()` 处理，最终在 013.php:30 被直接拼接进 UPDATE 语句 `UPDATE `users` SET password = '$pass_new' WHERE user = '...' LIMIT 1;`，并在 013.php:31 交给 `mysqli_query()` 执行。由于 `$pass_new` 是字符串拼接而非参数化查询，转义函数无法覆盖所有上下文（如多字节字符集/引号处理不当），且 md5 后的值仍以字符串形式拼入 SQL，攻击者可构造闭合单引号的输入改变查询语义。

影响：可篡改 users 表中的口令字段，实现任意用户口令重置/越权登录；结合报错回显（013.php:31 的 die 输出 mysqli_error）可进行报错型注入读取数据库结构与其他表数据，导致敏感数据泄露。

CVE/CWE 论证：CWE-89：外部可控输入 `password_new` 未经参数化直接进入 SQL 语句。入口为公开的修改密码表单，无需认证即可访问该页面（DVWA 场景下为低安全级别），利用链从 HTTP 参数到 mysqli_query 闭合，具备外部可达性与无需认证特征。

修复建议：改用预处理语句与参数绑定（mysqli_prepare/bind_param 或 PDO），禁止字符串拼接；对输入做长度与字符白名单校验；关闭详细数据库错误回显，改为通用错误页并记录日志；口令哈希改用 password_hash()/bcrypt 等强算法。

F-2 DVWA 密码修改接口 CAPTCHA 校验可被硬编码值 + User-Agent 伪造绕过

high captcha_bypass / CWE-804 · 置信度 0.93 · candidate / llm_inferred

位置：013.php:17-23

013.php 第 17-23 行的 CAPTCHA 判定条件为 `$resp || ($_POST['g-recaptcha-response'] == 'hidd3n_valu3' && $_SERVER['HTTP_USER_AGENT'] == 'reCAPTCHA')`。攻击者无需真正通过 reCAPTCHA，只要提交固定字符串 `hidd3n_valu3` 并把 User-Agent 头设为 `reCAPTCHA`，即可让整个条件恒真，进入第 25 行的密码修改分支，把当前用户密码改为攻击者指定值（第 26-31 行 UPDATE users SET password=md5(...)）。这使 CAPTCHA 这一唯一的人机/暴力破解防护完全失效，可被脚本化批量调用，配合 CSRF 缺失（第 52-53 行仅在页面渲染时生成 token，POST 处理分支未校验 token）可导致账户接管。

CVE/CWE 论证：CWE-804（Guessable CAPTCHA）/CWE-290（通过伪造绕过认证）。外部可达、仅需低权限登录，利用链在源码中闭合，硬编码值与 UA 判断均可由客户端控制。

修复建议：移除硬编码 'hidd3n_valu3' 后门分支；仅信任 recaptcha_check_answer 的服务端校验结果；在密码修改 POST 分支校验 CSRF token。

F-5 013.php 口令使用 MD5 哈希（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：013.php:26-27

013.php:27 使用 `$pass_new = md5( $pass_new );` 对口令做哈希后写入数据库（013.php:30-31）。MD5 为快速、无盐、已被证明存在碰撞的哈希算法，不适合用于口令存储。此处保护对象是用户口令，属于安全用途，应归类为 weak_hash（CWE-328）而非 weak_crypto。

影响：数据库泄露时，攻击者可用彩虹表/GPU 暴力快速还原用户明文口令；无盐设计使相同口令产生相同哈希，便于批量破解与撞库，进而导致账户接管。

CVE/CWE 论证：CWE-328：使用弱哈希算法保护口令。该弱点为配置/实现型，无需 HTTP 污点链即可成立；证据为 013.php:27 的 md5() 调用原文。外部可达性体现在修改密码流程会持续产生弱哈希口令记录。

修复建议：改用 password_hash()（PASSWORD_BCRYPT/ARGON2ID）并配合 password_verify()；为每个口令使用随机盐；对历史 MD5 记录在下次登录时透明升级；禁止在代码中直接使用 md5/sha1 处理口令。
