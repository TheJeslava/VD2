F-1 008.php 用户存在性检查处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.63 · candidate / rule_verified+llm

位置：008.php:21-23

攻击者通过 HTTP 请求参数 user_id 提供输入（008.php:19 读取 query `user_id`），该值未做类型转换或参数化即被拼接到字符串 $check_query 中（008.php:22："SELECT user_id FROM users WHERE user_id = $id"），随后在 008.php:23 通过 mysqli_query($GLOBALS["___mysqli_ston"], $check_query) 执行。代码中未见 intval()、mysqli_real_escape_string() 或预处理语句，因此单引号/布尔/联合注入均可闭合原语句。

影响：数据库数据泄露（可 UNION 读取 users 表及其他库表，如口令哈希、会话数据）、认证逻辑绕过（通过恒真条件使存在性检查通过）、在 MySQL 权限允许时可读写文件或堆叠语句导致进一步失陷。

CVE/CWE 论证：CWE-89：外部可控参数 user_id 未经参数化直接进入 SQL 语句并执行，攻击者无需认证即可通过公开 HTTP 端点触达，利用链闭合（source 008.php:19 → 拼接 008.php:22 → 执行 008.php:23）。

修复建议：改用 mysqli 预处理语句（$stmt = $mysqli->prepare('SELECT user_id FROM users WHERE user_id = ?'); $stmt->bind_param('i', $id);），或至少对 $id 强制 (int) 转换并校验为纯数字；同时以最小权限数据库账号运行，关闭 FILE 与堆叠查询能力。

F-4 DVWA BAC 页面 008.php 通过可篡改的 user_id Cookie 实现越权访问任意用户资料

high idor / CWE-639 · 置信度 0.85 · candidate / llm_inferred

位置：008.php:30-47

008.php 第 15-19 行从 $_GET['user_id'] 读取目标用户 ID，仅用正则 /^\d+$/ 校验为纯数字后 intval 转换；第 30-33 行的访问控制完全依赖客户端可控的 $_COOKIE['user_id']，将其 intval 后与请求的 $id 做相等比较，相等即视为「本人」并放行。攻击者只需把 Cookie user_id 改成与 GET 参数相同的任意数字，即可绕过归属校验，读取任意用户的 first_name/last_name/avatar（第 35-47 行）。服务端从未用会话中的真实身份（第 7-11 行查出的 $current_user_id）做比对，属于典型的信任客户端 Cookie 的越权（CWE-639 / CWE-565）。

影响：任意登录用户可枚举并读取所有用户的姓名、头像等资料，构成水平/垂直越权信息泄露。

CVE/CWE 论证：CWE-639 授权绕过、CWE-565 依赖不可信 Cookie。外部 HTTP 可达，无需高权限，链在源码内闭合。

修复建议：授权判定必须使用服务端会话中的真实用户 ID（$current_user_id），禁止信任客户端 Cookie 作为归属凭据；对 user_id 使用参数化查询。

F-6 008.php 角色 Cookie 由客户端可控且无完整性保护（CWE-330/CWE-565）

high weak_id / CWE-330 · 置信度 0.4 · candidate / rule_verified+llm

位置：008.php:93-94

008.php:93-94 在 $_COOKIE['user_role'] 不存在时直接 setcookie('user_role','regular_user', time()+3600, '/')，角色标识完全以明文 Cookie 形式存放于客户端，服务端后续若直接信任该 Cookie 判断权限，则攻击者可自行设置 user_role=admin 等值实现提权。该模式属于可预测/可伪造的标识与不安全会话状态管理，而非强随机令牌。

影响：权限提升：攻击者篡改 user_role Cookie 即可冒充管理员访问受限功能；同时 Cookie 未设置 HttpOnly/Secure/SameSite 属性，易被 XSS 窃取或在明文信道泄露。

CVE/CWE 论证：CWE-330（使用不充分随机/可预测值）与 CWE-565（依赖未受保护的 Cookie 做安全决策）：角色状态由客户端可写 Cookie 承载，缺少签名或服务端会话校验，外部无需认证即可构造。注意：输入未提供服务端读取该 Cookie 的代码行，读取点与授权判断点证据不足，故置信度较低。

修复建议：将角色等授权状态保存在服务端会话中，Cookie 仅存放不可猜测的会话 ID；对 Cookie 使用 HMAC 签名并校验完整性；设置 HttpOnly、Secure、SameSite=Lax/Strict；避免以客户端 Cookie 直接做权限判定。
