F-1 021.php 将 POST 参数 include 原样拼接进页面 body（反射型注入候选，非路径穿越）

high path_traversal / CWE-22 · 置信度 0.45 · candidate / rule_verified+llm

位置：021.php:14-16

021.php:15-16 中 `$page['body'] .= "\n\t" . $_POST['include'] . "..."` 把外部 POST 参数 include 未经任何编码直接拼接到响应 body。这是输出拼接，不是文件路径操作：片段中没有 include/require/fopen 等文件函数，也没有路径分隔符处理。因此按类型边界应归为反射型内容注入（若响应为 HTML 则为 XSS 类），而非 path_traversal。候选将其标为 CWE-22 属于类型误判。

影响：攻击者可通过 POST 参数 include 向返回页面注入任意 HTML/脚本内容，导致反射型 XSS（会话劫持、钓鱼、页面篡改）。不构成任意文件读写。

CVE/CWE 论证：CWE-79（跨站脚本）而非 CWE-22：外部输入无需认证即可通过 POST 到达 HTML 输出汇点，缺少 htmlspecialchars 等编码，利用链闭合；但需注意同文件第 3 行 CSP 含 'unsafe-inline' 与固定 nonce，实际脚本执行受 CSP 影响，需运行时确认。

修复建议：输出前对 $_POST['include'] 使用 htmlspecialchars($v, ENT_QUOTES, 'UTF-8') 编码；或改为白名单枚举页面标识；移除 CSP 中的 'unsafe-inline'，nonce 每次请求随机生成而非硬编码。

F-2 021.php 中 POST 参数 include 未编码直接拼入页面 body，导致反射型 XSS（CSP nonce 可绕过）

medium xss / CWE-79 · 置信度 0.85 · candidate / llm_inferred

位置：021.php:14-18

021.php 第 14-18 行读取 $_POST['include']，未做任何 HTML 实体编码（无 htmlspecialchars/htmlentities），直接字符串拼接进 $page['body']，随后该 body 被输出到页面。攻击者提交含 <script> 或事件处理器的 payload 即可在受害者浏览器执行任意 JS。第 3-5 行设置的 CSP 使用 script-src 'self' 'unsafe-inline' 'nonce-TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA='，其中 'unsafe-inline' 使内联脚本被允许；且 nonce 值硬编码在源码第 3 行与第 10 行注释中，攻击者可直接复用该 nonce 构造 <script nonce="..."> 绕过 CSP。第 8 行还显式关闭 X-XSS-Protection。

影响：反射型 XSS：攻击者可诱导受害者提交请求，在其浏览器上下文执行任意 JS，窃取会话/发起敏感操作。CSP 因 'unsafe-inline' 与硬编码 nonce 无法提供有效防护。

CVE/CWE 论证：CWE-79。外部无需认证即可通过 POST include 注入脚本，数据流 021.php:14→15-17→输出 闭合，CSP 因 unsafe-inline 与硬编码 nonce 可绕过。

修复建议：对 $_POST['include'] 使用 htmlspecialchars($v, ENT_QUOTES, 'UTF-8') 输出编码；移除 'unsafe-inline'，nonce 每次请求随机生成且不可硬编码；恢复 X-XSS-Protection。

F-3 021.php 硬编码 nonce 且 CSP 允许 'unsafe-inline'（CWE-693 防护机制失效）

medium csp / CWE-693 · 置信度 0.7 · candidate / rule_verified+llm

位置：021.php:2-3

021.php:3 定义 `$headerCSP = "Content-Security-Policy: script-src 'self' 'unsafe-inline' 'nonce-TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA=';"`。两个缺陷：其一，nonce 为固定常量（base64 解码为 "Never going to give you up"），对所有请求、所有用户相同，攻击者一旦读到一次即可在注入脚本上复用该 nonce，nonce 机制完全失效；其二，同时启用 'unsafe-inline'，使内联脚本无需 nonce 即可执行，进一步架空 CSP。二者叠加使 CSP 对 XSS 基本无防护能力。

影响：CSP 无法阻止内联脚本执行，与 021.php:15-16 的反射型输出拼接叠加时，攻击者注入的 <script> 可直接执行，导致会话窃取、页面篡改、钓鱼。属于防护机制弱化，本身不直接造成数据泄露。

CVE/CWE 论证：CWE-693（防护机制失效）。配置型弱点，无需污点链：证据为第 3 行策略字符串原文（'unsafe-inline' 与固定 nonce 值）。外部可达性成立（每个响应都携带该头），但单独不构成可利用漏洞，需与注入点组合。

修复建议：移除 script-src 中的 'unsafe-inline'；nonce 改为每次请求用 random_bytes(16) 生成并 base64 编码，服务端与页面脚本标签保持一致；考虑增加 object-src 'none'、base-uri 'self'、default-src 'self' 等指令。
