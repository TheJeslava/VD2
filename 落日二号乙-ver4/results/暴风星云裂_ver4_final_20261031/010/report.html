F-1 010.php 登录查询 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.7 · candidate / rule_verified+llm

位置：010.php:18-20

攻击者通过 HTTP 请求向 010.php 提交登录参数，源码在 010.php:8 从请求中读取 username（候选 source 记为 query `username`），该值未经任何转义或参数化即被拼接到 010.php:19 的 SQL 语句 "SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';" 中，随后在 010.php:20 由 mysqli_query 执行。虽然 010.php:15 对 $pass 调用了 mysqli_real_escape_string，但 $user 变量在拼接前没有任何对应的转义或白名单校验，因此单引号可闭合 user 字段的字符串字面量，注入任意 SQL 片段（如 ' OR '1'='1 绕过认证，或 UNION 读取其他表）。校验无效的原因是该处采用字符串拼接构造 SQL，而非预处理语句/参数绑定。

影响：可绕过登录认证并读取数据库任意数据（users 表及其他可访问表），结合 010.php:20 的 die(mysqli_error(...)) 错误回显还可进行报错型注入与数据库结构探测；若数据库账户权限过高，可能进一步导致数据篡改。属于未授权即可触发的数据泄露/认证绕过。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：注入点为登录请求参数 username，属公开 HTTP 入口，无需认证即可访问；利用链闭合：010.php:8 读取输入 → 010.php:19 字符串拼接 → 010.php:20 mysqli_query 执行，中间无有效净化（$user 未转义），且错误信息经 die() 回显，便于构造盲注/报错注入。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：改用 mysqli 预处理语句与参数绑定（prepare + bind_param），彻底避免字符串拼接；若必须拼接，对 $user 使用 mysqli_real_escape_string 并配合严格白名单校验；同时移除 010.php:20 中向客户端回显 mysqli_error 的 die() 分支，改为记录服务端日志并返回通用错误；数据库账户遵循最小权限，仅授予必要表的 SELECT 权限。

F-2 010.php 口令使用 MD5 哈希（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：010.php:15-16

010.php:16 对登录口令执行 $pass = md5($pass)，即使用 MD5 这一已被证明存在碰撞且计算速度极快的哈希算法处理口令。该值随后在 010.php:19 被拼入 SQL 与数据库中的口令字段比较，说明 MD5 被用于口令存储/校验的安全用途。MD5 无盐、无迭代、无工作因子，攻击者一旦获取口令哈希即可通过彩虹表或 GPU 高速暴力破解还原明文。注意：此处属于弱哈希（CWE-328），而非弱加密算法（CWE-327）。

影响：口令哈希可被离线快速破解，导致用户账户凭据泄露；若数据库泄露，攻击者可批量还原弱口令并横向登录，造成账户接管。

CVE/CWE 论证：CWE-328（使用弱哈希算法）。该弱点为配置/实现型，无需 HTTP 污点链即可成立：证据为 010.php:16 明文调用 md5() 处理口令，且 010.php:19 将其用于口令比对，属安全用途。外部可达性体现在登录接口可被反复调用以获取/验证哈希行为；利用前提是攻击者能获取哈希（如通过同文件 GEN-7034f0a19983 的 SQL 注入读取 users 表），两者可组合放大影响。证据等级为源码推断（llm_inferred）。

修复建议：改用专为口令设计的慢哈希算法，如 PHP 的 password_hash()（PASSWORD_BCRYPT 或 PASSWORD_ARGON2ID）配合 password_verify()，并为每个口令使用随机盐；对存量 MD5 哈希在用户下次登录时透明升级；同时修复同文件的 SQL 注入以避免哈希外泄。
