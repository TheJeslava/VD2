F-1 客户端令牌生成使用 MD5 弱哈希（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.7 · candidate / rule_verified+llm

位置：032.php:17-18

在 032.php 第 17-18 行，页面脚本读取表单元素 phrase 的值（document.getElementById("phrase").value），随后执行 md5(rot13(phrase)) 并把结果写入隐藏/令牌字段 token（document.getElementById("token").value）。即令牌由客户端可完全控制的输入经 ROT13（无密钥的可逆替换）与 MD5（无盐、无迭代、已知碰撞的弱哈希）派生。攻击者只需知道或猜到 phrase 的取值即可离线复算出同一 token，无需任何密钥；ROT13 不提供任何机密性，MD5 也不提供抗碰撞/抗原像强度。校验环节（服务端对 token 的比对）在给定片段中未出现，因此“校验无效”的具体实现属证据不足，但令牌派生算法本身已构成弱哈希弱点。

影响：令牌/校验值可被攻击者离线预测与伪造：任何能提交 phrase 的一方都能生成合法 token，从而绕过依赖该 token 的防篡改/防伪造校验，可能导致越权提交、请求伪造或业务逻辑绕过。由于是纯客户端计算，攻击者还可直接篡改 DOM 后提交任意 token 值。

CVE/CWE 论证：对应 CWE-328（Use of Weak Hash）：MD5 用于安全用途（令牌派生）且无盐、无密钥、无迭代；ROT13 为可逆替换，不构成密钥材料。外部可达性：该逻辑位于 032.php 返回给浏览器的脚本中，任何能访问该页面的未认证用户均可触发并观察/复算 token，利用链在客户端闭合，无需认证。注意：本条为配置/实现型弱点，不依赖 HTTP 污点链；服务端比对逻辑未在片段中出现，故不宣称已实现端到端绕过。

修复建议：1) 不要在客户端派生安全令牌：改由服务端使用 CSPRNG（如 Java SecureRandom / PHP random_bytes）生成至少 128 位随机令牌并绑定会话；2) 若必须做完整性校验，使用带密钥的 HMAC-SHA-256（服务端持有密钥）替代 md5(rot13(...))；3) 彻底移除 MD5 与 ROT13 在安全语义中的使用，口令场景改用 Argon2id/bcrypt/PBKDF2 并加盐；4) 服务端对 token 做常量时间比较并校验来源与会话绑定。
