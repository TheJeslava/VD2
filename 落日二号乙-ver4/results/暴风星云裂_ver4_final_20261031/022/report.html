F-1 022.php 修改密码处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：022.php:42-44

攻击者通过 HTTP 请求向 022.php 提交修改密码表单，外部输入在 022.php:25 被读入 $pass_new（候选 source 标注为 query `password_new`）。该值在 022.php:38 仅经过 mysqli_real_escape_string 转义，随后在 022.php:43 被直接拼接进 SQL 语句：$insert = "UPDATE `users` SET password = '" . $pass_new . "' WHERE user = '" . $current_user . "';";，并在 022.php:44 交给 mysqli_query 执行。转义函数只处理引号等字符，无法阻止在已闭合引号后追加 SQL 片段（如通过 password_new 注入闭合单引号并追加条件/子查询），且语句未使用预处理参数化，因此校验无效。$current_user 来自 dvwaCurrentUser()（022.php:42），同样以字符串拼接方式进入同一语句。

影响：可篡改 users 表中任意用户的 password 字段（包括 admin），实现账户接管与越权登录；通过布尔/联合注入可进一步读取数据库中的用户凭据等敏感数据。属于数据完整性与机密性双重破坏。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：022.php 为 Web 端点，通过 POST 表单参数 password_new 直接可达，无需认证即可触发（DVWA 场景下为低安全级别页面）；利用链闭合：source（022.php:25 的 password_new）→ 拼接（022.php:43）→ 执行（022.php:44 mysqli_query），中间仅有 mysqli_real_escape_string 这一非充分防护，无参数化、无白名单，链路完整。

修复建议：改用预处理语句与参数绑定：$stmt = $GLOBALS["___mysqli_ston"]->prepare("UPDATE `users` SET password = ? WHERE user = ?"); $stmt->bind_param('ss', $pass_new, $current_user); $stmt->execute();。移除字符串拼接；对 $current_user 同样使用绑定参数；对输入做长度与字符白名单校验；数据库账户遵循最小权限，仅授予必要表的 UPDATE 权限。

F-3 022.php 使用 MD5 存储口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：022.php:38-39

022.php:39 执行 $pass_new = md5( $pass_new );，将用户新口令以无盐 MD5 形式哈希后写入数据库（022.php:43-44 的 UPDATE 语句）。MD5 属于已被证明存在碰撞且计算极快的哈希算法，用于口令存储时无法抵抗离线暴力破解与彩虹表攻击；代码中未见加盐（salt）或迭代（如 bcrypt/Argon2/PBKDF2）处理。该弱点为配置/实现型，不依赖 HTTP 污点链，根因是算法选择与缺少盐值。

影响：数据库泄露后攻击者可用彩虹表或 GPU 高速爆破快速还原用户明文口令，进而横向登录其他系统（口令复用场景）；无盐设计使相同口令产生相同哈希，便于批量识别。

CVE/CWE 论证：CWE-328（Use of Weak Hash）。注意此处应归类为 weak_hash 而非 weak_crypto（CWE-327，指 DES/ECB 等加密算法问题）。外部可达性：通过修改密码功能即可写入 MD5 哈希；无需认证即可观察该实现（DVWA 低安全级别）。利用链为“口令 → md5 → 入库”，根因明确。

修复建议：改用 password_hash($pass_new, PASSWORD_DEFAULT)（bcrypt/Argon2）生成带盐慢哈希，校验时使用 password_verify；迁移期可对旧 MD5 值在用户下次登录时透明重哈希；禁止在代码中直接使用 md5/sha1 处理口令。
