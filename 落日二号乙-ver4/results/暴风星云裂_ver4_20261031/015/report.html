F-1 015.php 修改密码处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.55 · candidate / rule_verified+llm

位置：015.php:67-69

攻击者通过 POST 参数 password_new（015.php:8 读取，015.php:51 处进入 $pass_new）提交恶意字符串。该值在 015.php:64 仅经过 mysqli_real_escape_string 转义，随后在 015.php:68 被直接拼接进 UPDATE 语句：$insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . dvwaCurrentUser() . "';";，并在 015.php:69 交给 mysqli_query 执行。由于拼接发生在转义之后（转义只处理引号等字符，无法阻止已转义内容被再次放入 SQL 文本），且未使用参数化查询，攻击者可构造闭合单引号并注入任意 SQL 片段。注意：015.php:65 的 md5() 只改变值的表示形式，不构成 SQL 层面的净化。

影响：可篡改 users 表中任意用户（含 admin）的 password 字段，实现账户接管/越权登录；结合报错回显（mysqli_error 输出到页面）可进行报错型注入读取数据库结构与其他表数据，造成敏感数据泄露。

CVE/CWE 论证：CWE-89：外部可控输入（$_POST['password_new']）未经参数化直接拼入 SQL 并在 mysqli_query 执行，外部 HTTP 可达、无需额外权限即可触发（需处于已登录的修改密码流程），利用链闭合。

修复建议：改用预处理语句与绑定参数（mysqli_prepare + bind_param 或 PDO prepared statement），禁止字符串拼接 SQL；对输入做长度与字符白名单校验；关闭向页面回显数据库错误信息（移除 or die(mysqli_error(...))），统一记录到服务端日志。

F-4 015.php 使用 MD5 存储口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.86 · candidate / rule_verified+llm

位置：015.php:64-65

015.php:65 执行 $pass_new = md5( $pass_new );，将用户新口令以无盐 MD5 形式计算后写入数据库（015.php:68 的 UPDATE 语句）。MD5 属于快速、无盐、已被证明存在碰撞的哈希算法，不适合口令等安全用途；攻击者一旦获取数据库（例如通过同文件中的 SQL 注入或备份泄露），可用彩虹表/GPU 高速爆破还原明文口令。

影响：口令哈希可被离线快速破解，导致用户口令泄露与跨系统撞库；由于未加盐，相同口令产生相同哈希，可批量识别弱口令账户。

CVE/CWE 论证：CWE-328（Use of Weak Hash）：md5() 用于口令存储这一安全用途，属实现型弱点，无需 HTTP 污点链即可成立；外部可达性体现在修改密码接口 015.php:3 的 POST 处理路径。

修复建议：改用专为口令设计的慢哈希算法（bcrypt/Argon2id/PBKDF2），使用 password_hash()/password_verify() 并配合每用户随机盐与合适的工作因子；对历史 MD5 记录在用户下次登录时透明升级。
