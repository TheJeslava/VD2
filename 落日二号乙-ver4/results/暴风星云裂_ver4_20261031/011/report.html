F-1 011.php 登录接口 username 参数 SQL 注入（可绕过认证）

critical sql_injection / CWE-89 · 置信度 0.9 · candidate / llm_inferred

位置：011.php:5-13

011.php 第 3 行通过 $_GET['Login'] 触发登录逻辑，第 5 行直接取 $_GET['username'] 赋给 $user，未做任何转义或参数化；第 12 行将 $user 直接拼接进 SQL 语句 "SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';"，第 13 行交给 mysqli_query 执行。攻击者可在 username 中注入单引号闭合字符串，构造恒真条件（如 ' OR '1'='1' -- -），使查询返回任意一行用户记录，第 15 行 mysqli_num_rows == 1 成立即判定登录成功，从而绕过密码校验进入受保护区域。password 虽经 md5() 处理，但 md5 不是 SQL 转义，无法阻止注入。

影响：无需有效凭据即可绕过登录认证，并可进一步通过 UNION/报错注入读取数据库中的用户、口令哈希等敏感数据。

CVE/CWE 论证：CWE-89 SQL 注入。外部 GET 参数直接拼接进 SQL 并执行，无需认证，利用链在 CODE PACK 内完整闭合（011.php:5→12→13→15）。

修复建议：使用 mysqli 预处理语句（prepare + bind_param）绑定 username/password；或至少对 $user 使用 mysqli_real_escape_string 并避免字符串拼接；同时移除 die() 中的数据库错误回显。

F-2 011.php 登录接口缺少暴力破解防护（CWE-307）

F-3 011.php 口令使用 MD5 哈希（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.7 · candidate / rule_verified+llm

位置：011.php:8-9

011.php:8 从 $_GET['password'] 读取明文口令，011.php:9 调用 $pass = md5($pass); 将其转换为 MD5 摘要后用于 011.php:12 的登录比对。MD5 为快速、无盐、已被证明存在碰撞的哈希算法，用于口令存储/校验属不安全实现；攻击者一旦获取数据库中的 MD5 值，可用彩虹表或 GPU 高速爆破还原明文。此处为配置/实现型弱点，不依赖 HTTP 污点链，证据为 011.php:9 的 md5( 调用原文。

影响：口令摘要可被离线高速破解，导致用户口令泄露；若同一口令在其他系统复用，可造成横向账户接管。

CVE/CWE 论证：CWE-328（使用弱哈希算法）。外部可达性：登录接口 011.php:3 公开可达，攻击者可通过正常登录流程触发该哈希逻辑；弱点根因在 011.php:9 的算法选择，无需认证即可观察/利用其后果（如配合 SQL 注入导出哈希后离线破解）。

修复建议：改用带盐的自适应口令哈希算法，如 PHP 的 password_hash($pass, PASSWORD_ARGON2ID) 与 password_verify()，或至少 bcrypt（PASSWORD_BCRYPT）；迁移时对存量 MD5 摘要在用户下次登录成功后透明重哈希；禁止在查询中直接比较 MD5 值。

F-4 011.php 登录成功页 username 反射型 XSS

medium xss / CWE-79 · 置信度 0.7 · candidate / llm_inferred

位置：011.php:21-21

第 5 行读取的 $user 来自 $_GET['username']，在第 21 行被直接拼接进 HTML 输出 "<p>Welcome to the password protected area {$user}</p>"，未做 htmlspecialchars 等 HTML 编码。当攻击者构造使登录成功的请求（例如配合 SQL 注入恒真条件，或使用合法账号）时，username 中的 HTML/JS 会被浏览器解析执行，构成反射型 XSS。

影响：可在受害者浏览器执行任意 JS，窃取会话或发起 CSRF 操作；结合 SQL 注入可无需凭据触发。

CVE/CWE 论证：CWE-79 反射型 XSS。外部参数未编码直接输出到 HTML，链在 CODE PACK 内闭合（011.php:5→21）。

修复建议：输出前对 $user 使用 htmlspecialchars($user, ENT_QUOTES, 'UTF-8')；avatar 属性同样应做属性上下文编码。
