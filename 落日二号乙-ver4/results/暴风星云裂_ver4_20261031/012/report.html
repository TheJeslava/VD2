F-1 012.php 登录查询 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：012.php:13-15

攻击者通过 HTTP GET 参数 `username`（012.php:5 读取，随后赋给 `$user`）提交任意字符串。该值仅经过 mysqli_real_escape_string 处理（012.php:10 附近对 `$pass` 的处理），而 `$user` 在 012.php:14 被直接拼接进 SQL 语句：`$query = "SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';";`，随后在 012.php:15 由 `mysqli_query($GLOBALS["___mysqli_ston"], $query)` 执行。由于查询使用单引号包裹字符串且未做参数化，攻击者可闭合引号注入布尔/联合语句，例如 `username=' OR '1'='1' -- -`，使 WHERE 条件恒真并绕过口令校验。校验无效的原因：代码只对 `$pass` 做了转义与 md5，未对 `$user` 做任何转义或白名单校验，也未使用预处理语句。

影响：认证绕过：攻击者无需知道任何口令即可登录任意/首个用户账户（如 admin），获取应用内权限；结合 UNION 注入还可读取 `users` 表及其他数据库内容，造成敏感数据泄露。若数据库账户权限过高，可能进一步读写文件。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：注入点为 GET 参数 `username`，无需认证即可访问登录入口（012.php:3 判断 `$_GET['Login']`）。利用链闭合：`$_GET['username']` → `$user` → 字符串拼接 `$query`（012.php:14）→ `mysqli_query` 执行（012.php:15），中间无有效净化，构成完整 source→sink 链。

修复建议：改用参数化查询/预处理语句：`$stmt = $mysqli->prepare("SELECT * FROM users WHERE user = ? AND password = ?"); $stmt->bind_param('ss', $user, $pass);`，禁止将外部输入拼接进 SQL。同时对 `username` 做长度与字符白名单校验，关闭详细数据库错误回显（移除 `or die(mysqli_error(...))`），并为数据库账户授予最小权限。

F-2 012.php 登录接口缺少暴力破解防护（CWE-307）

high brute_force / CWE-307 · 置信度 0.4 · candidate / rule_verified+llm

位置：012.php:2-3

012.php:3 通过 `if( isset( $_GET[ 'Login' ] ) )` 进入登录处理流程，随后在 012.php:14-15 执行口令校验。代码中未见失败次数计数、账户锁定、验证码、延迟或速率限制等任何反暴力破解机制，攻击者可对同一账户无限次提交口令猜测。

影响：攻击者可对登录接口进行在线口令爆破或撞库，配合弱口令/弱散列（见 SEM-0ce3358fa05b）可高效猜解账户口令，导致账户接管。

CVE/CWE 论证：CWE-307（对过度认证尝试缺乏防护）。外部可达性：登录入口为 GET 参数 `Login`，无需认证即可反复调用。证据边界：本项为语义模式命中，输入中未提供失败计数/锁定相关代码，实际可利用性需在授权环境通过重复请求确认，故置信度较低。

修复建议：引入失败计数与账户/IP 维度限流（如 5 次失败后锁定或指数退避），增加验证码或二次验证；记录并告警异常登录尝试；避免通过 GET 提交登录凭据，改用 POST 并配合 CSRF 令牌。

F-3 012.php 使用 MD5 存储/校验口令（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：012.php:10-11

012.php:11 对用户口令执行 `$pass = md5( $pass );`，即使用 MD5 这一已被证明存在碰撞且计算速度极快的散列算法处理口令。该 md5 值随后在 012.php:14 被拼入登录查询与数据库中的口令值比较。MD5 无盐、无迭代、无慢哈希特性，属于口令存储/校验的安全用途误用。

影响：若数据库口令散列泄露，攻击者可用彩虹表或 GPU 高速暴力破解快速还原明文口令；MD5 碰撞特性也可能被用于构造等价散列，削弱口令校验强度，进而导致账户接管。

CVE/CWE 论证：CWE-328（使用弱散列算法）。属实现型弱点，无需 HTTP 污点链即可成立：证据为 012.php:11 的 `md5( $pass )` 直接用于口令校验路径（012.php:14 的 password 比较）。外部可达性：登录接口每次请求都会以 MD5 处理口令。

修复建议：改用专为口令设计的慢哈希算法，如 PHP `password_hash($pass, PASSWORD_ARGON2ID)` / `PASSWORD_BCRYPT` 并配合 `password_verify()` 校验；为每个口令使用唯一盐值；迁移期可对旧 MD5 值做一次再散列。

F-4 012.php 登录成功页反射型 XSS：username 参数未转义直接拼入 HTML

medium xss / CWE-79 · 置信度 0.75 · candidate / llm_inferred

位置：012.php:5-23

012.php 在 `isset($_GET['Login'])` 时读取 `$_GET['username']`（第 5 行），仅用 `mysqli_real_escape_string` 做 SQL 转义（第 6 行），该函数只处理 SQL 特殊字符（引号、反斜杠、NUL 等），对 `<`、`>`、`"`、`'` 等 HTML 元字符不做任何处理。随后第 23 行将 `$user` 直接插入 `$html .= "<p>Welcome to the password protected area {$user}</p>"`，未调用 htmlspecialchars/htmlentities。攻击者可构造带 HTML/JS 的 username，在受害者浏览器中执行脚本，窃取会话或发起钓鱼。触发需要登录成功（`mysqli_num_rows($result) == 1`），因此攻击者需知道有效凭据或诱导已登录用户点击链接。

影响：反射型 XSS，可在受害者浏览器执行任意 JS，窃取 Cookie/会话、发起 CSRF 或钓鱼。

CVE/CWE 论证：CWE-79。外部 GET 可达，链闭合；但需有效凭据才能进入成功分支，故定 medium。

修复建议：输出前对 $user 使用 htmlspecialchars($user, ENT_QUOTES, 'UTF-8')；avatar 同样需转义。
