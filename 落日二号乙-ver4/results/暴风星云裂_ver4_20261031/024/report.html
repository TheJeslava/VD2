F-1 024.php 密码修改功能 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：024.php:17-19

攻击者通过 GET 参数 password_new（024.php:7 `$pass_new = $_GET['password_new']`）提交输入。该值在 024.php:13 仅经过 mysqli_real_escape_string 转义，随后在 024.php:14 被 md5() 处理，再于 024.php:18 直接拼接进 UPDATE 语句：`$insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . $current_user . "';"`，最终在 024.php:19 交给 mysqli_query 执行。关键点在于：md5() 会把输入转换为 32 位十六进制字符串，因此 password_new 中的引号、注释符等 SQL 元字符在进入拼接前已被哈希消解，无法闭合 024.php:18 中的单引号，password_new 这一路径实际不可注入。真正未经过滤的是 024.php:18 中拼接的 $current_user（来自 024.php:17 dvwaCurrentUser()），但该值来源于会话/用户表而非本次请求参数，输入中未提供其可控证据。因此本条候选的污点链在 md5 处断裂，证据不足以确认可利用的 SQL 注入。

影响：若成立，可导致 users 表任意改写（含其他账户口令重置）、数据库内容泄露或通过报错信息（024.php:19 的 mysqli_error 回显）获取库结构。但基于现有代码，password_new 路径被 md5 消解，实际影响无法确认。

CVE/CWE 论证：CWE-89。外部可达性：024.php 为 DVWA 口令修改页面，GET 参数无需认证即可提交（取决于部署的会话校验）。但利用链未闭合：source（password_new）在到达 sink 前被 md5() 转换为定长十六进制串，无法注入 SQL 元字符；$current_user 的可控性缺乏证据。故不满足「无需认证 + 利用链闭合」的 CVE 论证条件。

修复建议：即便当前 md5 掩盖了注入，也应修复根因：改用预处理语句（mysqli_prepare + bind_param）绑定 password 与 user 参数，禁止字符串拼接；对 $current_user 同样参数化；关闭 024.php:19 的 mysqli_error 回显，改为记录日志并返回通用错误；同时将 md5 替换为 password_hash()（PASSWORD_BCRYPT/ARGON2）。

F-2 DVWA 密码修改接口仅用 HTTP_REFERER 做来源校验，可被 CSRF 绕过并接管账户

high csrf / CWE-352 · 置信度 0.85 · candidate / llm_inferred

位置：024.php:3-19

024.php 在收到 `Change` 参数时执行密码修改：读取 `password_new`/`password_conf`（第7-8行），比较一致后 md5 并 UPDATE 当前用户密码（第14-19行）。唯一的“来源校验”是第5行 `stripos($_SERVER['HTTP_REFERER'], $_SERVER['SERVER_NAME']) !== false`，即只要 Referer 字符串中任意位置包含服务器名即通过。攻击者可构造 Referer 包含目标域名的页面（如 `http://attacker.com/?TARGET` 或子串包含），或利用 Referer 缺失/可控场景，诱导已登录受害者访问，从而在无 CSRF token 的情况下修改其密码，实现账户接管。

影响：攻击者可在受害者不知情下修改其账户密码，实现账户接管。

CVE/CWE 论证：CWE-352 跨站请求伪造：密码修改操作无 CSRF token，仅依赖可伪造的 Referer 子串校验，外部可触发。

修复建议：引入随机 CSRF token 并在服务端校验；不要依赖 Referer 做安全判断；密码修改要求重新输入旧密码。

F-4 024.php 使用 MD5 存储口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.8 · candidate / rule_verified+llm

位置：024.php:13-14

024.php:14 执行 `$pass_new = md5( $pass_new );`，将用户新口令以无盐 MD5 单轮哈希后写入 users 表（024.php:18-19）。MD5 属快速哈希，抗碰撞与抗暴力能力均不足，且此处未加盐、未使用迭代 KDF。攻击者一旦通过数据库泄露、备份或 SQL 注入读取到哈希值，可用彩虹表/GPU 离线爆破在极短时间内还原常见口令。注意：该弱点本质是弱哈希（CWE-328），而非弱加密算法（CWE-327）。

影响：口令哈希可被离线快速破解，导致账户接管；相同口令产生相同哈希，便于横向撞库与用户枚举。

CVE/CWE 论证：CWE-328（Use of Weak Hash）。配置/实现型弱点，无需 HTTP 污点链即可成立：算法名与调用点（024.php:14 md5）为原文证据。外部可达性：任何通过该页面设置口令的用户都会生成 MD5 哈希，无需特殊权限。

修复建议：改用 password_hash($pass_new, PASSWORD_DEFAULT)（bcrypt/Argon2id）生成带盐、可调成本的哈希，校验用 password_verify()；对历史 MD5 记录在用户下次登录时透明升级；禁止在 SQL 中直接拼接哈希值，配合预处理语句。
