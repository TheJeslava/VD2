F-1 056.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：056.php:15-17

攻击者通过 HTTP 请求向 056.php 提交留言板表单，外部输入在 056.php:5 被读入变量 $message（候选标注为 query `mtxMessage`），随后在 056.php:16 被直接字符串拼接进 INSERT 语句：$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";，其中 $message 位于单引号字符串字面量内部，未做 mysqli_real_escape_string 转义、未使用预处理语句/参数绑定，也未做类型或白名单校验。拼接后的 $query 在 056.php:17 交给 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行，污点从输入到 SQL 执行引擎全程未被净化，因此单引号可闭合 VALUES 中的字符串字面量并注入任意 SQL 片段（如通过 ') 闭合后追加子查询或 UNION/堆叠语句，具体受 mysqli_query 单语句限制影响）。此外 056.php:17 的 or die(... mysqli_error(...) ...) 会把数据库错误信息回显到响应中，为布尔/报错型注入提供回显通道。

影响：数据库注入可导致 guestbook 表及同库其他表的任意读写：攻击者可插入/篡改/删除留言数据，借助报错回显与 UNION 类技巧枚举数据库结构、读取敏感表内容（数据泄露），在数据库账号权限过高时还可能通过文件写入或堆叠语句扩大影响。由于注入点位于公开留言提交功能，未认证用户即可利用。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：注入点为 056.php 的留言提交入口，读取请求参数（056.php:5），无需登录或特权；利用链闭合：外部输入 → $message（056.php:5）→ 字符串拼接 $query（056.php:16）→ mysqli_query 执行（056.php:17），中间无转义、无参数化、无白名单，且错误信息回显（056.php:17）辅助确认注入结果。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：1) 改用预处理语句与参数绑定：$stmt = mysqli_prepare($link, "INSERT INTO guestbook (comment, name) VALUES (?, ?)"); mysqli_stmt_bind_param($stmt, 'ss', $message, $name); mysqli_stmt_execute($stmt);，彻底消除拼接。2) 若短期无法改造，至少对 $message/$name 使用 mysqli_real_escape_string 并配合正确的字符集设置，但这只是缓解措施。3) 关闭错误回显：生产环境不要将 mysqli_error/mysqli_connect_error 输出到响应，改为记录到服务端日志。4) 对输入做长度与字符白名单校验，数据库账号遵循最小权限（仅授予 guestbook 表 INSERT 权限）。
