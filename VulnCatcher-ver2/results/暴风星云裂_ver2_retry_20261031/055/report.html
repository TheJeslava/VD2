F-1 055.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：055.php:17-19

攻击者通过 HTTP 请求向 055.php 提交留言表单，外部输入在 055.php:5 被读取为 `mtxMessage`（留言内容），随后在 055.php:18 被直接拼接进 SQL 语句：`$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";`，其中 `$message` 与 `$name` 均以单引号包裹的字符串字面量形式嵌入，未做任何转义或参数化。该拼接后的 `$query` 在 055.php:19 交给 `mysqli_query($GLOBALS["___mysqli_ston"], $query)` 执行。由于输入中的单引号可闭合字符串字面量，攻击者可构造如 `' , (SELECT ...))-- -` 之类的载荷改写 INSERT 的列值或追加子查询，从而控制 SQL 语义。校验无效的原因：代码路径中不存在 `mysqli_real_escape_string`、`addslashes`、白名单过滤或预处理语句，污点从读取点到汇点全程未净化。

影响：数据库写入内容可被攻击者任意控制，可向 guestbook 表注入伪造记录、通过子查询读取其他表数据（如用户表、凭据）并写入可回显的 comment 字段造成数据泄露；结合 055.php:19 的 `or die(mysqli_error(...))` 错误回显，攻击者可利用报错注入逐字节提取数据库结构、库名、表名与敏感数据，属于机密性/完整性双重破坏。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：055.php 为 Web 可访问脚本，留言提交为公开表单，无需认证即可触发；利用链闭合：055.php:5 读取 `mtxMessage` → 055.php:18 字符串拼接进 `$query` → 055.php:19 `mysqli_query` 执行，且 055.php:19 的 `die(mysqli_error(...))` 提供错误回显通道，使盲注/报错注入均可落地。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：改用预处理语句与参数绑定：`$stmt = mysqli_prepare($link, "INSERT INTO guestbook (comment, name) VALUES (?, ?)"); mysqli_stmt_bind_param($stmt, 'ss', $message, $name); mysqli_stmt_execute($stmt);`。若必须动态拼接，至少对每个值使用 `mysqli_real_escape_string($link, $value)` 并强制字符集；同时移除 055.php:19 中向客户端回显 `mysqli_error()` 的 `die(...)`，改为记录服务端日志并返回通用错误页；对留言长度与字符集做白名单校验，数据库账号遵循最小权限（仅 INSERT 权限）。
