F-1 056.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：056.php:15-17

攻击者通过 HTTP 请求向 056.php 提交留言内容（源码中对应变量 $message，候选描述里写作 query `mtxMessage`，即请求参数 mtxMessage），该值在 056.php:5 被读入后未做任何转义或参数化处理，于 056.php:16 被直接拼接进 SQL 字符串：$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";，随后在 056.php:17 交给 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行。由于 $message 被包裹在单引号内且未调用 mysqli_real_escape_string 或使用预处理语句，攻击者只需在参数中闭合单引号即可跳出字符串上下文，改写 INSERT 语句结构（例如追加子查询、改变 VALUES 表达式，或利用报错回显做布尔/报错注入）。校验无效的原因是该路径上不存在白名单、类型转换或转义函数，污点从读取点直达执行点。

影响：数据库写入逻辑可被攻击者任意改写：可向 guestbook 表注入任意内容（存储型二次风险）、通过报错信息（056.php:17 的 die() 会回显 mysqli_error）泄露数据库结构、库名、表名与版本；结合堆叠/子查询可读取其他表数据，造成数据泄露与数据完整性破坏。若数据库账户权限过高，还可进一步写入文件或篡改业务数据。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素的不当中和）。外部可达性：056.php 为可直接 HTTP 访问的脚本，注入点为请求参数 mtxMessage，无需认证即可提交；利用链闭合：056.php:5 读取外部输入 → 056.php:16 字符串拼接构造 $query → 056.php:17 mysqli_query 执行，中间无净化函数，且 die(mysqli_error(...)) 提供报错回显通道，满足未授权远程利用条件。

修复建议：1) 改用预处理语句：$stmt = $mysqli->prepare("INSERT INTO guestbook (comment, name) VALUES (?, ?)"); $stmt->bind_param('ss', $message, $name); $stmt->execute();；2) 若必须拼接，至少对 $message、$name 使用 mysqli_real_escape_string 并配合正确的字符集设置；3) 对输入做长度与字符白名单校验；4) 关闭错误回显，将 mysqli_error 写入服务端日志而非返回给客户端；5) 数据库账户遵循最小权限，仅授予 guestbook 表的 INSERT 权限。
