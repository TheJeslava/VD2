F-1 037.php 基于 query 参数 id 的 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：037.php:11-13

攻击者通过 HTTP 请求的 query 参数 `id` 提供输入（037.php:5 读取该参数），该值未经任何转义或类型校验即被拼接进 SQL 语句：037.php:11 构造 `$query = "SELECT first_name, last_name FROM users WHERE user_id = '$id' LIMIT 1;"`，将 `$id` 直接放入单引号字符串字面量中；随后在 037.php:13 通过 `mysqli_query($GLOBALS["___mysqli_ston"], $query)` 执行。由于 `$id` 未经过 `mysqli_real_escape_string`、整型强制转换或预处理语句参数化，单引号可闭合 `user_id = '...'` 字面量，从而注入任意 SQL 片段（如 `' OR '1'='1`、`' UNION SELECT ...`）。代码注释显示已移除 `or die` 以抑制 MySQL 错误回显，但这只是隐藏报错，并不构成任何输入校验，注入仍然成立。

影响：数据库查询逻辑可被任意篡改：可绕过 `user_id` 条件枚举/拖取 users 表全部记录（数据泄露），可通过 UNION 读取其他表（如凭据、会话数据），在数据库账户权限较高时可进一步读写文件或造成数据破坏。属于未授权远程可利用的 SQL 注入。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：注入点为 HTTP query 参数 `id`，无需认证即可访问 037.php；利用链闭合：037.php:5 读取 `id` → 037.php:11 字符串拼接进 `$query` → 037.php:13 `mysqli_query` 执行，中间无有效净化或参数化，攻击者输入直达 SQL 解析器。

修复建议：改用预处理语句与参数绑定：`$stmt = $mysqli->prepare('SELECT first_name, last_name FROM users WHERE user_id = ? LIMIT 1'); $stmt->bind_param('i', $id); $stmt->execute();`，并对 `id` 做整型校验（如 `filter_var($id, FILTER_VALIDATE_INT)`）。若必须拼接，至少使用 `mysqli_real_escape_string` 并加引号包裹，但优先参数化。同时为数据库账户配置最小权限，避免 FILE 等高风险权限。
