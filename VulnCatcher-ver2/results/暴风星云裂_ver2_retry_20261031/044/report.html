F-1 044.php 不安全文件上传导致任意文件写入（CWE-434）

critical file_upload / CWE-434 · 置信度 0.6 · candidate / rule_verified+llm

位置：044.php:7-9

攻击者通过 multipart/form-data 向 044.php 提交文件字段 `uploaded`，PHP 将临时文件路径放入 `$_FILES['uploaded']['tmp_name']`。044.php:9 直接调用 `move_uploaded_file($_FILES['uploaded']['tmp_name'], $target_path)` 把该临时文件移动到 `$target_path`，在给出的代码片段（044.php:7-9）中未见任何扩展名白名单、MIME 校验、文件内容检查或 `$target_path` 的规范化/固定目录约束，因此上传文件的原始文件名/路径与内容均未受控校验即落盘。校验无效的原因：唯一的安全相关操作是 `move_uploaded_file` 本身，它只保证源是合法上传临时文件，并不限制目标路径与文件类型；`$target_path` 的构造逻辑位于片段之外（044.php:1-6 未在证据中给出），其是否由用户可控文件名拼接无法从现有证据确认，属于证据不足部分。

影响：若 `$target_path` 落在 Web 可访问目录且保留可执行扩展名（如 .php），攻击者可上传 webshell 实现远程代码执行；即使不可执行，也可造成任意文件覆盖写入、磁盘占用与内容篡改。具体可利用性取决于 `$target_path` 的构造方式与目录可访问性，该部分证据不足。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部可达性：044.php 为可直接 HTTP 访问的脚本，上传字段 `uploaded` 无需认证即可提交（片段中未见任何鉴权/会话校验）。利用链闭合度：source（`$_FILES['uploaded']['tmp_name']`）→ sink（`move_uploaded_file`，044.php:9）在片段内闭合；但目标路径 `$target_path` 的赋值未在证据中给出，故「写入 Web 目录并可执行」这一环为推断而非已验证，置信度相应下调。

修复建议：1) 使用扩展名白名单（如仅 jpg/png/pdf）并基于服务端解析的真实 MIME 与文件头校验，不信任 `$_FILES['uploaded']['type']` 与客户端文件名；2) 目标文件名由服务端生成（UUID + 白名单扩展名），禁止将用户文件名拼入 `$target_path`；3) 用 `basename()` 剥离路径并用 `realpath()` 校验最终路径位于固定上传目录内，防止路径穿越；4) 上传目录置于 Web 根之外，或通过 Nginx/Apache 配置禁止该目录执行脚本（`php_flag engine off` / `location ~ \.php$ { deny all; }`）；5) 限制文件大小与类型，上传后重命名并去除可执行权限。

F-2 DVWA 044.php 无限制文件上传导致任意 PHP 文件写入 Web 目录（RCE）

high file_upload / CWE-434 · 置信度 0.93 · candidate / llm_inferred

位置：044.php:3-16

044.php 在收到 POST 参数 Upload 时，直接取 $_FILES['uploaded']['name'] 经 basename() 处理后拼接到 DVWA_WEB_PAGE_TO_ROOT."hackable/uploads/" 目录，并调用 move_uploaded_file() 落盘。全程没有扩展名白名单、MIME 校验、getimagesize 检查、文件大小限制或随机重命名，攻击者可上传 .php 文件到 Web 可访问目录并直接请求执行，形成远程代码执行。

影响：攻击者可在 Web 目录写入任意 PHP 代码并执行，获得服务器命令执行权限，完全控制应用与主机。

CVE/CWE 论证：CWE-434 Unrestricted Upload of File with Dangerous Type。外部可直接通过 HTTP multipart 触发，无需认证（脚本本身无鉴权），source→sink 链在 044.php:3-9 完整闭合，落盘目录位于 Web 根下可被直接请求执行。

修复建议：实施扩展名白名单（仅允许图片类型）、校验 MIME 与 getimagesize、随机重命名文件、将上传目录置于 Web 根之外或禁用该目录 PHP 执行（php_flag engine off / Nginx location 拒绝 .php），并加入认证与 CSRF 防护。
