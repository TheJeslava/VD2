F-1 020.php POST 参数 include 未编码直接拼入 <script src> 导致反射型 XSS（CSP 白名单可绕过）

high xss / CWE-79 · 置信度 0.88 · candidate / llm_inferred

位置：020.php:13-17

020.php 第 13-17 行读取 $_POST['include']，未做任何 HTML 实体编码或 URL 白名单校验，直接以单引号包裹拼入 <script src='...'></script> 并输出到页面。攻击者可注入单引号闭合 src 属性，插入任意 HTML/事件处理器（如 onerror、onload）或额外 <script> 标签，实现反射型 XSS。页面虽在第 3-5 行设置了 CSP（script-src 白名单），但白名单包含 unpkg.com、cdn.jsdelivr.net、pastebin.com 等可托管任意 JS 的公共 CDN，且注入点本身允许内联事件属性（CSP 未设置 script-src-attr 'none'，也未使用 nonce/hash），因此 CSP 无法阻止利用。

影响：在受害者浏览器上下文执行任意 JavaScript，可窃取会话 Cookie/令牌、伪造请求执行敏感操作、篡改页面内容；CSP 因白名单含公共 CDN 且未限制内联属性而无法缓解。

CVE/CWE 论证：CWE-79 跨站脚本。外部可达（HTTP POST 参数 include），无需认证，source→sink 链在 020.php:13-17 完整闭合，无输出编码，CSP 可绕过。

修复建议：对 $_POST['include'] 使用 htmlspecialchars($v, ENT_QUOTES, 'UTF-8') 编码后再输出；更佳做法是解析 URL 并校验 scheme/host 是否在严格白名单内，仅允许 https 且主机精确匹配；CSP 增加 script-src-attr 'none' 或使用 nonce/hash，移除可托管任意 JS 的公共 CDN 域。

F-2 020.php 中 $_POST['include'] 直接拼入 <script src> 属性（输出注入/路径穿越候选）

high path_traversal / CWE-22 · 置信度 0.45 · candidate / rule_verified+llm

位置：020.php:13-15

020.php 第 13-15 行：`if (isset ($_POST['include'])) { $page['body'] .= "<script src='" . $_POST['include'] . "'></script>"; }`。攻击者通过 POST 参数 `include` 提交的值被原样拼接进 `<script src='...'>` 的单引号属性中，未做 HTML 属性编码、URL 校验或路径规范化。由于属性使用单引号包裹，提交含单引号的值可闭合属性并注入任意 HTML/JS（存储或反射取决于 `$page['body']` 的输出时机，片段未展示输出点）。同时该值作为脚本 URL，可指向攻击者控制的域或 `../` 相对路径，构成客户端路径/资源加载操纵。

影响：可导致反射型/存储型 XSS（在受害者浏览器执行任意脚本、窃取会话），或通过 `src` 指向外部恶意脚本实现脚本注入；若该值同时被服务端用于文件定位，则可能演变为路径穿越。

CVE/CWE 论证：CWE-79（跨站脚本）/ CWE-22（路径穿越）。外部可达性：POST 参数 `include` 无需认证；利用链在片段内闭合（输入→字符串拼接→HTML 属性输出），但最终响应输出点未在片段中给出，故为推断级。

修复建议：对输出到 HTML 属性的值使用 `htmlspecialchars($v, ENT_QUOTES, 'UTF-8')`；对 `src` 使用 URL 白名单或固定前缀校验；避免将用户输入直接拼入标签属性，改用模板引擎自动转义。
