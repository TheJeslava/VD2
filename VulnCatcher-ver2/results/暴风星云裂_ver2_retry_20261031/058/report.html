F-1 058_05.php 登录查询 username 参数 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：058_05.php:29-31

攻击者通过 HTTP 请求的 query 参数 `username` 输入（058_05.php:25 读取），该值未经任何转义或参数化即被拼接进 SQL 语句：058_05.php:30 `$sql = "select count(*) from users where username='$username'"`，随后在 058_05.php:31 交由 `mysql_query($sql)` 执行。由于 `$username` 被直接放入单引号字符串上下文，攻击者可闭合引号并注入任意 SQL 片段（如 `' OR '1'='1`、`' UNION SELECT ...`），校验完全缺失，污点直达数据库执行汇点。

影响：数据库查询逻辑被完全控制：可绕过登录/计数校验、通过 UNION 读取 users 表及其他表数据（口令、用户信息泄露），并可结合 mysql 权限进行数据篡改。错误信息经 `die()` 回显，可辅助盲注/报错注入。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达：`username` 来自 HTTP query，无需认证即可触发；利用链闭合：058_05.php:25 取值 → 058_05.php:30 字符串拼接 → 058_05.php:31 `mysql_query` 执行，中间无白名单、转义或预处理。

修复建议：改用 PDO/MySQLi 预处理语句并绑定参数，例如 `$stmt = $pdo->prepare('select count(*) from users where username = ?'); $stmt->execute([$username]);`；禁止字符串拼接 SQL；对输入做长度与字符白名单校验；关闭 `mysql_error()` 细节回显，统一错误页；升级已废弃的 `mysql_*` 扩展。

F-2 058_06.php 登录认证 username/password 参数 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：058_06.php:22-24

攻击者通过 query 参数 `login_user` 相关输入（058_06.php:20 读取 `$username`、`$password`）提交数据，二者未经转义直接拼接进认证 SQL：058_06.php:22 `$sql = "SELECT * FROM users WHERE username='$username' and password='$password'"`，在 058_06.php:24 由 `mysql_query($sql)` 执行。单引号上下文可被闭合，攻击者可用 `' OR '1'='1' -- ` 之类载荷绕过口令校验，或以 UNION 注入读取任意数据。

影响：认证绕过（无需正确口令即可登录任意账户，包括管理员），并通过 UNION/报错注入读取 users 表及其他表数据，造成账户接管与敏感数据泄露。

CVE/CWE 论证：CWE-89。外部可达：`username`/`password` 来自 HTTP query，登录接口无需前置认证；利用链闭合：058_06.php:20 取值 → 058_06.php:22 拼接 → 058_06.php:24 `mysql_query` 执行，无预处理、无转义、无类型约束。

修复建议：使用预处理语句绑定 `username`、`password` 参数；口令以强哈希（如 password_hash/bcrypt）存储并比对，而非明文拼接查询；对输入做白名单与长度限制；移除 `die()` 中的数据库错误回显；废弃 `mysql_*` 扩展。

F-3 058_08.php 修改口令 current_password 参数 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：058_08.php:37-39

攻击者在修改口令流程中通过 query 参数 `current_password`（058_08.php:32 读取 `$curr_pass`，同时涉及 `$username`、`$pass`）提交输入，未经转义即拼接进 UPDATE 语句：058_08.php:38 `$sql = "UPDATE users SET PASSWORD='$pass' where username='$username' and password='$curr_pass' "`，在 058_08.php:39 由 `mysql_query($sql)` 执行。攻击者可闭合引号注入，篡改 WHERE 条件或追加语句，从而在不知道原口令的情况下修改任意用户口令。

影响：越权修改任意账户（含管理员）口令，导致账户接管；亦可利用报错/联合注入读取数据库内容。属于写操作注入，破坏数据完整性。

CVE/CWE 论证：CWE-89。外部可达：`current_password` 等参数来自 HTTP query，修改口令接口可被未认证或低权限用户直接调用；利用链闭合：058_08.php:32 取值 → 058_08.php:38 拼接 UPDATE → 058_08.php:39 `mysql_query` 执行，无参数化与转义。

修复建议：使用预处理语句绑定 `$pass`、`$username`、`$curr_pass`；在服务端会话中取当前用户身份而非信任请求参数中的 `username`；校验旧口令使用哈希比对；限制 UPDATE 影响行数并记录审计日志；移除数据库错误回显。

F-4 058_05.php 用户注册 username/pass 参数 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.73 · candidate / rule_verified+llm

位置：058_05.php:47-49

攻击者在注册流程中通过 query 参数 `username`（058_05.php:25 读取，另含 `$pass`）提交输入，未经转义即拼接进 INSERT 语句：058_05.php:48 `$sql = "insert into users ( username, password) values(\"$username\", \"$pass\")"`，在 058_05.php:49 由 `mysql_query($sql)` 执行。此处使用双引号包裹值，攻击者可用 `"` 闭合并注入额外列值或子查询，例如插入自定义口令的管理员账户，或通过报错信息泄露数据。

影响：可向 users 表插入任意内容（如伪造管理员账户实现提权/持久化），并通过 `mysql_error()` 回显进行报错注入读取数据库；破坏数据完整性并可能导致账户接管。

CVE/CWE 论证：CWE-89。外部可达：注册接口的 `username`/`pass` 来自 HTTP query，无需认证；利用链闭合：058_05.php:25 取值 → 058_05.php:48 双引号字符串拼接 → 058_05.php:49 `mysql_query` 执行，无预处理与转义。

修复建议：使用预处理语句绑定注册字段；对 `username` 施加字符白名单与唯一性约束；口令使用 `password_hash` 存储；移除 `mysql_error()` 回显；对注册接口增加限流与验证码。

F-5 058_06.php 登录逻辑使用客户端可控 Cookie Auth=1 作为认证凭据，可伪造登录态

high auth_bypass / CWE-287 · 置信度 0.8 · candidate / llm_inferred

位置：058_06.php:40-46

058_06.php 登录成功后仅设置 setcookie("Auth", 1, ...)（第 44 行），而 058_01.php/058_04.php/058_08.php 的访问控制仅检查 isset($_COOKIE["Auth"])（如 058_08.php:7、058_01.php:3、058_04.php:3），并不校验其值或与会话绑定。攻击者无需任何凭据，直接构造 Cookie: Auth=1 即可通过所有受保护页面的认证检查，访问登录后功能（改密页、登录成功页等）。

影响：未认证攻击者可访问登录后功能页面，结合二次注入可进一步接管账户。

CVE/CWE 论证：CWE-287/CWE-565 认证绕过（依赖客户端可控 Cookie）。外部无需凭据即可触发，链路闭合。

修复建议：认证状态完全依赖服务端 $_SESSION，移除对客户端 Cookie 存在性的信任；Cookie 仅作辅助且需签名校验。
