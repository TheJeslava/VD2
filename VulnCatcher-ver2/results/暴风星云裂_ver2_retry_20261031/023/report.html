F-1 023.php 修改密码功能 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：023.php:15-17

攻击者通过 HTTP 请求向 023.php 提交修改密码表单，输入从 query 参数 `password_conf`（023.php:6）进入脚本。该值被直接拼进 SQL 语句：023.php:16 构造 `$insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . $current_user . "';";`，其中 `$pass_new` 来自 `password_conf` 且未做任何转义或参数化；随后 023.php:17 调用 `mysqli_query($GLOBALS["___mysqli_ston"], $insert)` 执行。由于拼接发生在引号内部，攻击者可闭合单引号注入任意 SQL 片段（如 `' , user='admin' -- ` 改写任意用户口令，或用布尔/时间盲注读取数据）。代码中未见 mysqli_real_escape_string、预处理语句或白名单校验，因此校验无效。注意：`$current_user` 来自 dvwaCurrentUser()（023.php:15），属会话派生值，不是本 finding 的注入点；注入点为 `password_conf`。

影响：数据库任意读写：可越权修改任意用户（含 admin）的密码从而接管账户，或通过 UNION/盲注导出 users 表中的用户名与口令哈希，造成敏感数据泄露与权限提升；若数据库账户权限过高，还可能进一步读写文件。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：023.php 为 Web 可访问脚本，`password_conf` 为请求参数，无需认证即可到达拼接点（是否要求登录取决于外层会话校验，但注入点本身无输入校验）；利用链闭合：`password_conf` → `$pass_new` → `$insert`（023.php:16）→ `mysqli_query`（023.php:17），全程无净化，属典型一次注入，非二次注入。

修复建议：改用参数化查询：`$stmt = $db->prepare("UPDATE users SET password = ? WHERE user = ?"); $stmt->bind_param('ss', $pass_new, $current_user); $stmt->execute();`；若必须拼接，至少使用 mysqli_real_escape_string 并配合白名单校验；同时关闭 `or die(mysqli_error(...))` 的详细报错回显，避免错误信息泄露表结构；数据库账户遵循最小权限，禁止 FILE 权限。
