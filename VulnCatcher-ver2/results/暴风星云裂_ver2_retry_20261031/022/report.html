F-1 022.php 密码修改功能 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.73 · candidate / rule_verified+llm

位置：022.php:42-44

攻击者通过 HTTP 请求向 022.php 提交修改密码的表单，外部输入在 022.php:26 处被读取为 `password_conf`（密码确认字段），随后在 022.php:43 被直接字符串拼接进 UPDATE 语句：`$insert = "UPDATE `users` SET password = '" . $pass_new . "' WHERE user = '" . $current_user . "';"`，其中 `$pass_new` 来自该外部输入，未做 mysqli_real_escape_string 转义、未使用预处理语句、也未做类型/白名单校验；`$current_user` 由 dvwaCurrentUser() 提供（022.php:42）。拼接完成的 `$insert` 在 022.php:44 交给 `mysqli_query($GLOBALS["___mysqli_ston"], $insert)` 执行，污点从输入到 SQL 执行汇点全程无有效净化，构成一次注入。

影响：攻击者可构造 `$pass_new` 闭合单引号并注入任意 SQL，从而改写 users 表中任意用户（含 admin）的密码、读取数据库内容或通过堆叠/子查询扩展影响范围，导致账户接管与数据库数据泄露；由于该语句本身即 UPDATE，注入可直接造成持久化数据篡改。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：022.php 为 Web 可访问脚本，输入来自请求参数 `password_conf`，无需认证即可到达拼接点（若部署在 DVWA 中则受其登录态约束，但代码层面无鉴权与转义）。利用链闭合：source（022.php:26 `password_conf`）→ 拼接（022.php:43 `$insert`）→ sink（022.php:44 `mysqli_query`），中间无参数化、无转义、无白名单，链路完整。

修复建议：改用参数化查询（mysqli_prepare + bind_param 或 PDO 预处理），将 `$pass_new` 与 `$current_user` 作为绑定参数传入；对密码字段做长度与字符集白名单校验；对 `$current_user` 使用会话内服务端取值而非可拼接字符串；数据库账户遵循最小权限，禁止多语句执行（关闭 mysqli 多语句）。

F-2 022.php JSON 请求体读取被误判为路径穿越（证据不足）

high path_traversal / CWE-22 · 置信度 0.4 · candidate / rule_verified+llm

位置：022.php:6-8

候选将 022.php:8 的 `$data = json_decode(file_get_contents('php://input'), true);` 标记为 path_traversal 汇点。但该处 `file_get_contents` 的参数是固定字面量 `php://input`，并非来自外部输入的可控路径；外部输入是 POST body 内容，经 `json_decode` 解析为数组 `$data`，不构成对文件系统路径的控制。022.php:7 仅校验请求方法为 POST 且 CONTENT_TYPE 为 application/json。因此 source（body `*`）到 sink（固定 `php://input` 读取）之间不存在路径可控的污点链，该候选不成立。

影响：证据不足：当前代码片段中不存在由外部输入控制文件路径并到达文件读写操作的链路，无法论证任意文件读取/写入影响。若后续代码（022.php:8 之后）将 `$data` 中的键值用于拼接文件路径，需另行提供对应行号证据方可成立。

CVE/CWE 论证：CWE-22 不成立：sink 处路径为常量 `php://input`，攻击者无法改变读取目标；缺少“外部可控路径 → 文件操作”的必要环节，利用链不闭合。

修复建议：无需针对该行修复路径穿越；建议保留对 JSON 解析失败与字段类型的校验，并在后续若使用 `$data` 中的值构造文件路径时，采用白名单文件名、basename() 规范化与固定根目录拼接。
