F-1 010.php 登录查询 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.73 · candidate / rule_verified+llm

位置：010.php:18-20

攻击者通过 HTTP 请求向 010.php 提交登录参数，源码在 010.php:8 处从 query 中的 `username` 读取外部输入并赋给 $user（同一处还读取密码参数赋给 $pass）。在 010.php:19 处，程序把 $user 与 $pass 直接字符串拼接进 SQL 语句：`$query = "SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';";`，全程没有使用 mysqli_real_escape_string、预处理语句或类型约束，也没有白名单校验。随后在 010.php:20 处，该拼接结果被直接交给 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行，污点数据由此到达 SQL 执行汇点。由于单引号未被转义，攻击者可在 username 中闭合字符串并注入任意 SQL 片段（例如 `' OR '1'='1' -- `），从而改变 WHERE 条件。此外，010.php:20 的 `or die(... mysqli_error(...))` 会把数据库错误信息回显到页面，构成报错型注入的辅助信息泄露通道。

影响：可绕过登录认证（以 `' OR '1'='1' -- ` 之类载荷使 WHERE 恒真，返回 users 表首行完成登录）；可借助 UNION 查询读取 users 表及其他库表数据，造成敏感数据泄露；结合 mysqli 多语句能力（若驱动允许）可能进一步写入或篡改数据。错误回显还会泄露库名、表结构与 SQL 语法细节，降低后续利用门槛。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：010.php 为可直接请求的登录入口，参数经 HTTP query 传入，无需认证即可触发（注入发生在认证判定之前）。利用链闭合：010.php:8 外部输入 → $user/$pass → 010.php:19 字符串拼接 → 010.php:20 mysqli_query 执行，中间无任何净化函数，链路完整。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：改用参数化查询：`$stmt = mysqli_prepare($GLOBALS["___mysqli_ston"], "SELECT * FROM `users` WHERE user = ? AND password = ?"); mysqli_stmt_bind_param($stmt, 'ss', $user, $pass); mysqli_stmt_execute($stmt);`。若暂不能改造，至少对 $user/$pass 使用 mysqli_real_escape_string 并加长度/字符白名单校验。同时移除 010.php:20 中把 mysqli_error 直接输出到页面的逻辑，改为记录服务端日志并返回通用错误提示。口令比对建议使用 password_hash/password_verify，避免明文比较。

F-2 010.php 登录成功页反射型 XSS：username 参数未编码直接拼入 HTML

high xss / CWE-79 · 置信度 0.72 · candidate / llm_inferred

位置：010.php:8-28

010.php 第 8 行从 $_GET['username'] 读取用户输入，仅经过 stripslashes() 与 mysqli_real_escape_string() 处理（这两者只针对 SQL 上下文，不做 HTML 编码），随后在第 28 行被直接拼接进 HTML 输出 "<p>Welcome to the password protected area {$user}</p>"。攻击者可构造 username 含 HTML/JS 的请求，在受害者浏览器中执行任意脚本。触发该分支需要登录成功（$result 且 mysqli_num_rows==1），因此攻击者需知道一组有效凭据或诱导已登录用户点击链接；但一旦命中，脚本在应用同源下执行，可窃取会话、执行 CSRF 令牌读取等操作。

影响：在应用同源下执行任意 JavaScript，可窃取会话 Cookie、读取页面内 CSRF token、以受害者身份发起操作。

CVE/CWE 论证：CWE-79 反射型 XSS。外部 GET 参数直达 HTML 输出，无 HTML 编码，链路闭合；需有效凭据命中成功分支，属可利用但依赖认证条件。

修复建议：输出前对 $user 使用 htmlspecialchars($user, ENT_QUOTES, 'UTF-8') 编码；对 avatar 同样编码。
