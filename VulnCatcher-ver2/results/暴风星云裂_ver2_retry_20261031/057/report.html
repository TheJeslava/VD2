F-1 057.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：057.php:17-19

攻击者通过 HTTP 请求向留言板提交评论/姓名，输入在 057.php:5 处被读取为 `mtxMessage`（留言消息），随后在 057.php:18 被直接字符串拼接进 INSERT 语句：`$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";`，其中 `$message`、`$name` 均以单引号包裹但未做任何转义或参数化。057.php:19 通过 `mysqli_query($GLOBALS["___mysqli_ston"], $query)` 执行该拼接后的 SQL。由于没有使用 `mysqli_real_escape_string`、预处理语句或白名单校验，单引号可闭合字符串字面量，从而注入任意 SQL 片段（如通过 `$message` 注入 `', 'x'); ... -- ` 改变语句结构）。错误信息还会经 `mysqli_error` 回显到页面，进一步辅助注入调试。

影响：数据库写入被任意控制：可向 guestbook 表插入伪造/恶意记录，或通过堆叠/子查询读取其他表数据（数据泄露），在数据库账户权限较高时可导致数据篡改甚至通过文件写入类函数造成进一步危害。属于未认证远程可利用的 SQL 注入。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：留言提交为公开 HTTP 端点，无需认证；污点链闭合：057.php:5 读取外部输入 → 057.php:18 字符串拼接 → 057.php:19 `mysqli_query` 执行，中间无有效净化，满足注入成立条件。

修复建议：改用参数化查询/预处理语句（`mysqli_prepare` + `bind_param`），将 `$message`、`$name` 作为绑定参数传入，禁止字符串拼接；若必须拼接，至少使用 `mysqli_real_escape_string` 并配合严格类型校验；同时关闭生产环境的数据库错误回显（移除 `or die(mysqli_error(...))`），并遵循最小权限原则限制数据库账户权限。
