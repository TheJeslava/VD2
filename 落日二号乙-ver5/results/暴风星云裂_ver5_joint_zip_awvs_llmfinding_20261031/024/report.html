F-1 024.php 修改密码功能 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.63 · candidate / rule_verified+llm

位置：024.php:17-19

攻击者通过 HTTP GET 参数 password_new（024.php:7 `$pass_new = $_GET['password_new'];`）提交输入。该值在 024.php:13 仅经过 mysqli_real_escape_string 转义，随后在 024.php:14 被 md5() 处理，最终在 024.php:18 被直接拼接进 SQL 语句 `UPDATE `users` SET password = '$pass_new' WHERE user = '" . $current_user . "';`，并在 024.php:19 交由 mysqli_query 执行。校验无效的原因：md5() 对输入做的是哈希而非 SQL 转义，哈希结果虽为十六进制字符串，但拼接方式本身未使用参数化查询，且 $current_user 来自 dvwaCurrentUser()（024.php:17）同样以字符串拼接进入 WHERE 子句，未做绑定；一旦该值可被影响（如会话/用户名可控），即可闭合引号注入。此外 024.php:19 的 die() 分支会把 mysqli_error 内容回显到页面，构成报错型注入的信息泄露通道。

影响：可对 users 表执行任意 UPDATE 语义（如改写任意用户口令实现账户接管），并借助 024.php:19 的 mysqli_error 回显进行报错注入，逐字节读取数据库名、表名与 users 表内容（含口令哈希），造成敏感数据泄露与越权。

CVE/CWE 论证：CWE-89：外部可控输入（GET password_new）未经参数化直接进入 SQL 语句并在 024.php:19 执行，属典型一次注入；无需认证即可通过 HTTP 访问该脚本（DVWA 低安全级别下无令牌校验），利用链闭合：source(024.php:7) → 拼接(024.php:18) → sink(024.php:19)。

修复建议：改用预处理语句与参数绑定（mysqli_prepare + bind_param 或 PDO prepared statement），将 password 与 user 均作为占位符参数传入；移除 024.php:19 中向客户端回显 mysqli_error 的逻辑，改为记录服务端日志并返回通用错误；对 $current_user 做白名单/会话内取值校验；口令哈希改用 password_hash()（bcrypt/Argon2）而非 md5。

F-2 DVWA 密码修改功能仅依赖 HTTP_REFERER 校验，可被 CSRF 绕过并接管账户

high csrf / CWE-352 · 置信度 0.9 · candidate / llm_inferred

位置：024.php:3-19

024.php 的密码修改逻辑在 `isset($_GET['Change'])` 时执行，仅通过 `stripos($_SERVER['HTTP_REFERER'], $_SERVER['SERVER_NAME']) !== false` 判断请求来源。HTTP_REFERER 完全由客户端控制，攻击者可构造包含目标域名的 Referer（或利用浏览器策略/子串匹配缺陷）绕过该校验；同时该操作使用 GET 方法、无 CSRF token、无当前密码确认，攻击者诱导已登录受害者访问恶意页面即可把受害者密码改为攻击者指定值，导致账户接管。此外 `stripos` 子串匹配可被 `http://attacker.com/?TARGET_HOST` 形式的 Referer 欺骗。

影响：攻击者可接管任意已登录用户（含管理员）账户，完全控制应用

CVE/CWE 论证：CWE-352 CSRF：状态改变操作无 token、无当前密码确认，仅依赖可伪造的 Referer；外部可触发，链闭合

修复建议：使用 POST + CSRF token；要求输入当前密码；不要依赖 Referer 做安全校验

F-4 024.php 使用 MD5 存储口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.86 · candidate / rule_verified+llm

位置：024.php:13-14

024.php:14 `$pass_new = md5( $pass_new );` 对用户新口令直接使用 MD5 计算摘要，随后在 024.php:18-19 写入 users 表 password 字段。该处为配置/实现型弱点，无需 HTTP 污点链即可成立：算法为 MD5（无盐、单轮、快速），原文证据即 024.php:14 的 md5() 调用。

影响：口令以无盐 MD5 存储，攻击者一旦通过 SQL 注入或数据库泄露获取 password 字段，可用彩虹表/GPU 高速碰撞在极短时间内还原明文口令，进而横向复用至其他账户或系统，造成账户接管。

CVE/CWE 论证：CWE-328（Use of Weak Hash）：MD5 用于口令这一安全用途，属弱哈希而非弱加密（非 CWE-327 的 DES/ECB 类问题）；外部可达性体现在 024.php 的修改口令接口直接调用该逻辑，无需额外权限即可触发写入。

修复建议：改用 password_hash($pass_new, PASSWORD_DEFAULT)（bcrypt/Argon2id）生成带盐慢哈希，校验时用 password_verify()；迁移期可对存量 MD5 值在用户下次登录成功后透明重哈希；禁止在任何安全用途中使用 MD5/SHA-1。
