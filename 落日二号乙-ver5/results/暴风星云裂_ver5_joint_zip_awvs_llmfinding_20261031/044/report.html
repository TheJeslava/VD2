F-1 044.php 不安全文件上传（CWE-434）：上传文件被直接移动到目标路径，缺少扩展名/类型校验

critical file_upload / CWE-434 · 置信度 0.68 · candidate / rule_verified+llm

位置：044.php:7-9

攻击者通过 multipart 表单字段 `uploaded` 提交文件（044.php:9 的 `$_FILES['uploaded']['tmp_name']`）。代码在 044.php:9 直接调用 `move_uploaded_file($_FILES['uploaded']['tmp_name'], $target_path)`，把临时文件移动到 `$target_path`。输入片段中未见任何扩展名白名单、MIME 校验、`getimagesize()` 内容校验或文件名规范化逻辑；`$target_path` 的构造代码不在本次 code_pack 片段内（仅给出第 7-9 行），因此目标目录是否位于 Web 可访问路径、文件名是否由用户可控（如 `$_FILES['uploaded']['name']`）属于证据不足，需结合 044.php 第 1-6 行确认。就已给出的证据看，唯一约束是 `move_uploaded_file` 的返回值判断，它只反映移动是否成功，不构成安全校验。

影响：若 `$target_path` 落在 Web 根目录下且保留原始扩展名，攻击者可上传 `.php` 等可执行脚本，通过 HTTP 请求触发，形成远程代码执行（RCE）；即使不可执行，也可造成任意文件落盘、覆盖已有文件、磁盘占用，以及上传恶意 HTML/JS 用于钓鱼或存储型 XSS。具体影响等级取决于 `$target_path` 的目录位置与命名方式，该部分证据不足。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部可达性：上传入口为 HTTP multipart 请求的 `uploaded` 字段，无需认证（片段中未见任何鉴权/会话检查）。利用链闭合度：source（`$_FILES['uploaded']['tmp_name']`）→ sink（`move_uploaded_file`）在同一行完成，中间无净化函数；但链的最后一环（目标路径可 Web 访问、文件名可控）依赖 044.php 第 1-6 行，当前片段未覆盖，故按 llm_inferred 记录，置信度 0.68。

修复建议：1) 使用扩展名白名单（如仅 jpg/png/gif/pdf），并对上传内容做魔数或 `getimagesize()` 校验，不能只信 `$_FILES['uploaded']['type']`；2) 不要使用用户提供的文件名，改为服务端生成的随机名（如 `bin2hex(random_bytes(16))` + 白名单扩展名）；3) 将上传目录置于 Web 根之外，或在该目录禁用脚本执行（Apache `php_flag engine off` / Nginx `location ~ \.php$ { deny all; }`）；4) 限制文件大小与数量，校验 `is_uploaded_file()`；5) 上传目录设置最小权限，禁止覆盖已有文件。

F-2 DVWA 044.php 无限制文件上传导致任意 PHP 文件写入 Web 目录（RCE）

high file_upload / CWE-434 · 置信度 0.96 · candidate / externally_corroborated

位置：044.php:3-16

044.php 在收到 POST 参数 Upload 时，直接取 $_FILES['uploaded']['name'] 经 basename() 处理后拼接到 DVWA_WEB_PAGE_TO_ROOT . "hackable/uploads/" 目录，并调用 move_uploaded_file() 落盘。全程没有扩展名白名单、MIME 校验、getimagesize() 图像校验、文件大小限制或随机重命名，攻击者可上传 .php 文件到 Web 可访问的 hackable/uploads/ 目录，随后直接请求该文件即可执行任意 PHP 代码，形成远程代码执行。

影响：未认证攻击者可在 Web 根目录写入并执行任意 PHP 代码，完全控制服务器（读取配置、数据库凭据、横向移动）。

CVE/CWE 论证：CWE-434 Unrestricted Upload of File with Dangerous Type。外部 HTTP 可达、无需认证、source→sink 链在 044.php:3-9 完整闭合，落盘路径位于 Web 可访问目录且响应回显路径，可直接触发 RCE。

修复建议：使用扩展名白名单（仅允许图片等安全类型）、校验 MIME 与 getimagesize()、随机重命名文件、将上传目录置于 Web 根之外或禁止该目录执行 PHP（php_flag engine off / location 拒绝 .php），并加入认证与 CSRF 校验。
