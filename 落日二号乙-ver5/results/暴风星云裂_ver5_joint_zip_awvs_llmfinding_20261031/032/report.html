F-2 客户端令牌生成使用 MD5 弱哈希（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.66 · candidate / rule_verified+llm

位置：032.php:17-18

在 032.php 第 17-18 行，页面脚本从 DOM 元素 phrase 读取用户输入（var phrase = document.getElementById("phrase").value），随后执行 document.getElementById("token").value = md5(rot13(phrase))，把结果写入隐藏/表单字段 token。也就是说，令牌值完全由客户端 JavaScript 用 MD5 计算得出，且输入仅经过 ROT13（一种可逆的字符替换，不提供任何密码学强度）处理。攻击者可直接在浏览器控制台或本地脚本中复现同一算法：读取或猜测 phrase、执行 rot13 后做 MD5，即可离线生成任意合法 token，无需知道任何服务端密钥。校验无效的根因是：令牌的机密性与不可预测性依赖客户端算法，而 MD5 已被证明存在碰撞攻击且计算极快，ROT13 不引入任何熵，因此该令牌不具备抗伪造能力。最终危险操作是把可预测的弱哈希值作为 token 提交给服务端做身份/防伪校验。注意：本结论基于 code_pack 中给出的 032.php 片段，服务端如何比对 token 的代码未在输入中提供，故服务端校验逻辑属证据不足。

影响：令牌可被离线伪造：攻击者无需认证即可为任意 phrase 生成匹配的 token，从而绕过基于该 token 的防伪/会话/表单保护，导致越权提交、请求伪造或业务逻辑绕过。若该 token 被用作口令派生或签名，还会造成凭据可预测与离线爆破（MD5 高速计算）。具体业务影响取决于服务端对 token 的信任程度，该部分证据不足。

CVE/CWE 论证：CWE-328（Use of Weak Hash）：MD5 属已知弱哈希，用于令牌生成时无法提供抗碰撞与抗预测性；同时 ROT13 为可逆替换而非加密，不增加熵。外部可达性：032.php 为可通过浏览器访问的页面，脚本在客户端执行，任何访问者均可读取并复现算法，无需认证。利用链闭合：攻击者控制 phrase → rot13(phrase) → md5(...) → 写入 token 字段 → 提交，全链在客户端完成，不依赖服务端秘密。

修复建议：1) 停止在客户端生成安全令牌，改由服务端使用 CSPRNG（如 Java SecureRandom、Node crypto.randomBytes）生成至少 128 位随机令牌并绑定会话；2) 若必须做完整性校验，使用 HMAC-SHA-256 并以服务端密钥签名，替代裸 MD5；3) 移除 ROT13 这类可逆混淆，避免误当作保护措施；4) 服务端对 token 做一次性校验（nonce + 过期时间）并常量时间比较；5) 对已使用 MD5 的历史令牌做失效与轮换。
