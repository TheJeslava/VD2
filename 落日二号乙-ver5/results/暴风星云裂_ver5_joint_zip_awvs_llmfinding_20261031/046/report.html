F-1 046.php 会话标识由递增计数器派生，可预测（CWE-330）

high weak_id / CWE-330 · 置信度 0.73 · candidate / externally_corroborated

位置：046.php:5-6

046.php:5 判断 REQUEST_METHOD 为 POST 后，046.php:6 检查 $_SESSION['last_session_id_high'] 是否存在，不存在则在 046.php:7 置为 0，随后 046.php:9 自增、046.php:10 用 md5 派生 Cookie 值。会话标识的熵来源仅为服务端会话中的一个单调递增整数，攻击者可通过一次合法请求获得当前值，再线性推算前后所有取值；代码中没有任何随机数、时间抖动或服务端白名单校验来阻止伪造值被接受。

影响：攻击者可预测并伪造 dvwaSession 会话标识，实现会话固定/会话预测攻击，冒充其他用户身份访问受保护功能，造成越权与敏感数据泄露；由于 Cookie 未设置 secure/httponly，还可结合明文信道窃取进一步扩大影响。

CVE/CWE 论证：CWE-330（Use of Insufficiently Random Values）：会话标识取值空间为可枚举的整数序列，不满足不可预测性要求。外部可达性：046.php 为可直接访问的 Web 脚本，POST 即触发；无需认证即可获取样本并推算；利用链闭合：请求 → 计数器自增 → md5 派生 → setcookie 下发 → 攻击者构造同构值回放。

修复建议：使用 CSPRNG（random_bytes / random_int）生成至少 128 位熵的会话标识，或直接依赖 PHP session 并调用 session_regenerate_id(true) 在登录后轮换；服务端维护已签发令牌集合并做恒定时间校验；为 Cookie 设置 secure、httponly 与 SameSite 属性；避免使用自增计数器作为任何安全令牌的种子。

F-2 046.php 使用 MD5 生成会话 Cookie 值（弱哈希，CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：046.php:9-10

攻击者无需输入任何参数：服务端在 046.php:9 将 $_SESSION['last_session_id_high'] 自增，随后在 046.php:10 用 md5($_SESSION['last_session_id_high']) 计算 Cookie 值，并在 046.php:11 通过 setcookie("dvwaSession", $cookie_value, time()+3600, "/vulnerabilities/weak_id/", $_SERVER['HTTP_HOST'], false, false) 下发。该值完全由单调递增的整数派生，没有任何随机盐或密钥参与，因此不存在需要绕过的校验环节——校验本身缺失。注意：此处算法为 MD5，属弱哈希（CWE-328），不是 DES/ECB 类弱加密（CWE-327），候选的 vulnerability_type 标注为 weak_crypto 属类型串用，实际应按 weak_hash 归类。

影响：会话标识可被离线枚举/预测：攻击者只需知道或猜到一个合法 dvwaSession 值（其取值空间为 md5(0)、md5(1)、md5(2)… 的极小集合），即可伪造 Cookie 冒充其他会话，导致身份冒用与越权访问 /vulnerabilities/weak_id/ 下的受保护资源；同时 setcookie 的 secure 与 httponly 参数均为 false，Cookie 可在明文 HTTP 下被窃取。

CVE/CWE 论证：CWE-328（Use of Weak Hash）：MD5 抗碰撞与抗原像能力均不满足安全令牌用途，且此处输入为可预测的递增整数，熵接近零。外部可达性：046.php 位于 Web 根目录，POST 请求即可触发 Cookie 下发，无需认证即可获得样本值；利用链闭合：请求 → $_SESSION['last_session_id_high']++ → md5() → setcookie 下发 → 客户端回放伪造值。

修复建议：改用 CSPRNG 生成会话标识，例如 random_bytes(32) 后 base64/hex 编码，或直接使用 PHP 原生 session 机制（session_regenerate_id(true)）；不要用 MD5/SHA-1 派生令牌；setcookie 增加 secure=true、httponly=true，并考虑 SameSite=Lax/Strict；服务端保存令牌并做恒定时间比对，避免仅凭可推导值判定身份。
