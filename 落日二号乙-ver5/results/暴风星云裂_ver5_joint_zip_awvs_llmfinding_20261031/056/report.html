F-1 056.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：056.php:15-17

攻击者通过 HTTP 请求向 056.php 提交留言板表单，外部输入在 056.php:5 被读入变量 $message（候选标注的 source 为 query `mtxMessage`，即留言内容字段），随后在 056.php:16 被直接字符串拼接进 INSERT 语句：$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";，其中 $message 被单引号包裹但未做任何转义或参数化。056.php:17 将该拼接后的 $query 交给 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行，污点直达 SQL 汇点。由于代码中未使用 mysqli_real_escape_string、预处理语句或类型约束，单引号可闭合 VALUES 中的字符串字面量，从而改写 INSERT 语义（例如通过 ) 结束 VALUES 列表后追加子查询或堆叠语句，具体可行性取决于 mysqli 驱动是否允许多语句）。此外 056.php:17 的 or die(... mysqli_error(...) ...) 会把数据库错误信息回显到响应中，为布尔/报错型注入提供反馈通道。

影响：数据库写入被攻击者控制：可向 guestbook 表插入任意内容（存储型内容污染），并可通过报错回显与布尔差异逐位推断数据库结构与其他表数据，造成数据泄露；若底层驱动支持多语句，还可能执行额外的 INSERT/UPDATE 等写操作，破坏数据完整性。错误信息回显同时泄露数据库版本与表结构，降低后续利用门槛。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：056.php 为 Web 入口脚本，留言提交参数由 HTTP 请求直接提供，无需认证即可触达 056.php:5 的读取逻辑。利用链闭合：056.php:5 读取外部输入 → 056.php:16 字符串拼接构造 $query → 056.php:17 mysqli_query 执行，中间不存在任何净化函数或参数化绑定，候选 exploit_chain 的两步（source 与 sink）完整衔接，且 056.php:17 的 die(mysqli_error(...)) 提供错误回显。

修复建议：1) 改用预处理语句：$stmt = mysqli_prepare($GLOBALS["___mysqli_ston"], "INSERT INTO guestbook (comment, name) VALUES (?, ?)"); mysqli_stmt_bind_param($stmt, 'ss', $message, $name); mysqli_stmt_execute($stmt);，彻底消除拼接。2) 若必须保留拼接，至少对 $message、$name 使用 mysqli_real_escape_string 并显式加引号。3) 移除 056.php:17 中把 mysqli_error 直接输出到页面的逻辑，改为记录到服务端日志并返回通用错误页。4) 对留言长度与字符集做白名单校验，数据库账户按最小权限仅授予 guestbook 表的 INSERT 权限。
