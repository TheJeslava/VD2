F-1 021.php 未校验 POST 参数 include 导致路径穿越/任意文件包含（CWE-22）

high path_traversal / CWE-22 · 置信度 0.4 · candidate / rule_verified+llm

攻击者通过 HTTP POST 提交参数 include（021.php:14 的 isset($_POST['include']) 判断仅检查存在性，不做任何过滤）。该值在 021.php:16 被直接拼接进 $page['body'] 的 HTML 字符串（" . $_POST['include'] . 影响：若后续代码将该值用于 include/require 或文件读取，攻击者可读取服务器任意文件（如配置、密钥、/etc/passwd），在可包含 PHP 文件时可能导致代码执行；当前证据下可确认的是未净化外部输入进入路径处理，具体危害取决于未展示的下游调用。

CVE/CWE 论证：CWE-22 路径穿越。外部可达性：021.php 为 Web 端点，POST 参数 include 无需认证即可提交；利用链：POST include → $_POST['include']（021.php:14）→ 字符串拼接（021.php:16）→ 下游文件操作（片段未展示）。链在已给证据内闭合到未净化拼接，最终危险操作因片段截断证据不足。

修复建议：对 include 参数使用严格白名单（如仅允许预定义页面标识），或使用 basename() 并配合 realpath() 校验结果必须位于允许目录内；禁止将用户输入直接拼接进 include/require 路径；对输出到 HTML 的值做 htmlspecialchars() 编码。

F-2 021.php POST 参数 include 未编码直接拼接进页面导致反射型 XSS（CSP nonce 硬编码可绕过）

medium xss / CWE-79 · 置信度 0.85 · candidate / llm_inferred

位置：021.php:14-18

021.php 第 14-18 行读取 $_POST['include']，未做任何 HTML 编码（无 htmlspecialchars/htmlentities）即通过字符串拼接写入 $page['body']，随后该变量被输出到页面，构成反射型 XSS。同时第 3 行 CSP 使用硬编码 nonce 'TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA='，攻击者可直接在注入的 <script nonce="..."> 中复用该 nonce，使 CSP 的 script-src 限制失效；第 8 行还主动设置 X-XSS-Protection: 0 关闭浏览器 XSS 过滤。攻击者可构造恶意 POST 请求诱导受害者提交，在受害者浏览器上下文执行任意脚本，窃取会话或执行敏感操作。

影响：反射型 XSS：攻击者可在受害者浏览器上下文执行任意 JavaScript，窃取 Cookie/会话、伪造请求执行敏感操作。硬编码 nonce 使 CSP 无法防御。

CVE/CWE 论证：CWE-79。外部无需认证即可通过 POST 参数注入，链闭合：source($_POST['include'])→拼接→输出，无编码；CSP nonce 硬编码可复用，X-XSS-Protection 被关闭。

修复建议：对 $_POST['include'] 使用 htmlspecialchars($v, ENT_QUOTES, 'UTF-8') 编码后再输出；CSP nonce 每次请求随机生成且不可预测；移除 X-XSS-Protection: 0。

F-3 021.php CSP 同时启用 unsafe-inline 与固定 nonce，削弱脚本来源限制（CWE-693）

medium csp / CWE-693 · 置信度 0.72 · candidate / rule_verified+llm

位置：021.php:2-3

021.php:3 设置 Content-Security-Policy: script-src 'self' 'unsafe-inline' 'nonce-TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA='。其中 'unsafe-inline' 允许任意内联脚本执行，使 nonce 机制形同虚设；同时 nonce 为硬编码常量（base64 解码为固定字符串），对所有请求相同，攻击者一旦获知即可复用。该配置与 021.php:16 的未编码输出拼接叠加，使注入的内联脚本可被执行。

影响：CSP 无法有效缓解 XSS：注入的内联 <script> 或事件处理器可执行，导致会话窃取、页面篡改、恶意操作。

CVE/CWE 论证：CWE-693 保护机制失效。配置型弱点，无需污点链；证据为 021.php:3 的 CSP 头原文，含 'unsafe-inline' 与固定 nonce。外部可达：任意请求均返回该头。

修复建议：移除 'unsafe-inline'；nonce 改为每次响应随机生成（如 base64(random_bytes(16))）并仅对当次响应有效；对注入点输出做 HTML 编码；考虑使用 'strict-dynamic' 与哈希白名单。
