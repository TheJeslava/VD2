high auth_bypass / CWE-287 · 置信度 0.9 · candidate / llm_inferred

位置：013.php:17-23

013.php 的密码修改逻辑在 recaptcha_check_answer 返回假值后，仍存在一条硬编码后门分支：只要 POST 参数 g-recaptcha-response 等于固定字符串 'hidd3n_valu3' 且 HTTP User-Agent 头等于 'reCAPTCHA'，条件即为真，直接进入密码修改流程。这两个值完全由攻击者控制（一个在请求体、一个在请求头），无需真实通过 reCAPTCHA 人机校验，即可在无有效 CAPTCHA 的情况下修改当前登录用户的密码，构成认证/人机校验绕过（CWE-287 / CWE-804）。

影响：攻击者无需通过人机校验即可修改账户密码；若配合 CSRF（脚本第 53 行仅生成 token 但本流程未校验 token），可诱导受害者改密导致账户接管。

CVE/CWE 论证：CWE-287 认证绕过 / CWE-804 可猜测/硬编码凭证：外部 HTTP 可达，攻击者完全控制触发条件（请求体参数 + 请求头），无需真实 CAPTCHA，链闭合。

修复建议：移除硬编码的 'hidd3n_valu3'/'reCAPTCHA' 后门分支，仅以 recaptcha_check_answer 的真实返回值为准；同时在本流程中校验 CSRF token。
