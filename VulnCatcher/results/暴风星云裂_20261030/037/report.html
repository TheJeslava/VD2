F-1 DVWA SQL 注入（Cookie `id`）——`037.php` 中 `$_COOKIE['id']` 直接拼接进 SQL 查询

high sql_injection / CWE-89 · 置信度 0.9 · candidate / llm_inferred

位置：037.php:5-13

脚本从 Cookie `id` 读取用户输入（第 5 行），未做任何过滤/转义/参数化，直接以字符串拼接方式构造 SQL 语句（第 11 行 MySQL 分支、第 33 行 SQLite 分支），随后交给 `mysqli_query`（第 13 行）与 `$sqlite_db_connection->query`（第 35 行）执行。攻击者只需控制 Cookie 即可注入任意 SQL 片段，绕过 `user_id` 条件读取 `users` 表全部数据，或通过布尔/时间盲注逐字节提取数据库内容。这是 DVWA 经典的 SQL 注入练习点，链路完整闭合。

影响：未授权攻击者可读取/推断数据库中 users 表全部记录（用户名、口令哈希等），并可能进一步通过 UNION/堆叠查询访问其他表，造成敏感数据泄露。

CVE/CWE 论证：CWE-89 SQL 注入。外部可达（HTTP Cookie 直接进入查询），无需认证，source→sink 链路在 CODE PACK 内逐行闭合（第 5→11→13 行），无任何转义或参数化。

修复建议：使用预处理语句（mysqli_prepare / PDO::prepare）绑定参数；对 $id 做类型强转（如 (int)$id）；避免将用户输入直接拼接进 SQL。
