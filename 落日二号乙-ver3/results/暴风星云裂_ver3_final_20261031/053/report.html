攻击者通过 HTTP GET 请求参数 name 提供输入（053.php:8 的 $_GET['name']）。该值未经任何 HTML 实体编码、过滤或白名单校验，直接被字符串拼接进 $html 累积变量：$html .= '<pre>Hello ' . $_GET[ 'name' ] . '</pre>'（053.php:8）。随后 $html 作为页面响应输出（输出语句在 code_pack 片段之外，属未覆盖范围，但该变量命名与注释「Feedback for end user」表明其用于回显给终端用户）。由于拼接发生在 <pre> 元素内容上下文中，攻击者提交 name=<script>...</script> 或 <img src=x onerror=...> 即可闭合/逃逸文本上下文，在受害者浏览器中执行任意 JavaScript。校验无效的原因：代码路径上不存在 htmlspecialchars/htmlentities 等编码调用，也不存在标签/字符白名单，属于典型的「直接回显」模式。

影响：反射型 XSS：攻击者可构造带恶意 name 参数的链接诱导受害者点击，在目标站点源下执行任意脚本，从而窃取会话 Cookie（若未设 HttpOnly）、读取页面敏感数据、以受害者身份发起操作（CSRF 绕过）、篡改页面内容或进行钓鱼跳转。危害程度取决于会话保护与 CSP 配置。

CVE/CWE 论证：CWE-79（Improper Neutralization of Input During Web Page Generation，跨站脚本）。外部可达性：注入点为 HTTP GET 参数 name，任何能访问 053.php 的远程用户均可触发，无需认证、无需本地访问。利用链闭合：source（$_GET['name']）→ 无净化拼接（053.php:8）→ $html 输出到响应，链路在片段内已完整可见；唯一未在 code_pack 中直接展示的是最终 echo/print 语句，属证据缺口，但变量语义与注释足以支撑回显用途。

修复建议：1) 输出编码：在拼接前对用户输入执行 htmlspecialchars($_GET['name'], ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8')，确保 <、>、&、"、' 被实体化；2) 上下文感知编码：若未来输出到属性或 JS 上下文，改用对应编码器（如 json_encode 用于 JS）；3) 输入校验：对 name 施加长度上限与字符白名单（如仅字母数字与空格）；4) 纵深防御：为会话 Cookie 设置 HttpOnly 与 SameSite，并部署限制内联脚本的 CSP（如 script-src 'self'）。
