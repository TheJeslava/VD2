F-1 055.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.7 · candidate / rule_verified+llm

位置：055.php:17-19

攻击者通过 HTTP 请求向 055.php 提交留言板表单，外部输入在 055.php:5 被读入变量 $message（候选标注的 source 为 query `mtxMessage`，即留言内容字段）。该值未经任何转义或参数化，在 055.php:18 被直接拼接进 SQL 字符串：$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );",随后在 055.php:19 通过 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行。由于 $message 位于单引号字符串字面量内部且未调用 mysqli_real_escape_string 等转义函数、也未使用预处理语句，攻击者可闭合单引号并注入任意 SQL 片段（如 ' , (SELECT ...))-- - 形式），使 INSERT 语句被改写或追加子查询。校验无效的原因是该路径上不存在白名单、类型校验或参数绑定，仅有字符串拼接。最终危险操作是 055.php:19 的 mysqli_query 执行被污染的 $query；此外该行在失败时通过 die() 回显 mysqli_error，构成基于报错的注入反馈通道，便于攻击者构造盲注/报错注入。

影响：数据库写入与读取权限被攻击者控制：可向 guestbook 表插入任意数据、通过子查询读取其他表（如用户表、凭据）内容并借助报错回显外带，造成敏感数据泄露；在数据库账户权限较高时可进一步读写文件或篡改数据，属于数据泄露与数据完整性破坏。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：055.php 为可直接 HTTP 访问的留言板脚本，注入点为表单提交的留言字段，无需认证即可触发；利用链闭合：055.php:5 读取外部输入 → 055.php:18 字符串拼接构造 $query → 055.php:19 mysqli_query 执行，且失败分支回显数据库错误，形成完整可利用链。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：1) 改用预处理语句与参数绑定：$stmt = mysqli_prepare($link, "INSERT INTO guestbook (comment, name) VALUES (?, ?)"); mysqli_stmt_bind_param($stmt, 'ss', $message, $name); mysqli_stmt_execute($stmt); 2) 若必须拼接，至少对每个值调用 mysqli_real_escape_string 并加引号；3) 对 $message/$name 做长度与字符白名单校验；4) 关闭生产环境的数据库错误回显，改为记录日志并返回通用错误页；5) 数据库账户遵循最小权限，仅授予 guestbook 表的 INSERT 权限。
