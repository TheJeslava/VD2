F-1 012.php 登录查询 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：012.php:13-15

攻击者通过 HTTP GET 参数 `username`（012.php:5 读取）提交任意字符串，该值被直接拼进 012.php:14 的 SQL 语句 `SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';`，随后在 012.php:15 交给 mysqli_query 执行。代码中仅对 `$pass` 调用了 mysqli_real_escape_string（012.php:10），`$user` 没有任何转义、类型约束或参数化处理，因此单引号可闭合字符串字面量，注入任意 SQL 片段（例如 `username=' OR '1'='1' -- ` 绕过认证，或使用 UNION/布尔/时间盲注读取 users 表）。查询失败时 012.php:15 的 die() 还会把 mysqli_error 原文回显到页面，构成报错型注入的信息泄露通道。

影响：可绕过登录认证、读取/篡改 users 表中的账号与口令哈希（口令为 MD5，见 SEM-0ce3358fa05b，可离线破解），并借助报错回显获取数据库结构信息；若数据库账号权限过高，可进一步读写其他表数据。

CVE/CWE 论证：CWE-89：外部可控输入 `username` 未经参数化即拼入 SQL 并在 012.php:15 执行，属典型一次注入。攻击面为公开的登录入口（012.php:3 仅判断 `$_GET['Login']` 是否存在），无需认证即可触发；source（012.php:5）→ 拼接（012.php:14）→ sink（012.php:15）链路在单文件内闭合，无净化环节。

修复建议：改用预处理语句与参数绑定（mysqli_prepare + bind_param，或 PDO 的 prepare/execute），彻底移除字符串拼接；对 `username` 做长度与字符白名单校验；关闭错误详情回显，将 mysqli_error 写入服务端日志而非响应体；数据库账号按最小权限授予，仅允许对必要表执行 SELECT。

F-2 012.php 登录接口缺少暴力破解防护（CWE-307）

high brute_force / CWE-307 · 置信度 0.6 · candidate / rule_verified+llm

位置：012.php:2-3

012.php:3 通过 `if( isset( $_GET[ 'Login' ] ) )` 进入登录处理，随后在 012.php:14-15 校验用户名与口令。整个流程中未见失败次数计数、账号/IP 锁定、验证码、指数退避或速率限制等任何反暴力破解机制，且登录凭据通过 GET 参数传递（`username`、`password`），便于脚本化批量重放。

影响：攻击者可对任意已知或枚举出的用户名进行在线口令爆破/撞库，配合 SEM-0ce3358fa05b 的弱哈希与 GEN-3b547dba7a60 的注入绕过，可高效获取有效账号，造成账户接管。

CVE/CWE 论证：CWE-307（Improper Restriction of Excessive Authentication Attempts）：认证入口 012.php:3 对外公开、无需前置认证，且无任何尝试次数约束；证据为 012.php:2-3 的登录分支与 012.php:14-15 的校验逻辑中不存在计数/锁定代码。该结论基于源码静态观察，实际限流可能由前置网关提供，属证据缺口。

修复建议：在服务端按账号与来源 IP 实施失败计数与临时锁定/指数退避；引入验证码或二次验证；将登录改为 POST 并配合 CSRF Token，避免凭据出现在 URL 与日志中；对登录失败统一返回模糊提示，避免用户名枚举；集中记录并告警异常登录频率。

F-3 012.php 使用 MD5 存储口令（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：012.php:10-11

012.php:11 执行 `$pass = md5( $pass );`，将用户口令以无盐 MD5 单轮哈希形式处理，随后在 012.php:14 的查询中与数据库中的口令值比较。MD5 属已被证明存在实用碰撞且计算速度极快的哈希算法，用于口令存储时无法抵抗离线暴力破解与彩虹表攻击；代码中未见盐值（salt）或迭代（如 bcrypt/Argon2/PBKDF2）等加固措施。

影响：一旦数据库泄露（可经 GEN-3b547dba7a60 的 SQL 注入读取 users 表），攻击者可用彩虹表或 GPU 高速枚举在短时间内还原大量用户明文口令，进而横向登录其他系统（口令复用场景）。

CVE/CWE 论证：CWE-328（Use of Weak Hash）：MD5 被用于口令这一安全用途，属弱哈希而非弱加密算法（非 CWE-327）。该弱点为配置/实现型，不依赖 HTTP 污点链；证据为 012.php:11 的 `md5( $pass )` 原文调用，且 012.php:10 仅做转义、未引入盐或迭代。外部可达性体现在登录流程每次都会以 MD5 处理口令。

修复建议：改用专为口令设计的慢哈希：PHP 的 password_hash()（PASSWORD_BCRYPT 或 PASSWORD_ARGON2ID）配合 password_verify()，自动生成随机盐；迁移期可对存量 MD5 值在用户下次登录时透明重算；禁止在任何新代码中使用 md5()/sha1() 处理口令或令牌。

F-4 012.php 登录成功页反射型 XSS：username 参数经 mysqli_real_escape_string 后直接拼入 HTML

medium xss / CWE-79 · 置信度 0.65 · candidate / llm_inferred

位置：012.php:5-23

012.php 第 5 行从 $_GET['username'] 读取用户输入，第 6 行仅用 mysqli_real_escape_string 做 SQL 转义（该函数只转义 SQL 特殊字符，不处理 HTML 元字符 < > " '），第 23 行将 $user 直接拼接进 HTML 字符串 "<p>Welcome to the password protected area {$user}</p>" 并输出。攻击者可构造含 HTML/JS 的 username，在登录成功后于受害者浏览器执行脚本。注意：该 XSS 仅在登录成功分支（第 17 行 mysqli_num_rows==1）触发，需要有效凭据或 SQL 注入配合，因此利用条件受限。

影响：在受害者浏览器上下文执行任意 JS，可窃取会话或发起操作；但需登录成功分支，实际影响中等

CVE/CWE 论证：CWE-79 反射型 XSS，外部可达，但触发依赖登录成功，链不完全闭合于未认证场景

修复建议：输出前对 $user 使用 htmlspecialchars($user, ENT_QUOTES, 'UTF-8') 编码
