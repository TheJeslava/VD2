影响：数据库写操作被劫持：攻击者可利用 UPDATE 语句的注入点改写 users 表中任意用户（含 admin）的 password 字段，实现账户接管与越权登录；配合错误回显（024.php:19 的 die(mysqli_error(...))）可泄露库名、表结构与数据，属于数据篡改与敏感信息泄露。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：该逻辑位于 DVWA 的密码修改页面，登录用户通过 HTTP 表单即可触达；利用链闭合：外部输入 $pass_new（024.php:7）→ 字符串拼接 $insert（024.php:18）→ mysqli_query 执行（024.php:19），中间无参数化或转义，且错误信息直接回显，便于注入验证。无需额外权限即可在已认证会话内完成注入。

修复建议：改用预处理语句与参数绑定：$stmt = $db->prepare("UPDATE users SET password = ? WHERE user = ?"); $stmt->bind_param('ss', $pass_new, $current_user); $stmt->execute();。若必须拼接，至少对 $pass_new 使用 mysqli_real_escape_string 并配合白名单校验；同时移除 024.php:19 中把 mysqli_error 直接输出到页面的 die 分支，改为记录日志并返回通用错误。

F-2 DVWA 密码修改功能仅依赖 HTTP_REFERER 子串校验，可被 CSRF 绕过并接管账户

high csrf / CWE-352 · 置信度 0.85 · candidate / llm_inferred

位置：024.php:3-19

024.php 的密码修改逻辑在 `isset($_GET['Change'])` 时执行，用 `stripos($_SERVER['HTTP_REFERER'], $_SERVER['SERVER_NAME']) !== false` 判断请求来源，随后直接读取 `password_new`/`password_conf` 并执行 `UPDATE users SET password=...`。Referer 头完全由客户端控制，攻击者只需让 Referer 包含目标主机名（例如 `http://TARGET/...` 或 `http://evil.com/?TARGET`）即可通过校验；同时该操作没有任何 CSRF token、没有要求提交原密码、也没有二次确认，属于典型的认证后状态改变缺少 token 的 CSRF。攻击者可诱导已登录受害者访问恶意页面，自动发起 GET 请求把受害者密码改为攻击者已知值，从而接管账户。

影响：任意已登录用户可被跨站请求伪造修改密码，导致账户接管；若受害者是管理员则进一步控制后台。

CVE/CWE 论证：CWE-352 跨站请求伪造。外部可达（GET 请求），无需原密码，仅依赖受害者已登录会话；Referer 校验为可绕过的假防护，链闭合。

修复建议：引入 CSRF token 并在服务端校验；要求提交原密码；将状态改变操作改为 POST；不要依赖 Referer 做安全判断。

F-3 密码修改使用无盐 MD5 存储口令

medium weak_hash / CWE-328 · 置信度 0.8 · candidate / llm_inferred

位置：024.php:14-18

024.php 第 14 行对用户新密码执行 `md5($pass_new)` 后直接写入 users 表。MD5 为快速哈希且未加盐，攻击者一旦获取数据库即可通过彩虹表/暴力破解快速还原明文口令，属于 CWE-328 弱哈希。

影响：数据库泄露后口令可被快速破解，导致账户接管与撞库扩散。

CVE/CWE 论证：CWE-328 弱哈希。源码明确使用 md5 且无盐，属配置/实现型缺陷，无需 HTTP 污点即可成立。

修复建议：改用 password_hash()/password_verify()（bcrypt/argon2）并加盐。
