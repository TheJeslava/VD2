F-1 058_05.php 登录查询 username 参数 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.78 · candidate / rule_verified+llm

位置：058_05.php:29-31

攻击者通过 HTTP 请求的 query 参数 `username`（058_05.php:25 读取）提交输入，该值未经任何转义或参数化即被拼接进 058_05.php:30 的 `$sql = "select count(*) from users where username='$username'"`，随后在 058_05.php:31 交给 `mysql_query($sql)` 执行。由于单引号包裹的字符串上下文未做 `mysql_real_escape_string` 或预处理绑定，攻击者可闭合引号注入任意 SQL 片段（如 `' OR '1'='1` 或 UNION 子查询），校验完全缺失。

影响：数据库查询逻辑被完全控制：可绕过登录/计数校验、通过 UNION 或布尔/时间盲注逐位读取 users 表中的用户名与口令哈希，造成敏感数据泄露；结合数据库高权限账户还可能读写文件。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达：参数来自 HTTP query，无需认证即可触发；利用链闭合：058_05.php:25 取值 → 058_05.php:30 字符串拼接 → 058_05.php:31 mysql_query 执行，中间无净化函数。

修复建议：改用 PDO/MySQLi 预处理语句并绑定参数（如 `SELECT count(*) FROM users WHERE username=?`）；若必须拼接，使用 `mysql_real_escape_string` 并强制字符集；对 username 施加长度与字符白名单校验；数据库账户最小权限，关闭详细错误回显（当前 die 分支会暴露 SQL 执行状态）。

F-6 058_08.php 口令修改接口缺少 CSRF 防护（CWE-352）

medium csrf / CWE-352 · 置信度 0.56 · candidate / rule_verified+llm

位置：058_08.php:37-38

058_08.php:37-38 的口令修改逻辑直接依据请求参数 `$pass`、`$username`、`$curr_pass` 构造 `UPDATE users SET PASSWORD=...` 并执行，代码片段中未见任何 CSRF token 校验、Origin/Referer 校验或二次确认。攻击者可构造第三方页面，诱导已登录用户浏览器自动提交修改口令请求，从而在用户不知情下更改其口令。需注意：该接口同时存在 SQL 注入（见 GEN-14a19460b45a），且片段未展示会话认证与 Cookie SameSite 配置，实际可利用性依赖运行时条件。

影响：登录用户被诱导后其账户口令被静默修改，导致账户被攻击者接管；若目标为管理员则造成权限提升。

CVE/CWE 论证：CWE-352（跨站请求伪造）。外部可达：状态改变请求通过 HTTP 参数触发；利用链闭合依赖两点未在片段中证实的条件——(1) 接口依赖 Cookie 会话认证，(2) 无 token/Origin 校验。因此证据等级为推断，需运行时复核。

修复建议：为所有状态改变表单引入随机 CSRF token 并在服务端校验；校验 Origin/Referer；会话 Cookie 设置 SameSite=Lax/Strict 与 Secure；修改口令前要求重新输入原口令（服务端校验）；优先使用 POST 而非 GET 传参。
