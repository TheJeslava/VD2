F-1 058_05.php 注册流程 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：058_05.php:47-49

攻击者通过 HTTP 请求的 query 参数 `username`（058_05.php:25 读取）提交输入，该值未经转义直接拼接进 INSERT 语句：058_05.php:48 `$sql = "insert into users ( username, password) values(\"$username\", \"$pass\")"`，随后在 058_05.php:49 交给 `mysql_query($sql)` 执行。代码中未见 mysql_real_escape_string、addslashes、预处理语句或类型白名单，双引号包裹的字符串字面量可被 `"` 或反斜杠转义序列闭合，因此校验无效。

影响：可向 users 表写入任意行（伪造/覆盖账号），并通过报错信息 `mysql_error()` 回显（058_05.php:49）实施报错型注入读取数据库内容，导致账号数据泄露与认证绕过；结合堆叠/子查询可进一步篡改数据。

CVE/CWE 论证：CWE-89：外部可控的 query 参数 `username` 未经参数化直接进入 SQL 语句并执行，属典型一次注入；入口为公开注册页面，无需认证即可触发，source→sink 链在 058_05.php:25→48→49 内闭合。

修复建议：改用 PDO/MySQLi 预处理语句并绑定参数（如 `INSERT INTO users(username,password) VALUES(?,?)`）；对 username 做长度与字符白名单校验；关闭 `or die(mysql_error())` 的详细错误回显，改为记录日志并返回通用错误；数据库账号按最小权限仅授予 INSERT 所需权限。

F-6 058_06.php 认证 Cookie 使用固定值（CWE-330/CWE-565）

high weak_id / CWE-330 · 置信度 0.4 · candidate / rule_verified+llm

位置：058_06.php:43-44

058_06.php:44 `setcookie("Auth", 1, time()+3600)` 将认证标志 Cookie 设为常量 1，而非不可预测的随机会话标识；058_06.php:43 仅把用户名写入 `$_SESSION["username"]`。任何客户端只要自行设置 `Auth=1` 即可伪造该标志，服务端无法区分合法与伪造。

影响：攻击者可手工构造 `Cookie: Auth=1` 冒充已认证状态，若下游页面仅以该 Cookie 判断登录，则导致认证绕过与越权访问。

CVE/CWE 论证：CWE-330（弱随机/可预测标识）与 CWE-565（依赖不可信 Cookie 做安全决策）：标识为常量而非随机值，可被任意客户端复现。证据边界：片段未展示下游对 Auth 的校验逻辑，实际绕过效果需跨文件复核。

修复建议：不要用常量 Cookie 表示认证状态；改用服务端会话（session_regenerate_id 后仅依赖 PHPSESSID），Cookie 设置 HttpOnly、Secure、SameSite；对会话标识使用 CSPRNG 生成。

F-7 058_08.php 登出使用固定值 Cookie 且缺少安全属性（CWE-330/CWE-614）

high weak_id / CWE-330 · 置信度 0.4 · candidate / rule_verified+llm

位置：058_08.php:65-66

058_08.php:65-66 在 `session_destroy()` 后执行 `setcookie('Auth', 1, time()-3600)`，以常量 1 作为 Cookie 值并仅通过过期时间清除；该 Cookie 未设置 HttpOnly/Secure/SameSite 属性。常量值本身不携带随机性，且清除依赖客户端时间。

影响：若下游逻辑以 `Auth` 存在与否判断登录，攻击者可自行设置 `Auth=1` 维持/伪造认证状态；缺少 HttpOnly 使该标志可被脚本读取，配合 XSS 可被窃取或篡改。

CVE/CWE 论证：CWE-330（可预测/常量标识）与 CWE-614（敏感 Cookie 未设 Secure/HttpOnly）：证据为 058_08.php:66 的常量值与缺失属性。证据边界：登出路径本身不直接造成越权，实际影响取决于下游对 Auth 的信任方式，需跨文件复核。

修复建议：认证状态完全交由服务端会话管理，登出时销毁会话并重新生成会话 ID；Cookie 统一设置 HttpOnly、Secure、SameSite；避免使用常量值表达安全状态。

F-8 058_08.php 口令修改缺少 CSRF 防护（CWE-352）

medium csrf / CWE-352 · 置信度 0.56 · candidate / rule_verified+llm

位置：058_08.php:37-38

058_08.php:37-38 的口令修改逻辑直接依据请求参数执行 `UPDATE users SET PASSWORD=...`，代码片段中未见 CSRF token、Origin/Referer 校验或二次确认。攻击者可构造第三方页面，诱导已登录用户浏览器向该端点提交修改口令请求。

影响：在受害者已登录且浏览器自动携带会话的前提下，攻击者可将其口令改为已知值，实现账号接管。

CVE/CWE 论证：CWE-352：状态改变请求缺少不可预测令牌校验。证据边界：片段未展示会话校验与 Cookie SameSite 属性，实际可利用性依赖受害者处于已认证状态且会话 Cookie 被跨站携带，属需运行时复核的语义命中。

修复建议：为口令修改表单引入一次性 CSRF token 并在服务端校验；校验 Origin/Referer；会话 Cookie 设置 SameSite=Lax/Strict 与 Secure；修改口令要求重新输入当前口令。
