F-1 014.php 密码修改处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：014.php:59-61

攻击者通过 POST 参数 password_new（014.php:8 读取，014.php:50 附近进入 $pass_new）提交恶意字符串。该值在 014.php:56 仅经过 mysqli_real_escape_string 处理，随后在 014.php:57 被 md5() 哈希，最终在 014.php:60 被直接拼接进 UPDATE 语句：$insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . dvwaCurrentUser() . "';";，并在 014.php:61 由 mysqli_query 执行。由于 md5() 会把输入转换为 32 位十六进制串，password_new 中的引号等元字符在进入 SQL 前已被哈希消解，因此该条链在源码层面并不闭合；真正可注入的通道是 dvwaCurrentUser() 的返回值（若其来源可被外部控制），但输入未提供该函数实现，证据不足。

影响：若注入通道成立，攻击者可改写 users 表中任意用户的 password 字段，实现账户接管或越权登录；错误信息回显（mysqli_error）还会泄露数据库结构。当前证据下具体影响无法确认。

CVE/CWE 论证：CWE-89：SQL 语句由字符串拼接构造而非参数化。外部可达性：014.php 为 DVWA 密码修改页面，POST 可达且无需额外权限（需已登录会话）。但利用链闭合性存疑：password_new 经 md5() 后不再携带 SQL 元字符，候选给出的 source→sink 链在源码上不成立，故不满足 CVE 级论证。

修复建议：改用预处理语句与参数绑定（mysqli_prepare/bind_param 或 PDO），禁止将任何变量拼接进 SQL；对 dvwaCurrentUser() 的返回值同样参数化；关闭 die(mysqli_error(...)) 的详细错误回显，改为通用错误页并记录服务端日志。

F-2 DVWA 密码修改功能 CAPTCHA 状态机可绕过（step=2 直接提交跳过 recaptcha 校验）

high captcha_bypass / CWE-804 · 置信度 0.85 · candidate / llm_inferred

位置：014.php:45-61

014.php 的密码修改流程被拆成两步：step=1 时调用 recaptcha_check_answer() 校验第三方 CAPTCHA，通过后把 password_new/password_conf 放进隐藏字段并渲染 step=2 表单；step=2 分支（第 45-73 行）只检查 password_new == password_conf，随后直接 md5 并 UPDATE users 表，完全没有再次校验 CAPTCHA，也没有任何服务端会话标记证明 step=1 已通过。攻击者（或自动化脚本）可跳过 step=1，直接 POST Change=Change&step=2&password_new=X&password_conf=X 完成密码修改，CAPTCHA 保护形同虚设。结合该功能本身无 CSRF token，攻击者可构造自动提交表单诱导已登录受害者修改密码，实现账户接管。

影响：绕过 CAPTCHA 保护修改账户口令，配合无 CSRF token 可对已登录用户实施账户接管

CVE/CWE 论证：CWE-804 (Guessable CAPTCHA)/CWE-352 (CSRF)：step=2 分支缺少对 step=1 CAPTCHA 通过状态的服务端绑定，外部可直接 POST 触发，链闭合

修复建议：在服务端会话中记录 CAPTCHA 已通过的一次性令牌，step=2 校验该令牌并立即失效；为表单增加 CSRF token

F-3 014.php 验证码流程可被 step 参数绕过（CWE-804）

high captcha_bypass / CWE-804 · 置信度 0.7 · candidate / rule_verified+llm

位置：014.php:2-3

014.php:3 以 if( isset( $_POST['Change'] ) && ( $_POST['step'] == '1' ) ) 作为流程分支条件，客户端提交的 step 值直接决定是否跳过验证码展示与校验阶段。攻击者可直接构造 POST Change=Change&step=1&password_new=...&password_conf=...，跳过验证码环节直达口令修改逻辑（014.php:7-9 读取参数，014.php:60-61 执行更新）。源码中未见服务端会话绑定的验证码校验状态。

影响：攻击者可自动化、批量化提交口令修改请求，绕过人机验证，配合弱口令或撞库实现账户接管，并使反自动化防护失效。

F-4 014.php 使用 MD5 存储口令哈希（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.8 · candidate / rule_verified+llm

位置：014.php:56-57

014.php:57 执行 $pass_new = md5( $pass_new );，将用户新口令以无盐 MD5 单轮哈希后写入数据库（014.php:60-61 的 UPDATE 语句）。MD5 属已破解的弱哈希算法，且此处未加盐、未使用慢哈希，属于口令存储用途的弱哈希实现。

影响：数据库泄露后，攻击者可用彩虹表/GPU 暴力快速还原用户明文口令；相同口令产生相同哈希，便于横向撞库，导致账户接管。

CVE/CWE 论证：CWE-328（Use of Weak Hash）。配置/实现型弱点，无需 HTTP 污点链：算法名 md5 与调用点 014.php:57 为原文证据。外部可达性：任何通过该页面修改口令的用户都会生成弱哈希，无需特殊权限。

修复建议：改用 password_hash()（PASSWORD_ARGON2ID 或 PASSWORD_BCRYPT）生成带盐慢哈希，校验用 password_verify()；迁移期可对旧 MD5 值在用户下次登录时透明重哈希。

F-5 014.php 口令修改缺少 CSRF 防护（CWE-352）

medium csrf / CWE-352 · 置信度 0.6 · candidate / rule_verified+llm

位置：014.php:7-8

014.php:7-9 直接读取 $_POST['password_new'] 与 $_POST['password_conf']，并在 014.php:60-61 执行 UPDATE users SET password 的状态改变操作。源码片段中未见 CSRF token、Origin/Referer 校验或二次身份确认。攻击者可构造恶意页面，诱导已登录受害者在不知情下提交口令修改表单。

影响：受害者会话有效期内，攻击者可将其账户口令改为攻击者已知值，随后登录接管账户，造成越权与数据泄露。

CVE/CWE 论证：CWE-352。外部可达性：014.php 为浏览器可访问的表单端点，跨站 POST 即可触发；利用链闭合：无 token 校验、无来源校验，状态改变请求可被第三方站点伪造。

修复建议：为表单引入每会话随机 CSRF token 并在服务端比对；校验 Origin/Referer；会话 Cookie 设置 SameSite=Lax/Strict；修改口令前要求重新输入当前口令。
