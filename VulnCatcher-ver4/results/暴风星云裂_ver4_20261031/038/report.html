F-1 038.php 基于 query 参数 id 的 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：038.php:11-13

攻击者通过 HTTP 请求的 query 参数 `id` 提供输入，该输入在 038.php:5 被读取后未做任何类型转换、转义或参数化，直接以字符串拼接方式进入 038.php:11 构造的 SQL 语句：`$query = "SELECT first_name, last_name FROM users WHERE user_id = '$id';"`。由于 `$id` 被包裹在单引号内且未经过 mysqli_real_escape_string 或预处理语句处理，攻击者可闭合单引号并注入任意 SQL 片段（如 `1' OR '1'='1` 或 UNION 查询）。随后该拼接后的 `$query` 在 038.php:13 被传入 `mysqli_query($GLOBALS["___mysqli_ston"], $query)` 执行，污点从 source 到 sink 全程无有效净化，利用链闭合。代码注释显示已移除 'or die' 以抑制 MySQL 错误回显，但这只影响报错信息的可见性，不构成任何防护。

影响：数据库查询逻辑可被任意篡改：攻击者可绕过 user_id 过滤条件读取 users 表全部记录（first_name、last_name），并通过 UNION 注入进一步读取其他表（如用户名、口令哈希等敏感数据），造成数据泄露；在数据库账户权限过高时还可能读写文件或进一步影响数据库服务。属于机密性与完整性层面的严重风险。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素的不当中和）。外部可达性：注入点为 HTTP query 参数 `id`，无需认证即可访问该脚本；利用链闭合：038.php:5 读取输入 → 038.php:11 字符串拼接进 SQL → 038.php:13 mysqli_query 执行，中间无参数化、无转义、无白名单校验，攻击者完全控制 SQL 语法结构。

修复建议：改用参数化查询（预处理语句）：使用 mysqli_prepare 配合 `SELECT first_name, last_name FROM users WHERE user_id = ?`，通过 bind_param('s' 或 'i', $id) 绑定参数，杜绝字符串拼接；同时对 `id` 做严格的类型校验（如强制转换为整数并校验范围）。若必须保留动态拼接，至少使用 mysqli_real_escape_string 并配合白名单，但首选参数化。另建议为数据库账户配置最小权限，避免 UNION 后可跨库读取。

F-2 038.php 用户 ID 查询参数 id 直接拼接进 SQL 语句导致 SQL 注入（DVWA SQL Injection 场景）

high sql_injection / CWE-89 · 置信度 0.9 · candidate / llm_inferred

位置：038.php:5-34

脚本在 `isset($_GET['Submit'])` 成立时，直接把 `$_GET['id']` 赋给 `$id`（第 5 行），未做任何类型转换、转义或参数化，随后在第 11 行（MySQL 分支）与第 32 行（SQLite 分支）以单引号包裹方式拼接进 `SELECT first_name, last_name FROM users WHERE user_id = '$id';`，并分别交给 `mysqli_query()`（第 13 行）与 `$sqlite_db_connection->query()`（第 34 行）执行。攻击者可通过闭合单引号注入任意 SQL 片段（如 UNION SELECT 读取其他表、布尔/时间盲注），从而读取数据库中的任意数据（用户表、凭据等）。代码中不存在白名单、`intval()`、`mysqli_real_escape_string()` 或预处理语句，属于典型的 source→sink 直连。

影响：攻击者可读取数据库中任意表数据（包括用户凭据），在具备多语句/文件权限时可进一步扩展；属于高危数据泄露与数据库接管风险。

CVE/CWE 论证：CWE-89 SQL 注入。外部 GET 参数 `id` 未经任何转义直接拼接进 SQL 并执行，无需认证即可触发（脚本本身无鉴权逻辑），source→sink 链在 CODE PACK 内完整闭合。

修复建议：使用预处理语句（mysqli_prepare/bind_param 或 PDO 参数绑定）；对 `id` 强制转换为整数（如 `$id = (int)$_GET['id'];`）；移除拼接式 SQL。
