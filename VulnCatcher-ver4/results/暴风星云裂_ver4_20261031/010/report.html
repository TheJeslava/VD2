F-1 010.php 登录查询 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.73 · candidate / rule_verified+llm

位置：010.php:18-20

攻击者通过 HTTP 请求参数 `username`（010.php:8 读取）提交任意字符串，该值被直接拼进 010.php:19 的 SQL 语句 `SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';`，随后在 010.php:20 由 mysqli_query 执行。代码中仅对 `$pass` 调用了 mysqli_real_escape_string（010.php:15），`$user` 未做任何转义、白名单或参数化处理，因此单引号可闭合 `user = '...'` 字面量，注入任意 SQL 片段（如 `' OR '1'='1` 绕过认证，或 UNION 读取其他表）。校验无效的根因是字符串拼接构造 SQL 且 `$user` 完全未净化。

影响：可绕过登录认证并以数据库连接账号权限读取/篡改 users 表及其他可访问表的数据（凭据泄露、越权登录）；若数据库账号权限较高，还可进一步读写文件或扩展影响。错误信息经 die(mysqli_error(...)) 回显，便于注入调试与数据回显。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：注入点为 HTTP 请求参数 `username`，无需认证即可访问登录逻辑；利用链闭合：010.php:8 读取参数 → 010.php:19 字符串拼接 → 010.php:20 mysqli_query 执行，中间无有效净化（`$user` 未转义、未参数化）。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：改用预处理语句与参数绑定（mysqli_prepare + bind_param 或 PDO prepared statement），彻底避免字符串拼接；对 `username` 做长度与字符白名单校验；移除 die(mysqli_error(...)) 的详细错误回显，改为记录日志并返回通用错误；数据库账号遵循最小权限，仅授予业务所需表的必要权限。

F-2 010.php 口令使用 MD5 哈希（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：010.php:15-16

010.php:16 对用户口令执行 `$pass = md5( $pass );`，即使用 MD5 这一已被证明存在碰撞且计算速度极快的算法处理口令。该哈希值随后在 010.php:19 被拼入登录查询用于口令比对，说明 MD5 被用于安全用途（口令存储/校验）。MD5 无盐、无迭代、无慢哈希特性，攻击者一旦获取哈希即可通过彩虹表或高速暴力破解还原口令。此处属于弱哈希（CWE-328），而非加密算法误用（CWE-327）。

影响：口令哈希泄露后可被快速离线破解，导致用户账户被接管；相同口令产生相同哈希，便于批量撞库与横向扩散。

CVE/CWE 论证：CWE-328（使用弱哈希算法）。配置/实现型弱点，无需 HTTP 污点链即可成立；证据为 010.php:16 的 `md5( $pass )` 原文调用，且该值在 010.php:19 用于口令比对，属安全用途。外部可达性：登录接口对外暴露，攻击者可通过其他途径（如 SQL 注入、备份泄露）获取哈希后离线破解。证据等级为源码推断（llm_inferred）。

修复建议：改用专为口令设计的慢哈希算法，如 PHP 的 password_hash()（PASSWORD_BCRYPT 或 PASSWORD_ARGON2ID）配合 password_verify() 校验；为每个口令使用独立随机盐；设定合理的工作因子；对历史 MD5 口令在用户下次登录时透明升级为强哈希。

F-3 010.php 登录成功页反射型 XSS：username 参数未转义直接拼入 HTML

medium xss / CWE-79 · 置信度 0.75 · candidate / llm_inferred

位置：010.php:8-28

脚本在 `$_GET['Login']` 存在时读取 `$_GET['username']`（第 8 行），仅做 stripslashes 与 mysqli_real_escape_string（第 9-10 行），这两者只针对 SQL 上下文，不做 HTML 转义。登录成功后第 28 行将 `$user` 直接拼入 `$html .= "<p>Welcome to the password protected area {$user}</p>"`，随后输出到页面，构成反射型 XSS。攻击者可构造带脚本的 username，诱导受害者点击链接，在目标域执行任意 JS，窃取会话或发起 CSRF 操作。

影响：在目标域执行任意 JS，可窃取会话 Cookie、发起 CSRF、钓鱼

CVE/CWE 论证：CWE-79 反射型 XSS；外部 GET 可达，需有效凭据但凭据可被受害者自身持有，链闭合

修复建议：输出前使用 htmlspecialchars($user, ENT_QUOTES, 'UTF-8') 转义
