F-1 051.php 开放重定向候选（CWE-601）——证据不足以确认

medium open_redirect / CWE-601 · 置信度 0.4 · candidate / rule_verified+llm

位置：051.php:7-9

候选声称 051.php:5 从 query 参数 `default` 读取外部输入，并在 051.php:9 通过 header("location: ?default=English") 形成开放重定向。但按输入给出的代码片段，第 9 行的 Location 值是硬编码字符串 "?default=English"，其中不含变量 $default，因此外部输入并未到达该 header 汇点；第 8 行的 stripos($default, "<script") 只是对输入做 XSS 关键字检查，与重定向目标无关。输入未提供 051.php:5 的实际读取语句（如 $_GET['default']），也未提供任何将 $default 拼接进 Location 头的代码行，故 source→sink 链在给定证据下不闭合。

影响：证据不足：若确实存在将用户可控值写入 Location 头的代码，则可能被用于钓鱼跳转（诱导用户从可信域跳转到攻击者站点）；但当前片段中 Location 为固定值，无法据此认定可利用的开放重定向。

CVE/CWE 论证：CWE-601（URL 重定向到不可信站点）要求外部可控输入进入重定向目标。给定证据中 051.php:9 的 header 值为常量 "?default=English"，不满足外部可达且可控的利用链闭合条件；无认证要求这一点也无法从片段确认。故不满足 CVE 论证所需的外部可达性与链闭合。

修复建议：若后续确认存在动态 Location 拼接：1) 不要直接把请求参数作为跳转目标；2) 使用服务端白名单映射（如 default→已知页面 ID），或仅允许相对路径并校验以单个 '/' 开头、拒绝 '//'、'\\'、'http:'、'https:' 等；3) 跳转前用 parse_url 规范化并比对允许的 host；4) 对无法校验的输入回退到固定默认页。
