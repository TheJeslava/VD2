F-1 013.php 修改密码处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：013.php:29-31

攻击者通过修改密码表单提交新口令，输入在 013.php:8 被读取为 $pass_new，随后在 013.php:26 仅经过 mysqli_real_escape_string 处理，在 013.php:27 被 md5() 哈希，最终在 013.php:30 被直接拼接进 UPDATE 语句：$insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . dvwaCurrentUser() . "' LIMIT 1;"，并在 013.php:31 交给 mysqli_query 执行。关键点在于：md5() 在拼接之前执行，因此攻击者无法通过引号闭合注入——引号会被 md5 哈希吞掉，实际进入 SQL 的是 32 位十六进制串，单引号闭合路径不成立。真正可注入的通道是 dvwaCurrentUser() 的返回值（若其来源可被外部影响，例如会话中的用户名），以及 $pass_new 在 md5 之前的任何非哈希化使用；就当前片段看，$pass_new 进入 SQL 前已被哈希为定长十六进制，常规引号注入被阻断。因此该候选的污点链在 013.php:27 处被 md5 削弱，证据不足以确认可利用的注入点，需补充 dvwaCurrentUser() 的实现与会话写入点才能闭合。

影响：若 dvwaCurrentUser() 的返回值可被攻击者控制（如会话用户名可篡改），则可构造 UPDATE 语句注入，导致任意用户口令被改写、通过 UNION/子查询读取 users 表口令哈希，进而账户接管；若仅 $pass_new 可控，则因 md5 定长十六进制化，实际影响有限。

CVE/CWE 论证：CWE-89：SQL 命令中特殊元素未正确中和。外部可达性：013.php 为 DVWA 修改密码页面，POST 参数 Change/password_new/password_conf 无需认证即可访问（DVWA 默认 low 安全级别）。但利用链闭合存在缺口：$pass_new 在拼接前经 md5() 变为定长十六进制，引号注入不成立；dvwaCurrentUser() 的数据流未在片段中给出，无法证明其外部可控。故当前证据等级为推断，不足以支撑 CVE 级结论。

修复建议：1) 使用预处理语句与参数绑定：$stmt = $db->prepare('UPDATE users SET password = ? WHERE user = ? LIMIT 1'); $stmt->bind_param('ss', $pass_new, dvwaCurrentUser()); 2) 停止使用 md5 存储口令，改用 password_hash()/password_verify()（PASSWORD_BCRYPT/ARGON2ID）；3) 对 dvwaCurrentUser() 的返回值做白名单校验（仅允许已知用户名集合）；4) 关闭 die(mysqli_error()) 的详细错误回显，避免报错注入与信息泄露。

F-2 DVWA 密码修改页 CAPTCHA 校验可被硬编码值+User-Agent 绕过，导致任意密码重置（CSRF 链）

high captcha_bypass / CWE-804 · 置信度 0.93 · candidate / llm_inferred

位置：013.php:17-31

013.php 在处理 POST Change 时，先调用 recaptcha_check_answer 校验第三方 CAPTCHA，但第 17-23 行的判定条件为 `$resp || ($_POST['g-recaptcha-response']=='hidd3n_valu3' && $_SERVER['HTTP_USER_AGENT']=='reCAPTCHA')`。攻击者只要提交固定字符串 hidd3n_valu3 并把 User-Agent 设为 reCAPTCHA，即可让整个 CAPTCHA 校验短路为真，无需任何真实 reCAPTCHA 令牌。随后第 25 行仅比较两次新密码是否相等，第 26-27 行做 mysqli_real_escape_string + md5，第 30-31 行直接 UPDATE users 表把当前用户密码改为攻击者指定值。由于该页面没有校验 CSRF token（第 52-53 行的 generateSessionToken 只在渲染表单时生成，处理分支未验证），攻击者可构造一个自动提交的跨站表单，诱导已登录受害者浏览器提交，从而在受害者不知情下重置其密码，实现账户接管。

影响：绕过 CAPTCHA 保护，结合缺失 CSRF token 校验，可在受害者不知情下重置其账户密码，实现账户接管；若受害者是管理员则导致后台完全失陷。

CVE/CWE 论证：CWE-804（Guessable CAPTCHA）/CWE-352（CSRF）。外部 HTTP 可达，无需真实 CAPTCHA 令牌，硬编码后门值 hidd3n_valu3 与可伪造的 User-Agent 头使校验恒真，链闭合至数据库密码更新。

修复建议：移除硬编码后门值 hidd3n_valu3 及基于 User-Agent 的判定；仅在 recaptcha_check_answer 返回成功时放行；在密码修改处理分支强制校验 CSRF token（如 generateSessionToken 生成、处理时比对）；密码修改要求输入旧密码。

F-4 密码修改使用无盐 MD5 存储口令（013.php:27）

medium weak_hash / CWE-328 · 置信度 0.85 · candidate / llm_inferred

位置：013.php:27-27

第 27 行对用户新密码仅执行 md5($pass_new) 后写入数据库，未使用盐值或 password_hash 等自适应算法。MD5 计算速度极快且无盐，一旦数据库泄露可通过彩虹表/GPU 快速还原明文，且相同密码产生相同哈希，便于横向撞库。

影响：数据库泄露时用户口令可被快速离线破解，导致账户接管与撞库扩散。

CVE/CWE 论证：CWE-328（Use of Weak Hash）。代码明确使用 md5 存储口令，属可确认的实现缺陷。

修复建议：改用 password_hash()/password_verify()（bcrypt/argon2）并加盐。

F-5 013.php 使用 MD5 存储口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.8 · candidate / rule_verified+llm

位置：013.php:26-27

013.php:27 执行 $pass_new = md5( $pass_new );，将用户新口令以无盐 MD5 形式哈希后写入 users 表（013.php:30-31 的 UPDATE）。MD5 为快速、无盐、已被证明存在碰撞的哈希算法，用于口令存储时无法抵抗离线暴力破解与彩虹表攻击。此处属于 weak_hash（CWE-328），而非 weak_crypto（CWE-327，指 DES/ECB 等加密算法问题）。该弱点为配置/实现型，无需 HTTP 污点链即可成立，原文证据为 013.php:27 的 md5( 调用。

影响：数据库泄露后，攻击者可用彩虹表或 GPU 暴力破解在极短时间内还原用户明文口令；由于 DVWA 用户口令常被复用，可导致跨系统账户接管。无盐哈希还使相同口令产生相同哈希，便于批量识别。

CVE/CWE 论证：CWE-328：使用已被破解或强度不足的哈希算法。外部可达性：修改密码功能对任意访问者开放，无需认证即可触发哈希写入路径（DVWA low 级别）。利用链闭合：口令经 md5() 后直接入库，攻击者获取库文件即可离线破解，链路完整，不依赖额外污点。

修复建议：1) 改用 password_hash($pass_new, PASSWORD_DEFAULT)（bcrypt/Argon2id），校验用 password_verify()；2) 每用户独立随机盐（password_hash 自动处理）；3) 迁移期对存量 MD5 哈希在下次登录时透明重哈希；4) 增加口令复杂度与长度策略，限制弱口令。
