F-1 022.php 修改密码功能 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.55 · candidate / rule_verified+llm

位置：022.php:42-44

攻击者通过 HTTP 请求向 022.php 的修改密码功能提交 password_new 参数（022.php:25 读取），该值在 022.php:38 仅经过 mysqli_real_escape_string 转义后，于 022.php:39 被 md5() 处理，随后在 022.php:43 被直接拼接进 UPDATE 语句：$insert = "UPDATE `users` SET password = '" . $pass_new . "' WHERE user = '" . $current_user . "';"，并在 022.php:44 交给 mysqli_query 执行。由于 md5() 的输出是 32 位十六进制字符串，正常情况下会消除引号等元字符，因此单看 password_new 路径，注入被 md5 输出字符集限制；但同一 UPDATE 语句还拼接了 $current_user（022.php:42 由 dvwaCurrentUser() 取得），该值未经参数化即进入 SQL。校验无效的原因在于整条语句采用字符串拼接而非预处理语句，任何进入拼接的变量都缺少类型/白名单约束。最终危险操作是 mysqli_query 执行被拼接的 UPDATE 语句。

影响：若 $current_user 或其它拼接变量可被外部影响，攻击者可改写 UPDATE 语句结构，实现越权修改任意用户口令（包括 admin）、绕过认证或通过报错/布尔差异枚举数据库内容，导致账户接管与数据泄露。就 password_new 单一路径而言，md5 输出字符集显著限制了注入可行性，实际可利用性取决于 $current_user 的来源是否可控。

CVE/CWE 论证：CWE-89（SQL 注入）：外部可达（022.php 为 Web 入口，POST 参数 password_new 直接读取）、无需认证即可访问该脚本（DVWA 低安全级别下无令牌/权限校验），利用链为 022.php:25 读取参数 → 022.php:43 字符串拼接 → 022.php:44 mysqli_query 执行。需注意 md5 对 password_new 的字符集收敛作用，因此该链的闭合程度依赖 $current_user 的可控性，证据等级为源码推断。

修复建议：改用参数化查询（mysqli_prepare + bind_param 或 PDO 预处理），将 password 与 user 作为绑定参数；对 $current_user 使用会话内服务端取值并做白名单校验，禁止从请求派生；对 password_new 做长度与字符集校验；移除对 SQL 语句的手工拼接，统一使用 ORM/查询构造器。

F-2 022.php JSON 请求体读取被误标为路径穿越（CWE-22）

high path_traversal / CWE-22 · 置信度 0.4 · candidate / rule_verified+llm

位置：022.php:6-8

候选将 022.php:8 的 $data = json_decode(file_get_contents('php://input'), true); 标记为路径穿越汇点。实际分析：file_get_contents 的参数是固定字面量 'php://input'，不包含任何来自请求的路径片段；外部输入是请求体内容，经 json_decode 解析为数组 $data，属于数据解析而非文件路径选择。因此不存在攻击者可控路径进入文件系统 API 的链路，不满足 CWE-22 的构成要件。022.php:7 仅校验 REQUEST_METHOD 为 POST 且 CONTENT_TYPE 为 application/json，属于内容类型分支，与路径无关。

影响：证据不足，无法确认路径穿越影响。若强行按原候选描述，会错误声称可任意文件读写，但源码中不存在可控路径参数，故不成立。

CVE/CWE 论证：不满足 CWE-22：source 为请求体内容而非路径字符串，sink 的路径参数为常量 'php://input'，无污点从外部输入流向文件路径。外部可达性成立但利用链不闭合，判定为误报。

修复建议：无需针对路径穿越修复。建议保留对 JSON 解析结果的字段级校验（类型、长度、允许键白名单），并对 json_decode 失败情况返回 400；如后续引入基于 $data 中字段的文件操作，必须使用 basename/realpath 规范化并限制在固定根目录内。

F-3 022.php 使用 MD5 存储口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.8 · candidate / rule_verified+llm

位置：022.php:38-39

022.php:39 执行 $pass_new = md5( $pass_new );，将用户新口令以无盐 MD5 单轮哈希后写入 users 表 password 字段（022.php:43-44 的 UPDATE 语句）。保护对象是账户口令这一安全敏感数据，属于口令存储用途。MD5 计算极快且无盐，攻击者一旦通过数据库泄露、备份泄露或 SQL 注入读取到哈希值，可用彩虹表或 GPU 暴力在极短时间内还原常见口令；相同口令产生相同哈希，便于横向比对。此处应归类为 weak_hash（CWE-328），而非 weak_crypto（CWE-327，指 DES/ECB 等加密算法缺陷）。

影响：口令哈希可被离线快速破解，导致账户接管；无盐导致相同口令哈希一致，泄露用户间口令复用关系；若与前述 SQL 注入结合，攻击者可直接读取或覆写哈希，进一步扩大账户沦陷范围。

CVE/CWE 论证：CWE-328（使用弱哈希算法）：配置/实现型弱点，无需 HTTP 污点链即可成立。原文证据为 022.php:39 的 md5( $pass_new ) 调用，作用于口令字段；外部可达性体现在任何触发修改密码流程的请求都会生成该哈希，无需额外认证条件即可观察到该实现。

修复建议：改用 password_hash()（PASSWORD_ARGON2ID 或 PASSWORD_BCRYPT）生成带盐慢哈希，校验使用 password_verify()；迁移期可对旧 MD5 值在用户下次登录成功后透明重哈希；禁止在任何新代码中使用 md5/sha1 处理口令、令牌或签名。
