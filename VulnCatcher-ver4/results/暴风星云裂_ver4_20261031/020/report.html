020.php:13-15：`if (isset ($_POST['include'])) { $page['body'] .= "\n\t<script src='" . $_POST['include'] . 影响：反射型 HTML/脚本注入：攻击者可构造恶意 POST 表单或自动提交页面，使受害者浏览器加载攻击者指定的脚本源或注入内联事件处理器，从而在目标站点源下执行任意 JavaScript，窃取会话 Cookie、发起 CSRF 操作或篡改页面内容。实际可利用性受第 3 行 CSP 限制（见 SEM-582e93de1b73），但 CSP 白名单包含多个第三方 CDN，若攻击者能在其中任一域托管脚本，则可绕过。

F-3 020.php 中 POST 参数 include 未编码直接拼入 <script src> 导致反射型 XSS

medium xss / CWE-79 · 置信度 0.9 · candidate / llm_inferred

位置：020.php:13-17

020.php 第 13-17 行读取 $_POST['include']，未做任何 HTML 属性编码或白名单校验，直接拼接进 <script src='...'> 的 src 属性并输出到响应体。攻击者可提交包含单引号闭合属性的 payload（如 `' onerror='alert(1)` 或 `'></script><script>alert(1)</script>`），突破 script 标签属性上下文，注入任意 HTML/JS。虽然页面设置了 CSP（第 3-5 行），但 CSP 的 script-src 白名单包含 unpkg.com、cdn.jsdelivr.net、pastebin.com 等可托管任意 JS 的公共 CDN，攻击者可借助这些域加载自己的脚本，CSP 无法阻止。

影响：反射型 XSS，可在受害者浏览器上下文执行任意 JS，窃取会话/发起 CSRF/钓鱼；CSP 因白名单含公共 CDN 而无法有效缓解

CVE/CWE 论证：CWE-79：外部可达、无需认证，source（$_POST['include']）到 sink（HTML 输出）链路完整闭合，无编码/校验

修复建议：对 include 值使用 htmlspecialchars($v, ENT_QUOTES) 编码；或仅允许 CSP 白名单内的固定域名并做严格 URL 校验；收紧 CSP 移除可托管任意内容的公共 CDN

F-4 020.php 第 3 行 CSP script-src 白名单过宽（CWE-693 防护机制失效）

medium csp / CWE-693 · 置信度 0.7 · candidate / rule_verified+llm

位置：020.php:2-3

020.php:3 定义 `$headerCSP = "Content-Security-Policy: script-src 'self' https://pastebin.com hastebin.com www.toptal.com example.com code.jquery.com https://ssl.google-analytics.com unpkg.com cdn.jsdelivr.net digi.ninja ;"`。该策略允许从 pastebin.com、hastebin.com、unpkg.com、cdn.jsdelivr.net 等用户可发布内容的第三方站点加载脚本。这些站点允许任意用户上传/托管 JS，因此 CSP 无法有效阻止攻击者注入的 `<script src>` 指向其托管内容，防护形同虚设。此外策略中缺少 object-src 'none'、base-uri 等指令，且未使用 nonce/hash。

影响：CSP 作为 XSS 缓解措施失效：结合 020.php:15 的输出注入，攻击者可将脚本托管在 pastebin/hastebin/unpkg/jsdelivr 等白名单域，使注入的 `<script src>` 通过 CSP 校验并在受害者浏览器执行，导致会话劫持、页面篡改、凭证窃取。

CVE/CWE 论证：CWE-693（防护机制失效）：CSP 是用于缓解 XSS 的安全控制，但其 script-src 白名单包含可被任意用户写入内容的域，控制未达到设计目的。该缺陷为配置型弱点，无需污点链即可成立；外部可达性由 020.php 的公开 HTTP 端点保证，无需认证。

修复建议：将 script-src 收紧为 'self' 加必要的固定业务域，移除 pastebin/hastebin/unpkg/jsdelivr 等用户内容托管域；引入 nonce 或 hash 机制；补充 object-src 'none'、base-uri 'self'、frame-ancestors 'none'；对第三方脚本使用 SRI 完整性校验。
