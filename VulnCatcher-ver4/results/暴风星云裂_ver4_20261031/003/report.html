F-2 003.php 基于 REQUEST_URI 的路径处理与 API 信息泄露（CWE-200）

high api_info_disclosure / CWE-200 · 置信度 0.4 · candidate / rule_verified+llm

位置：003.php:3-4

证据仅覆盖 003.php 第 3-4 行：第 3 行 `$request_url = $_SERVER['REQUEST_URI'];` 将客户端可控的请求 URI（含路径与查询串）读入变量；第 4 行 `$stripped_url = str_replace("/vulnerabilities/api/", "", $request_url);` 仅做一次固定子串删除，未做规范化、未校验前缀、未限制输出字段。攻击者输入点即 HTTP 请求行中的 URI（任意路径/查询串），经 `$_SERVER['REQUEST_URI']` → `$request_url` → `str_replace` → `$stripped_url`。由于 `str_replace` 只删除字面子串且不区分大小写变体、重复出现、URL 编码形式（如 `%2f`、`..%2f`、`//vulnerabilities/api/`），剥离结果仍可能保留攻击者构造的路径片段；同时该变量后续如何被用于路由分发或响应拼装，在给定片段中不可见，因此“信息泄露”的具体汇点（是否回显 `$stripped_url`、是否据此选择 API 资源并返回用户对象字段）证据不足。当前只能确认：该端点以请求 URI 作为唯一输入并做非规范化字符串处理，属于典型的路径/资源标识处理缺陷面，但缺少读取后的危险汇点证据。

影响：若后续代码将 `$stripped_url` 直接用于资源定位或响应回显，可能导致：未授权读取其他 API 资源/用户对象字段（越权信息泄露）、通过路径变体绕过 `/vulnerabilities/api/` 前缀限制访问内部端点、以及在错误响应中回显内部路径结构。基于现有片段，上述影响为推断，未验证。

CVE/CWE 论证：CWE-200（向未授权方暴露信息）。外部可达性：入口为 `$_SERVER['REQUEST_URI']`，任意远程 HTTP 请求即可触达，无需认证（片段中未见任何鉴权判断）。利用链闭合性：source（第 3 行）与中间处理（第 4 行）已确认，但缺少“读取后的危险汇点”（响应输出或资源分发）证据，链未闭合，故不满足 CVE 级论证；需补充 003.php 第 5 行之后的代码以确认汇点。

修复建议：1) 不要用 `str_replace` 做前缀剥离，改为解析后比较：用 `parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH)` 取路径并 `rawurldecode` 规范化，再用 `str_starts_with($path, '/vulnerabilities/api/')` 严格校验前缀，不匹配直接返回 404；2) 对剥离后的资源标识使用白名单映射（固定路由表/枚举），禁止把用户输入直接拼入资源查找；3) 响应仅返回显式声明的字段（DTO 白名单），避免整对象序列化；4) 该 API 端点强制鉴权与对象级授权校验；5) 统一错误响应，不回显内部路径或堆栈。
