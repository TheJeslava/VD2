F-1 055.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：055.php:17-19

攻击者通过 HTTP 请求向 055.php 提交留言表单，外部输入在 055.php:5 被读入变量 $message（候选 source 记为 query `mtxMessage`，即留言内容字段），随后在 055.php:18 被直接字符串拼接进 INSERT 语句：$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";，其中 $message 被单引号包裹但未做任何转义或参数化。该拼接后的 $query 在 055.php:19 传入 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行，构成从外部输入到 SQL 执行汇点的完整污点链。由于缺少 mysqli_real_escape_string / 预处理语句，攻击者只需在留言内容中闭合单引号即可跳出字符串字面量并注入任意 SQL 片段；055.php:19 的 or die(...) 分支还会把 mysqli_error 内容回显到页面，为报错型注入提供了回显通道。

影响：数据库层面的任意 SQL 执行：可读取、篡改或删除 guestbook 及其他同库表数据（数据泄露/完整性破坏），可结合报错回显进行盲注或联合查询提取凭据；若数据库账户权限过高，还可通过文件读写或堆叠语句进一步扩大影响，具体取决于 MySQL 账户权限与驱动是否允许多语句（证据不足，未在片段中体现）。

CVE/CWE 论证：CWE-89（SQL 注入）：外部可控输入 $message 未经参数化或转义即拼接进 SQL 语句并在 055.php:19 执行，属于典型的注入类缺陷。外部可达性：055.php 为 Web 可访问脚本，输入来自请求参数，无需认证即可提交留言；利用链闭合：source（055.php:5 读取留言内容）→ 拼接（055.php:18）→ sink（055.php:19 mysqli_query），中间无有效净化，且错误信息回显降低了利用门槛。

修复建议：改用预处理语句与参数绑定：$stmt = mysqli_prepare($link, "INSERT INTO guestbook (comment, name) VALUES (?, ?)"); mysqli_stmt_bind_param($stmt, "ss", $message, $name); mysqli_stmt_execute($stmt);。若必须使用拼接，至少对每个变量调用 mysqli_real_escape_string 并强制使用正确的字符集。同时关闭生产环境的数据库错误回显（移除 or die(mysqli_error(...))），改为记录日志并返回通用错误页；数据库账户遵循最小权限，仅授予该表 INSERT 权限。
