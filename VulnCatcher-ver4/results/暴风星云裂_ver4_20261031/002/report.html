high api_info_disclosure / CWE-200 · 置信度 0.4 · candidate / rule_verified+llm

位置：002.php:9-10

攻击者通过任意 HTTP 请求控制请求行中的 URI，该值在 002.php:9 被读入 $request_url = $_SERVER['REQUEST_URI']，随后在 002.php:10 通过 $stripped_url = str_replace("/vulnerabilities/api/", "", $request_url) 仅做字符串替换后即被用于后续逻辑（输入片段止于第 11 行，后续使用点未在 code_pack 中给出）。校验无效的原因在于：str_replace 只做字面量删除，不做路径规范化、白名单匹配或前缀强校验，攻击者可通过大小写变体、URL 编码（%2f、%2e%2e）、重复片段、查询串或路径参数等方式构造 URI，使替换结果偏离预期路由键，从而影响后续基于 $stripped_url 的分支/回显/资源定位。当前证据仅覆盖第 9-10 行的取值与替换，尚未看到 $stripped_url 的具体汇点（是否进入 echo、文件包含、路由分发或错误信息输出），因此“信息泄露”的具体形态（端点枚举、内部路径/字段暴露）属于基于语义模式的推断。

影响：若 $stripped_url 后续被用于路由分发或错误回显，攻击者可枚举内部 API 端点、触发差异化错误信息，泄露服务端路径结构、可用接口与字段布局，为后续越权或注入攻击提供侦察面。具体泄露内容（版本号、鉴权状态、返回字段）证据不足，需结合 002.php 第 11 行之后的代码与运行时响应确认。

CVE/CWE 论证：CWE-200（Exposure of Sensitive Information to an Unauthorized Actor）。外部可达性：该逻辑位于 002.php 请求处理入口，直接读取 $_SERVER['REQUEST_URI']，任意未认证 HTTP 客户端均可触发，无需认证或特殊权限。利用链闭合度：source（REQUEST_URI）→ 变换（str_replace 字面量剥离）→ 汇点（$stripped_url 的后续使用）中，最后一环未在给定片段中出现，故不满足完整闭合，暂不作为已确认 CVE 级漏洞，仅作为高置信度候选。

修复建议：1) 不要用 str_replace 剥离路径前缀，改用 parse_url() 提取 path 后与固定前缀做严格前缀比较（str_starts_with / 正则 ^/vulnerabilities/api/），不匹配直接返回 404；2) 对路径做 rawurldecode 后再规范化（realpath/去除 ../ 与重复斜杠），并拒绝包含 %00、..、反斜杠的输入；3) 路由使用白名单映射表（端点名 → 处理器），未知端点统一返回同一错误页，避免差异化回显；4) 生产环境关闭 display_errors，错误响应不返回内部路径与堆栈；5) 对 API 响应做字段级最小化，敏感字段（版本、内部主机名、调试信息）不下发。
