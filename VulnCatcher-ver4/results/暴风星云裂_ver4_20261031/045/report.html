F-1 045.php 不安全文件上传导致任意文件落盘（CWE-434）

critical file_upload / CWE-434 · 置信度 0.73 · candidate / rule_verified+llm

位置：045.php:16-18

攻击者通过 HTTP 文件上传字段 `uploaded` 提交文件（045.php:18 的 `$_FILES['uploaded']['tmp_name']`），代码在 045.php:18 直接调用 `move_uploaded_file($_FILES['uploaded']['tmp_name'], $target_path)` 将临时文件移动到 `$target_path`。输入片段仅覆盖第 16-18 行，未出现对扩展名、MIME 类型、文件内容或目标路径的任何白名单校验，也未出现 `$target_path` 的构造与规范化代码，因此从可见证据看不存在有效净化，污点从上传字段直达文件落盘汇点。需注意：`$target_path` 的具体取值（是否包含用户可控的文件名、是否固定目录）在给定片段中不可见，属于证据缺口。

影响：若 `$target_path` 位于 Web 可访问目录且文件名/扩展名可控，攻击者可上传 .php 等可执行脚本，通过访问上传后的 URL 触发远程代码执行，进而读取配置、数据库凭据、篡改站点内容或作为内网跳板；即使不可执行，也可造成任意文件写入/覆盖、磁盘占满与恶意内容托管。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部可达性：上传入口为 HTTP 请求的 multipart 表单字段 `uploaded`，无需认证即可访问该脚本；利用链闭合：`$_FILES['uploaded']['tmp_name']` → `move_uploaded_file(..., $target_path)` 直接落盘，可见代码段内无扩展名/类型/路径校验。证据等级为源码推断（llm_inferred），`$target_path` 构造逻辑未在片段中给出，故不宣称已完全验证。

修复建议：1) 对上传文件使用扩展名白名单（如仅 jpg/png/pdf）并同时校验服务端 MIME 与文件魔数，不信任客户端 Content-Type；2) 上传文件名由服务端生成（UUID + 白名单扩展名），禁止使用用户提供的文件名拼接路径；3) 使用 `basename()` 与 `realpath()` 规范化并校验目标路径必须落在固定上传目录内，防止路径穿越；4) 上传目录置于 Web 根之外，或通过 Nginx/Apache 配置禁止该目录执行 PHP（如 `php_flag engine off`）；5) 限制文件大小与数量，上传后重命名并设置最小权限（0644、非可执行）；6) 对图片等做二次编码/重采样以剥离潜在脚本载荷。

F-2 DVWA 上传端点 045.php 仅校验客户端可控的 MIME 类型，可上传 PHP 脚本并远程执行

high file_upload / CWE-434 · 置信度 0.88 · candidate / llm_inferred

位置：045.php:3-26

045.php 在收到 POST 参数 Upload 后，把上传文件写入 DVWA_WEB_PAGE_TO_ROOT . "hackable/uploads/" 目录，文件名取自 $_FILES['uploaded']['name'] 经 basename() 处理。唯一的“是不是图片”校验使用 $_FILES['uploaded']['type']（即 HTTP 请求中的 Content-Type，完全由客户端控制）与 $_FILES['uploaded']['size']（同样由客户端声明），既没有校验扩展名，也没有用 getimagesize()/finfo 检查真实内容。攻击者只要把 Content-Type 伪造成 image/jpeg 并控制文件大小，就能把任意 .php 文件写入 Web 可访问的 uploads 目录，随后直接请求该文件即可在服务器上执行任意 PHP 代码（RCE）。

影响：未认证/低权限攻击者可在服务器写入并执行任意 PHP 代码，完全控制 Web 应用与主机（RCE）。

CVE/CWE 论证：CWE-434 不受限制的危险文件上传。外部 HTTP 可达，无需认证即可触发，source（$_FILES 客户端字段）到 sink（move_uploaded_file）链路在 CODE PACK 内完整闭合，校验可被 Content-Type 伪造绕过。

修复建议：使用服务端内容检测（getimagesize/finfo_file）验证真实图片类型；对文件名做白名单扩展名与随机化重命名；将上传目录置于 Web 根之外或禁止其执行脚本；限制文件大小在服务端校验。
