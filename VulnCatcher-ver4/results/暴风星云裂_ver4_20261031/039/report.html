F-1 039.php 基于 query 参数 id 的 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.78 · candidate / rule_verified+llm

位置：039.php:13-15

攻击者通过 HTTP 请求的 query 参数 `id` 提供输入，该输入在 039.php:5 被读取后未做任何类型校验、转义或参数化，直接以字符串拼接方式进入 039.php:13 构造的 SQL 语句：`SELECT first_name, last_name FROM users WHERE user_id = $id;`，随后在 039.php:15 通过 `mysqli_query($GLOBALS["___mysqli_ston"], $query)` 执行。由于 `$id` 被原样嵌入 SQL 文本，攻击者可闭合/改写 WHERE 条件（如布尔盲注、UNION 联合查询、时间盲注），校验无效的根本原因是全程缺少 `intval()`/`mysqli_real_escape_string()`/预处理语句等任何净化手段，且代码注释显示已移除 `or die` 以抑制错误回显，进一步降低攻击者探测成本。

影响：数据库查询逻辑可被任意篡改：可越权读取 users 表及其他表的数据（如凭据、个人信息），可借助 UNION/布尔/时间盲注逐字节提取数据；若数据库账户权限过高，还可能读写文件或进一步影响底层主机。属于数据泄露与数据库层面的越权访问。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：注入点为 HTTP query 参数 `id`，无需认证即可访问该脚本；利用链闭合：039.php:5 读取输入 → 039.php:13 字符串拼接进 SQL → 039.php:15 `mysqli_query` 执行，中间无任何过滤或参数化，攻击者完全控制 SQL 片段。

修复建议：改用预处理语句与参数绑定（`mysqli_prepare` + `bind_param('i', $id)`），或将 `$id` 强制转换为整数（`$id = (int)$_GET['id']`）并配合白名单校验；禁止将外部输入直接拼接进 SQL 文本；为数据库账户授予最小权限，关闭详细错误回显。
