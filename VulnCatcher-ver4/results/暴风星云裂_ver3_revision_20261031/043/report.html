位置：043.php:18-20

攻击者通过上传表单字段 `uploaded`（043.php:12 读取上传文件）提交文件，脚本将上传文件的临时路径保存到 `$uploaded_tmp`，随后在 043.php:20 直接调用 `move_uploaded_file($uploaded_tmp, $target_path)` 把文件移动到目标路径。代码片段中未见对扩展名、MIME 类型、文件内容或目标路径的白名单校验，也未见对 `$target_path` 的规范化与目录限制，因此上传文件的类型与落盘位置均未受约束。由于输入仅给出 043.php:12 与 043.php:18-20 的片段，`$target_path` 的具体构造逻辑（是否拼接用户可控文件名/路径）在证据中不可见，此点标注为证据不足。

影响：若 `$target_path` 位于 Web 可访问目录且扩展名未受限，攻击者可上传 .php 等可执行脚本，通过 HTTP 请求触发后获得服务器端代码执行（RCE）；即使不可执行，也可造成任意文件写入/覆盖、磁盘占用，并可能借上传的 HTML/SVG 实施存储型 XSS 或钓鱼。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部可达性：上传入口为 HTTP 文件上传参数 `uploaded`，无需认证即可访问（片段中未见鉴权逻辑）。利用链闭合：外部上传 → `$uploaded_tmp` → `move_uploaded_file($uploaded_tmp, $target_path)` 落盘，中间无类型/扩展名/路径校验。证据等级为 llm_inferred，`$target_path` 的构造与目录可访问性未在片段中体现，故 RCE 结论依赖该前提。

修复建议：1) 使用扩展名白名单（如仅 jpg/png/pdf）并同时校验 MIME 与文件魔数，拒绝双扩展名与可执行类型；2) 上传目录置于 Web 根之外，或关闭该目录的脚本执行权限；3) 服务端生成随机文件名，禁止用户控制 `$target_path`，并对路径做 realpath 规范化后校验其位于允许目录内；4) 限制文件大小与数量；5) 上传后重命名并去除执行位，必要时做病毒/内容扫描。
