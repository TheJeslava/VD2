F-1 010.php 登录查询 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.73 · candidate / rule_verified+llm

位置：010.php:18-20

攻击者通过 HTTP 请求的 query 参数 `username`（010.php:8 读取）提交任意字符串，该值被直接拼进 010.php:19 的 SQL 语句 `SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';`，随后在 010.php:20 交给 mysqli_query 执行。代码中仅对 `$pass` 做了 mysqli_real_escape_string（010.php:15），`$user` 没有任何转义、白名单或参数化处理，因此单引号可闭合字符串字面量，注入任意 SQL 片段（如 `' OR '1'='1` 绕过认证，或 UNION 读取其他表）。校验无效的根因是字符串拼接构造 SQL 且未使用预处理语句。

影响：可绕过登录认证（以任意已知用户身份登录）、读取 users 表及其他库表数据（凭据泄露）、在数据库权限允许时篡改或删除数据；错误信息经 die() 回显（010.php:20）还会泄露数据库结构与版本，为进一步利用提供信息。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：注入点为 HTTP query 参数 `username`，无需认证即可访问登录接口；利用链闭合：010.php:8 读取输入 → 010.php:19 字符串拼接 → 010.php:20 mysqli_query 执行，全程无有效净化，攻击者可控完整 SQL 语义。

修复建议：改用参数化查询/预处理语句（mysqli_prepare + bind_param 或 PDO prepared statement），将 `$user` 与 `$pass` 作为绑定参数传入，禁止字符串拼接；对输入做长度与字符白名单校验；关闭错误详情回显（不要用 die(mysqli_error()) 输出到页面），改为记录服务端日志；数据库账号遵循最小权限，仅授予必要表的 SELECT 权限。

F-2 010.php 口令使用 MD5 哈希（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：010.php:15-16

010.php:16 对用户口令执行 `$pass = md5( $pass );`，将 MD5 用作口令存储/比对的哈希算法。MD5 为快速、无盐、抗碰撞性已被攻破的哈希，不适合口令等安全用途；代码中未见盐值或迭代（如 password_hash/PBKDF2/bcrypt/Argon2）。攻击者一旦获取 users 表（例如借助同文件 GEN-7034f0a19983 的 SQL 注入读取数据），可对 MD5 摘要进行高速字典/彩虹表破解，还原明文口令。

影响：口令摘要可被离线高速暴力破解或彩虹表命中，导致用户凭据泄露；结合 SQL 注入可批量导出并破解口令，进而横向登录其他系统（凭据复用）。

CVE/CWE 论证：CWE-328（使用弱哈希算法）。属实现型弱点，无需 HTTP 污点链即可成立：证据为 010.php:16 明文调用 md5() 处理口令；外部可达性体现在登录流程对用户口令做 MD5 后比对，且摘要可经数据库泄露路径（同文件 SQL 注入）被外部获取。

修复建议：改用专为口令设计的慢哈希：PHP 的 password_hash()（PASSWORD_BCRYPT 或 PASSWORD_ARGON2ID）配合 password_verify()，自动加盐并支持成本参数；迁移时对存量 MD5 摘要在用户下次登录成功后透明重哈希；禁止在口令路径使用 MD5/SHA-1。

F-3 010.php 登录成功后用户名未编码回显导致反射型 XSS（$user 直接拼入 $html）

medium xss / CWE-79 · 置信度 0.72 · candidate / llm_inferred

位置：010.php:8-28

010.php 第 8 行从 $_GET['username'] 读取用户名，仅经过 stripslashes 与 mysqli_real_escape_string（第 9-10 行），这两个函数只针对 SQL 上下文转义，不做 HTML 编码。第 22-29 行登录成功后，第 28 行把 $user 直接拼进 $html 的 <p> 标签中输出，未调用 htmlspecialchars/htmlentities，攻击者可在 username 中注入 HTML/JS，在受害者浏览器执行。

影响：反射型 XSS，可窃取会话 Cookie 或诱导管理员执行敏感操作

CVE/CWE 论证：CWE-79；外部 GET 可达，需有效登录凭据（降低可利用性），链闭合

修复建议：输出前对 $user 使用 htmlspecialchars($user, ENT_QUOTES, 'UTF-8')
