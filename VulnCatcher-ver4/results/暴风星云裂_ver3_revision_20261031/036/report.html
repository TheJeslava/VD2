medium open_redirect / CWE-601 · 置信度 0.87 · candidate / llm_inferred

位置：036.php:3-13

036.php 第 3 行从 $_GET['redirect'] 读取外部输入，第 4 行用正则 /http:\/\/|https:\/\//i 做黑名单校验，仅拦截以 http:// 或 https:// 开头的绝对 URL；第 11 行将未经过滤的原始值直接拼入 header("location: " . $_GET['redirect'])。攻击者可提交以 // 开头的协议相对 URL（如 //evil.example）或其它不含 http://、https:// 字样的跳转目标，绕过黑名单，使服务端返回 302 将用户重定向到攻击者控制的站点，可用于钓鱼、OAuth/SSO 令牌窃取或绕过基于域名的访问控制。

影响：攻击者可构造指向恶意站点的链接，诱导已登录用户点击后跳转至钓鱼页面，或用于 OAuth/SSO 回调参数污染窃取授权码；也可绕过依赖域名白名单的访问控制。

CVE/CWE 论证：CWE-601 URL 重定向到不可信站点。入口为公开 GET 参数，无需认证；source（036.php:3）→ 黑名单校验（036.php:4，可绕过）→ sink（036.php:11 header Location）链路在 CODE PACK 内完整闭合。

修复建议：不要使用黑名单。改为白名单校验：仅允许相对路径（拒绝以 // 或 /\ 开头、拒绝包含 :// 与 scheme），或维护允许跳转的域名列表并解析后比对 host；也可用固定映射表将逻辑名映射到内部路径。
