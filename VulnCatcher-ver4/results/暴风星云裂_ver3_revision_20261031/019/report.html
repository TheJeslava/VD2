high path_traversal / CWE-22 · 置信度 0.4 · candidate / rule_verified+llm

攻击者通过 POST 参数 include 提交外部输入（019.php:8 的 isset($_POST['include']) 仅做存在性判断，未做任何白名单、basename 或 realpath 规范化）。该值在 019.php:10 被直接拼接进 $page['body'] 的字符串中（" . $_POST['include'] . 影响：可读取/包含服务器上任意可读文件（如配置文件、密钥、/etc/passwd），若可包含上传文件或日志则可能进一步导致代码执行；也可造成敏感信息泄露。

CVE/CWE 论证：CWE-22 路径穿越：外部可控输入（POST include）未经规范化直接进入文件包含/路径拼接汇点（019.php:10），无需认证即可通过 HTTP POST 触达，利用链闭合。证据等级为源码推断，未做动态验证。

修复建议：对 include 参数使用固定白名单映射（如允许的页面名到文件路径的字典），拒绝包含 ../、绝对路径与协议前缀；使用 basename() 与 realpath() 规范化并校验结果仍位于允许目录内；避免把用户输入直接拼接进包含路径或页面内容。

F-3 DVWA CSP 页面 POST 参数 include 未编码直接拼接进 HTML 响应体（反射型 XSS）

medium xss / CWE-79 · 置信度 0.72 · candidate / llm_inferred

位置：019.php:8-12

019.php 第 8-12 行读取 $_POST['include']，未做任何 HTML 实体编码或白名单过滤，直接以字符串拼接方式追加到 $page['body']，随后该 body 被输出到页面。攻击者可构造包含 <script> 或事件处理器的 POST 请求，使恶意脚本在受害者浏览器中执行。页面第 2-4 行设置了 Content-Security-Policy: script-src 'self'，会阻止内联脚本与外部域脚本执行，因此经典 <script> 注入被 CSP 削弱；但注入的 HTML 标记本身仍被渲染（如 <img src=x onerror=...> 受 CSP 限制同样被拦），实际可利用性依赖 CSP 是否被绕过或页面是否在其它上下文输出。根因是缺少输出编码（CWE-79）。

影响：反射型 XSS，可在受害者浏览器执行脚本；受 script-src 'self' CSP 限制，内联脚本被拦，实际危害取决于 CSP 绕过或其它输出上下文。

CVE/CWE 论证：CWE-79：外部可控 POST 参数未经编码进入 HTML 输出，链闭合；但 CSP 削弱了脚本执行，故定为 medium。

修复建议：对 $_POST['include'] 使用 htmlspecialchars($v, ENT_QUOTES, 'UTF-8') 后再输出，或改用白名单。

F-4 019.php CSP 配置为 script-src 'self' 的语义命中（CWE-693）

medium csp / CWE-693 · 置信度 0.4 · candidate / rule_verified+llm

位置：019.php:1-2

019.php:2 定义 $headerCSP = "Content-Security-Policy: script-src 'self';";。该策略限制脚本来源为同源，但同源下若存在可控脚本文件（如 019.php:20 引用的 source/high.js）或可上传/可写入的同源资源，则 CSP 无法阻止脚本执行。当前证据仅显示策略字符串定义，未显示其被发送到响应头，也未确认同源可控脚本的存在，属语义模式命中。

影响：若同源存在可控脚本或上传点，CSP 保护可被绕过，导致脚本注入/XSS 类影响；当前证据不足以确认实际可利用性。

CVE/CWE 论证：CWE-693 保护机制失效：CSP 策略过宽或未生效。外部可达性依赖响应头实际下发与同源资源可控性，证据不足，未闭合利用链。

修复建议：确认 $headerCSP 通过 header() 实际下发；收紧策略（如增加 nonce/hash、object-src 'none'、base-uri 'none'）；审计同源 source/high.js 等资源是否可被攻击者写入或替换。
