F-1 045.php 不安全文件上传（CWE-434）：上传文件被直接 move_uploaded_file 落盘，缺少类型/扩展名校验

critical file_upload / CWE-434 · 置信度 0.68 · candidate / rule_verified+llm

位置：045.php:16-18

攻击者通过 HTTP 文件上传字段 `uploaded` 提交任意文件（045.php:18 的 `$_FILES['uploaded']['tmp_name']`）。代码在 045.php:18 直接调用 `move_uploaded_file($_FILES['uploaded']['tmp_name'], $target_path)` 将临时文件移动到目标路径，输入中给出的代码片段（045.php:16-18）未出现任何扩展名白名单、MIME 校验、`getimagesize()` 校验或文件名规范化逻辑，因此校验无效/缺失。污点从上传字段 `uploaded` 进入 `$_FILES['uploaded']['tmp_name']`，经 `move_uploaded_file()` 到达文件系统写入汇点。注意：`$target_path` 的构造代码不在本次 code_pack 片段内，其是否包含原始文件名、是否落在 Web 可访问目录，证据不足，需结合 045.php 其余行确认。

影响：若目标目录位于 Web 根下且可执行脚本，攻击者可上传 .php/.phtml 等文件并获得远程代码执行（RCE）；即使不可执行，也可造成任意文件写入、覆盖已有文件、磁盘占用，以及上传恶意内容用于钓鱼/挂马。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部可达性：上传接口为 HTTP 表单处理逻辑，无需认证即可触达（输入中未见鉴权判断）。利用链闭合：`$_FILES['uploaded']['tmp_name']` → `move_uploaded_file()` → 目标路径落盘，中间无有效净化。RCE 成立的前提是 `$target_path` 指向可执行目录，该前提在片段中未给出，故按 llm_inferred 记录。

修复建议：1) 使用扩展名白名单（如仅 jpg/png/gif/pdf）并基于服务端解析的真实类型校验（`finfo_file`/`getimagesize`），不要信任 `$_FILES['uploaded']['type']` 与客户端文件名；2) 用 `basename()` + 随机生成的文件名重命名，禁止路径分隔符与 `..`；3) 上传目录置于 Web 根之外，或通过 Web 服务器配置禁止该目录执行脚本；4) 限制文件大小与数量，设置目录最小权限；5) 上传后做病毒/内容扫描。

F-2 DVWA 文件上传页面仅校验客户端可控的 MIME 类型，可上传任意 PHP 脚本并 RCE

high file_upload / CWE-434 · 置信度 0.9 · candidate / llm_inferred

位置：045.php:3-25

045.php 处理 POST 上传时，仅用 $_FILES['uploaded']['type']（完全由客户端 multipart 请求的 Content-Type 决定）与 size<100000 作为“是否为图片”的判断，未校验扩展名、未校验真实文件内容（无 getimagesize/finfo）、未做白名单重命名。$target_path 由 DVWA_WEB_PAGE_TO_ROOT."hackable/uploads/" 拼接 basename(原始文件名) 得到，攻击者可将文件名设为 shell.php，并把 multipart 分片的 Content-Type 伪造成 image/jpeg，从而通过第 14 行判断，在第 18 行 move_uploaded_file 落盘为可执行 PHP 文件，随后访问该文件即可远程执行任意代码。

影响：未认证攻击者可上传并执行任意 PHP 代码，完全控制 Web 服务器（RCE）。

CVE/CWE 论证：CWE-434 无限制文件上传 / CWE-646 依赖不可信文件元数据。外部 HTTP 可达，无需认证，source→sink 链在 045.php:3-18 完整闭合，MIME 校验可被客户端伪造绕过。

修复建议：使用扩展名白名单并重命名为随机名；用 getimagesize()/finfo 校验真实文件内容；将上传目录置于 web 根之外或禁止脚本执行；校验失败时拒绝落盘。
