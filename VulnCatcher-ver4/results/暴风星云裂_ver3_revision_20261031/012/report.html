F-1 012.php 登录表单 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：012.php:13-15

攻击者通过 HTTP GET 参数 `username`（以及同表单的 `password`）提交输入。012.php:5 从请求中读取 `username` 到 `$user`，012.php:10 仅对 `$pass` 调用 mysqli_real_escape_string，而 `$user` 未见任何转义或参数化处理；012.php:14 将 `$user` 与 `$pass` 直接拼接进 SQL 语句 "SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';"，012.php:15 通过 mysqli_query 执行该语句。由于 `$user` 未经转义即进入单引号字符串上下文，攻击者可闭合引号注入任意 SQL 片段（如 `' OR '1'='1' -- `），校验完全失效。此外 012.php:15 的 die() 分支会把 mysqli_error 的数据库错误信息回显到页面，构成报错型注入的辅助信息泄露通道。

影响：可绕过登录认证（以任意用户身份登录，包括管理员）；可借助 UNION/布尔/报错注入读取 `users` 表及其他库表数据（口令哈希、用户信息），在数据库账号权限较高时可进一步读写文件或造成数据篡改，属于认证绕过与敏感数据泄露。

CVE/CWE 论证：CWE-89：外部可控输入 `username` 未经参数化或转义即拼接到 SQL 语句并在 012.php:15 执行，污点链闭合。该入口为 GET 参数，无需认证即可访问登录页触发，远程可利用；错误信息回显进一步降低利用门槛。

修复建议：改用预处理语句与参数绑定（mysqli_prepare + bind_param 或 PDO prepared statement），彻底避免字符串拼接；对 `username`/`password` 做长度与字符白名单校验；关闭数据库错误详情回显，改为记录服务端日志并返回通用错误页；数据库账号遵循最小权限，禁止 FILE 等特权。

F-2 012.php 登录接口缺少暴力破解防护（CWE-307）

F-3 012.php 使用 MD5 存储口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：012.php:10-11

012.php:10 先对 `$pass` 做 mysqli_real_escape_string，随后 012.php:11 执行 `$pass = md5( $pass );`，将用户口令以无盐 MD5 形式参与后续 SQL 比较（012.php:14 的 password 字段）。MD5 为快速、无盐、已被证明存在碰撞的哈希算法，用于口令存储/校验属安全用途误用。注意：此处应归类为 weak_hash（CWE-328），而非 weak_crypto（CWE-327，指 DES/ECB 等加密算法问题）。

影响：一旦 `users` 表泄露（可与本文件 SQL 注入叠加），攻击者可用彩虹表/GPU 高速爆破在极短时间内还原弱口令，导致账号接管；无盐设计使相同口令产生相同哈希，便于批量破解与撞库。

CVE/CWE 论证：CWE-328：012.php:11 明确对安全敏感数据（登录口令）使用 MD5。该弱点为配置/实现型，不依赖 HTTP 污点链，但可通过登录接口与数据库读取路径被外部间接利用。

修复建议：改用 password_hash()（PASSWORD_BCRYPT/Argon2id）生成带盐慢哈希，校验使用 password_verify()；对历史 MD5 记录在用户下次登录成功时透明升级；禁止在任何新代码中使用 md5()/sha1() 处理口令或令牌。
