F-1 043.php 不安全文件上传导致任意文件写入（CWE-434）

critical file_upload / CWE-434 · 置信度 0.73 · candidate / rule_verified+llm

位置：043.php:18-20

攻击者通过 HTTP 文件上传字段 `uploaded` 提交文件（043.php:12 读取上传内容并写入 `$uploaded_tmp`），代码未对上传文件的扩展名、MIME 类型或内容做任何白名单校验，随后在 043.php:20 直接调用 `move_uploaded_file($uploaded_tmp, $target_path)` 将临时文件移动到 `$target_path`。由于 `$target_path` 的构造逻辑（文件名/目录来源）在给定片段中未体现，无法确认文件名是否完全由用户控制，但已确认从上传输入到文件落盘汇点之间不存在有效净化，属于典型的无限制文件上传。

影响：若目标目录位于 Web 可访问路径且允许 PHP 等可执行扩展名，攻击者可上传 WebShell 实现远程代码执行（RCE）；即使不可执行，也可覆盖/写入任意文件造成数据篡改或磁盘占用。具体可利用程度取决于 `$target_path` 的目录与命名规则，该部分证据不足。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部可达性：上传入口为 HTTP 请求，无需认证即可触达（片段中未见鉴权逻辑）；利用链闭合：`uploaded` 上传输入 → `$uploaded_tmp` → `move_uploaded_file()` 落盘，中间无扩展名/类型校验。因缺少 `$target_path` 构造代码，最终落盘路径可控性为推断，故置信度中等。

修复建议：1) 使用扩展名白名单（如仅 jpg/png/pdf）并基于服务端解析的真实内容类型校验，而非客户端 Content-Type；2) 将上传目录置于 Web 根之外，或对目录禁用脚本执行；3) 上传文件重命名为随机名并去除路径分隔符，防止路径穿越；4) 限制文件大小与数量；5) 上传后以只读、非执行权限存储。

F-2 DVWA 文件上传端点（043.php）扩展名校验可被绕过，导致上传任意 PHP 脚本并远程执行

high file_upload / CWE-434 · 置信度 0.85 · candidate / llm_inferred

位置：043.php:5-26

043.php 接收 multipart 上传（字段名 uploaded，提交按钮 Upload），仅通过 substr(strrpos(name,'.')+1) 取最后一段扩展名并与 jpg/jpeg/png 比较，同时要求 size<100000 且 getimagesize() 返回真。校验只针对扩展名字符串与图片头，未对文件内容做真实图片解析后的重编码，也未限制上传目录的可执行权限。攻击者可构造「合法图片头 + PHP 代码」的 polyglot 文件，并用双扩展名（如 shell.php.jpg）或大小写/尾随点等技巧使扩展名判定为 jpg，从而把可执行 PHP 写入 hackable/uploads/ 目录，随后直接请求该文件触发代码执行。

影响：攻击者可在服务器上写入并执行任意 PHP 代码，完全控制 Web 应用与主机（RCE），读取数据库凭据、横向移动。

CVE/CWE 论证：CWE-434 无限制危险类型文件上传。外部可通过 HTTP multipart 直接触发，无需高权限；扩展名白名单与 getimagesize 均可被 polyglot + 双扩展名绕过，source→sink 链在 043.php 内闭合。

修复建议：对上传文件做服务端真实图片解析并重编码（如 imagecreatefrom* 后重新保存）；使用随机生成的文件名且强制安全扩展名；将上传目录置于 web 根之外或禁用该目录的脚本执行（php_flag engine off / 独立域名）；校验 MIME 与内容而非仅扩展名。
