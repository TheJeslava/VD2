F-1 010.php 登录查询 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.78 · candidate / rule_verified+llm

位置：010.php:18-20

攻击者通过 HTTP 请求向 010.php 提交登录参数，源码在 010.php:8 从请求中读取用户名（候选记为 query `username`），随后在 010.php:19 直接以字符串拼接方式构造 SQL：$query = "SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';";，并在 010.php:20 交给 mysqli_query 执行。$user 在进入拼接前没有经过 mysqli_real_escape_string 或参数化处理（对比 010.php:15 仅对 $pass 做了 mysqli_real_escape_string，且随后在 010.php:16 被 md5() 覆盖），因此单引号可闭合 user 字面量，注入任意 SQL 片段。校验无效的原因是该查询完全依赖字符串拼接，没有使用 prepared statement，也没有对 $user 做转义或白名单校验。最终危险操作是 010.php:20 的 mysqli_query 执行被污染的 $query。

影响：可绕过登录认证（例如 user 处注入 ' OR '1'='1 使 WHERE 恒真），并可进一步通过 UNION/布尔/报错注入读取 users 表及其他库表数据，造成账户凭据与业务数据泄露；若数据库账户权限过高，还可能读写文件或篡改数据。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：010.php 为登录入口，参数来自 HTTP 请求，无需认证即可触发；利用链闭合：010.php:8 外部输入 → 010.php:19 字符串拼接进 $query → 010.php:20 mysqli_query 执行，中间无有效净化，满足注入条件。

修复建议：改用 mysqli/PDO 预处理语句并绑定参数，例如 $stmt = $mysqli->prepare("SELECT * FROM users WHERE user = ? AND password = ?"); $stmt->bind_param('ss', $user, $passHash);；禁止将外部输入直接拼接进 SQL；对输入做长度与字符白名单校验；数据库账户遵循最小权限，关闭详细错误回显（当前 die(mysqli_error(...)) 会泄露 SQL 结构）。

F-2 010.php 登录成功页反射型 XSS：username 参数未编码直接拼入 HTML

medium xss / CWE-79 · 置信度 0.7 · candidate / llm_inferred

位置：010.php:8-28

010.php 第 8 行从 $_GET['username'] 取用户输入，仅经过 stripslashes 与 mysqli_real_escape_string（后者只针对 SQL 上下文转义，对 HTML 无任何作用），随后在第 28 行被直接拼接进 $html 的 <p> 标签中输出。攻击者构造带 HTML/JS 的 username，在登录成功（或利用已知凭据）后即可在受害者浏览器执行脚本，窃取会话或发起 CSRF。

影响：反射型 XSS，可在受害者浏览器执行任意 JS，窃取会话 Cookie、伪造请求。

CVE/CWE 论证：CWE-79；外部 GET 参数直达 HTML 输出，无需高权限，链闭合。

修复建议：输出前使用 htmlspecialchars($user, ENT_QUOTES, 'UTF-8') 编码。

F-3 010.php 口令使用 MD5 哈希（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.66 · candidate / rule_verified+llm

位置：010.php:15-16

010.php:15 先对 $pass 做 mysqli_real_escape_string，随后在 010.php:16 调用 $pass = md5( $pass ); 对口令做哈希。MD5 属于快速、无盐、已被证明存在碰撞的哈希算法，用于口令存储/校验属弱哈希实现。此处为配置/实现型弱点，不依赖 HTTP 污点链，证据为 010.php:16 的 md5() 调用原文。注意：该弱点类型应为 weak_hash（CWE-328），而非 weak_crypto（CWE-327，指 DES/ECB 等加密算法问题）。

影响：若数据库泄露，攻击者可用彩虹表或 GPU 高速爆破在极短时间内还原弱口令；无盐 MD5 还使相同口令产生相同摘要，便于批量撞库与横向扩散，削弱账户认证强度。

CVE/CWE 论证：CWE-328（使用弱哈希算法）。外部可达性：口令哈希在登录处理路径 010.php:16 执行，任何登录请求都会触发；无需认证。利用前提是攻击者获得哈希值（如通过同文件 GEN-7034f0a19983 的 SQL 注入读取 users 表），两者可组合形成凭据泄露链。

修复建议：改用 password_hash($pass, PASSWORD_DEFAULT)（bcrypt/Argon2）生成带盐慢哈希，校验时用 password_verify()；迁移期可对旧 MD5 摘要在用户下次登录时透明重哈希；禁止在安全用途中使用 MD5/SHA-1。
