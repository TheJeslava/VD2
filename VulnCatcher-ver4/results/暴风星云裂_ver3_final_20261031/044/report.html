F-1 044.php 不安全文件上传导致任意文件写入（CWE-434）

critical file_upload / CWE-434 · 置信度 0.83 · candidate / rule_verified+llm

位置：044.php:7-9

攻击者通过 HTTP 文件上传字段 `uploaded` 提交文件（044.php:9 的 `$_FILES['uploaded']['tmp_name']`），代码在 044.php:9 直接调用 `move_uploaded_file()` 将临时文件移动到 `$target_path`。从给出的片段看，第 7-9 行之间没有任何扩展名白名单、MIME 校验、文件内容检查或 `$target_path` 的规范化/重命名逻辑，`$target_path` 的构造（推测位于第 9 行之前）在片段中不可见，因此无法确认其是否包含原始文件名或用户可控路径；但可以确认的是，上传动作本身没有对文件类型做任何校验，校验缺失即为绕过原因。最终危险操作是 `move_uploaded_file()` 把攻击者控制的文件内容写入 Web 可访问目录。

影响：若上传目录位于 Web 根下且允许 PHP 等可执行扩展名，攻击者可上传 webshell 并访问对应 URL，实现远程代码执行（RCE）；即使不可执行，也可造成任意文件写入/覆盖、存储型恶意内容托管（钓鱼、恶意脚本分发）以及磁盘占用。具体可利用性取决于 `$target_path` 的构造与目录权限，该部分证据不足。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部可达性：上传入口为 HTTP 表单字段 `uploaded`，无需认证即可触达（片段中未见任何鉴权/会话校验）。利用链闭合：`$_FILES['uploaded']['tmp_name']` → `move_uploaded_file()` → 目标路径落盘，缺少类型/扩展名校验，攻击者可直接控制落盘内容。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：1) 使用扩展名白名单（如仅 jpg/png/pdf）并基于服务端解析的真实 MIME 与文件头校验，而非客户端 `Content-Type`；2) 忽略客户端文件名，由服务端生成随机文件名并固定扩展名；3) 将上传目录置于 Web 根之外，或配置该目录禁止脚本执行（如 PHP 的 `php_admin_flag engine off`）；4) 对 `$target_path` 做 `realpath()` 规范化并校验其位于允许目录内，防止路径穿越；5) 限制文件大小与上传频率，上传后做病毒/内容扫描；6) 上传接口增加认证与 CSRF 防护。

F-2 DVWA 044.php 无限制文件上传导致任意 PHP 文件写入 uploads 目录（可 RCE）

high file_upload / CWE-434 · 置信度 0.85 · candidate / llm_inferred

位置：044.php:3-16

044.php 在收到 POST 参数 Upload 时，直接取 $_FILES['uploaded']['name'] 经 basename() 处理后拼接到 DVWA_WEB_PAGE_TO_ROOT . "hackable/uploads/" 目录，并调用 move_uploaded_file() 将临时文件移动到该路径。代码未校验扩展名、MIME 类型、文件内容，也未做白名单/重命名，攻击者可上传 .php 文件到 Web 可访问的 hackable/uploads/ 目录，随后请求该文件即可执行任意 PHP 代码，形成远程代码执行。

影响：攻击者可在服务器写入并执行任意 PHP 代码，完全控制 Web 应用与主机（在 PHP 进程权限范围内）。

CVE/CWE 论证：CWE-434 无限制文件上传。外部 HTTP 可达，无需高权限，source（上传文件名/内容）到 sink（move_uploaded_file 落盘到 Web 目录）链路在 044.php:3-16 完整闭合，落盘路径可预测且可回显。

修复建议：使用扩展名与 MIME 白名单校验，重命名上传文件为随机名并去除可执行扩展名，将上传目录置于 Web 根之外或禁用该目录的脚本执行（如 php_flag engine off），限制文件大小与内容类型。
