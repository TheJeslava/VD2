F-1 037.php 基于 query 参数 id 的 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：037.php:11-13

攻击者通过 HTTP 请求的 query 参数 `id` 提供输入（037.php:5 读取），该值未经任何过滤、转义或类型校验，被直接拼接进 SQL 语句：037.php:11 构造 `$query = "SELECT first_name, last_name FROM users WHERE user_id = '$id' LIMIT 1;"`，随后在 037.php:13 通过 `mysqli_query($GLOBALS["___mysqli_ston"], $query)` 执行。由于 `$id` 被单引号包裹但未做 `mysqli_real_escape_string` 或参数化处理，攻击者可闭合单引号注入任意 SQL 片段（如 `1' OR '1'='1` 或 UNION 查询）。代码中仅用 try/catch 抑制了 MySQL 错误回显（037.php:12-13 注释“Removed 'or die' to suppress mysql errors”），这并不构成任何输入净化，只是隐藏报错，无法阻止注入生效。

影响：数据库查询逻辑被完全控制：可绕过 user_id 条件读取 users 表全部记录（first_name、last_name），并通过 UNION 注入进一步读取其他表（如用户名/口令哈希），造成敏感数据泄露；在数据库账户权限较高时还可能读写文件或执行管理操作。属于未认证远程可利用的严重数据泄露风险。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：注入点为 HTTP query 参数 `id`，无需认证即可访问 037.php；利用链闭合：source（037.php:5 的 `id`）→ 字符串拼接（037.php:11）→ 执行汇点 `mysqli_query`（037.php:13），中间无有效净化，仅错误抑制不影响注入。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：改用预处理语句与参数绑定：`$stmt = $mysqli->prepare("SELECT first_name, last_name FROM users WHERE user_id = ? LIMIT 1"); $stmt->bind_param('i', $id); $stmt->execute();`，并对 `id` 做整数类型强校验（如 `filter_var($id, FILTER_VALIDATE_INT)`）。若必须拼接，至少使用 `mysqli_real_escape_string` 并加引号，但优先参数化。同时遵循最小权限原则，限制数据库账户权限，避免使用可读写文件或跨库的高权限账号。
