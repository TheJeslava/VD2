F-1 056.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：056.php:15-17

攻击者通过 HTTP 请求向 056.php 提交留言板表单，外部输入在 056.php:5 被读入变量 $message（候选标注为 query `mtxMessage`，即留言内容字段），随后在 056.php:16 被直接字符串拼接进 INSERT 语句：$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";，$message 被包裹在单引号内但未做任何转义或参数化处理。056.php:17 将该拼接后的 $query 交给 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行，构成危险汇点。由于缺少 mysqli_real_escape_string / 预处理语句，攻击者只需在留言内容中闭合单引号（如 ' , (SELECT ...))-- -）即可改变 SQL 语义。校验无效的原因：代码路径上不存在任何白名单、类型校验、转义或参数绑定，输入从读取到拼接全程保持原始污点状态。

影响：可对后端 MySQL 数据库执行任意 INSERT 语义篡改，并通过闭合引号注入子查询/联合结构读取 guestbook 及其他表数据（数据泄露）；配合报错回显（die 中输出 mysqli_error）可实施报错型注入枚举库表结构；在数据库账号权限过高时可进一步读写文件或篡改业务数据。属于未认证远程可利用的 critical 级注入。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：056.php 为 Web 可直接访问脚本，留言提交参数来自 HTTP 请求，无需认证；利用链闭合：056.php:5 读取外部输入 → 056.php:16 字符串拼接进 INSERT → 056.php:17 mysqli_query 执行，三步在同一脚本内闭合，无净化环节。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：改用预处理语句与参数绑定：$stmt = $mysqli->prepare("INSERT INTO guestbook (comment, name) VALUES (?, ?)"); $stmt->bind_param('ss', $message, $name); $stmt->execute();。若必须保留拼接，至少对 $message/$name 使用 mysqli_real_escape_string 并强制字符集；同时对输入做长度与内容白名单校验；关闭 die() 中的数据库错误回显，改为记录日志并返回通用错误；数据库账号遵循最小权限，禁用 FILE 权限。
