F-1 015.php 密码修改处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：015.php:67-69

攻击者通过 POST 参数 password_new（015.php:8 读取，随后在 015.php:64 经 mysqli_real_escape_string 处理并 md5 后赋给 $pass_new）进入密码更新语句。015.php:68 将 $pass_new 直接拼接进 "UPDATE `users` SET password = '$pass_new' WHERE user = '" . dvwaCurrentUser() . "';"，015.php:69 通过 mysqli_query 执行。虽然 015.php:64 对 $pass_new 做了 mysqli_real_escape_string，但 015.php:65 的 md5() 会先把转义后的字符串哈希成 32 位十六进制，再拼入 SQL，因此实际进入 SQL 的是哈希值而非原始输入，单引号无法由攻击者控制；同时 WHERE 子句使用 dvwaCurrentUser() 而非用户输入。基于所给片段，注入点是否真正闭合存在缺口：若 md5 在转义之后执行（如片段所示），则 password_new 无法注入。

影响：若注入成立，可篡改 users 表任意记录（含其他账户密码），导致越权与账户接管；但按当前片段证据，实际可利用性未确认。

CVE/CWE 论证：CWE-89：SQL 命令中特殊元素未正确中和。外部可达性：password_new 为 POST 参数，无需认证即可提交（DVWA 低安全级别下会话即可）。但利用链闭合性存疑：md5 在 mysqli_real_escape_string 之后执行，使引号被哈希消除，且 WHERE 使用 dvwaCurrentUser()，故不能确认注入可达。

修复建议：改用预处理语句与参数绑定（mysqli_prepare/bind_param 或 PDO），禁止字符串拼接 SQL；对用户标识使用服务端会话值并参数化；移除 or die(mysqli_error(...)) 以免泄露数据库错误信息。

F-2 DVWA 密码修改流程 CAPTCHA 状态机可绕过（step=2 直接提交 passed_captcha=true）

high captcha_bypass / CWE-804 · 置信度 0.9 · candidate / llm_inferred

位置：015.php:46-69

脚本把 CAPTCHA 校验放在 step=1 分支（第 12-23 行），而真正执行密码更新的逻辑在 step=2 分支（第 46-81 行）。step=2 分支只检查客户端提交的 $_POST['passed_captcha'] 是否为真（第 55 行），并不重新校验 reCAPTCHA 响应，也不校验服务端会话中是否真的通过过 CAPTCHA。攻击者可直接构造 step=2 请求并附带 passed_captcha=true，跳过第三方 CAPTCHA 校验，完成任意密码修改（配合 CSRF 可强制受害者改密）。

影响：攻击者无需通过 CAPTCHA 即可修改账户密码；结合 CSRF 可强制已登录用户改密，导致账户接管。

CVE/CWE 论证：CWE-804 (Guessable CAPTCHA)/CWE-602 (Client-Side Enforcement of Server-Side Security)：CAPTCHA 校验仅在 step=1 执行，step=2 仅信任客户端 passed_captcha 标志，服务端无状态校验，外部可直接触发。

修复建议：在服务端会话中记录 CAPTCHA 通过状态（如 $_SESSION['captcha_passed']=true），step=2 时校验该会话标志而非客户端字段；或每次更新前重新校验 reCAPTCHA。

F-4 015.php 使用 MD5 存储口令（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.8 · candidate / rule_verified+llm

位置：015.php:64-65

015.php:65 执行 $pass_new = md5( $pass_new );，将用户新密码以无盐 MD5 形式计算后写入数据库（015.php:68-69 的 UPDATE 语句）。MD5 属快速哈希，且此处未见盐值或迭代，属于口令存储的弱哈希实现。

影响：数据库泄露时，攻击者可用彩虹表/GPU 高速碰撞快速还原用户明文口令，导致账户接管与横向移动。

CVE/CWE 论证：CWE-328：使用弱哈希算法。配置/实现型弱点，无需 HTTP 污点链；原文证据为 015.php:65 的 md5( $pass_new )。外部可达性：任何修改密码请求都会触发该哈希路径。

修复建议：改用 Argon2id、bcrypt 或 PBKDF2 等带盐、可调工作因子的口令哈希（PHP password_hash/password_verify），并对既有 MD5 记录在下次登录时透明升级。
