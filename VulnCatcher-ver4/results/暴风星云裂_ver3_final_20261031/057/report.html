F-1 057.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：057.php:17-19

攻击者通过 HTTP 请求向 057.php 提交留言内容（源码中对应变量 $message，来自 query 参数 mtxMessage，见 057.php:5），该值未经任何转义或参数化即被拼接进 SQL 语句：057.php:18 构造 $query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );",随后在 057.php:19 通过 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行。由于 $message 被直接放入单引号字符串字面量中，攻击者只需闭合单引号即可注入任意 SQL 片段（例如在 comment 值中构造 ' , (SELECT ...))-- - 之类的载荷），从而改变 INSERT 的语义或追加子查询。代码中未见 mysqli_real_escape_string、预处理语句或类型白名单，校验完全缺失，因此污点从 mtxMessage 参数直达 mysqli_query 汇点，链路闭合。

影响：可对后端 MySQL 数据库执行任意 INSERT/子查询语句：篡改或伪造留言数据、通过子查询读取其他表（如用户表）内容并写入 guestbook 造成数据泄露、在数据库权限允许时写入任意表；错误信息经 die() 回显（mysqli_error）还会泄露库结构，为进一步攻击提供情报。属于数据完整性与机密性破坏，严重级别 critical。

CVE/CWE 论证：CWE-89（SQL 注入）：外部可控输入 $message 未经参数化直接拼接进 SQL 并在 057.php:19 执行，满足外部可达（HTTP 参数 mtxMessage）、无需认证（留言板提交接口默认匿名可访问）、利用链闭合（source→拼接→mysqli_query）三要素。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：1) 改用预处理语句：$stmt = $mysqli->prepare("INSERT INTO guestbook (comment, name) VALUES (?, ?)"); $stmt->bind_param('ss', $message, $name); $stmt->execute(); 2) 若暂不能改造，至少对 $message/$name 使用 mysqli_real_escape_string 并配合正确的字符集设置；3) 关闭错误详情回显，将 mysqli_error 写入服务端日志而非输出到页面；4) 对输入长度与字符集做白名单校验，数据库账号遵循最小权限（仅 INSERT 权限）。
