F-1 027.php ping 功能通过 $_REQUEST['ip'] 拼接 shell_exec 导致命令注入（黑名单可绕过）

critical command_injection / CWE-78 · 置信度 0.9 · candidate / llm_inferred

位置：027.php:3-27

027.php 在收到 POST 参数 Submit 后，从 $_REQUEST['ip'] 读取用户输入 $target（第 5 行），仅用 str_replace 删除 '&&' 与 ';' 两个子串（第 8-14 行）作为黑名单，随后直接把 $target 拼接到 shell_exec('ping -c 4 ' . $target)（*nix，第 23 行）或 shell_exec('ping ' . $target)（Windows，第 19 行）执行。黑名单只过滤 '&&' 和 ';'，未过滤管道符 '|'、后台执行 '&'、命令替换反引号、$()、换行等 shell 元字符，也未使用 escapeshellarg/escapeshellcmd，因此攻击者可在 ip 参数中注入任意系统命令，实现远程命令执行。

影响：未认证远程攻击者可在服务器上以 Web 服务进程权限执行任意系统命令，读取敏感文件、横向移动、植入后门，完全控制主机。

CVE/CWE 论证：CWE-78 OS 命令注入。外部 HTTP 参数 ip 直接拼接进 shell_exec，黑名单仅过滤 '&&' 与 ';'，可用 '|' 等元字符绕过，source→sink 链在 CODE PACK 内完整闭合，无需认证。

修复建议：不要将用户输入拼接进 shell 命令；改用 escapeshellarg($target) 对参数整体转义，或使用白名单校验 IP 格式（filter_var($target, FILTER_VALIDATE_IP)），并避免使用 shell_exec 执行外部命令。

F-2 027.php Windows 分支 ping 命令拼接导致 OS 命令注入（CWE-78）

critical command_injection / CWE-78 · 置信度 0.83 · candidate / rule_verified+llm

位置：027.php:17-19

攻击者通过 HTTP query 参数 `ip` 提供输入，027.php:5 将其读入 `$target`；027.php:17 用 `stristr(php_uname('s'),'Windows NT')` 判断运行平台，命中 Windows 分支后，027.php:19 执行 `$cmd = shell_exec( 'ping ' . $target );`，把 `$target` 直接字符串拼接到 shell 命令中。代码未对 `$target` 做任何白名单校验、转义（如 escapeshellarg）或参数化，因此 `ip` 中的 shell 元字符（`&`、`|`、`;`、`&&` 等）会被 shell 解释，形成命令注入。该分支仅在 Windows 主机上触发，属于平台相关但外部可达的注入点。

影响：远程未认证攻击者可在 Web 服务进程权限下执行任意系统命令，导致服务器完全失陷（RCE）、敏感文件读取、内网横向移动与持久化。

CVE/CWE 论证：CWE-78（OS Command Injection）。外部可达性：注入点位于 HTTP query 参数 `ip`，无需认证即可访问；利用链闭合：`ip` → `$target`（027.php:5）→ `shell_exec('ping ' . $target)`（027.php:19），中间无有效净化；触发条件为 Windows 平台（027.php:17 分支），在目标为 Windows 时无需额外前置条件。

修复建议：不要用字符串拼接构造 shell 命令：改用参数数组形式（如 `proc_open`/`exec` 传入参数数组）或 PHP 的 `escapeshellarg($target)`/`escapeshellcmd` 组合；同时对 `ip` 做严格白名单校验（仅允许 IPv4/IPv6 字面量，如 `filter_var($target, FILTER_VALIDATE_IP)`），拒绝含空白与 shell 元字符的输入；以最小权限账户运行 Web 服务。

F-3 027.php *nix 分支 ping -c 4 命令拼接导致 OS 命令注入（CWE-78）

critical command_injection / CWE-78 · 置信度 0.83 · candidate / rule_verified+llm
