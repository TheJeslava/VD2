F-1 056.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：056.php:15-17

攻击者通过 HTTP 请求向 056.php 提交留言内容（源码中对应变量 $message，候选标注的 source 为 query `mtxMessage`，即请求参数 mtxMessage），该值在 056.php:16 被直接字符串拼接进 INSERT 语句：$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";，随后在 056.php:17 交给 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行。整条链路上没有 mysqli_real_escape_string、预处理语句（prepare/bind_param）或类型白名单等任何净化措施，单引号可直接闭合 VALUES 中的字符串字面量，从而改写 SQL 语义。此外 056.php:17 的 or die(...) 会把 mysqli_error() 的原始错误信息回显到页面，为报错型注入提供了回显通道。

影响：可对后端 MySQL 执行任意 INSERT/UNION/子查询语句：读取 guestbook 及其他库表数据（如用户凭据、配置），在具备相应权限时可借助堆叠/文件写入能力进一步扩大影响；错误回显还会泄露库名、表结构与 SQL 语句细节，降低后续利用门槛。属于未授权远程可利用的数据库层注入。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：056.php 为 Web 入口脚本，参数 mtxMessage 由 HTTP 请求直接提供，无需认证；利用链闭合：056.php:5 读取外部输入 → 056.php:16 字符串拼接进 $query → 056.php:17 mysqli_query 执行，中间无净化，且错误信息经 die() 回显。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：改用参数化查询：$stmt = mysqli_prepare($GLOBALS["___mysqli_ston"], "INSERT INTO guestbook (comment, name) VALUES (?, ?)"); mysqli_stmt_bind_param($stmt, "ss", $message, $name); mysqli_stmt_execute($stmt);。若短期无法改造，至少对 $message/$name 使用 mysqli_real_escape_string 并限制长度与字符集；同时移除 or die(mysqli_error(...)) 的原始错误回显，改为记录服务端日志并返回通用错误页；数据库账号按最小权限授予，仅保留 guestbook 表的 INSERT 权限。
