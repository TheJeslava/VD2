F-1 013.php 密码更新语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：013.php:29-31

攻击者通过 HTTP 请求参数 `password_new`（013.php:8 处读取）提交恶意字符串，该值被直接拼接进 `$pass_new`，随后在 013.php:30 被拼入 UPDATE 语句：`UPDATE `users` SET password = '$pass_new' WHERE user = '...' LIMIT 1;`，最终在 013.php:31 由 `mysqli_query()` 执行。代码未对 `$pass_new` 做任何转义（无 mysqli_real_escape_string）、类型约束或参数化处理，单引号可直接闭合字符串字面量，从而改写 SET 子句或注入额外 SQL。注意：`user` 字段使用 `dvwaCurrentUser()` 而非直接外部输入，注入点集中在 `password_new` 参数值。

影响：可越权修改任意用户口令（包括 admin），进而登录后台；亦可借助报错回显（013.php:31 的 `or die(mysqli_error(...))`）进行报错型注入读取数据库内容，造成敏感数据泄露与账户接管。

CVE/CWE 论证：CWE-89：外部可控参数 `password_new` 未经参数化/转义直接进入 SQL 语句并执行，构成典型 SQL 注入。该页面为 DVWA 公开端点，无需认证即可访问（取决于部署配置），利用链闭合：source（013.php:8 参数）→ 拼接（013.php:30）→ sink（013.php:31 mysqli_query）。

修复建议：改用预处理语句与参数绑定（mysqli_prepare + bind_param 或 PDO prepared statement），将 `$pass_new` 作为绑定参数传入；对输入做长度与字符白名单校验；关闭详细数据库错误回显，改为记录日志；数据库账户遵循最小权限，仅授予必要表的 UPDATE 权限。

F-2 DVWA CAPTCHA 绕过导致任意用户密码重置（硬编码验证码 + User-Agent 伪造）

high captcha_bypass / CWE-804 · 置信度 0.93 · candidate / llm_inferred

位置：013.php:17-23

013.php 在处理密码修改时，CAPTCHA 校验逻辑存在硬编码后门：当 `g-recaptcha-response` 等于字符串 `hidd3n_valu3` 且 `HTTP_USER_AGENT` 等于 `reCAPTCHA` 时，条件恒真，完全绕过第三方 reCAPTCHA 校验。攻击者无需通过真实验证码即可进入密码修改分支，随后将 `password_new` 与 `password_conf` 设为相同值，即可把当前登录用户（dvwaCurrentUser()）的密码改为攻击者控制的值。结合 CSRF token 在密码修改逻辑之后才生成（第 53 行），攻击者可构造跨站请求诱导受害者提交，实现账户接管。

影响：攻击者可在不通过真实验证码的情况下重置任意已登录用户密码，实现账户接管；结合 CSRF 可对管理员账户发起攻击，获取后台控制权。

CVE/CWE 论证：CWE-804（Guessable CAPTCHA）/ CWE-287（Improper Authentication）。硬编码验证码值与可伪造 User-Agent 构成恒真条件，外部无需真实验证码即可触发密码修改，链路在 CODE PACK 内闭合。

修复建议：移除硬编码后门条件（hidd3n_valu3 / User-Agent 判断），仅信任 recaptcha_check_answer 的返回值；将 CSRF token 校验前置到密码修改逻辑之前；对密码修改要求二次认证。

F-3 密码修改接口缺少 CSRF token 校验（token 在修改逻辑之后生成）

medium csrf / CWE-352 · 置信度 0.8 · candidate / llm_inferred

位置：013.php:3-31

013.php 在 POST Change 分支内直接执行密码修改，而 generateSessionToken() 在第 53 行、即密码修改逻辑之后才调用，说明密码修改请求本身不校验 Anti-CSRF token。攻击者可构造跨站表单，诱导已登录用户提交 password_new/password_conf，配合硬编码 CAPTCHA 后门完成静默密码重置。

影响：攻击者可跨站重置受害者密码，实现账户接管。

CVE/CWE 论证：CWE-352（Cross-Site Request Forgery）。密码修改无 token 校验，token 生成滞后，外部可构造请求触发。

修复建议：在密码修改逻辑前校验 CSRF token，并确保 token 一次性且与会话绑定。

F-4 用户密码使用无盐 MD5 哈希存储

low weak_hash / CWE-328 · 置信度 0.85 · candidate / llm_inferred

位置：013.php:27-27

013.php 第 27 行对用户新密码直接调用 md5($pass_new) 后写入数据库，未加盐、未使用 password_hash 等慢哈希算法。数据库泄露时攻击者可通过彩虹表快速还原明文密码。

影响：数据库泄露时用户密码可被快速破解，导致账户接管与撞库风险。

CVE/CWE 论证：CWE-328（Use of Weak Hash）。代码明确使用无盐 MD5 存储口令。

修复建议：改用 password_hash()/password_verify()（bcrypt/argon2）并加盐。
