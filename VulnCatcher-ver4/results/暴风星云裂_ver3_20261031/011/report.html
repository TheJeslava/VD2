F-1 011.php 登录处 username 参数直接拼接进 SQL 导致认证绕过式 SQL 注入

critical sql_injection / CWE-89 · 置信度 0.9 · candidate / llm_inferred

位置：011.php:5-13

011.php 第 3 行判断 $_GET['Login'] 存在后，第 5 行直接读取 $_GET['username'] 到 $user，未做任何转义/参数化；第 12 行将 $user 以单引号包裹拼进 SELECT 语句，第 13 行交给 mysqli_query 执行。攻击者可通过 username 注入恒真条件（如 ' OR '1'='1' -- -）绕过密码校验，返回 users 表首行，从而以任意/首个用户身份登录受保护区域；也可用 UNION/布尔/报错注入读取任意数据库内容。password 虽经 md5() 处理（第 9 行），但 md5 输出为固定 32 位十六进制，无法注入，因此注入点唯一在 username。

影响：未授权绕过登录进入受保护区域；可进一步通过 UNION/布尔/报错注入读取 users 表及其它数据库数据，导致账户凭据泄露与数据库整体失陷。

CVE/CWE 论证：CWE-89 SQL 注入。外部 GET 参数 username 直达 mysqli_query，无认证前置、无参数化，利用链在单文件内完全闭合，属典型可申报 CVE 的注入。

修复建议：改用预处理语句（mysqli_prepare + bind_param）绑定 username/password；对输入做类型与长度校验；避免将用户输入拼接进 SQL；错误信息不要回显数据库错误。

F-3 011.php 使用 MD5 处理口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：011.php:8-9

011.php:8 从 $_GET['password'] 取得明文口令，011.php:9 直接 $pass = md5($pass) 后用于 011.php:12 的登录比对。MD5 为快速、无盐、已被证明存在碰撞的哈希算法，用于口令存储/校验属弱哈希。注意：该弱点本质是 weak_hash（CWE-328），而非 weak_crypto（CWE-327，指 DES/ECB 等加密算法误用）。

影响：若数据库泄露，攻击者可用彩虹表/GPU 高速爆破在极短时间内还原用户明文口令；无盐设计使相同口令产生相同哈希，便于批量破解与撞库，进而横向接管账号。

CVE/CWE 论证：CWE-328（使用弱哈希算法）。属实现型弱点，无需 HTTP 污点链即可成立：算法名 md5( 在 011.php:9 有原文证据，保护对象为登录口令（011.php:8 的 password 参数）。外部可达性：登录接口无需认证即可触发哈希计算路径。

修复建议：改用 password_hash($pass, PASSWORD_DEFAULT)（bcrypt/Argon2）存储，校验用 password_verify()；为每个口令使用独立随机盐（password_hash 已内置）；对历史 MD5 数据在用户下次登录时透明升级；禁止在日志或错误信息中输出哈希。

F-4 011.php 登录成功页将 username 原样回显导致反射型 XSS

medium xss / CWE-79 · 置信度 0.7 · candidate / llm_inferred

位置：011.php:5-21

第 21 行将 $user（来自 $_GET['username']，第 5 行）直接拼入 HTML 输出 "<p>Welcome to the password protected area {$user}</p>"，未做 htmlspecialchars 等编码。虽然该分支需登录成功才触发，但结合同文件 SQL 注入（username 恒真注入）可让攻击者构造同时满足注入与脚本注入的 payload，使页面回显攻击者脚本，构成反射型 XSS。

影响：可在受害者浏览器执行任意脚本，窃取会话/发起 CSRF 操作；结合注入可扩大影响。

CVE/CWE 论证：CWE-79 反射型 XSS。username 从 GET 直达 HTML 输出无编码，链闭合；但触发依赖登录成功分支，故定级 medium。

修复建议：输出前对 $user 使用 htmlspecialchars($user, ENT_QUOTES, 'UTF-8')；对 avatar 等数据库字段同样做输出编码与 URL 校验。
