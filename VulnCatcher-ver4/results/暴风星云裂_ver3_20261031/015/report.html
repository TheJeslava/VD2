F-1 015.php 口令修改处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：015.php:67-69

攻击者通过修改口令表单提交 password_new 参数（015.php:8 处 $pass_new = $_POST['password_new']），该值在 015.php:64 仅经过 mysqli_real_escape_string 转义后，于 015.php:65 被 md5() 处理，随后在 015.php:68 被直接拼接进 UPDATE 语句：$insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . dvwaCurrentUser() . "'"，最终在 015.php:69 由 mysqli_query 执行。由于 md5() 输出为固定 32 位十六进制串，password_new 的原始内容无法以引号形式进入 SQL，因此该路径上的注入不成立；真正未参数化的是 dvwaCurrentUser() 的返回值被直接拼入 WHERE 子句，但该值来自会话而非请求参数，外部不可控。综合判断：候选所声称的 password_new→$insert 污点链在 md5 处被截断，证据不足以支撑可利用的 SQL 注入。

影响：若成立可导致数据库任意读写、口令表被篡改或数据泄露；但按现有代码证据，password_new 经 md5 后无法携带 SQL 元字符，实际影响无法确认。

CVE/CWE 论证：CWE-89 要求外部可控数据未经参数化进入 SQL。本候选的 source（password_new）在 015.php:65 被 md5 归一化为十六进制串，破坏了注入所需的引号闭合条件；WHERE 子句中的 dvwaCurrentUser() 非请求可控。外部可达性与利用链闭合性均不满足，故不构成可确认的 CWE-89。

修复建议：即便当前 md5 阻断了注入，仍应改为预处理语句：$stmt = $db->prepare('UPDATE users SET password = ? WHERE user = ?'); $stmt->bind_param('ss', $pass_new, dvwaCurrentUser()); 避免任何字符串拼接；同时对 dvwaCurrentUser() 的返回值做白名单校验。

F-2 DVWA 密码修改流程 CAPTCHA 状态机可绕过（直接提交 step=2 与 passed_captcha=true）

high captcha_bypass / CWE-804 · 置信度 0.87 · candidate / llm_inferred

位置：015.php:46-69

015.php 的密码修改被拆成两步：step=1 时调用 recaptcha_check_answer 校验验证码，通过后渲染一个隐藏表单，其中包含 step=2、passed_captcha=true 以及用户输入的 password_new/password_conf；step=2 分支只检查 $_POST['passed_captcha'] 是否为真值，完全不重新校验 CAPTCHA，也不校验该值是否由服务端签发。攻击者可以跳过 step=1，直接 POST step=2、passed_captcha=true、password_new、password_conf，从而在未通过任何 CAPTCHA 的情况下修改当前登录用户的密码。该逻辑使 CAPTCHA 保护形同虚设，可被用于自动化口令变更/账户接管链（配合 CSRF 或撞库后的会话）。

影响：CAPTCHA 保护被完全绕过，攻击者可在无验证码交互的情况下自动化修改账户口令，削弱防暴力破解/防自动化能力，可并入账户接管链。

CVE/CWE 论证：CWE-804 (Guessable CAPTCHA) / CWE-841 (Improper Enforcement of Behavioral Workflow)：状态机信任客户端提交的 passed_captcha 标志，服务端未绑定会话，外部可直接触发，链闭合。

修复建议：将 CAPTCHA 通过状态记录在服务端会话（如 $_SESSION['captcha_passed']=true 并一次性消费），step=2 时校验会话标志而非客户端字段；或合并为单步并在提交时重新校验 reCAPTCHA。

F-4 015.php 使用 MD5 存储口令（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.8 · candidate / rule_verified+llm

位置：015.php:64-65

015.php:65 执行 $pass_new = md5( $pass_new );，将用户新口令以无盐 MD5 摘要形式写入数据库（015.php:68 的 UPDATE users SET password = '$pass_new'）。MD5 属快速哈希，抗碰撞与抗暴力能力弱，且此处未加盐、未使用迭代型口令哈希，口令摘要一旦泄露可被彩虹表/GPU 快速还原。

影响：数据库泄露时攻击者可在极短时间内还原用户明文口令；由于用户常跨站复用口令，可进一步导致账户接管与横向越权。

CVE/CWE 论证：CWE-328（使用弱哈希算法）适用于口令等安全用途。015.php:65 明确对安全敏感的口令使用 MD5，属实现型弱点，无需 HTTP 污点链；外部可达性体现在任意改密请求都会生成 MD5 摘要。

修复建议：改用 password_hash($pass_new, PASSWORD_DEFAULT) 生成带盐的 bcrypt/Argon2 摘要，校验时用 password_verify；对历史 MD5 记录在用户下次登录时透明升级。
