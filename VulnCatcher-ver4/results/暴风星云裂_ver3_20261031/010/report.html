F-1 010.php 登录查询 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：010.php:18-20

攻击者通过 HTTP 请求向 010.php 提交登录参数，其中 username 参数（源码 010.php:8 读取，对应查询串 `username`）被直接拼接到 SQL 语句中。010.php:19 构造 `$query = "SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';";`，$user 未经任何转义、类型约束或参数化即进入单引号字符串字面量；010.php:20 将该 $query 交给 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行。由于用户输入可闭合单引号并追加任意 SQL 片段（如 `' OR '1'='1` 或 UNION 查询），校验完全失效。此外 010.php:20 的 `or die(... mysqli_error(...) ...)` 会把数据库错误信息回显到页面，为报错型注入提供回显通道。

影响：可绕过登录认证（以任意用户身份登录，包括管理员），并通过 UNION/报错注入读取 users 表及其他库表数据（口令哈希、账号信息），造成敏感数据泄露；若数据库账号权限较高，还可进一步读写数据甚至通过文件写入扩展影响服务器。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：010.php 为 Web 入口脚本，username 参数来自 HTTP 请求，无需认证即可访问登录页并提交；利用链闭合：010.php:8 外部输入 → 010.php:19 字符串拼接 → 010.php:20 mysqli_query 执行，中间无白名单、转义或预处理，且错误信息回显降低利用门槛。

修复建议：改用预处理语句与参数绑定：`$stmt = $mysqli->prepare("SELECT * FROM users WHERE user = ? AND password = ?"); $stmt->bind_param('ss', $user, $pass); $stmt->execute();`；若必须拼接，使用 mysqli_real_escape_string 并配合严格白名单校验；关闭错误详情回显（生产环境不输出 mysqli_error），统一异常处理；数据库账号按最小权限授予，仅允许所需表的 SELECT。

F-2 010.php 登录成功页将用户名与数据库 avatar 字段未编码输出，形成反射型/存储型 XSS

medium xss / CWE-79 · 置信度 0.77 · candidate / llm_inferred

位置：010.php:28-29

010.php 第 3 行在 $_GET['Login'] 存在时进入登录流程，第 8 行从 $_GET['username'] 读取用户名，仅做 stripslashes 与 mysqli_real_escape_string（只针对 SQL 上下文转义，对 HTML 上下文无效），第 28 行把 $user 直接拼进 HTML 字符串 $html 输出；第 25 行从数据库读取 $row['avatar']，第 29 行直接拼进 <img src="{$avatar}"> 属性。两处均无 htmlspecialchars 等 HTML 编码，攻击者可控的 username 或可写入的 avatar 字段可注入 HTML/JS。

影响：可在受害者浏览器执行任意 JS，窃取会话或发起操作；avatar 字段若可被其他途径写入则为存储型 XSS

CVE/CWE 论证：CWE-79，外部 GET 参数直达 HTML 输出，无需高权限，链闭合；但需登录成功分支才回显，且依赖 user_token

修复建议：输出前使用 htmlspecialchars($user, ENT_QUOTES, 'UTF-8')，avatar 同样编码或做 URL 白名单校验

F-3 010.php 使用 MD5 对密码做摘要后比对

low weak_hash / CWE-328 · 置信度 0.8 · candidate / llm_inferred

位置：010.php:16-19

第 16 行 $pass = md5($pass)，第 19 行将 MD5 值拼入 SQL 与数据库存储值比较。MD5 为已知弱哈希（CWE-328），无盐、快速，易被彩虹表/暴力破解，且若数据库泄露可直接碰撞。

影响：数据库泄露后口令可快速还原，导致账户接管

CVE/CWE 论证：CWE-328，源码明确使用 md5()，属配置/实现类弱点

修复建议：改用 password_hash()/password_verify()（bcrypt/argon2）并加盐
