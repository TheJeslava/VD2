F-1 DVWA SQL 注入（low 级别）：$_SESSION['id'] 直接拼接进 MySQL/SQLite 查询

high sql_injection / CWE-89 · 置信度 0.82 · candidate / llm_inferred

位置：040.php:5-11

脚本从 $_SESSION['id'] 取出用户可控值 $id，未做任何转义或参数化，直接以单引号包裹拼接进 SQL 语句（第 10 行 MySQL 分支、第 28 行 SQLite 分支），随后分别交给 mysqli_query 与 sqlite 的 query() 执行。攻击者只要能让会话中的 id 变为任意字符串（例如通过 DVWA 的 SQL 注入页面把 id 写入会话，或任何可写该会话键的入口），即可闭合单引号注入任意 SQL 语法，读取 users 表之外的数据（如 dvwa 库中的 users/password 哈希），造成数据库信息泄露与潜在的数据篡改。

影响：可读取数据库中任意表（如用户凭据哈希），并可进一步通过 UNION/子查询进行数据篡改或提权，导致数据库信息泄露与账户接管风险。

CVE/CWE 论证：CWE-89：外部可控会话值未经参数化直接拼接进 SQL 并执行，链闭合；DVWA 场景下需已登录会话，属认证后注入，但仍是真实可利用的 SQL 注入。

修复建议：使用预处理语句（mysqli_prepare/bind_param 或 PDO），对 id 做 intval 强类型转换，禁止字符串拼接 SQL。

F-2 040.php 将 $id 未编码回显到 HTML（反射/存储型 XSS）

medium xss / CWE-79 · 置信度 0.7 · candidate / llm_inferred

位置：040.php:20-20

第 20 行与第 44 行把 $id 直接插入 $html 字符串并输出到页面，未做 htmlspecialchars 等编码。若会话中的 id 含 HTML/JS，浏览器会执行，可窃取会话或触发敏感操作。

影响：可在受害者浏览器执行任意 JS，窃取会话 Cookie 或发起 CSRF 式操作。

CVE/CWE 论证：CWE-79：会话值未编码回显到 HTML，链闭合；需会话可控。

修复建议：输出前使用 htmlspecialchars($id, ENT_QUOTES, 'UTF-8')。
