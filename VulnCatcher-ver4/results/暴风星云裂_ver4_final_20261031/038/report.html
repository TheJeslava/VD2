F-1 038.php 基于 query 参数 id 的 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：038.php:11-13

攻击者通过 HTTP 请求的 query 参数 `id` 提供输入（038.php:5 读取），该值未经任何过滤、类型转换或参数化，被直接拼接进 SQL 语句：038.php:11 `$query = "SELECT first_name, last_name FROM users WHERE user_id = '$id';";`，随后在 038.php:13 通过 `mysqli_query($GLOBALS["___mysqli_ston"], $query)` 执行。由于 `$id` 位于单引号字符串字面量内部且未做 `mysqli_real_escape_string` 转义、未使用预处理语句，攻击者可闭合单引号注入任意 SQL 片段（如 `1' OR '1'='1` 或 UNION 查询），校验完全缺失。代码注释显示已移除 'or die' 以抑制 MySQL 错误回显，但这只影响报错可见性，不构成任何防护。

影响：数据库数据泄露：可读取 users 表及其他表的任意数据（如凭据、个人信息）；可进一步通过 UNION/子查询枚举数据库结构；在数据库账户权限较高时可能导致数据篡改或删除。属于机密性与完整性破坏。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：注入点为 HTTP query 参数 `id`，无需认证即可访问该脚本；利用链闭合：038.php:5 读取参数 → 038.php:11 字符串拼接 → 038.php:13 mysqli_query 执行，全程无净化或参数化，攻击者输入直接控制 SQL 语义。

修复建议：改用预处理语句与参数绑定：`$stmt = $mysqli->prepare('SELECT first_name, last_name FROM users WHERE user_id = ?'); $stmt->bind_param('i', $id); $stmt->execute();`；若必须动态拼接，至少对 `$id` 做整型强制转换 `(int)$id` 或 `mysqli_real_escape_string` 转义，并对输入做白名单校验；同时遵循最小权限原则，为应用数据库账户仅授予必要的 SELECT 权限，避免使用高权限账户。
