F-1 014.php 密码修改功能 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：014.php:59-61

攻击者在密码修改表单的 password_new 参数（014.php:8 读取 $_POST['password_new']）提交恶意字符串。该值在 014.php:56 仅经过 mysqli_real_escape_string 转义后，于 014.php:57 被 md5() 处理，随后在 014.php:60 被直接拼接进 UPDATE 语句：$insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . dvwaCurrentUser() . "';";，最终在 014.php:61 交给 mysqli_query 执行。由于 md5() 输出为固定 32 位十六进制字符，password_new 中的引号、注释符等元字符在进入 SQL 前已被哈希消解，因此该路径上的注入实际不可达；候选给出的 source（query `password_new`）与 sink 之间的污点链在 md5 处被截断。真正未参数化的是 dvwaCurrentUser() 的返回值拼接，但其来源为会话用户标识，非直接外部可控。综合判断：该候选的注入链证据不足，置信度低。

影响：若注入成立，攻击者可改写 users 表中任意用户口令，导致账户接管；但基于现有代码，password_new 经 md5 后无法携带 SQL 元字符，实际影响受限。证据不足，无法确认可利用的越权写入。

CVE/CWE 论证：CWE-89：SQL 命令中特殊元素未正确中和。外部可达性：014.php 为 DVWA 口令修改页面，需已认证会话；无需额外权限即可提交 POST。利用链闭合性：source（password_new）→ md5() 哈希 → 字符串拼接 → mysqli_query，哈希步骤破坏了注入所需的元字符，链条不闭合，故不满足完整可利用条件。

修复建议：使用预处理语句与参数绑定：$stmt = $mysqli->prepare('UPDATE users SET password = ? WHERE user = ?'); $stmt->bind_param('ss', $pass_new, dvwaCurrentUser()); $stmt->execute();。同时对 dvwaCurrentUser() 的返回值也做参数化处理，避免任何字符串拼接；口令哈希改用 password_hash()/password_verify()。

F-5 014.php 使用 MD5 存储口令（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.75 · candidate / rule_verified+llm

位置：014.php:56-57

014.php:57 执行 $pass_new = md5( $pass_new );，将用户新口令以无盐 MD5 形式哈希后写入数据库（014.php:60-61 的 UPDATE 语句）。MD5 为快速哈希，抗碰撞与抗暴力破解能力弱，且此处未加盐、未使用迭代 KDF，属于口令存储场景的弱哈希实现。

影响：一旦 users 表泄露，攻击者可用彩虹表或 GPU 高速爆破在短时间内还原大量口令，导致账户接管与横向移动。

CVE/CWE 论证：CWE-328：使用弱哈希算法保护口令等敏感数据。外部可达性：014.php 口令修改接口公开可达，任何提交的新口令都会以 MD5 落库。利用链闭合：password_new（014.php:8）→ md5（014.php:57）→ UPDATE 落库（014.php:60-61），存储路径完整。注意此处为哈希弱点，非加密算法弱点（非 CWE-327）。

修复建议：改用 password_hash($pass_new, PASSWORD_DEFAULT)（bcrypt/Argon2）存储，校验时用 password_verify()；迁移期可对旧 MD5 值在用户下次登录时透明重哈希；禁止无盐快速哈希用于口令。
