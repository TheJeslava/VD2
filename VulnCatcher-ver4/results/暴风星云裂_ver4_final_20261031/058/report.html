F-1 058_08.php 密码修改页仅校验 Cookie Auth 存在性，可伪造 Cookie 绕过登录并篡改任意已知用户名口令

critical auth_bypass / CWE-287 · 置信度 0.8 · candidate / llm_inferred

位置：058_08.php:7-14

058_08.php 的访问控制只判断 $_COOKIE["Auth"] 是否被设置（第7行），未校验其值、未校验签名、未与 $_SESSION 绑定；而 058_06.php 登录成功后把 Auth 固定写成 1（第44行），登出时写 1 并置过期（第66行）。攻击者无需任何凭据，只要手工发送 Cookie: Auth=1 即可通过第7-14行的守卫，进入密码修改逻辑。修改口令的 SQL（第38行）以 $_SESSION["username"] 作为 WHERE 条件，但该会话变量在未登录时为空，因此攻击者需先通过 058_06.php 的登录接口（其 SQL 使用 mysql_real_escape_string，第20-22行）或直接构造会话获得一个已知用户名；更直接的利用是：攻击者先用自己注册的账号（058_05.php 注册接口）登录拿到会话，再借伪造 Auth Cookie 在会话失效后继续访问改密页。核心缺陷是认证状态完全由客户端可控 Cookie 决定，属于典型的信任边界错误/认证绕过。

影响：认证绕过，攻击者可在会话失效后继续访问受保护页面并修改口令，导致账户接管。

CVE/CWE 论证：CWE-287/CWE-639：认证状态由客户端 Cookie 存在性决定，无需有效凭据即可访问改密功能，链闭合。

修复建议：改用服务端会话校验身份，Auth Cookie 不应作为唯一认证依据；对会话变量做完整性校验。

F-2 058_05.php 登录查询 username 参数 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.78 · candidate / rule_verified+llm

位置：058_05.php:29-31

攻击者通过 HTTP 请求向 058_05.php 提交 query 参数 username（058_05.php:25 读取），该值未经任何转义或参数化即被拼接到 SQL 语句 $sql = "select count(*) from users where username='$username'"（058_05.php:30），随后在 058_05.php:31 由 mysql_query($sql) 执行。由于输入被直接放入单引号字符串字面量中，攻击者可闭合引号并注入任意 SQL 片段（如 ' OR '1'='1、UNION SELECT 等），校验完全缺失，污点直达数据库执行汇点。

影响：数据库查询逻辑被篡改：可绕过登录/计数校验、通过 UNION 或布尔/时间盲注逐位读取 users 表中的用户名与口令等敏感数据，并可能借 mysql_query 的堆叠/报错信息（die 输出）辅助枚举数据库结构。属于数据泄露与认证绕过。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：username 来自 HTTP query 参数，无需认证即可访问该脚本；利用链闭合：source（058_05.php:25）→ 字符串拼接（058_05.php:30）→ mysql_query 执行（058_05.php:31），中间无白名单、类型转换或转义函数，故可稳定注入。

修复建议：改用参数化查询（PDO/MySQLi 预处理语句，绑定 :username），彻底避免字符串拼接；若必须保留旧 mysql_* 接口，至少使用 mysql_real_escape_string 并强制类型转换，同时移除 die(mysql_error()) 以免泄露数据库错误信息；对 username 施加长度与字符白名单校验。

F-3 058_05.php 用户注册 INSERT 语句 username/password 参数 SQL 注入（CWE-89）
