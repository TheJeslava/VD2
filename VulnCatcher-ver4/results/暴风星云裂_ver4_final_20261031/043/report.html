F-1 043.php 不安全文件上传导致任意文件写入（CWE-434）

critical file_upload / CWE-434 · 置信度 0.63 · candidate / rule_verified+llm

位置：043.php:18-20

攻击者通过 HTTP 上传请求的 `uploaded` 文件字段（043.php:12 读取上传文件，临时路径进入 `$uploaded_tmp`）提交任意内容与文件名的文件。代码在 043.php:20 直接调用 `move_uploaded_file( $uploaded_tmp, $target_path )` 将临时文件移动到 `$target_path`，在给出的片段（043.php:18-20）中未见任何扩展名白名单、MIME 校验、文件内容检查或目标路径规范化/限制。由于校验缺失，攻击者可控制落盘文件名与内容，将可执行脚本（如 .php）写入 Web 可访问目录。

影响：任意文件写入 Web 根目录可导致远程代码执行（上传 PHP webshell 后访问即执行），进而完全控制服务器；也可覆盖/植入文件造成持久化后门或数据篡改。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部可达性：上传接口为 HTTP 端点，无需认证即可提交 multipart 请求；利用链闭合：`uploaded` 文件 → `$uploaded_tmp`（043.php:12）→ `move_uploaded_file($uploaded_tmp, $target_path)`（043.php:20）→ 文件落盘于 Web 可访问路径。片段中未见任何净化或类型限制，故无需绕过即可利用。

修复建议：1) 使用扩展名白名单（如仅 jpg/png/pdf）并基于服务端解析的真实 MIME/魔数校验，而非客户端 Content-Type；2) 上传文件重命名为随机名，禁止使用用户提供的文件名；3) 上传目录置于 Web 根之外，或配置该目录禁止脚本执行（如 PHP 引擎关闭）；4) 对 `$target_path` 做规范化并校验其位于允许目录内，防止路径穿越；5) 限制文件大小与权限（最小权限运行）。

F-2 DVWA 文件上传页面 043.php 仅校验扩展名与 getimagesize，可上传含 PHP 代码的图片并写入 web 可访问目录

high file_upload / CWE-434 · 置信度 0.78 · candidate / llm_inferred

位置：043.php:3-27

043.php 处理 multipart 上传：从 $_FILES['uploaded']['name'] 取文件名，用 strrpos 取最后一个点后的子串作为扩展名，仅做 strtolower 白名单（jpg/jpeg/png）、大小 <100000 与 getimagesize() 校验，随后 basename() 后直接拼接 DVWA_WEB_PAGE_TO_ROOT."hackable/uploads/" 并 move_uploaded_file 落盘。getimagesize 只检查文件头是否为合法图片，不阻止图片尾部附加任意 PHP 代码（polyglot 图片马）；扩展名白名单只约束后缀，不约束内容。落盘目录 hackable/uploads/ 在 DVWA 部署中为 web 可直接访问目录，若服务器对 .jpg/.png 不做 PHP 解析则需配合解析配置，但该页面本身缺失内容级校验与上传目录执行禁用，属于典型的 unrestricted file upload 弱点。

影响：攻击者可上传含服务端代码的文件到 web 可访问目录，在解析配置允许时实现远程代码执行；即使不解析，也可作为存储型内容托管/钓鱼载体。

CVE/CWE 论证：CWE-434 Unrestricted Upload of File with Dangerous Type。外部无需认证即可通过 POST 上传触发，source→sink 链在 043.php 内闭合；getimagesize 与扩展名白名单为可绕过的弱防护。

修复建议：对上传内容做真实图像重编码（如 GD/Imagick 重新生成图片）去除附加数据；随机化落盘文件名并强制安全扩展名；上传目录禁用脚本执行（php_flag engine off / Nginx location 拒绝 .php）；限制 MIME 与文件头一致性校验。
