F-1 012.php 登录查询 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.78 · candidate / rule_verified+llm

位置：012.php:13-15

攻击者通过 HTTP GET 参数 Login 触发登录分支（012.php:3），随后 username 与 password 参数被读取（012.php:5 附近）。username 仅经过 mysqli_real_escape_string 处理（012.php:9），password 先经 mysqli_real_escape_string 再被 md5() 处理（012.php:10-11），因此 password 因哈希而失去注入能力，但 username 仍以原始字符串拼接进 SQL。012.php:14 构造 "SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';"，012.php:15 直接调用 mysqli_query 执行。由于未使用参数化查询，且 mysqli_real_escape_string 在非 utf8/特定字符集或宽字节场景下可被绕过，同时该转义只处理引号而不改变拼接结构，攻击者可在 username 中闭合单引号注入任意 SQL 片段。

影响：可绕过登录认证（如 username 注入 ' OR '1'='1 使 WHERE 恒真），并可进一步通过 UNION/布尔/报错注入读取 users 表全部账号口令哈希，造成敏感数据泄露与认证绕过；错误信息经 die() 回显（012.php:15）为报错注入提供通道。

CVE/CWE 论证：CWE-89：外部可控的 GET 参数 username 未经参数化即拼接进 SQL 并在 012.php:15 执行，链路闭合、无需认证即可访问登录端点，属典型可远程利用的 SQL 注入。

修复建议：改用 PDO 或 mysqli 预处理语句（prepare + bind_param）绑定 username/password；对输入做长度与字符白名单校验；关闭错误详情回显，统一返回通用错误页；数据库账号遵循最小权限，禁止对 users 表以外的写权限。

F-3 012.php 使用 MD5 存储口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：012.php:10-11

012.php:11 对用户口令调用 md5($pass) 生成摘要，012.php:14 将该 MD5 值与数据库中的 password 字段直接比较完成认证。MD5 为快速、无盐、可碰撞的哈希算法，不适合口令等安全用途；代码中未见盐值或迭代加盐（如 password_hash/bcrypt/argon2）。注意：该问题本质是弱哈希（CWE-328），而非弱加密算法（CWE-327）。

影响：一旦 users 表泄露，攻击者可用彩虹表/GPU 高速爆破在极短时间内还原弱口令；无盐设计使相同口令产生相同摘要，便于批量破解与撞库，导致账号接管。

CVE/CWE 论证：CWE-328：MD5 被用于口令存储与校验这一安全用途，属可被离线加速破解的弱哈希实现；该弱点为配置/实现型，无需 HTTP 污点链即可成立，证据为 012.php:11 的 md5( $pass ) 原文。

修复建议：改用 password_hash()（PASSWORD_BCRYPT 或 PASSWORD_ARGON2ID）生成带盐慢哈希，校验使用 password_verify()；对存量 MD5 摘要在用户下次登录时透明升级；禁止在任何安全用途中使用 MD5/SHA-1。

F-4 012.php 登录成功页将 GET 参数 username 未编码回显导致反射型 XSS

medium xss / CWE-79 · 置信度 0.72 · candidate / llm_inferred

位置：012.php:5-23

012.php 第 3 行以 $_GET['Login'] 存在为入口，第 5 行读取 $_GET['username'] 到 $user，第 6 行仅做 mysqli_real_escape_string（只转义 SQL 特殊字符，不转义 HTML），第 23 行把 $user 直接拼接进 HTML 输出 "<p>Welcome to the password protected area {$user}</p>"，未做 htmlspecialchars 等 HTML 编码。攻击者可构造带脚本的 username，并配合任意能通过登录校验的凭据（或利用第 14 行 SQL 注入使查询返回一行），使页面渲染攻击者脚本，造成反射型 XSS，可窃取会话或钓鱼。

影响：反射型 XSS，可在受害者浏览器执行任意脚本，窃取 Cookie/会话或实施钓鱼。

CVE/CWE 论证：CWE-79：外部 GET 参数直达 HTML 输出且无 HTML 编码，链闭合；但需登录成功分支，故为中危。

修复建议：输出前对 $user 使用 htmlspecialchars($user, ENT_QUOTES, 'UTF-8') 编码。
