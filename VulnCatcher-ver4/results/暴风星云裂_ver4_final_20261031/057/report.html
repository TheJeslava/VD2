F-1 057.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：057.php:17-19

攻击者通过 HTTP 请求向 057.php 提交留言板表单，外部输入在 057.php:5 被读入变量 $message（候选标注的 source 为 query `mtxMessage`）。该值未经任何转义或参数化，在 057.php:18 被直接拼接进 SQL 字符串：$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";，随后在 057.php:19 交给 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行。由于 $message 位于单引号字符串字面量内部，攻击者只需闭合单引号即可跳出值上下文注入任意 SQL 片段（例如在 comment 字段中构造 ' , (SELECT ...))-- - 之类的载荷），无需任何认证即可触发。代码中不存在 mysqli_real_escape_string、prepared statement 或类型白名单，因此校验完全缺失。注意：输入片段仅给出 057.php:17-19 与 source 行 057.php:5，$name 的具体取值行未在片段中展示，其是否同样可注入属证据不足，本 finding 仅就 $message 链闭合。

影响：数据库写入型注入：攻击者可任意改写 INSERT 语句，向 guestbook 表写入伪造/恶意内容，或通过子查询读取其他表数据（如用户表、凭据表）并借助 057.php:19 的 die(mysqli_error(...)) 错误回显把查询结果/结构泄露到 HTTP 响应中，造成敏感数据泄露；在数据库账号权限过高时还可能通过堆叠/文件写入原语进一步扩大影响。无需认证、外部网络可达。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：注入点为留言板提交参数，属匿名可访问的 Web 入口；无需认证；利用链闭合：057.php:5 读取外部输入 → 057.php:18 字符串拼接进 $query → 057.php:19 mysqli_query 执行，中间无净化函数，且错误信息经 die() 回显，可作为注入成功的判定与数据外带通道。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：改用参数化查询：$stmt = mysqli_prepare($GLOBALS["___mysqli_ston"], "INSERT INTO guestbook (comment, name) VALUES (?, ?)"); mysqli_stmt_bind_param($stmt, 'ss', $message, $name); mysqli_stmt_execute($stmt);。若短期无法改造，至少对 $message/$name 使用 mysqli_real_escape_string 并配合长度/字符白名单校验；同时移除 057.php:19 中把 mysqli_error 直接输出到页面的 die() 分支，改为记录服务端日志并返回通用错误；数据库账号按最小权限授予，仅保留 guestbook 表的 INSERT 权限。
