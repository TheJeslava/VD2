F-1 056.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.78 · candidate / rule_verified+llm

位置：056.php:15-17

攻击者通过 HTTP 请求向 056.php 提交留言板表单，外部输入在 056.php:5 被读入变量 $message（候选标注的 source 为 query `mtxMessage`，即留言内容字段）。该值未经任何转义或参数化，在 056.php:16 被直接拼接进 SQL 字符串：$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";，随后在 056.php:17 交由 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行。由于 $message 位于单引号字符串字面量内部，攻击者只需闭合单引号即可跳出字符串上下文并注入任意 SQL 片段（例如在 comment 值中构造 ' , (SELECT ...))-- - 之类的载荷），从而改变语句结构。代码中未见 mysqli_real_escape_string、预处理语句或类型白名单等任何有效净化，因此校验无效。注意：$name 同样以拼接方式进入同一语句，属于同一注入面。

影响：数据库注入可导致 guestbook 表数据被任意篡改或伪造（数据完整性破坏），并可通过 UNION/子查询/报错回显读取同库其他表（如用户凭据）造成敏感数据泄露；结合 056.php:17 的 die(mysqli_error(...)) 报错回显，攻击者可获得数据库错误信息辅助盲注与结构探测。在数据库账户权限过高或支持堆叠/文件写入的情况下，存在进一步扩大影响（如写入文件）的可能，但该点证据不足，未在片段中确认。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：056.php 为 Web 入口脚本，输入来自 HTTP 请求参数，无需认证即可访问；利用链闭合：056.php:5 读取外部输入 → 056.php:16 字符串拼接构造 $query → 056.php:17 mysqli_query 执行，全程无净化函数介入，构成完整 source→sink 链。

修复建议：改用参数化查询：使用 mysqli_prepare 配合 bind_param 将 comment 与 name 作为绑定参数传入，例如 $stmt = mysqli_prepare($link, "INSERT INTO guestbook (comment, name) VALUES (?, ?)"); mysqli_stmt_bind_param($stmt, 'ss', $message, $name); mysqli_stmt_execute($stmt);。若必须保留拼接，至少对两处变量统一使用 mysqli_real_escape_string 并显式加引号，同时校验输入长度与字符集。生产环境应关闭 056.php:17 的 mysqli_error 直接回显，改为记录日志并返回通用错误页。数据库账户遵循最小权限，仅授予 guestbook 表的 INSERT 权限。
