F-1 025.php ping 功能通过 $_REQUEST['ip'] 拼接 shell_exec 导致命令注入（黑名单可绕过）

critical command_injection / CWE-78 · 置信度 0.9 · candidate / llm_inferred

位置：025.php:5-30

脚本在 $_POST['Submit'] 存在时读取 $_REQUEST['ip']（第 5 行），仅用 str_replace 对 ||、&、;、'| '、-、$、(、)、` 做黑名单删除（第 8-21 行），随后直接拼接进 shell_exec('ping -c 4 ' . $target)（第 30 行，Windows 分支第 26 行同理）。黑名单未过滤换行符 \n、空格、重定向符 >、<、通配符 *、?、以及字母数字，攻击者可用换行分隔第二条命令（shell 将换行视为命令分隔符），或用 > 重定向写文件，从而在服务器上执行任意命令。由于 $_REQUEST 同时接受 GET/POST/Cookie，攻击面更宽。

影响：远程未认证攻击者可在服务器上以 Web 进程权限执行任意系统命令，读取敏感文件、写入 webshell、横向移动，完全控制主机。

CVE/CWE 论证：CWE-78 OS 命令注入。source（$_REQUEST['ip']）到 sink（shell_exec）链路完整且在同一文件内闭合；黑名单可被换行符绕过；无需认证即可触发（仅需 POST Submit 参数），外部可达，符合 CVE 申报条件。

修复建议：不要将用户输入拼接进 shell 命令。使用 escapeshellarg($target) 包裹参数，或改用 filter_var($target, FILTER_VALIDATE_IP) 严格校验为合法 IP 后再拼接；更佳做法是使用 proc_open 传数组参数避免 shell 解释。

F-2 025.php 通过 query 参数 ip 造成 OS 命令注入（Windows 分支，CWE-78）

critical command_injection / CWE-78 · 置信度 0.83 · candidate / rule_verified+llm

位置：025.php:24-26

攻击者通过 HTTP query 参数 `ip` 提供输入，该输入在 025.php:5 被读入变量 `target`，随后在 025.php:24 通过 `stristr(php_uname('s'),'Windows NT')` 判断运行平台；当平台为 Windows 时，代码在 025.php:26 执行 `$cmd = shell_exec( 'ping ' . $target );`。`target` 未经任何转义、白名单校验或参数化处理，被直接以字符串拼接方式拼入 shell 命令，因此 `ip` 中的 shell 元字符（如 `&`、`|`、`&&`）会被命令解释器执行。代码中不存在 escapeshellarg/escapeshellcmd 等净化，也没有对输入做 IP 格式校验，校验环节完全缺失。

影响：远程未认证攻击者可在 Web 服务器进程权限下执行任意系统命令，导致服务器被完全控制（RCE）、读取/篡改应用与系统文件、横向移动。Windows 分支下可借助 `&`、`|` 等分隔符追加任意命令。

CVE/CWE 论证：CWE-78（OS 命令注入）。外部可达性：注入点为 HTTP query 参数 `ip`，无需认证即可访问该脚本；利用链闭合：`ip` → `target`（025.php:5）→ 字符串拼接 → `shell_exec`（025.php:26），中间无有效净化，攻击者可控命令内容，满足命令注入的完整条件。

修复建议：避免将用户输入拼入 shell 字符串。优先使用参数数组形式并禁用 shell，例如在 PHP 中用 `escapeshellarg($target)` 包裹参数，或改用 `proc_open` 传数组参数；同时对 `ip` 做严格白名单校验（仅允许合法 IPv4/IPv6 字符集，如 `filter_var($target, FILTER_VALIDATE_IP)`），校验失败直接拒绝；以最小权限账户运行 Web 服务。
