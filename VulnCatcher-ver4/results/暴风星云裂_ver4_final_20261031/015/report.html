F-1 015.php 修改密码处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：015.php:67-69

攻击者在修改密码表单的 password_new 参数（015.php:8 读取 $_POST['password_new']）提交恶意字符串，该值先经 mysqli_real_escape_string 处理（015.php:64），随后在 015.php:65 被 md5() 哈希，最终在 015.php:68 被拼接进 UPDATE `users` SET password = '$pass_new' WHERE user = '...' 语句，并在 015.php:69 交给 mysqli_query 执行。由于 $pass_new 在拼接前已被 md5() 转换为 32 位十六进制串，单引号等元字符无法原样进入 SQL 语句，因此候选给出的 password_new→SQL 污点链在源码层面并不闭合；真正可注入的通道是 dvwaCurrentUser() 的返回值（015.php:68 的 user 字段），其来源不在本次 code_pack 内，证据不足。此外 015.php:69 的 die(mysqli_error(...)) 会把数据库错误回显给客户端，构成错误信息泄露，可辅助注入探测。

影响：若 user 字段可被外部影响，攻击者可改写任意用户口令或通过 UNION/布尔盲注读取 users 表数据，导致账户接管与数据泄露；即使注入不成立，015.php:69 的 mysqli_error 回显也会泄露 SQL 结构与数据库版本信息。当前证据仅能确认错误回显与不安全的字符串拼接写法，无法确认可利用的注入点。

CVE/CWE 论证：CWE-89：SQL 命令中特殊元素未正确中和。外部可达性：015.php 为 DVWA 修改密码页面，需已登录会话（DVWA 默认 low 级别），无需额外权限即可提交 POST。利用链闭合性：password_new 经 md5() 后元字符被消除，链不闭合；dvwaCurrentUser() 的实现未在 code_pack 中给出，无法证明其可控，故不满足闭合条件。

修复建议：改用预处理语句与参数绑定（mysqli_prepare + bind_param），彻底移除字符串拼接；对 dvwaCurrentUser() 的返回值同样参数化；关闭错误回显，将 mysqli_error 写入服务端日志而非输出到页面；对 password_new/password_conf 做长度与字符白名单校验。

F-2 DVWA 密码修改功能 CAPTCHA 状态机可绕过（step=2 直接提交 passed_captcha=true）

high captcha_bypass / CWE-804 · 置信度 0.9 · candidate / llm_inferred

位置：015.php:46-69

脚本用两阶段状态机实现 CAPTCHA 校验：step=1 时调用 recaptcha_check_answer 校验验证码，通过后渲染一个隐藏表单，其中包含 step=2、password_new、password_conf 和 passed_captcha=true。step=2 分支（第 46-81 行）只检查 $_POST['passed_captcha'] 是否为真值（第 55 行），完全不重新校验 CAPTCHA，也不校验该值是否由服务端签发（无签名、无 session 绑定、无一次性 token）。攻击者可以跳过 step=1，直接构造 step=2 请求并自带 passed_captcha=true，从而在从未通过 CAPTCHA 的情况下修改当前用户密码。这使 CAPTCHA 对密码修改这一敏感操作完全失效，可被用于自动化撞库/批量改密/CSRF 辅助。

影响：CAPTCHA 保护被完全绕过，攻击者可在无验证码交互的情况下自动化修改密码，配合 CSRF 可诱导受害者改密，削弱对暴力/自动化攻击的防护。

CVE/CWE 论证：CWE-804（Guessable CAPTCHA）/CWE-841（行为强制不当）。外部可直接 POST 触发，无需通过验证码，链闭合：step=2 分支仅信任客户端 passed_captcha 标志即执行改密。

修复建议：在 step=2 分支服务端重新校验 CAPTCHA，或将 step=1 的通过结果以服务端 session 中的一次性随机 token 记录并在 step=2 校验后失效，禁止信任客户端提交的 passed_captcha 标志。

F-4 015.php 使用 MD5 存储口令（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.85 · candidate / rule_verified+llm

位置：015.php:64-65

015.php:65 执行 $pass_new = md5( $pass_new );，将用户新口令以无盐 MD5 单次哈希后写入数据库（015.php:68-69 的 UPDATE 语句）。MD5 为快速哈希，且此处未加盐、未使用迭代，属于口令存储场景的弱哈希。注意：该问题应归类为 weak_hash（CWE-328），而非 weak_crypto（CWE-327，指 DES/ECB 等加密算法缺陷）。

影响：数据库泄露后攻击者可用彩虹表或 GPU 高速爆破在极短时间内还原明文口令；相同口令产生相同哈希，可横向撞库，导致账户接管。

CVE/CWE 论证：CWE-328：使用可被高效计算的弱哈希算法保护口令。外部可达性：015.php 修改密码接口公开可达。利用链闭合性：md5() 调用与写库语句在源码中直接可见，无需运行时条件即可确认。

修复建议：改用 password_hash()（PASSWORD_ARGON2ID 或 PASSWORD_BCRYPT）生成带盐慢哈希，校验使用 password_verify()；迁移旧 MD5 记录时在用户下次登录成功后重新哈希；禁止在任何安全用途中使用 MD5/SHA-1。
