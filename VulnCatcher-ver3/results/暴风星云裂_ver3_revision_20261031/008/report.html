F-1 008.php 用户存在性检查处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.68 · candidate / rule_verified+llm

位置：008.php:21-23

攻击者通过 HTTP 请求参数 user_id 提供输入（008.php:19 读取 query `user_id`），该值未做类型转换或参数化，直接拼接进 $check_query = "SELECT user_id FROM users WHERE user_id = $id"（008.php:22），随后在 008.php:23 交给 mysqli_query($GLOBALS["___mysqli_ston"], $check_query) 执行。代码中未见 intval/类型转换、mysqli_real_escape_string 或预处理语句，因此数字型上下文可被 `1 OR 1=1`、`1 UNION SELECT ...` 等载荷突破，校验无效。

影响：数据库查询逻辑被篡改：可绕过用户存在性判断、枚举/读取 users 表及其他表数据（如凭据、个人信息），在数据库权限允许时可进一步读写文件或堆叠查询，造成数据泄露与认证逻辑绕过。

CVE/CWE 论证：CWE-89：外部可控参数 user_id 未经参数化直接进入 SQL 语句并执行，属典型一次注入；入口为公开 HTTP 参数，无需认证即可触发，source（008.php:19）到 sink（008.php:23）链路闭合。

修复建议：改用预处理语句：$stmt = mysqli_prepare($GLOBALS["___mysqli_ston"], "SELECT user_id FROM users WHERE user_id = ?"); mysqli_stmt_bind_param($stmt, 'i', $id); 并对 $id 做 intval 白名单校验；禁止字符串拼接 SQL。

F-5 008.php 基于 Cookie 的角色标识可被客户端伪造（CWE-330/CWE-565）

high weak_id / CWE-330 · 置信度 0.4 · candidate / rule_verified+llm

位置：008.php:93-94

008.php:93-94 在 $_COOKIE['user_role'] 不存在时执行 setcookie('user_role', 'regular_user', time() + 3600, '/')，即用户角色这一安全相关标识完全由客户端 Cookie 承载，且未签名、未与服务器端会话绑定。攻击者可直接构造 Cookie user_role=admin 之类的值提交，服务端若直接信任该 Cookie 判断权限即被绕过。注意：输入证据仅显示写入默认值，未给出读取该 Cookie 做鉴权的具体行号，故“服务端信任该值”的部分属推断，需结合未提供的鉴权代码复核。

影响：若下游逻辑依据 user_role Cookie 做授权判断，攻击者可将其改为管理员角色实现垂直越权，访问管理功能或他人数据；同时该标识可预测/可枚举，缺乏完整性保护。

CVE/CWE 论证：CWE-330（使用不充分随机/可预测值）与 CWE-565（依赖未受保护的 Cookie 做安全决策）：安全相关标识由客户端可控 Cookie 承载，无签名或服务端校验，外部无需认证即可设置。

修复建议：不要在 Cookie 中存放角色等授权信息；角色应保存在服务端会话（$_SESSION）中，Cookie 仅保存不可猜测的会话 ID（session_regenerate_id、HttpOnly/Secure/SameSite 标志）；对任何客户端提交的权限相关值做服务端校验与签名。
