F-1 020.php 未校验 POST 参数 include 直接进入页面拼接（CWE-22 路径/资源引用注入）

影响：若下游存在文件包含或文件读取逻辑，可导致任意本地文件读取/包含（取决于部署环境）；在当前可见片段中，至少可将攻击者控制的 URL/路径注入 `<script src>`，造成外部脚本加载与前端逻辑劫持。具体 RCE/文件读写影响证据不足。

CVE/CWE 论证：CWE-22（路径穿越）要求外部输入未经规范化即用于路径构造。此处外部可达（POST 参数 include，无需认证），但利用链在给定片段内未闭合到文件系统 API，故仅能确认“未校验输入进入路径/资源引用”，不能断言任意文件读写。

修复建议：对 include 参数使用严格白名单（枚举允许的页面/资源名），拒绝包含 `../`、绝对路径、协议前缀（`http:`、`//`）的值；使用 `realpath()` 规范化后校验结果仍位于允许目录内；输出到 HTML 属性时进行 HTML 实体编码与引号转义。

F-3 020.php 中 POST 参数 include 未编码直接拼入 <script src> 导致反射型 XSS

medium xss / CWE-79 · 置信度 0.82 · candidate / llm_inferred

位置：020.php:13-17

脚本在第 13 行读取 $_POST['include']，在第 14-16 行将其原样拼接进 <script src='...'></script> 并输出到响应体，未做 HTML 实体编码、URL 校验或白名单过滤。攻击者可通过构造 include 值闭合单引号并注入任意 HTML/JS，实现反射型 XSS。虽然第 3-5 行设置了 CSP（script-src 白名单），但 CSP 仅限制脚本来源，不阻止注入内联 HTML 结构（如 <img onerror>、<svg onload> 等事件处理器在部分浏览器/配置下仍可执行），且白名单中包含 pastebin.com、unpkg.com、cdn.jsdelivr.net 等可托管任意 JS 的公共 CDN，攻击者可借助这些域加载恶意脚本，CSP 无法有效防护。

影响：反射型 XSS，可在受害者浏览器上下文执行任意 JS，窃取会话、发起 CSRF 或钓鱼。CSP 因白名单含公共 CDN 而可被绕过。

CVE/CWE 论证：CWE-79：外部可控 POST 参数未经编码直接进入 HTML 输出，链闭合，无需认证，外部可达。

修复建议：对 $_POST['include'] 做 HTML 实体编码（htmlspecialchars），并校验 URL 协议与域名白名单；收紧 CSP，移除可托管任意内容的公共 CDN 域。

F-4 020.php CSP script-src 白名单过宽（CWE-693 防护机制失效）

medium csp / CWE-693 · 置信度 0.6 · candidate / rule_verified+llm

位置：020.php:2-3

020.php:3 定义 `Content-Security-Policy: script-src 'self' https://pastebin.com hastebin.com www.toptal.com example.com code.jquery.com https://ssl.google-analytics.com unpkg.com cdn.jsdelivr.net digi.ninja ;`。该策略允许从多个第三方托管/CDN 与 pastebin 类站点加载脚本，其中 pastebin.com、hastebin.com 允许匿名发布任意内容，unpkg.com、cdn.jsdelivr.net 允许托管任意公开包，均可被攻击者用于托管恶意脚本。结合 020.php:15 的 `<script src>` 注入点，CSP 无法阻止攻击者从这些白名单域加载脚本。

影响：CSP 作为纵深防御失效：即使存在脚本注入点，攻击者仍可从白名单中的匿名托管域加载任意 JS，导致 XSS 防护被绕过、会话劫持与数据窃取。

CVE/CWE 论证：CWE-693（防护机制失效）。属配置型弱点，无需污点链；证据为 020.php:3 的策略原文。外部可达性取决于响应是否实际下发该头，片段内未显示 header() 调用，故为推断。

修复建议：移除 pastebin.com、hastebin.com、unpkg.com、cdn.jsdelivr.net 等可匿名托管任意内容的源；仅保留确需的固定版本 CDN 并配合 SRI；增加 `object-src 'none'`、`base-uri 'none'`、`frame-ancestors 'none'`；优先使用 nonce/hash 而非域名白名单。
