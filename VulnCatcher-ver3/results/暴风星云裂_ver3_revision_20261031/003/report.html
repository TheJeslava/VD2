F-1 003.php 通过 REQUEST_URI 反射注入 JavaScript 字符串（DOM/反射型 XSS）

high xss / CWE-79 · 置信度 0.85 · candidate / llm_inferred

位置：003.php:3-51

脚本在第 3 行读取 $_SERVER['REQUEST_URI']，第 4 行仅用 str_replace 删除字面量 "/vulnerabilities/api/"，未做任何 HTML/JS 编码或白名单校验，随后在第 31、51 行把 $stripped_url 直接拼接进 <script> 内的单引号 JS 字符串常量（const url = '...'）。攻击者可在请求路径中构造包含单引号与 JS 代码的 URI，闭合字符串后注入任意 JavaScript，在受害者浏览器中执行，属于反射型 XSS。

影响：攻击者可在受害者浏览器上下文执行任意 JavaScript，窃取会话、伪造请求、篡改页面内容

CVE/CWE 论证：CWE-79 反射型 XSS：外部 URI 直接进入脚本上下文，无编码/白名单，链闭合，无需认证

修复建议：对 $stripped_url 使用 json_encode 或 htmlspecialchars 输出到 JS 上下文，或改用固定相对路径而非从 REQUEST_URI 派生

F-2 003.php 通过 REQUEST_URI 字符串替换暴露 API 路径信息（CWE-200）

high api_info_disclosure / CWE-200 · 置信度 0.4 · candidate / rule_verified+llm

位置：003.php:3-4

证据仅覆盖 003.php 第 3-4 行：第 3 行 `$request_url = $_SERVER['REQUEST_URI'];` 读取客户端可控的请求 URI（攻击者输入点），第 4 行 `$stripped_url = str_replace("/vulnerabilities/api/", "", $request_url);` 仅做一次字面量字符串替换，把 `/vulnerabilities/api/` 前缀从 URI 中剥离，未做任何白名单校验、路径规范化或输出编码。该 `$stripped_url` 后续如何被使用（是否回显到响应体、是否用于文件/路由拼接、是否进入日志或错误页）在给定片段中不可见，因此“信息泄露”的具体汇点无法从现有证据闭合。当前证据只能确认：请求 URI 被原样读取并做弱处理，属于语义模式命中，尚不足以证明存在可观测的敏感信息返回。

影响：若 `$stripped_url` 被回显或用于构造响应/错误信息，可能向未认证请求方泄露内部 API 路径结构、版本或路由信息，辅助后续攻击面枚举；但由于缺少下游使用点证据，实际泄露内容与影响范围证据不足，不能断言可读取敏感数据或越权。

CVE/CWE 论证：CWE-200（Exposure of Sensitive Information to an Unauthorized Actor）。外部可达性：`$_SERVER['REQUEST_URI']` 由任意 HTTP 请求控制，无需认证即可触达第 3-4 行。但利用链未闭合：缺少 `$stripped_url` 的输出/使用汇点，无法证明敏感信息实际返回给攻击者，故不满足 CVE 论证所需的“可达 + 泄露内容明确 + 链路闭合”三要素，当前仅为候选。

修复建议：1) 不要基于原始 REQUEST_URI 做字符串替换来推导路由，改用框架路由或显式白名单映射；2) 对 URI 做规范化（解码、去除 `..`、多重斜杠）后再匹配；3) 任何回显到响应/错误页的路径信息应做最小化处理，避免暴露内部目录与版本；4) 对 API 端点统一加鉴权与统一错误响应，避免差异化信息泄露。
