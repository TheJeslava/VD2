F-1 024.php 修改口令处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.45 · candidate / rule_verified+llm

位置：024.php:17-19

攻击者通过 HTTP GET 参数 password_new（024.php:7 `$pass_new = $_GET['password_new'];`）提交输入。该值在 024.php:13 仅经过 mysqli_real_escape_string 转义，随后在 024.php:14 被 md5() 处理，最终在 024.php:18 被直接拼接进 SQL 语句 `UPDATE `users` SET password = '$pass_new' WHERE user = '" . $current_user . "';`，并在 024.php:19 交给 mysqli_query 执行。由于 md5() 的输出是 32 位十六进制字符串，正常情况下会消除引号等元字符，因此单看 password_new 这条链，注入难以闭合；真正的风险点在于 024.php:18 中 $current_user 由 dvwaCurrentUser()（024.php:17）返回并直接拼接进 SQL，而该函数的值来源于会话中的用户名，属于可被攻击者间接影响的数据。此外，024.php:19 在查询失败时通过 die() 输出 mysqli_error，构成报错型注入的信息泄露通道。当前证据只能确认拼接与报错回显存在，尚未看到 dvwaCurrentUser() 的实现，无法确认其是否可被外部控制，因此该注入的可利用性证据不足。

影响：若 $current_user 可被攻击者影响（例如通过注册或修改用户名的功能写入恶意用户名），则可篡改 users 表中任意用户的 password 字段，导致账号接管；即使不能注入，024.php:19 的 mysqli_error 回显也会泄露 SQL 结构、表名与列名，为后续攻击提供信息。

CVE/CWE 论证：CWE-89：外部输入未经参数化即拼接进 SQL 并执行，且错误信息回显。外部可达性：024.php 为 DVWA 的 CSRF 模块页面，GET 参数可直接访问；无需认证即可到达代码路径（DVWA 默认低安全级别下会话可建立）。利用链闭合度：password_new 经 md5 后元字符被消除，注入闭合依赖 $current_user 的可控性，该环节证据不足，故不能断言完整可利用链。

修复建议：改用预处理语句与参数绑定：`$stmt = $mysqli->prepare('UPDATE users SET password = ? WHERE user = ?'); $stmt->bind_param('ss', $pass_new, $current_user);`；对 $current_user 做白名单校验（仅允许已存在用户名）；关闭错误回显，将 mysqli_error 写入服务端日志而非响应体；口令哈希改用 password_hash()/password_verify()。

F-2 DVWA 密码修改功能仅依赖 HTTP_REFERER 校验，可被 CSRF 绕过实现账户接管

high csrf / CWE-352 · 置信度 0.85 · candidate / llm_inferred

位置：024.php:3-19

024.php 第 3 行通过 `$_GET['Change']` 触发密码修改流程，第 5 行仅用 `stripos($_SERVER['HTTP_REFERER'], $_SERVER['SERVER_NAME']) !== false` 判断请求来源，随后第 7-8 行直接读取 `password_new`/`password_conf`，第 11 行比较相等后在第 14 行 md5 并在第 18-19 行执行 UPDATE 修改当前用户密码。HTTP_REFERER 完全由客户端控制，攻击者可在恶意页面中构造 Referer 包含目标域名的请求，或直接省略/伪造该头，从而绕过唯一的“来源校验”。整个流程没有任何 CSRF token、没有对原密码的验证、没有二次确认，属于典型的认证后 CSRF 导致账户接管。

影响：任意已登录用户的密码可被第三方静默修改，导致账户完全接管；若受害者是管理员则进一步控制整个应用。

CVE/CWE 论证：CWE-352 跨站请求伪造。外部可达、无需知道原密码、仅依赖可伪造的 Referer 头作为防护，链完整闭合，属于 DVWA 已知 CSRF 漏洞模式。

修复建议：引入每个会话唯一的 CSRF token 并在服务端校验；修改密码前要求验证原密码；不要依赖 HTTP_REFERER 作为安全控制。

F-4 024.php 使用 MD5 存储口令（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.8 · candidate / rule_verified+llm

位置：024.php:13-14

024.php:14 `$pass_new = md5( $pass_new );` 对口令使用 MD5 做单次无盐哈希，随后在 024.php:18-19 写入 users 表 password 字段。MD5 为快速哈希，抗碰撞与抗暴力破解能力不足，且未加盐，相同口令产生相同摘要，可被彩虹表与 GPU 离线爆破直接还原。该弱点为配置/实现型，无需 HTTP 污点链即可成立。

影响：数据库泄露后攻击者可离线快速还原用户明文口令；相同口令用户摘要一致，便于横向撞库，导致账号接管。

CVE/CWE 论证：CWE-328（Use of Weak Hash）：MD5 用于口令等安全用途。外部可达性：024.php 为可直接访问的修改口令页面，任意用户提交口令即触发该哈希路径；无需特殊权限。利用链闭合：算法选择本身即缺陷，不依赖额外输入。

修复建议：改用 password_hash($pass_new, PASSWORD_DEFAULT)（bcrypt/Argon2）存储，校验使用 password_verify()；迁移期可对旧 MD5 摘要做二次哈希升级；禁止在安全用途中使用 MD5/SHA-1。
