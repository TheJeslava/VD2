F-1 055.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：055.php:17-19

攻击者通过 HTTP 请求向 055.php 提交留言内容（源码中对应变量 $message，来自 query 参数 mtxMessage，见 055.php:5）以及姓名变量 $name。这两个外部输入未经任何转义或参数化处理，在 055.php:18 被直接拼接进 INSERT 语句：$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";，随后在 055.php:19 由 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行。由于 $message 与 $name 被单引号包裹但未调用 mysqli_real_escape_string 或使用预处理语句，攻击者可闭合单引号注入任意 SQL 片段（例如在 mtxMessage 中提交 ' , (SELECT ...))-- - 之类的载荷），从而改变 INSERT 语义或追加子查询。校验无效的原因：代码路径中不存在任何白名单、类型校验、转义或参数化，污点从 055.php:5 直达 055.php:19 汇点。

影响：可对后端 MySQL 数据库执行任意 INSERT/子查询语句，导致留言表数据被伪造或污染、通过报错回显（die 中输出 mysqli_error）泄露数据库结构与版本信息；结合堆叠/子查询可进一步读取其他表数据（数据泄露），在数据库账号权限过高时可能造成数据篡改。属于未授权远程可利用的 SQL 注入。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：055.php 为 Web 入口，参数 mtxMessage 由 HTTP 请求直接提供，无需认证即可触发；利用链闭合：055.php:5 读取外部输入 → 055.php:18 字符串拼接构造 $query → 055.php:19 mysqli_query 执行，中间无净化函数，构成完整 source→sink 链。

修复建议：改用预处理语句与参数绑定：$stmt = $mysqli->prepare("INSERT INTO guestbook (comment, name) VALUES (?, ?)"); $stmt->bind_param('ss', $message, $name); $stmt->execute();。若必须拼接，至少对 $message/$name 使用 mysqli_real_escape_string 并配合严格字符白名单与长度限制；同时关闭生产环境的 mysqli_error 回显（die 中不应输出数据库错误详情），并遵循最小权限原则为应用数据库账号仅授予必要表的 INSERT 权限。
