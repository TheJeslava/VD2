F-1 015.php 密码修改处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：015.php:67-69

攻击者通过 POST 参数 password_new（015.php:8 读取，经 015.php:64 的 mysqli_real_escape_string 转义后赋给 $pass_new）进入密码更新语句。015.php:68 用字符串拼接构造 `UPDATE `users` SET password = '$pass_new' WHERE user = '...'`，015.php:69 直接交给 mysqli_query 执行。虽然 $pass_new 在 64 行做了 mysqli_real_escape_string，但该转义依赖连接字符集；若连接字符集为 GBK 等宽字节字符集，可用 %bf%27 之类的宽字节序列绕过转义闭合单引号，从而在 UPDATE 语句中注入任意 SQL（例如改写 WHERE 条件或追加子查询）。此外 69 行的 die() 会把 mysqli_error 原文回显到页面，为报错型注入提供回显通道。

影响：可越权修改任意用户的 password 字段（包括 admin），或通过报错/布尔差异枚举数据库内容，导致账户接管与数据泄露；结合 MySQL 权限可能进一步读写文件。

CVE/CWE 论证：CWE-89：外部可控输入（POST password_new）未经参数化即拼入 SQL 并在 015.php:69 执行，属典型 SQL 注入。外部可达：该逻辑位于密码修改表单处理分支，任何能访问该页面的用户均可提交；利用链闭合：source(015.php:8) → 转义(015.php:64，宽字节可绕过) → 拼接(015.php:68) → 执行(015.php:69)。是否需要认证取决于部署配置，证据不足，但页面本身为公开 DVWA 模块。

修复建议：改用预处理语句与参数绑定（mysqli_prepare + bind_param 或 PDO prepared statement），彻底移除字符串拼接；显式设置连接字符集为 utf8mb4（mysqli_set_charset）；关闭错误详情回显，改为记录日志并返回通用错误页；对 password_new 做长度与字符白名单校验。

F-6 015.php 使用 MD5 存储口令（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.46 · candidate / rule_verified+llm

位置：015.php:64-65

015.php:65 对新密码执行 `$pass_new = md5($pass_new)`，随后在 015.php:68 写入 users 表 password 字段。MD5 为快速、无盐的弱哈希，用于口令存储时易受彩虹表与 GPU 暴力破解；且此处未见每用户随机盐值。

影响：数据库泄露后攻击者可快速还原用户明文口令，并利用口令复用横向接管其他系统账户。

CVE/CWE 论证：CWE-328：使用 MD5 这一已破解的弱哈希保护口令。属配置/实现型弱点，无需 HTTP 污点链；原文证据为 015.php:65 的 md5( $pass_new ) 调用与 015.php:68 的 password 字段写入。外部可达性体现在密码修改接口对任意用户开放。

修复建议：改用 password_hash()（PASSWORD_ARGON2ID 或 PASSWORD_BCRYPT）生成带盐慢哈希，校验使用 password_verify()；对历史 MD5 记录在用户下次登录时透明升级；禁止在任何安全用途中使用 MD5/SHA-1。
