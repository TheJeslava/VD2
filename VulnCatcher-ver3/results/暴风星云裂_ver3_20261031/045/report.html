F-1 045.php 不安全文件上传：未校验扩展名/类型即 move_uploaded_file 落盘（CWE-434）

critical file_upload / CWE-434 · 置信度 0.78 · candidate / rule_verified+llm

位置：045.php:16-18

攻击者通过 HTTP 多部分表单上传文件，文件字段名为 `uploaded`（045.php:18 的 `$_FILES['uploaded']['tmp_name']`）。脚本把上传临时文件直接交给 `move_uploaded_file($_FILES['uploaded']['tmp_name'], $target_path)`（045.php:18）写入 `$target_path` 指向的上传目录。在给出的代码片段（045.php:16-18）中，落盘前没有任何扩展名白名单、MIME/魔数校验、文件重命名或大小限制，`$target_path` 的构造逻辑位于片段之外（证据不足，无法确认是否含用户可控文件名），因此校验环节缺失，污点从上传字段直达文件写入汇点。

影响：若上传目录位于 Web 可访问路径且允许 PHP 等可执行扩展名，攻击者可上传 webshell 并请求该文件，导致远程代码执行（RCE）；即使不可执行，也可造成任意文件写入/覆盖、存储型恶意内容托管（钓鱼、恶意脚本分发）与磁盘占用。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部可达性：上传接口为常规 HTTP POST 多部分请求，无需认证（片段中未见任何鉴权/会话检查）；利用链闭合：`$_FILES['uploaded']['tmp_name']` → `move_uploaded_file()` → 目标路径落盘，中间无净化。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：1) 使用扩展名白名单（如仅 jpg/png/gif/pdf）并基于服务端解析的真实 MIME/魔数校验，不信任客户端 Content-Type；2) 服务端生成随机文件名，禁止使用用户提供的文件名拼接 `$target_path`，并对路径做规范化后校验其仍位于上传根目录内（防路径穿越）；3) 上传目录置于 Web 根之外，或通过下载脚本以 `Content-Disposition: attachment` 与正确 Content-Type 输出；4) 上传目录禁用脚本执行（如 PHP 的 open_basedir/引擎关闭、Nginx location 拒绝 .php）；5) 限制文件大小并做病毒/内容扫描；6) 上传操作要求认证与 CSRF 令牌。

F-2 DVWA 文件上传端点仅校验客户端可控的 MIME 类型，可上传任意 PHP 脚本导致远程代码执行

high file_upload / CWE-434 · 置信度 0.88 · candidate / llm_inferred

位置：045.php:3-26

045.php 在收到 POST 参数 Upload 后，把上传文件保存到 DVWA_WEB_PAGE_TO_ROOT."hackable/uploads/" 目录，文件名取自 $_FILES['uploaded']['name'] 经 basename() 处理。唯一的“是不是图片”校验使用 $_FILES['uploaded']['type']（即 HTTP 请求中的 Content-Type，完全由客户端控制）与 $_FILES['uploaded']['size']（同样由客户端控制），既没有校验文件扩展名，也没有用 getimagesize()/finfo 检查真实文件内容。攻击者只要把 Content-Type 伪造成 image/jpeg 或 image/png，就能把任意内容的 .php 文件写入 Web 可访问的 uploads 目录，随后直接请求该文件即可执行任意 PHP 代码，形成 RCE。

影响：未认证攻击者可在服务器上写入并执行任意 PHP 代码，完全控制 Web 应用与主机（RCE）。

CVE/CWE 论证：CWE-434 无限制危险类型文件上传。入口 045.php:3 无认证，校验 045.php:14 仅依赖客户端可控的 MIME 类型，sink 045.php:18 直接落盘到 Web 目录，链路闭合且外部可达。

修复建议：使用 finfo_file()/getimagesize() 校验真实文件类型；对扩展名做白名单并重命名为随机名；把上传目录移出 Web 根或禁止脚本执行；增加认证与 CSRF 校验。
