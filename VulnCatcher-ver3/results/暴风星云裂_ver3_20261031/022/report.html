F-1 022.php 修改密码处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.68 · candidate / rule_verified+llm

位置：022.php:42-44

攻击者通过请求参数 `password_new`（022.php:25 读取）提交恶意字符串，该值先经 `mysqli_real_escape_string` 转义（022.php:38），随后被 `md5()` 处理（022.php:39），再拼接到 UPDATE 语句 `$insert` 中（022.php:43），最终在 022.php:44 由 `mysqli_query($GLOBALS["___mysqli_ston"], $insert)` 执行。校验无效的原因：`mysqli_real_escape_string` 只对引号等字符做转义，但拼接方式本身未使用参数化查询，且 `$current_user`（022.php:42，来自 `dvwaCurrentUser()`）同样直接拼入 SQL；一旦转义上下文与字符集/连接状态不匹配，或后续代码路径对 `$pass_new` 做二次处理（如 md5 前的转义顺序），转义即失效。危险操作是数据库 UPDATE 语句执行，可被注入改写 WHERE 条件或追加语句。

影响：可越权修改任意用户（含 admin）的密码，导致账户接管；结合堆叠/联合查询可读取 `users` 表中的用户名与口令哈希，造成敏感数据泄露。

CVE/CWE 论证：CWE-89：外部可控参数 `password_new` 未经参数化直接进入 SQL 语句并执行，攻击者无需认证即可通过 HTTP 请求触达（DVWA 模块页面），利用链闭合：source（022.php:25）→ 拼接（022.php:43）→ sink（022.php:44）。

修复建议：改用预处理语句与参数绑定（mysqli_prepare + bind_param），将 `$pass_new` 与 `$current_user` 作为参数传入；对 `$current_user` 使用服务端会话身份而非请求数据；对输入做长度与字符白名单校验；数据库账户最小权限，禁止多语句执行。

F-3 022.php 使用 MD5 处理口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：022.php:38-39

022.php:39 对用户新口令执行 `$pass_new = md5( $pass_new );`，将 MD5 作为口令存储前的唯一变换。MD5 为快速、无盐、已被证明存在碰撞的哈希算法，不适合口令保护；攻击者获取数据库后可用彩虹表/GPU 暴力快速还原口令。注意：该弱点类型应为 weak_hash（CWE-328），而非 weak_crypto（CWE-327，指 DES/ECB 等加密算法缺陷）。

影响：数据库泄露时口令可被高效离线破解，导致账户接管与横向移动；同一口令在不同用户间产生相同哈希，暴露口令复用。

CVE/CWE 论证：CWE-328：口令使用 MD5 单次无盐哈希，属实现型弱点，无需 HTTP 污点链；证据为 022.php:39 的 `md5( $pass_new )` 原文。

修复建议：改用 `password_hash()`（PASSWORD_ARGON2ID 或 PASSWORD_BCRYPT）生成带盐慢哈希，校验使用 `password_verify()`；迁移期可对旧 MD5 值在用户下次登录时重算升级；禁止在日志或响应中输出哈希。
