F-1 057.php 留言板 INSERT 语句 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：057.php:17-19

攻击者通过 HTTP 请求向 057.php 提交留言板表单，外部输入在 057.php:5 被读入变量 $message（候选标注的 source 为 query `mtxMessage`，即留言内容字段），随后在 057.php:18 被直接字符串拼接进 INSERT 语句：$query = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";，其中 $message 被单引号包裹但未做任何转义或参数化处理。该 $query 在 057.php:19 传入 mysqli_query($GLOBALS["___mysqli_ston"], $query) 执行，构成从外部输入到 SQL 执行汇点的完整污点链。由于拼接发生在引号内部，攻击者只需在留言内容中闭合单引号即可注入任意 SQL 片段；代码中未见 mysqli_real_escape_string、预处理语句或白名单校验，校验完全缺失。

影响：可对后端数据库执行任意 SQL：读取 guestbook 及其他表数据（数据泄露）、篡改或删除记录、在数据库权限允许时通过 UNION/子查询进一步窃取凭据；若数据库账户权限过高还可能写入文件。属于未认证远程可利用的严重注入。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：057.php 为 Web 入口，留言内容经 HTTP 请求参数直接进入；无需认证即可提交留言；利用链闭合：057.php:5 读取输入 → 057.php:18 字符串拼接进 $query → 057.php:19 mysqli_query 执行，中间无有效净化，满足远程未认证注入的 CVE 论证要素。

修复建议：改用参数化查询：使用 mysqli_prepare 配合 bind_param 将 comment、name 作为绑定参数传入，禁止字符串拼接；若必须拼接，至少对 $message/$name 使用 mysqli_real_escape_string 并校验长度与字符集；数据库账户遵循最小权限，禁用 FILE 权限；关闭 die(mysqli_error(...)) 的详细错误回显，避免报错注入与信息泄露。
