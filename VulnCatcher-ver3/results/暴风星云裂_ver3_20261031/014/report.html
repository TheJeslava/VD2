F-1 014.php 密码修改处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：014.php:59-61

攻击者通过 POST 参数 password_new（014.php:8 读取，014.php:50 处作为 query `password_new` 进入流程）提交恶意字符串；该值被直接拼接进 UPDATE 语句：014.php:60 `$insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . dvwaCurrentUser() . "';";`，随后在 014.php:61 交给 mysqli_query 执行。代码中未见 mysqli_real_escape_string、预处理语句或类型约束，单引号可闭合 password 字面量，从而改写 WHERE 条件或追加语句，因此校验无效。最终危险操作是 014.php:61 的 mysqli_query 执行拼接 SQL。

影响：可越权修改任意用户（含 admin）口令，进而登录后台；结合报错回显（014.php:61 的 die 输出 mysqli_error）可进行报错型注入读取数据库内容，造成账户接管与数据泄露。

CVE/CWE 论证：CWE-89。外部可达：014.php 为 Web 入口，参数来自 $_POST；无需认证即可到达该分支（DVWA 低安全级别下无 token/权限校验）；利用链闭合：password_new → $pass_new → $insert 字符串拼接 → mysqli_query。证据等级为源码推断，未做动态验证。

修复建议：改用预处理语句（mysqli_prepare + bind_param）绑定 password_new；若必须拼接，使用 mysqli_real_escape_string 并加引号包裹；对输入做长度与字符白名单校验；关闭详细数据库报错回显，改为通用错误页；数据库账户遵循最小权限，仅授予必要表的 UPDATE 权限。

F-2 DVWA 密码修改流程 CAPTCHA 状态机可绕过（step=2 直接提交跳过 recaptcha 校验）

high captcha_bypass / CWE-804 · 置信度 0.87 · candidate / llm_inferred

位置：014.php:45-61

014.php 的密码修改被拆成两步：step=1 时调用 recaptcha_check_answer() 校验第三方 CAPTCHA，通过后渲染一个隐藏表单（step=2）让用户确认。但服务端在 step=2 分支（第 45-73 行）完全没有再次校验 CAPTCHA，也没有任何一次性令牌/会话标记来证明 step=1 曾经通过。攻击者（或自动化脚本）可以直接 POST Change=Change&step=2&password_new=X&password_conf=X，跳过 recaptcha_check_answer() 直接进入第 54 行的密码一致性判断并执行第 60-61 行的 UPDATE 语句修改当前用户密码。CAPTCHA 作为防自动化/防 CSRF 的唯一屏障被完全绕过。

影响：攻击者无需通过 CAPTCHA 即可自动化修改账户密码；结合 CSRF 可诱导已登录用户静默改密，导致账户接管。CAPTCHA 防自动化保护完全失效。

CVE/CWE 论证：CWE-804（Guessable CAPTCHA）/ CWE-841（行为强制不一致）：服务端状态机缺少对前置校验结果的绑定，外部可直接访问 step=2 分支，无需认证绕过即可触发敏感写操作。

修复建议：在 step=1 通过 CAPTCHA 后于服务端会话中写入一次性令牌（如 $_SESSION['pwd_change_token']），step=2 必须校验该令牌并立即失效；或在 step=2 重新校验 CAPTCHA。

F-4 密码使用无盐 MD5 存储（014.php:57）

medium weak_hash / CWE-328 · 置信度 0.8 · candidate / llm_inferred

位置：014.php:56-61

第 57 行对用户新密码仅做 md5() 后写入数据库，未使用盐值或慢哈希（bcrypt/argon2）。MD5 属快速哈希，配合彩虹表/GPU 爆破可高效还原明文；若数据库泄露将直接导致账户口令暴露。

影响：数据库泄露时口令可被快速离线破解，导致账户接管。

CVE/CWE 论证：CWE-328（Use of Weak Hash）/ CWE-916：使用无盐 MD5 存储口令，属可申报的弱哈希实现缺陷。

修复建议：改用 password_hash()（PASSWORD_BCRYPT/ARGON2ID）并配合 password_verify()。

F-5 014.php 口令修改缺少 CSRF 防护（CWE-352）

medium csrf / CWE-352 · 置信度 0.66 · candidate / rule_verified+llm

位置：014.php:7-8

014.php:7-9 直接读取 $_POST['password_new'] 与 $_POST['password_conf'] 并进入口令修改流程，014.php:60-61 执行 UPDATE。代码片段中未见 CSRF token、Origin/Referer 校验或二次确认，状态改变请求仅依赖浏览器自动携带的会话凭据。攻击者可构造第三方页面自动提交表单，使已登录受害者在不知情下修改口令。

影响：受害者账户口令被改为攻击者已知值，导致账户接管；若受害者为管理员，可进一步控制整个应用。

CVE/CWE 论证：CWE-352。外部可达：攻击者只需诱导受害者访问恶意页面；利用链闭合：跨站表单 POST password_new/password_conf → 014.php:8-9 → 014.php:60-61 UPDATE。认证与 SameSite Cookie 条件需运行时复核，故置信度中等。

修复建议：为口令修改表单引入每会话随机 CSRF token 并在服务端校验；校验 Origin/Referer；会话 Cookie 设置 SameSite=Lax/Strict；修改口令等敏感操作要求重新输入当前口令。
