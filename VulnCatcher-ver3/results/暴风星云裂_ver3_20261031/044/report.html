F-1 044.php 不安全文件上传导致任意文件写入（CWE-434）

critical file_upload / CWE-434 · 置信度 0.73 · candidate / rule_verified+llm

位置：044.php:7-9

攻击者通过 HTTP 文件上传字段 `uploaded` 提交文件，PHP 将其临时文件路径放入 `$_FILES['uploaded']['tmp_name']`，随后在 044.php:9 直接调用 `move_uploaded_file($_FILES['uploaded']['tmp_name'], $target_path)` 把上传内容移动到 `$target_path`。代码片段（044.php:7-9）中，在调用 `move_uploaded_file` 之前没有任何扩展名白名单、MIME 类型校验、文件内容检查或文件名规范化处理；`$target_path` 的构造逻辑未在给定片段中体现，但汇点处对上传文件不做任何类型/后缀约束，因此校验缺失，上传内容被原样落盘。

影响：攻击者可上传 .php/.phtml 等可执行脚本到 Web 可访问目录，通过访问该文件触发服务端代码执行，进而获得 Web 进程权限下的远程代码执行（RCE）；也可用于覆盖/写入任意可写路径文件、投放 webshell、作为进一步横向移动的据点。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部可达性：上传入口为 HTTP multipart 请求的 `uploaded` 字段，无需认证即可访问 044.php；利用链闭合：`$_FILES['uploaded']['tmp_name']` → `move_uploaded_file(..., $target_path)` → 文件落盘至 Web 目录 → 请求该文件执行。缺少扩展名/类型校验是链闭合的关键缺口。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：1) 使用扩展名白名单（如仅 jpg/png/gif/pdf）并基于服务端解析的真实 MIME 与文件头（finfo）双重校验；2) 上传文件名由服务端随机生成，禁止使用客户端提供的文件名；3) 上传目录置于 Web 根之外，或配置该目录禁止脚本执行（如 Nginx `location ~ \.php$ { deny all; }`）；4) 限制文件大小与数量；5) 以最小权限账户运行 Web 进程，落盘目录不可执行。
