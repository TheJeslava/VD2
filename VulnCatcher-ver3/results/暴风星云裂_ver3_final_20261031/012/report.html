F-1 012.php 登录查询 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：012.php:13-15

攻击者通过 HTTP GET 参数 `username`（012.php:5 读取，`$_GET['username']`）提交输入，该值被直接拼接到 SQL 语句中：012.php:14 构造 `$query = "SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';";`，随后在 012.php:15 由 `mysqli_query($GLOBALS["___mysqli_ston"], $query)` 执行。代码中仅对 `$pass` 调用了 `mysqli_real_escape_string`（012.php:10），`$user` 未见任何转义、类型约束或参数化处理，因此单引号可闭合 `user = '...'` 字面量，注入任意 SQL 片段（例如 `' OR '1'='1' -- ` 绕过认证，或 UNION/布尔盲注读取 `users` 表）。错误信息经 `or die('<pre>'.mysqli_error(...).'</pre>')` 回显，进一步为报错注入提供通道。

影响：可绕过登录认证（以任意用户身份进入），并可读取/篡改数据库中的 `users` 表（用户名、口令哈希等），造成敏感数据泄露与越权；结合堆叠/UNION 能力可进一步扩大至数据库层面的数据操纵。

CVE/CWE 论证：CWE-89（SQL 注入）：外部可达（GET 参数 `username`，无需认证即可访问登录入口）、无需认证、利用链闭合（source 012.php:5 → 拼接 012.php:14 → 执行 012.php:15），且缺少参数化/转义，属典型注入。

修复建议：改用预处理语句与参数绑定（`mysqli_prepare` + `bind_param`，或 PDO 的 `prepare/execute`），彻底避免字符串拼接；对 `username` 做长度与字符白名单校验；关闭向客户端回显数据库错误（改为记录服务端日志并返回通用错误）；数据库账号遵循最小权限，仅授予必要的 SELECT 权限。

F-2 012.php 登录接口缺少暴力破解防护（CWE-307）

high brute_force / CWE-307 · 置信度 0.55 · candidate / rule_verified+llm

位置：012.php:2-3

012.php:3 以 `if( isset( $_GET[ 'Login' ] ) ) {` 进入登录处理流程，随后读取用户名/口令并执行查询。代码中未见失败次数计数、账号/IP 锁定、验证码、指数退避或速率限制等任何反暴力破解机制，攻击者可对同一账号无限次提交口令猜测。该弱点与同文件的 MD5 无盐哈希（012.php:11）叠加，进一步降低猜测与离线破解成本。

影响：攻击者可对已知用户名进行在线口令爆破或撞库，最终实现账号接管；缺少锁定/限速也使攻击难以被察觉，可长期持续。

CVE/CWE 论证：CWE-307（对过度认证尝试缺乏防护）：外部可达的登录入口（012.php:3，GET 参数 `Login` 触发），无需认证即可反复请求，利用链为「重复提交口令 → 无任何阻断 → 命中正确口令」。

修复建议：在登录流程中引入失败计数与账号/IP 维度锁定或指数退避；加入验证码或二次验证；记录并告警异常登录频率；结合强口令策略与多因素认证；对登录响应时间做恒定化处理以减少时序侧信道。

F-3 012.php 使用 MD5 处理口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：012.php:10-11

012.php:11 执行 `$pass = md5( $pass );`，将用户提交的口令（012.php:10 经 `mysqli_real_escape_string` 处理后）以无盐 MD5 单轮哈希形式参与后续登录查询。MD5 属已破译的快速哈希算法，无盐、无迭代、无工作因子，无法抵抗离线暴力破解与彩虹表攻击。注意：该弱点本质是弱哈希（CWE-328），而非弱加密算法（CWE-327）。

影响：一旦数据库（`users` 表）泄露，攻击者可用彩虹表或 GPU 高速碰撞在极短时间内还原用户明文口令；由于用户常跨站复用口令，可导致账号接管与横向渗透。

CVE/CWE 论证：CWE-328（弱哈希）：属实现型弱点，无需 HTTP 污点链即可成立；原文证据为 012.php:11 的 `md5( $pass )`，用于口令校验这一安全用途，外部可达（登录接口），无需认证。

修复建议：改用专为口令设计的慢哈希：PHP `password_hash($pass, PASSWORD_ARGON2ID)` 或 `PASSWORD_BCRYPT`（自带随机盐与工作因子），校验时用 `password_verify`；对存量 MD5 哈希在用户下次登录成功时透明升级；禁止在任何安全用途中使用 MD5/SHA-1。

F-4 012.php 登录成功页将用户可控 username 未转义回显（反射型 XSS）

medium xss / CWE-79 · 置信度 0.72 · candidate / llm_inferred

位置：012.php:5-23

脚本从 $_GET['username'] 取值，仅经 mysqli_real_escape_string 处理（该函数只针对 SQL 上下文转义，对 HTML 无任何作用），随后在登录成功分支直接拼接进 HTML 输出 `$html .= "<p>Welcome to the password protected area {$user}</p>"`，未调用 htmlspecialchars/htmlentities。攻击者可构造带脚本的 username，诱导受害者访问特制链接；若受害者已登录或攻击者能通过 SQL 注入/已知凭据使查询命中一行，脚本即被反射执行，可窃取会话或发起敏感操作。

影响：反射型 XSS，可在受害者浏览器上下文执行任意脚本，窃取 Cookie/会话、伪造操作。

CVE/CWE 论证：CWE-79：外部可控 GET 参数未经 HTML 编码进入响应，链闭合，无需认证即可投递。

修复建议：输出前对 $user 使用 htmlspecialchars($user, ENT_QUOTES, 'UTF-8')；avatar 同样需转义并校验 URL scheme。
