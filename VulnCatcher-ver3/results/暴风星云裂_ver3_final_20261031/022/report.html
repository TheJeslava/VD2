F-1 022.php 修改密码功能 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.55 · candidate / rule_verified+llm

位置：022.php:42-44

攻击者通过 HTTP 请求向 022.php 提交修改密码表单，其中 password_new 参数（022.php:25 读取）进入 $pass_new。代码在 022.php:38 仅用 mysqli_real_escape_string 对 $pass_new 做转义，随后在 022.php:39 执行 $pass_new = md5($pass_new)，把转义后的字符串整体哈希成 32 位十六进制串。哈希结果只含 [0-9a-f]，因此后续拼接进 SQL 时不再携带任何引号或元字符，单看 $pass_new 这一路，转义加哈希实际上阻断了注入。真正的注入点在 022.php:43 的拼接语句：$insert = "UPDATE `users` SET password = '" . $pass_new . "' WHERE user = '" . $current_user . "';"; 其中 $current_user 由 022.php:42 的 dvwaCurrentUser() 取得，直接以字符串拼接方式进入 SQL，未做参数化或转义，最终在 022.php:44 由 mysqli_query 执行。若 dvwaCurrentUser() 的返回值可被攻击者影响（例如来源于会话中可写字段、Cookie 或请求头映射的用户名），则可在 user 条件处闭合引号注入任意 SQL。需要说明：本次输入未提供 dvwaCurrentUser() 的实现，该函数的可控性证据不足，因此该链的闭合性属于推断而非已验证。

影响：若 $current_user 可控，攻击者可构造 user 条件注入，篡改 users 表中任意账号（含 admin）的 password 字段，实现账号接管与越权登录；也可借助 UPDATE 语句的布尔/时间盲注逐位读取数据库内容（如其他用户口令哈希、会话数据），造成敏感数据泄露。由于该语句本身是 UPDATE，注入还可扩展为堆叠或多条件更新，破坏数据完整性。

CVE/CWE 论证：CWE-89：SQL 语句由字符串拼接构造（022.php:43），外部可控数据（$current_user，经 dvwaCurrentUser()）未经参数化即进入 mysqli_query（022.php:44）。外部可达性：022.php 为 DVWA 的 Web 端点，修改密码表单无需额外权限即可提交，属远程可达；无需认证的前提取决于部署配置（DVWA 默认需登录，低安全级别下会话即可触达），因此“无需认证”应表述为“在已获得普通会话的前提下无需更高权限”。利用链闭合性：source（请求参数/会话用户标识）→ $current_user → 字符串拼接 → mysqli_query 的路径在源码中成立，但 dvwaCurrentUser() 的具体数据来源未在证据中给出，闭合性为 llm_inferred。

修复建议：1) 将 022.php:43-44 改为预处理语句：$stmt = $GLOBALS["___mysqli_ston"]->prepare("UPDATE `users` SET password = ? WHERE user = ?"); $stmt->bind_param('ss', $pass_new, $current_user); $stmt->execute(); 彻底消除拼接。2) 对 $current_user 做服务端白名单校验（仅允许已认证会话绑定的用户名），不要从请求可控字段推导当前用户。3) 保留 mysqli_real_escape_string 仅作为纵深防御，不作为主要防护。4) 数据库账号遵循最小权限，仅授予 users 表必要列的 UPDATE 权限。5) 修改密码操作增加 CSRF token 与旧密码校验。

F-2 022.php 使用 MD5 存储口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.8 · candidate / rule_verified+llm

位置：022.php:38-39

022.php:38 先用 mysqli_real_escape_string 处理 $pass_new，随后 022.php:39 执行 $pass_new = md5( $pass_new );，把用户新口令以无盐 MD5 单轮哈希形式写入数据库（022.php:43 的 UPDATE 语句将 password 列设为该哈希值）。MD5 属于已破译的快速哈希算法，存在已知碰撞攻击，且对高速 GPU 暴力破解与彩虹表几乎无抵抗力；此处未使用盐值、未使用慢哈希（bcrypt/scrypt/Argon2），保护对象是用户登录口令这一安全敏感数据。该弱点为配置/实现型，不依赖 HTTP 污点链，证据即 022.php:39 的 md5( 调用原文。

影响：数据库一旦泄露（如通过同文件 GEN-e38e01cf9ba5 的 SQL 注入读取 users 表），攻击者可用彩虹表或 GPU 集群在极短时间内还原大量用户明文口令，进而横向登录其他系统；相同口令产生相同哈希，也便于批量撞库与用户画像关联。

CVE/CWE 论证：CWE-328（Use of Weak Hash）：MD5 用于口令存储，属安全用途的弱哈希，而非 CWE-327 的加密算法误用。外部可达性：口令哈希在用户注册/改密时生成并持久化，攻击者通过数据库泄露或注入读取即可离线攻击，无需在线交互；无需认证即可对已获取的哈希进行离线破解。利用链闭合性：022.php:39 的 md5() 调用与 022.php:43 的写入路径在源码中直接可见，闭合性成立；实际破解难度取决于口令强度，属推断。

修复建议：1) 改用 password_hash($pass_new, PASSWORD_DEFAULT)（bcrypt/Argon2id）生成带盐慢哈希，校验用 password_verify。2) 迁移期可对存量 MD5 哈希在用户下次登录成功后透明重哈希升级。3) 强制口令复杂度与长度下限，禁止常见弱口令。4) 数据库连接与备份加密，限制 users 表读取权限，降低哈希外泄面。5) 结合 GEN-e38e01cf9ba5 的修复，阻断通过注入批量导出哈希的路径。
