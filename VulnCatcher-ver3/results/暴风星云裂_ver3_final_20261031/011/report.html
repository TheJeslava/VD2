F-1 011.php 登录接口 username 参数 SQL 注入（可绕过认证）

critical sql_injection / CWE-89 · 置信度 0.9 · candidate / llm_inferred

位置：011.php:5-13

脚本在 `isset($_GET['Login'])` 成立时，直接读取 `$_GET['username']` 与 `$_GET['password']`，仅对 password 做 md5，username 未做任何转义或参数化，直接以单引号拼接进 SELECT 语句，随后交给 mysqli_query 执行。攻击者可在 username 中注入 SQL 语法，构造恒真条件绕过密码校验，或使用 UNION 读取任意表数据。查询失败时 mysqli_error 被 die() 直接回显，构成报错型注入，便于快速提取数据。

影响：未授权攻击者可绕过登录进入受保护区域，并通过 UNION/报错注入读取 users 表及其它任意表数据（含口令哈希），进而横向渗透。

CVE/CWE 论证：CWE-89 SQL 注入。外部 GET 参数 username 未经转义直接拼接进 SQL 并执行，链路在 011.php:5→12→13 完整闭合，无需认证，属典型可申报 CVE 的注入漏洞。

修复建议：使用预处理语句（mysqli_prepare + bind_param）绑定 username 与 password；对输入做类型与长度校验；关闭 die(mysqli_error) 的详细错误回显，改为记录日志并返回通用错误。

F-3 011.php 使用 MD5 处理口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：011.php:8-9

011.php:8 从 `$_GET['password']` 取口令，011.php:9 直接调用 `md5($pass)` 生成摘要后用于与数据库中的口令值比较。MD5 为快速、无盐的通用哈希，抗碰撞与抗暴力能力均已失效，且此处未见盐值或迭代（如 bcrypt/Argon2/PBKDF2）。注意：该问题本质是弱哈希（CWE-328），而非弱加密算法（CWE-327）。

影响：一旦数据库泄露，攻击者可用彩虹表/GPU 高速离线爆破还原用户明文口令；相同口令产生相同摘要，便于横向撞库。影响范围为用户凭据机密性。

CVE/CWE 论证：CWE-328（可逆单向哈希函数使用不当）。该弱点为配置/实现型，无需 HTTP 污点链即可成立；证据为 011.php:9 的 `md5(` 调用原文。外部可达性体现在登录接口对任意提交口令执行该哈希。

修复建议：改用带盐的自适应口令哈希：PHP `password_hash($pass, PASSWORD_ARGON2ID)` 与 `password_verify()`；迁移存量 MD5 摘要时在用户下次登录成功后重算；禁止对安全用途使用 MD5/SHA-1。

F-4 011.php 登录成功页 username 反射型 XSS

medium xss / CWE-79 · 置信度 0.75 · candidate / llm_inferred

位置：011.php:21-22

登录成功后，脚本将用户可控的 $user 直接拼入 HTML 输出 `<p>Welcome to the password protected area {$user}</p>`，未做 htmlspecialchars 等编码。虽然该分支要求查询命中一行，但结合上一条 SQL 注入（username 注入恒真条件）即可让任意 username 内容进入成功分支，从而在响应中执行脚本；即便不依赖注入，若存在同名用户亦可直接触发。

影响：可在受害者浏览器上下文执行任意 JS，窃取会话或发起 CSRF 式操作；结合 SQL 注入可稳定触发。

CVE/CWE 论证：CWE-79 反射型 XSS。username 未编码输出到 HTML，链路 011.php:5→21 闭合；成功分支可通过同文件 SQL 注入保证命中，外部可达且无需认证。

修复建议：输出前对 $user 使用 htmlspecialchars($user, ENT_QUOTES, 'UTF-8')；对 avatar 属性值做 URL/属性编码或白名单校验。
