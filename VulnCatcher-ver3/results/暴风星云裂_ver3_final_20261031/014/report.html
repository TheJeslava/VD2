F-2 014.php 验证码流程可被 step 参数绕过（CWE-804）

high captcha_bypass / CWE-804 · 置信度 0.6 · candidate / rule_verified+llm

位置：014.php:2-3

攻击者通过 POST 提交 `Change` 与 `step` 参数（014.php:3 `isset($_POST['Change']) && $_POST['step']=='1'`）直接进入密码修改分支，跳过验证码校验环节。代码中验证码的展示/校验依赖客户端可控的 `step` 状态值，服务端未在会话中绑定验证码一次性令牌，也未校验验证码答案与当前会话的一致性，因此攻击者只需把 `step` 置为 `1` 即可绕过验证码。

影响：验证码防护失效，攻击者可对密码修改接口进行自动化/批量尝试，配合弱口令或撞库实现账户接管；验证码作为反自动化与防暴力破解的唯一屏障被移除。

CVE/CWE 论证：CWE-804（Guessable CAPTCHA）类弱点：验证码状态由客户端 `step` 参数决定，服务端未做会话绑定与一次性校验，外部无需认证即可通过构造 POST 请求绕过，利用链闭合（请求 → step 判断 → 进入密码修改逻辑）。

修复建议：将验证码答案与一次性 nonce 存入服务端会话，提交时校验会话中的答案并立即失效；不要用客户端可控的 `step` 决定是否校验验证码；对密码修改接口增加频率限制与失败锁定。

F-3 密码使用无盐 MD5 存储（014.php:57）

medium weak_hash / CWE-328 · 置信度 0.85 · candidate / llm_inferred

位置：014.php:57-60

第 57 行对用户新口令仅做 md5() 后写入 users.password，未使用盐值或 password_hash()/bcrypt/argon2。MD5 计算速度快、易被彩虹表与 GPU 暴力破解，一旦数据库泄露口令可被快速还原。

影响：数据库泄露后口令可被离线快速破解，导致账户接管。

CVE/CWE 论证：CWE-328（Use of Weak Hash）。代码直接可见，无需认证即可确认实现方式。

修复建议：改用 password_hash($pass, PASSWORD_DEFAULT) 与 password_verify()，并迁移历史 MD5 记录。

F-4 014.php 使用 MD5 存储口令（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.7 · candidate / rule_verified+llm

位置：014.php:56-57

014.php:57 `$pass_new = md5( $pass_new );` 对新口令仅做单次 MD5 摘要后写入数据库（前置 56 行仅做 mysqli_real_escape_string 转义）。MD5 为快速、无盐、可并行化的哈希，不适用于口令存储。

影响：数据库泄露后攻击者可用彩虹表/GPU 暴力快速还原用户明文口令；相同口令产生相同摘要，可横向撞库，导致账户接管。

CVE/CWE 论证：CWE-328（Use of Weak Hash）：MD5 用于口令等安全用途，算法本身抗碰撞与抗暴力能力不足，且未见加盐与迭代；属于实现型弱点，无需 HTTP 污点链即可成立。

修复建议：改用 password_hash()（bcrypt/Argon2id）并配合 password_verify()；为每个口令生成独立随机盐；迁移期可对旧 MD5 值在用户下次登录时透明升级。
