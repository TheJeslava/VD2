F-1 039.php 基于 query 参数 id 的 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.78 · candidate / rule_verified+llm

位置：039.php:13-15

攻击者通过 HTTP 请求的 query 参数 `id` 提供输入，该输入在 039.php:5 被读取后未做任何类型转换、转义或参数化，直接以字符串拼接方式进入 039.php:13 构造的 SQL 语句：`$query = "SELECT first_name, last_name FROM users WHERE user_id = $id;"`。由于 `$id` 被原样嵌入 SQL 文本，攻击者可闭合/改写 WHERE 条件（如 `1 OR 1=1`、`1 UNION SELECT ...`）。039.php:14-15 将该拼接后的 `$query` 交给 `mysqli_query($GLOBALS["___mysqli_ston"], $query)` 执行，代码中仅用 try/catch 抑制错误回显（注释“Removed 'or die' to suppress mysql errors”），并未做任何输入校验或参数绑定，因此校验完全无效，污点直达 SQL 执行汇点。

影响：数据库查询逻辑可被任意篡改：可绕过 user_id 条件读取 users 表全部记录（first_name、last_name），并通过 UNION 注入进一步读取其他表/库中的敏感数据（如凭据、个人信息），造成数据泄露；在数据库账户权限过高时还可能读写文件或影响数据完整性。属于未授权即可远程触发的数据泄露风险。

CVE/CWE 论证：CWE-89（SQL 注入）。外部可达性：注入点为 HTTP query 参数 `id`，无需认证即可访问 039.php 触发；利用链闭合：039.php:5 读取 `id` → 039.php:13 字符串拼接进 `$query` → 039.php:15 `mysqli_query` 执行，链路上不存在转义、白名单或参数化，攻击者输入直接决定 SQL 语义。证据等级为源码推断（llm_inferred），未做动态验证。

修复建议：改用预处理语句与参数绑定：`$stmt = mysqli_prepare($link, "SELECT first_name, last_name FROM users WHERE user_id = ?"); mysqli_stmt_bind_param($stmt, 'i', $id); mysqli_stmt_execute($stmt);`，并对 `id` 做整数类型强校验（如 `filter_var($id, FILTER_VALIDATE_INT)`，失败即拒绝）。禁止将外部输入拼接进 SQL 文本；数据库账户遵循最小权限，关闭详细错误回显。
