# 暴风星云裂代码预处理与清洗规则

## 1. 范围与目标

本数据集包含 001–057 共 57 个 DVWA 单文件样本，以及 058.zip 中 8 个 SQLi-Labs Less-24 PHP 文件（共 65 个 PHP 源文件）；原始 ZIP、PHP 文件和 `编号对应表.md` 均作为基准保留。预处理产物写入同级目录 `暴风星云裂_预处理`，供后续静态审计/模型输入使用。清洗目标是降低无关文本噪声、统一文本格式，同时保持源到汇点、鉴权、过滤、分支、数据库/文件/命令调用和跨文件关系不变。

## 2. 逐条清洗规则

| 编号 | 对象与判定标准 | 处理方式 | 作用及边界 |
|---|---|---|---|
| C01 | 空白格式：仅含空格/制表符的行、行尾空格、CRLF/LF 混杂 | 空白行删除；行尾空白删除；统一 UTF-8、LF | 减少无信息字符、稳定 diff 与哈希；不改写非空代码行。 |
| C02 | 连续空行：代码行之间连续两个及以上空行 | 与 C01 一并删除空白行；文件首尾空行同样删除 | 统一输入形态，去除版式噪声；当前样本不依赖空行表达语义。 |
| C03 | 无效注释：纯装饰分隔线、空注释、重复解释代码字面含义的注释、已失效/与当前代码不符的注释 | 逐条审核后删除；注释内容记录到清洗日志/审计记录 | 降低模型把注释当证据的风险。不能仅因注释“看起来普通”就自动删除。 |
| C04 | 需保留注释：解释安全边界/漏洞意图、已知绕过、危险调用、输入来源、信任假设、TODO/FIXME、安全测试提示、HTML/JS 运行行为的注释 | 保留；如含与代码矛盾的安全说法，标记为“待核实注释”，不作为事实 | 保住漏洞语境，避免丢失攻击路径线索或把注入提示清掉。 |
| C05 | 冗余符号/空语句：确定不改变语义的重复分隔符、纯格式分隔符、注释掉的调试输出 | 仅在语法/上下文可证明无影响时删除；空语句需确认不承担循环体、标签或兼容用途 | 降低词法噪声；禁止全局替换 `;`、括号、引号、点号、运算符或 PHP 标签。 |
| C06 | 调试残留：仅用于调试的 `var_dump`、`print_r`、临时 `console.log`、调试输出 | 仅在确认不可达或与样本行为无关后移除；若会形成信息泄露则保留并标记为安全行为 | 清理开发噪声，同时避免误删真实漏洞汇点/输出行为。 |
| C07 | 无关业务代码：与当前样本入口、数据流、权限/状态、漏洞触发条件、可观察响应及跨文件调用均无依赖的业务逻辑 | 通过引用/调用关系审查后，才能从“分析副本”剔除；把被删文件/代码范围、依据、依赖检查写入清洗清单 | 缩小审计上下文。不得按业务名称或代码长度判断无关。 |
| C08 | 必须保留的上下文代码：初始化、会话/认证、CSRF、输入读取与校验、编码/过滤、数据库和文件操作、响应拼接、错误处理、条件/循环、函数定义/调用及配置常量 | 一律保留，即使该段自身不含漏洞；058 的 8 个文件作为一个整体处理 | 防止截断 source→sink、认证绕过、二次注入或跨文件调用链。 |
| C09 | 数据集元数据与包结构：样本编号、文件名、ZIP 内路径、编号对应表与 SHA-256 | 原样保留；不合并、不重命名、不丢弃样本 | 保证样本可追溯、标签对应关系可复核。 |
| C10 | 静态安全样本中的“看似多余”过滤/校验/安全代码 | 不删除、不修复、不重构；保留各安全等级之间的差异 | 清洗只去噪，不改变漏洞真值、严重性或对照条件。 |
| C11 | 高风险/含混候选（注释与 PHP/HTML/JS 混合、可疑空语句、依赖不明代码） | 保留原文，进入人工复核清单，不自动修改 | 将误删风险控制在可审计范围内。 |
| C12 | ZIP 与源文件一致性 | 每个源 PHP 对应复制到输出目录；每个 ZIP 只包含其原有 PHP 成员及原有成员名；逐文件检查计数和解压内容 | 保持批量扫描输入契约，同时与原始数据隔离。 |

## 3. 本次自动执行口径

自动化只执行 C01、C02、C09、C12 中可机械证明安全的部分：删除空白行、去除行尾空格、统一 UTF-8/LF，并在独立输出目录重建 PHP 文件与 ZIP。C03–C08、C10–C11 属于语义判断规则，不能靠正则表达式批量删除；本次不擅自改写漏洞样本。这样做是为了满足可重复预处理，同时不改变漏洞标签和 source→sink 证据。

每次运行生成 `预处理清单.json`，记录文件数、每个文件的源/目标 SHA-256、输入/输出行数及格式处理统计。若后续人工执行注释或业务代码清理，应另增逐文件删除记录与差异审查；不得覆盖原始目录或原 ZIP。

## 4. 验收标准

1. 输入 65 个 PHP 源文件，输出仍为 65 个 PHP 文件；ZIP 数量、名称、成员名及成员数量与原始数据一致。
2. 预处理后不得包含空白行、行尾空格或 CRLF；非空代码行除 UTF-8/LF 格式化外逐行保持一致。
3. 原始文件与原始 ZIP 的 SHA-256 不发生变化；清单中的目标哈希可重复计算。
4. PHP CLI 不在当前环境中，故无法运行 `php -l`；验收采用逐行内容对比和 ZIP 成员/内容一致性检查。语义清理候选须在有 PHP 解析器和人工复核后另行进行。
