F-1 023.php 口令修改处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：023.php:15-17

攻击者通过 GET 参数 password_new（023.php:5 `$pass_new = $_GET['password_new'];`）提交输入，与 password_conf 一起进入口令修改流程。023.php:11 仅用 mysqli_real_escape_string 处理 $pass_new，随后 023.php:12 对其做 md5()，因此进入 SQL 的值是 32 位十六进制串，单引号等元字符已被 md5 归一化，无法从 password_new 直接闭合 023.php:16 中 `password = '$pass_new'` 的引号。真正未经过滤拼接的是 023.php:16 的 `$current_user`（来自 dvwaCurrentUser()，023.php:15），它被直接拼进 `WHERE user = '...'`，最终在 023.php:17 由 mysqli_query 执行。因此候选标注的 source（password_new）与 sink 之间的污点链在源码层面并不闭合：password_new 经 md5 后不具备注入能力；可利用点取决于 dvwaCurrentUser() 的返回值是否可被外部影响（该函数定义不在本次 code_pack 中，证据不足）。

影响：若 $current_user 可被攻击者影响，则可篡改 UPDATE 语句的 WHERE 条件，批量改写 users 表中任意用户口令，导致账户接管；若仅 password_new 可控，则实际影响为口令被 md5 后写入，不构成 SQL 注入。当前证据下无法确认可利用性。

CVE/CWE 论证：CWE-89：SQL 命令中特殊元素未正确中和。外部可达性成立（GET 参数、无需认证即可到达 023.php 的修改逻辑，认证条件取决于 DVWA 会话配置）；但利用链未闭合——password_new 经 md5() 后无法注入，唯一未净化拼接点为 $current_user，其可控性证据不足，故不满足 CVE 级论证。

修复建议：对 023.php:16 的 UPDATE 使用预处理语句并绑定参数（mysqli_prepare + bind_param），不要字符串拼接 $current_user；对 $current_user 做白名单校验（仅允许已登录会话中的用户名，且与 session 中的身份比对）；口令哈希改用 password_hash()/password_verify()（PASSWORD_DEFAULT），不要用 md5；同时移除 023.php:17 中把 mysqli_error 直接回显到页面的 die() 分支，避免报错信息泄露。

F-4 023.php 使用 MD5 存储口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.8 · candidate / rule_verified+llm

位置：023.php:11-12

023.php:12 `$pass_new = md5( $pass_new );` 对口令使用 MD5 做无盐单轮哈希，随后在 023.php:16-17 写入 users 表 password 字段。MD5 计算极快且无盐，攻击者一旦获取数据库（如通过备份泄露、SQL 注入或数据库直连），可用 GPU/彩虹表在极短时间内还原常见口令；相同口令产生相同哈希，也便于横向比对。注意：该问题本质是弱哈希（CWE-328），不是弱加密算法（CWE-327）。

影响：数据库泄露后口令可被快速离线爆破还原，导致用户账户接管；相同口令哈希一致，泄露用户间口令复用关系。属于配置/实现型弱点，无需 HTTP 污点链即可成立。

CVE/CWE 论证：CWE-328（Use of Weak Hash）：MD5 用于口令这一安全用途，算法本身不具备口令哈希所需的慢速与加盐特性。外部可达性：任何能触发口令修改的请求都会写入 MD5 值；无需特殊权限即可观察到该实现（源码级）。利用链为「数据库读取 → 离线爆破 → 账户接管」，闭合性依赖数据库泄露前提。

修复建议：改用 password_hash($pass_new, PASSWORD_DEFAULT)（bcrypt/Argon2id）生成带盐慢哈希，校验用 password_verify()；迁移期可对存量 MD5 值在用户下次登录成功后透明重哈希；禁止在任何新代码中使用 md5()/sha1() 处理口令或令牌。

F-6 023.php 口令修改接口缺少 CSRF 防护（CWE-352）

medium csrf / CWE-352 · 置信度 0.7 · candidate / rule_verified+llm

位置：023.php:4-5

023.php:4-6 通过 GET 读取 password_new / password_conf 并直接进入口令修改流程，023.php:16-17 执行 UPDATE users SET password。整个流程未见 CSRF token 校验、Origin/Referer 校验，也未要求重新输入原口令。攻击者可构造 `<img src="http://TARGET/023.php?password_new=attacker&password_conf=attacker">` 诱导已登录受害者访问，从而在受害者会话下把其口令改为攻击者已知值。使用 GET 触发状态变更进一步放大了风险（可被图片标签、预取、日志回放触发）。

影响：已登录用户的账户口令被静默篡改，攻击者随后用新口令登录，实现账户接管；若受害者是高权限账户，则导致权限提升。

CVE/CWE 论证：CWE-352：状态改变请求缺少不可预测令牌与来源校验。外部可达性成立（任意第三方页面可发起跨站 GET）；无需认证即可投递请求，但需受害者处于已登录会话中，利用链为「诱导访问 → 会话携带 Cookie → 口令被改」，闭合。
