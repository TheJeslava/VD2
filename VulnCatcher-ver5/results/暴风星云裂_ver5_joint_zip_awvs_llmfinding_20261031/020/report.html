F-1 020.php 中 $_POST['include'] 直接拼入 <script src> 导致脚本来源可控（CWE-79/CWE-22 交叉）

high path_traversal / CWE-22 · 置信度 0.45 · candidate / rule_verified+llm

位置：020.php:13-15

020.php:15 将 $_POST['include'] 原样拼接进 `<script src='" . $_POST['include'] . "'></script>`。攻击者可通过 POST 参数 include 指定任意外部脚本地址（如 https://attacker.example/x.js），或利用单引号闭合属性注入额外 HTML/JS。该处无 htmlspecialchars()、无 URL 白名单、无协议限制，校验完全缺失。严格来说这是输出编码/资源引用校验缺失问题，规则将其归为 path_traversal 属于推断；从代码事实看更接近可控脚本加载（可导致 XSS）。

影响：攻击者可诱导受害者加载攻击者控制的 JavaScript，在目标站点源下执行任意脚本，窃取会话 Cookie、发起 CSRF、读取页面敏感数据；若配合宽松 CSP（见 SEM-582e93de1b73），外部脚本域被显式放行，利用更容易。

CVE/CWE 论证：CWE-79（跨站脚本）/CWE-22（外部资源路径可控）。外部可达性：POST 参数 include 无需认证即可控制输出。利用链闭合：source（$_POST['include']）→ 无编码/白名单 → 直接进入 HTML 属性，链路在给定片段内闭合。

修复建议：对输出到 HTML 属性的值使用 htmlspecialchars($v, ENT_QUOTES, 'UTF-8')；对脚本来源使用固定白名单并校验 scheme 与 host；优先改为服务端映射的固定脚本名，禁止用户直接提供 URL；同时收紧 CSP 的 script-src 列表。

F-3 020.php POST 参数 include 未编码直接拼入 <script src> 导致反射型 XSS（CSP 可被绕过）

medium xss / CWE-79 · 置信度 0.85 · candidate / llm_inferred

位置：020.php:13-17

020.php 第 13-17 行读取 $_POST['include']，未做任何 HTML 实体编码或 URL 白名单校验，直接以单引号包裹拼接到 <script src='...'></script> 中并输出到响应体。攻击者可闭合单引号并注入任意 HTML/JS，例如 include='></script><script>alert(document.domain)</script> 或 include=x' onerror='alert(1)。虽然第 3-5 行设置了 CSP script-src 白名单，但该 CSP 允许 unpkg.com、cdn.jsdelivr.net、pastebin.com、hastebin.com 等可托管任意 JS 的域名（注释第 7-9 行亦明示），且注入点本身位于 script-src 允许的 inline 属性/标签上下文，攻击者可借助白名单 CDN 加载任意脚本，CSP 不构成有效防护。

影响：反射型 XSS，可在受害者浏览器上下文执行任意 JS，窃取会话/凭证、发起 CSRF 操作、钓鱼；CSP 因白名单含可托管任意内容的 CDN 而无法有效阻断。

CVE/CWE 论证：CWE-79 跨站脚本。外部匿名可达，无需认证，source→sink 链在 020.php:13-17 完整闭合，POC 可直接构造。

修复建议：对 $_POST['include'] 使用 htmlspecialchars($v, ENT_QUOTES, 'UTF-8') 输出编码；对 src 做 URL 解析并严格白名单校验协议与主机；收紧 CSP，移除 unpkg.com/cdn.jsdelivr.net/pastebin.com/hastebin.com 等可托管任意脚本的域名，改用 nonce/hash。

F-4 020.php CSP script-src 白名单过宽（CWE-693 防护机制失效）

medium csp / CWE-693 · 置信度 0.7 · candidate / rule_verified+llm

位置：020.php:2-3

020.php:3 定义 `$headerCSP = "Content-Security-Policy: script-src 'self' https://pastebin.com hastebin.com www.toptal.com example.com code.jquery.com https://ssl.google-analytics.com unpkg.com cdn.jsdelivr.net digi.ninja ;"`。该策略显式允许 pastebin.com、hastebin.com、unpkg.com、cdn.jsdelivr.net 等可公开托管任意内容的第三方域，且部分条目缺少 scheme（hastebin.com、www.toptal.com、example.com、code.jquery.com、unpkg.com、cdn.jsdelivr.net、digi.ninja），浏览器会按同 scheme 匹配。攻击者可在这些域上托管恶意 JS，从而绕过 CSP 的脚本限制。

影响：CSP 作为 XSS 缓解手段基本失效：结合 020.php:15 的可控 <script src>，攻击者只需把脚本放在被放行的第三方域即可执行任意 JS，导致会话劫持、数据窃取、页面篡改。

CVE/CWE 论证：CWE-693（防护机制失效）。外部可达性：CSP 随每个响应下发，任何访问者均受影响。利用链闭合：宽松 script-src（020.php:3）+ 可控脚本来源（020.php:15）构成完整绕过路径；无需认证。

修复建议：将 script-src 收敛为 'self' 加必要的固定、受控域；移除 pastebin/hastebin/unpkg/jsdelivr 等可托管任意内容的公共域；为所有条目显式指定 https: scheme；考虑引入 nonce 或 hash 机制替代宽泛域名白名单；部署 CSP 报告端点监控违规。
