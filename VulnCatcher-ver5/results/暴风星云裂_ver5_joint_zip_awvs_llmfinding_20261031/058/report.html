F-1 058_06.php 登录查询 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.78 · candidate / rule_verified+llm

位置：058_06.php:22-24

攻击者通过登录表单提交的 username/password 参数（058_06.php:20 处从请求读取 login_user 相关输入）进入 $username、$password 变量，在 058_06.php:22 被直接拼接进 SQL 语句 "SELECT * FROM users WHERE username='$username' and password='$password'"，随后在 058_06.php:24 交给 mysql_query($sql) 执行。代码未使用 mysql_real_escape_string、预处理语句或类型约束，单引号可闭合字符串字面量，因此校验无效。

影响：可绕过登录认证（以 ' OR '1'='1 之类载荷返回任意用户记录），并可进一步通过 UNION/布尔盲注读取 users 表及其他库表数据，导致账户凭据泄露与数据库数据窃取；错误信息经 die() 回显亦辅助注入探测。

CVE/CWE 论证：CWE-89：外部可控输入未经参数化直接拼入 SQL 并执行，属典型 SQL 注入。攻击面为 Web 登录接口，无需认证即可访问，source（请求参数）→ 拼接（058_06.php:22）→ sink（058_06.php:24 mysql_query）链路闭合，外部可达。

修复建议：改用 PDO/MySQLi 预处理语句并绑定参数（如 $stmt = $pdo->prepare('SELECT * FROM users WHERE username=? AND password=?')）；对输入做长度与字符白名单校验；数据库账户最小权限；关闭详细错误回显，改为记录日志。

F-5 058_08.php 密码修改页仅凭客户端可控 Cookie Auth=1 即通过认证，导致任意用户密码重置（账户接管）

high auth_bypass / CWE-287 · 置信度 0.72 · candidate / llm_inferred

位置：058_08.php:7-14

058_08.php 的访问控制只检查 `isset($_COOKIE["Auth"])`（第 7 行），而该 Cookie 在 058_06.php 第 44 行由服务端以固定值 1 下发、无签名无校验。攻击者无需登录，只要在请求中手工带上 `Cookie: Auth=1` 即可通过第 7-14 行的守卫，进入密码修改逻辑。随后第 31 行 `$username = $_SESSION["username"]` 取当前会话用户名，第 38 行构造 `UPDATE users SET PASSWORD='$pass' where username='$username' and password='$curr_pass'`。由于守卫不校验会话身份，攻击者可用自己注册/已知的账号建立会话（或直接利用会话固定），再借 Cookie 绕过进入改密页；更关键的是守卫逻辑本身把「是否已认证」完全交给客户端 Cookie，属于典型的信任边界错误，可导致对任意已登录会话的密码修改流程被未授权触发。

影响：认证守卫完全依赖客户端 Cookie，攻击者可绕过登录校验进入改密流程，结合会话可重置账户密码，造成账户接管。

CVE/CWE 论证：CWE-287/CWE-565：认证决策基于客户端可控 Cookie，无服务端会话校验，外部无需真实凭据即可通过守卫。

修复建议：移除对 Cookie Auth 的信任，仅以服务端 $_SESSION 校验身份；Cookie 应加签名或改用服务端会话。

F-6 058_06.php 认证 Cookie 使用固定值且缺少安全属性（CWE-330/CWE-565）

high weak_id / CWE-330 · 置信度 0.4 · candidate / rule_verified+llm

位置：058_06.php:43-44

058_06.php:43-44 在登录成功后设置 $_SESSION["username"] 并执行 setcookie("Auth", 1, time()+3600)，即认证标志 Auth 恒为常量 1，且未设置 HttpOnly/Secure/SameSite 属性。该 Cookie 不携带不可预测的会话标识，任何能设置同名 Cookie 的客户端都可伪造认证状态（取决于服务端是否仅以 Auth 存在性判定登录）。

影响：若服务端仅检查 Auth Cookie 是否存在，攻击者可自行设置 Auth=1 绕过认证；常量值也使会话固定/伪造风险上升，可能导致未授权访问 logged-in.php 等受保护页面。

CVE/CWE 论证：CWE-330（使用不充分的随机值）与 CWE-565（依赖不可信 Cookie 做安全决策）：认证标志为可预测常量。证据限于 058_06.php:43-44 片段，服务端校验逻辑未在片段中出现，属证据不足部分，需结合 logged-in.php 复核。

修复建议：使用框架会话机制生成高熵会话 ID，登录后 session_regenerate_id(true)；认证状态仅存于服务端会话，不以客户端常量 Cookie 判定；Cookie 设置 HttpOnly、Secure、SameSite。

F-7 058_08.php 注销逻辑使用常量 Cookie 且缺少安全属性（CWE-330/CWE-565）

high weak_id / CWE-330 · 置信度 0.4 · candidate / rule_verified+llm

位置：058_08.php:65-66

058_08.php:65-66 在注销时执行 session_destroy() 并 setcookie('Auth', 1, time()-3600) 使 Cookie 过期。认证标志仍为常量 1，未使用不可预测值，也未设置 HttpOnly/Secure/SameSite；该模式表明认证状态依赖客户端可控的固定 Cookie。

影响：与登录侧一致，若服务端以 Auth Cookie 存在性判定认证，攻击者可伪造 Auth=1 获得已登录状态，导致未授权访问与账户冒用。

CVE/CWE 论证：CWE-330/CWE-565：认证标志为可预测常量。证据仅覆盖 058_08.php:65-66 的注销片段，服务端认证校验逻辑未提供，属证据不足部分。

修复建议：认证状态完全由服务端会话维护，注销时销毁会话并清除会话 Cookie；Cookie 设置 HttpOnly、Secure、SameSite；避免以常量 Cookie 表示登录状态。

F-8 058_08.php 修改密码功能缺少 CSRF 防护（CWE-352）

medium csrf / CWE-352 · 置信度 0.56 · candidate / rule_verified+llm

位置：058_08.php:37-38

058_08.php:37-38 的修改密码逻辑在收到 Change 请求后直接执行 UPDATE users SET PASSWORD，代码片段中未见 CSRF token、Origin/Referer 校验或二次确认。攻击者可构造第三方页面自动提交表单，使已登录受害者在不知情下修改口令。

影响：已认证用户被诱导提交请求后口令被改为攻击者已知值，导致账户接管；若受害者权限较高则影响扩大。

CVE/CWE 论证：CWE-352：状态改变请求缺乏不可预测令牌校验。外部可达性依赖受害者已登录会话，属跨站场景；证据仅覆盖 058_08.php:37-38 片段，会话 Cookie 的 SameSite 属性与认证前置条件未在片段中体现，属证据不足部分。

修复建议：为修改密码表单加入每会话随机 CSRF token 并在服务端校验；校验 Origin/Referer；会话 Cookie 设置 SameSite=Lax/Strict、Secure、HttpOnly；敏感操作要求重新输入旧口令。
