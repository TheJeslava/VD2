F-1 013.php 修改密码功能 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：013.php:29-31

攻击者通过修改密码表单提交新口令，输入在 013.php:8 处由 query `password_new` 读取并赋给 $pass_new；013.php:26 仅用 mysqli_real_escape_string 做转义，随后 013.php:27 对 $pass_new 做 md5() 处理，013.php:30 将结果直接拼接进 UPDATE 语句：$insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . dvwaCurrentUser() . "' LIMIT 1;"，最终在 013.php:31 由 mysqli_query 执行。由于 md5() 会把输入规整为 32 位十六进制串，单看 $pass_new 位置难以注入；但同一语句中 dvwaCurrentUser() 的返回值未经参数化直接拼入 WHERE 子句，若该函数返回可被外部影响的值（如会话中的用户名），则构成注入通道。当前 code_pack 未提供 dvwaCurrentUser() 的实现，无法确认其返回值是否可控，因此该注入点的可利用性证据不足。

影响：若 dvwaCurrentUser() 返回值可控，攻击者可构造 WHERE 子句注入，绕过 LIMIT 1 限制批量改写 users 表 password 字段，导致任意账户口令被重置（账户接管）；同时 013.php:31 的 die(mysqli_error(...)) 会把数据库错误信息回显到页面，造成数据库结构/版本等信息泄露。若仅 $pass_new 位置，因 md5 规整化实际不可注入。

CVE/CWE 论证：CWE-89：外部输入经字符串拼接进入 SQL 语句且未使用预处理语句。外部可达性：该逻辑位于 isset($_POST['Change']) 分支（013.php:3），为 Web 表单直接可达的修改密码接口，无需额外权限即可提交。利用链闭合性：source（表单参数）→ $pass_new / dvwaCurrentUser() → $insert 拼接 → mysqli_query 执行，链路在文件内闭合；但关键一环 dvwaCurrentUser() 的实现未在 code_pack 中给出，故按 llm_inferred 记录，未达外部验证级别。

修复建议：改用参数化查询：$stmt = $db->prepare('UPDATE users SET password = ? WHERE user = ? LIMIT 1'); $stmt->bind_param('ss', $pass_new, dvwaCurrentUser()); $stmt->execute(); 禁止将任何变量（包括 dvwaCurrentUser() 返回值）拼接进 SQL；对用户名做白名单/长度校验；移除 die(mysqli_error(...)) 的详细错误回显，改为记录日志并返回通用错误；口令哈希改用 password_hash()/password_verify()（bcrypt/Argon2）替代 md5。

F-2 DVWA 密码修改功能 CAPTCHA 校验可被伪造请求头绕过（013.php）

high captcha_bypass / CWE-804 · 置信度 0.9 · candidate / llm_inferred

位置：013.php:17-23

013.php 在处理密码修改时，先调用 recaptcha_check_answer() 校验第三方 CAPTCHA，但随后在 if 条件中使用逻辑或 `$resp || (...)`，其中第二个分支仅要求 POST 参数 g-recaptcha-response 等于硬编码字符串 'hidd3n_valu3' 且 HTTP_USER_AGENT 等于 'reCAPTCHA'。攻击者无需真正通过 CAPTCHA，只要在请求中伪造这两个值即可让条件恒真，进入密码修改逻辑，从而在无有效 CAPTCHA 的情况下修改当前用户密码。该硬编码后门值（第20-21行）是根因，属于认证/校验机制绕过。

影响：攻击者可在无有效 CAPTCHA 的情况下修改账户密码，绕过反自动化保护，配合 CSRF 可进一步扩大影响。

CVE/CWE 论证：CWE-804/CWE-287：硬编码后门校验值使 CAPTCHA 校验可被任意请求伪造绕过，外部可直接触发，链闭合。

修复建议：移除硬编码后门分支，仅依赖 recaptcha_check_answer 的真实返回值；不要信任客户端可伪造的 User-Agent 作为校验依据。

F-4 013.php 使用 MD5 存储口令哈希（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.86 · candidate / rule_verified+llm

位置：013.php:26-27

013.php:27 执行 $pass_new = md5( $pass_new );，将用户新口令以无盐 MD5 形式计算后，于 013.php:30 拼入 UPDATE 语句写入 users 表 password 字段。MD5 为快速、无盐、已被证明存在碰撞的哈希算法，用于口令存储属弱哈希实现。原文证据：013.php:27 `$pass_new = md5( $pass_new );`，写入点 013.php:30 `UPDATE `users` SET password = '$pass_new' ...`。

影响：数据库泄露后，攻击者可用彩虹表/GPU 暴力快速还原用户明文口令（MD5 计算极快且无盐，相同口令哈希相同），导致账户接管；相同口令用户哈希一致还会暴露口令复用关系。属于配置/实现型弱点，不依赖 HTTP 污点链。

CVE/CWE 论证：CWE-328（Use of Weak Hash）：MD5 用于口令等安全用途。外部可达性：修改密码接口（013.php:3 的 isset($_POST['Change']) 分支）直接可达，任意用户提交新口令即触发。无需认证前提之外的额外条件，利用链为“弱哈希写入存储 → 库泄露后离线破解”，闭合。

修复建议：使用 PHP 内置 password_hash($pass_new, PASSWORD_DEFAULT)（bcrypt/Argon2id）生成带盐慢哈希，校验用 password_verify()；迁移期可对存量 MD5 在用户下次登录时透明重哈希；禁止在口令路径使用 md5/sha1。
