F-1 041.php 查询参数 id 直接拼接进 SQL 语句导致 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：041.php:9-11

攻击者通过 HTTP 请求的 query 参数 `id` 提供输入（041.php:5 读取该参数），该值未经任何过滤、转义或类型校验，被直接拼接进 SQL 字符串：041.php:10 构造 `$query = "SELECT first_name, last_name FROM users WHERE user_id = '$id';"`，随后在 041.php:11 通过 `mysqli_query($GLOBALS["___mysqli_ston"], $query)` 执行。由于 `$id` 位于单引号字符串字面量内部且未调用 mysqli_real_escape_string 等转义函数、也未使用预处理语句/参数绑定，攻击者可闭合单引号并注入任意 SQL 片段（如 `1' OR '1'='1`、`1' UNION SELECT ...`），校验完全失效。执行结果或错误信息还会经 041.php:11 的 `die(... mysqli_error(...) ...)` 回显，进一步为报错注入与数据回显提供通道。

影响：数据库数据泄露：可读取 users 表及其他表的任意数据（如用户名、口令哈希），可结合 UNION 查询跨表窃取；可造成认证绕过与数据完整性破坏（修改/删除记录）；错误回显（mysqli_error）暴露数据库结构与版本信息，便于进一步利用。若数据库账户权限过高，影响可扩展至整个数据库实例。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：注入点为 HTTP query 参数 `id`，任何能访问该页面的远程用户均可触发；无需认证（代码片段中未见任何鉴权/会话校验）；利用链闭合：041.php:5 读取参数 → 041.php:10 字符串拼接 → 041.php:11 mysqli_query 执行，全程无净化，且错误信息回显增强可利用性。

修复建议：改用预处理语句与参数绑定：`$stmt = $mysqli->prepare('SELECT first_name, last_name FROM users WHERE user_id = ?'); $stmt->bind_param('i', $id); $stmt->execute();`，并对 `id` 做整型强制转换（如 `$id = (int)$_GET['id'];`）。若必须拼接，至少使用 mysqli_real_escape_string 并加单引号包裹，但优先参数化。生产环境关闭详细数据库错误回显（移除 die(mysqli_error(...))），统一返回通用错误页；数据库账户遵循最小权限，仅授予所需表的 SELECT 权限。
