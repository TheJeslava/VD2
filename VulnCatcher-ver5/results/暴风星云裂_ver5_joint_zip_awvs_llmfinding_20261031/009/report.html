F-1 009.php 日志写入 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.63 · candidate / rule_verified+llm

位置：009.php:71-73

攻击者通过 HTTP 请求的 query 参数 `user_id`（009.php:17 读取）控制 `$id`，该值被赋给 `$current_user_id` 后直接以字符串插值方式拼入 INSERT 语句 `$log_query`（009.php:71-72），最终在 009.php:73 交给 `mysqli_query($GLOBALS["___mysqli_ston"], $log_query)` 执行。代码未使用 `mysqli_real_escape_string`、预处理语句或类型强制转换（如 `intval`），因此单引号可闭合 `'{$ip}'` 或数字位 `{$current_user_id}` 上下文注入任意 SQL。

影响：可对 `bac_log` 表执行任意 INSERT/子查询，进而通过报错或时间盲注读取 `users` 等库内数据（账号、口令哈希、日志），在数据库账号权限较高时可写入任意表数据，造成数据泄露与数据完整性破坏。

CVE/CWE 论证：CWE-89：外部可控的 query 参数未经参数化直接拼接进 SQL 并执行，攻击者无需认证即可通过公开页面触发，利用链 source(009.php:17)→拼接(009.php:71-72)→sink(009.php:73) 闭合。

修复建议：改用 mysqli 预处理语句并为占位符绑定参数（`$stmt = $mysqli->prepare("INSERT INTO bac_log (user_id,target_id,ip_address) VALUES (?,?,?)"); $stmt->bind_param('iis', $current_user_id, $target_id, $ip);`）；对 `user_id`/`target_id` 强制 `intval()`，对 `$ip` 使用 `filter_var(..., FILTER_VALIDATE_IP)` 校验；数据库账号遵循最小权限，仅授予 INSERT 权限。

F-3 009.php 用户信息查询 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：009.php:27-29

在 `$user_exists` 为真分支中，009.php:28 将 `$id` 直接拼入 `"SELECT first_name, last_name, user_id, avatar FROM users WHERE user_id = '$id';"`，并在 009.php:29 由 `mysqli_query` 执行。`$id` 源自 009.php:17 的 query 参数 `user_id`，无转义、无参数化。

影响：可注入 UNION/布尔/时间盲注读取 `users` 表任意列（姓名、头像路径、user_id 等），造成敏感数据泄露；结合前两处注入可扩大读取范围。

CVE/CWE 论证：CWE-89：外部可控 query 参数拼接进 SELECT 并执行，无需认证，source(009.php:17)→拼接(009.php:28)→sink(009.php:29) 闭合。

修复建议：改为预处理语句绑定参数（`SELECT first_name,last_name,user_id,avatar FROM users WHERE user_id = ?`），对 `user_id` 做整数校验；输出侧对 `avatar` 等字段做转义以防二次利用。

F-4 009.php 用户资料越权访问（硬编码 token 绕过访问控制）

medium idor / CWE-639 · 置信度 0.8 · candidate / llm_inferred

位置：009.php:26-40

第 26 行以 $_GET['token'] == 'user_token' 作为访问控制，token 为硬编码常量且与当前用户无关；第 28 行按客户端提供的 user_id 查询任意用户资料，未校验该 user_id 是否属于当前登录用户（第 7 行虽查询了当前用户 ID 但未用于授权判断）。任意攻击者提供 token=user_token 即可读取任意用户资料。

影响：未授权读取任意用户个人资料（姓名、头像路径），构成水平越权。

CVE/CWE 论证：CWE-639：访问控制依赖客户端可控的硬编码 token，且未校验对象归属，外部可直接触发。

修复建议：基于服务端会话确定当前用户，禁止客户端指定 user_id；移除硬编码 token。
