F-1 010.php 登录查询 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.83 · candidate / rule_verified+llm

位置：010.php:18-20

攻击者通过 HTTP 请求的 query 参数 `username`（010.php:8 读取）提交任意字符串，该值被直接拼进 010.php:19 的 SQL 语句 `SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';`，随后在 010.php:20 由 mysqli_query 执行。代码中未见对 `$user` 的引号转义或参数化处理（对比 010.php:15 对 `$pass` 调用了 mysqli_real_escape_string，而 `$user` 没有同等处理），因此单引号可闭合字符串字面量，注入任意 SQL 片段。此外 010.php:20 的 `or die(... mysqli_error ...)` 会把数据库错误信息回显到响应中，为报错型注入和结构探测提供便利。

影响：可绕过登录认证（如构造 `username=' OR '1'='1' -- ` 使 WHERE 恒真），并通过 UNION/布尔/报错注入读取 users 表及其他库表数据（口令哈希、用户信息），在数据库账号权限较高时还可能读写文件或进一步影响数据库主机；错误回显进一步降低利用门槛。

CVE/CWE 论证：CWE-89（SQL 命令中特殊元素未正确中和）。外部可达性：注入点为 HTTP query 参数 `username`，无需认证即可访问登录逻辑；利用链闭合：010.php:8 取参 → 010.php:19 字符串拼接 → 010.php:20 mysqli_query 执行，中间无有效净化或参数化，且错误信息回显（010.php:20）辅助确认注入。证据等级为源码推断，未做动态验证。

修复建议：改用预处理语句与参数绑定（mysqli_prepare + bind_param 或 PDO prepared statement），彻底避免字符串拼接；对输入做类型/长度白名单校验；关闭数据库错误详情回显，改为记录服务端日志并返回通用错误；数据库账号遵循最小权限，禁止 FILE 等高风险权限。

F-2 010.php 登录成功页将用户可控 username 未转义回显（反射型 XSS）

medium xss / CWE-79 · 置信度 0.8 · candidate / llm_inferred

位置：010.php:8-28

脚本从 $_GET['username'] 取值，仅做 stripslashes 与 mysqli_real_escape_string 处理（后者只针对 SQL 上下文转义，对 HTML 上下文无效），随后在登录成功分支直接拼接进 HTML 输出：$html .= "<p>Welcome to the password protected area {$user}</p>"。攻击者可构造带 HTML/JS 的 username，诱导受害者点击链接；若受害者凭据有效（或攻击者自身登录成功），脚本将原样输出脚本标签，导致在站点源下执行任意 JS，可窃取会话或发起 CSRF 令牌读取等操作。

影响：在站点源下执行任意 JavaScript，可窃取会话 Cookie、读取 CSRF token 并发起敏感操作，或对管理员实施钓鱼。

CVE/CWE 论证：CWE-79 反射型 XSS；外部 GET 可达，无需特殊权限（仅需有效凭据触发成功分支），source→sink 链在 CODE PACK 内闭合。

修复建议：输出前对 $user 使用 htmlspecialchars($user, ENT_QUOTES, 'UTF-8')；avatar 输出同样应做属性编码与 URL 白名单校验。

F-3 010.php 使用 MD5 处理口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：010.php:15-16

010.php:16 执行 `$pass = md5( $pass );`，将用户提交的口令用 MD5 做单次无盐哈希后再用于 010.php:19 的登录比对。MD5 属于已破译的快速哈希算法，抗碰撞与抗暴力破解能力不足，且此处未见加盐或迭代（如 password_hash/bcrypt/Argon2）。注意：该弱点本质是弱哈希（CWE-328），不是加密算法模式问题（CWE-327）。

影响：一旦 users 表口令哈希泄露（可与同文件 GEN-7034f0a19983 的 SQL 注入结合导出），攻击者可用彩虹表/GPU 暴力快速还原明文口令，导致账号接管；相同口令产生相同哈希也便于横向撞库。

CVE/CWE 论证：CWE-328（使用弱哈希算法）。属实现/配置型弱点，不要求 HTTP 污点链；原文证据为 010.php:16 的 `md5( $pass )` 调用及 010.php:19 中该哈希参与口令比对。外部可达性体现在登录接口接受外部口令输入，无需认证。

修复建议：改用专为口令设计的慢哈希：PHP 的 password_hash()（PASSWORD_BCRYPT 或 PASSWORD_ARGON2ID）配合 password_verify()，自动加盐并支持成本参数；对存量 MD5 哈希在用户下次登录成功时透明升级；强制口令复杂度并限制登录失败次数。
