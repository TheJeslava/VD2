F-1 015.php 修改密码处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：015.php:67-69

攻击者在修改密码表单的 password_new 参数（015.php:8 通过 $_POST['password_new'] 读取）提交恶意字符串。该值在 015.php:64 仅经过 mysqli_real_escape_string 转义，随后在 015.php:65 被 md5() 处理，最终在 015.php:68 被直接拼接进 UPDATE 语句：$insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . dvwaCurrentUser() . "';";，并在 015.php:69 交给 mysqli_query 执行。由于 md5() 会把输入规整为 32 位十六进制串，password_new 本身在进入 SQL 前已被哈希，单次注入路径实际被 md5 截断，普通引号注入难以闭合；真正可注入面取决于 dvwaCurrentUser() 的返回值是否可控（本片段未给出其实现，证据不足）。因此该候选的污点链在 md5 处被削弱，需结合 dvwaCurrentUser() 实现复核才能确认可利用性。

影响：若 dvwaCurrentUser() 返回值可被外部影响，则可构造 UPDATE 语句注入，篡改 users 表中任意用户口令或读取数据库内容（数据泄露/越权改密）。就当前片段而言，password_new 经 md5 后无法直接闭合引号，实际可利用性证据不足。

CVE/CWE 论证：CWE-89：SQL 语句由字符串拼接构造（015.php:68），未使用参数化查询，汇点为 mysqli_query（015.php:69）。外部可达性：password_new 来自 POST 表单，无需额外权限即可提交；但利用链在 md5()（015.php:65）处被削弱，闭合条件依赖 dvwaCurrentUser() 的返回值，当前证据不足以判定链完全闭合。

修复建议：改用预处理语句与参数绑定（mysqli_prepare + bind_param 或 PDO），彻底移除字符串拼接；对 dvwaCurrentUser() 的返回值同样参数化；口令哈希改用 password_hash()/password_verify()（bcrypt/Argon2）替代 md5；关闭 die(mysqli_error(...)) 的详细错误回显，避免报错注入与信息泄露。

F-2 DVWA 密码修改功能 CAPTCHA 状态机可绕过（step=2 直接提交 passed_captcha=true）

high captcha_bypass / CWE-804 · 置信度 0.9 · candidate / llm_inferred

位置：015.php:46-72

脚本用两阶段状态机实现“先过 CAPTCHA 再改密码”：step=1 时调用 recaptcha_check_answer 校验，通过后渲染隐藏表单，其中包含 step=2、passed_captcha=true。但 step=2 分支（第 46-81 行）只检查 $_POST['passed_captcha'] 是否为真（第 55 行），完全不校验该值是否由服务端签发、也不校验 CAPTCHA 是否真的通过。攻击者无需任何 CAPTCHA 令牌，直接 POST step=2&passed_captcha=true&password_new=X&password_conf=X 即可进入第 62-72 行的改密逻辑，把当前登录用户的密码改为任意值。若配合 CSRF（改密请求无 token），可对已登录管理员发起跨站改密，导致账户接管。

影响：无需通过 CAPTCHA 即可修改账户密码；结合无 CSRF token 的改密请求，可对管理员实施跨站请求伪造，实现账户接管。

CVE/CWE 论证：CWE-804（Guessable CAPTCHA）/CWE-602（客户端强制服务端安全）；外部 HTTP 可达，仅需普通登录态，链闭合。

修复建议：在服务端 session 中记录 CAPTCHA 校验通过状态与一次性 nonce，step=2 时校验服务端状态而非客户端 passed_captcha；改密请求加入 CSRF token 并在使用后失效。

F-6 015.php 使用 MD5 存储口令（CWE-328）

medium weak_crypto / CWE-327 · 置信度 0.55 · candidate / rule_verified+llm

位置：015.php:64-65

015.php:65 执行 $pass_new = md5( $pass_new );，将用户新口令以无盐 MD5 形式处理后写入数据库（015.php:68-69 的 UPDATE users SET password）。MD5 属快速哈希，易受彩虹表与 GPU 暴力破解，且此处未见盐值或迭代。该弱点为配置/实现型，无需 HTTP 污点链即可成立。

影响：数据库泄露时攻击者可快速还原用户明文口令（凭据泄露），并可能在其他系统复用导致横向扩散。

CVE/CWE 论证：CWE-328（Use of Weak Hash）：口令等安全用途使用 MD5，属弱哈希而非弱加密算法（非 CWE-327）。外部可达性：任何注册/改密请求都会触发该哈希路径；无需特殊权限。

修复建议：改用 password_hash()（bcrypt/Argon2id）并配合 password_verify()；为每个口令生成独立盐；必要时增加迭代成本参数；迁移期可对旧 MD5 值做透明升级。
