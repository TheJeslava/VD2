F-1 043.php 不安全文件上传导致任意文件写入（CWE-434）

critical file_upload / CWE-434 · 置信度 0.68 · candidate / rule_verified+llm

位置：043.php:18-20

攻击者通过 HTTP 文件上传字段 `uploaded` 提交文件（043.php:12 读取上传内容，临时文件路径进入 `$uploaded_tmp`）。代码随后在 043.php:20 调用 `move_uploaded_file( $uploaded_tmp, $target_path )` 将上传文件移动到 `$target_path`。从给出的片段看，在 043.php:12 到 043.php:20 之间没有出现扩展名白名单、MIME 校验、文件内容检查或目标文件名规范化等有效净化逻辑，因此上传文件的类型与落盘名称未受约束，攻击者可控制写入 Web 目录的文件。证据仅覆盖 043.php:12 与 043.php:18-20 片段，`$target_path` 的具体构造代码未在输入中给出，其是否完全由用户控制属推断。

影响：若 `$target_path` 位于 Web 可访问目录且扩展名可控，攻击者可上传 .php 等可执行脚本，通过访问上传后的 URL 触发任意 PHP 代码执行，进而读取/篡改服务器文件、窃取数据库凭据、横向移动；即使不可执行，也可造成任意文件覆盖写入（覆盖配置、模板、其他用户文件），导致数据完整性破坏或拒绝服务。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部可达性：上传入口为 HTTP multipart 请求的 `uploaded` 字段，无需认证即可访问该脚本（片段中未见任何鉴权/会话校验）。利用链闭合：外部输入 `uploaded` → `$uploaded_tmp`（043.php:12）→ `move_uploaded_file($uploaded_tmp, $target_path)`（043.php:20）→ 文件落盘至目标路径，中间无类型/扩展名/路径校验。证据等级为 llm_inferred：`$target_path` 的赋值与目录可执行性未在输入片段中出现，需以实际部署配置确认。

修复建议：1) 使用扩展名白名单（如仅 jpg/png/pdf）并基于服务端解析的真实 MIME 与文件头校验，不信任客户端 Content-Type 与文件名；2) 目标文件名由服务端生成（UUID/哈希 + 白名单扩展名），禁止使用用户提供的文件名拼接路径；3) 对 `$target_path` 做规范化（realpath）并校验其位于预设上传目录内，防止路径穿越；4) 上传目录置于 Web 根之外，或关闭该目录的脚本执行权限（如 Nginx `location ~ \.php$ { deny all; }`）；5) 上传接口增加认证与 CSRF 防护，限制文件大小与数量。

F-2 DVWA 文件上传端点（043.php）仅校验扩展名与 getimagesize，可上传含 PHP 代码的图片并写入 web 可访问目录导致 RCE

high file_upload / CWE-434 · 置信度 0.83 · candidate / externally_corroborated

位置：043.php:5-26

043.php 在收到 POST 参数 Upload 时，从 $_FILES['uploaded'] 读取文件名、扩展名、大小与临时文件。校验逻辑为：扩展名（strrpos 取最后一个点之后的部分，strtolower 后）必须为 jpg/jpeg/png，大小 < 100000 字节，且 getimagesize() 返回真。校验通过后调用 move_uploaded_file() 将临时文件移动到 DVWA_WEB_PAGE_TO_ROOT . "hackable/uploads/" 目录，文件名使用 basename($_FILES['uploaded']['name'])。该目录位于 web 根下且可被 HTTP 直接访问。校验只检查文件头是否为合法图片（getimagesize 只解析图像头），不检查文件内容中是否夹带 PHP 代码，也不重命名文件、不限制上传目录执行权限。攻击者可构造一个合法 PNG/JPEG 文件头 + 尾部嵌入 PHP 代码的多语言文件（polyglot），扩展名保持 .png/.jpg 通过校验，上传后通过 HTTP 访问该文件，若服务器对 uploads 目录未禁用 PHP 解析，则嵌入的 PHP 代码被执行，形成远程代码执行。

影响：攻击者可在服务器上写入并执行任意 PHP 代码，获得 web 进程权限，读取敏感文件、横向移动，形成远程代码执行。

CVE/CWE 论证：CWE-434（Unrestricted Upload of File with Dangerous Type）。外部无需认证即可通过 HTTP 上传，校验仅基于扩展名与图像头，可被 polyglot 绕过，链闭合至 move_uploaded_file 写入 web 可访问目录。

修复建议：上传后重命名文件为随机名并强制安全扩展名；将上传目录移出 web 根或禁用该目录的脚本解析；对文件内容做真实图像重编码（如 GD/Imagick 重新生成图像）剥离嵌入代码；校验 MIME 与文件内容一致性；限制上传目录权限。
