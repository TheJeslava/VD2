F-1 014.php 修改口令处 SQL 注入（CWE-89）

critical sql_injection / CWE-89 · 置信度 0.4 · candidate / rule_verified+llm

位置：014.php:59-61

攻击者通过 POST 参数 password_new（014.php:8 读取 $_POST['password_new']）提交口令，代码在 014.php:56 仅用 mysqli_real_escape_string 处理，随后 014.php:57 做 md5，再在 014.php:60 以字符串拼接方式构造 UPDATE `users` SET password = '$pass_new' WHERE user = '...'，最终在 014.php:61 交给 mysqli_query 执行。由于 $pass_new 是 md5 后的 32 位十六进制串，正常情况下无法携带引号等元字符，因此该路径的注入可行性依赖 md5 之前/之后是否存在可绕过转义的分支（例如 dvwa 低安全级别下 md5 与转义顺序差异），当前 code_pack 仅给出 56-61 行，无法确认是否存在未转义分支，故按 llm_inferred 记录。

影响：若注入成立，攻击者可改写 users 表中任意用户（含 admin）的 password 字段，实现账户接管/越权登录；错误信息经 die() 回显（014.php:61）还会泄露数据库结构与 SQL 语句细节。

CVE/CWE 论证：CWE-89：外部可控输入进入 SQL 语句拼接且未使用参数化查询。外部可达性：014.php 为 Web 入口，POST 参数无需额外权限即可提交（需已登录会话，属 DVWA 设计前提）；利用链为 password_new → $pass_new → $insert → mysqli_query，链路在文件内闭合。但 md5 归一化削弱了元字符可控性，故置信度偏低。

修复建议：改用预处理语句：$stmt = mysqli_prepare($link, 'UPDATE users SET password = ? WHERE user = ?'); mysqli_stmt_bind_param($stmt, 'ss', $pass_new, dvwaCurrentUser()); 并移除 die(mysqli_error()) 的详细错误回显，改为记录日志并返回通用错误；口令哈希改用 password_hash()。

F-2 DVWA CSRF 模块：step=2 密码修改缺少 CSRF token，可被跨站强制改密并接管账户

high csrf / CWE-352 · 置信度 0.85 · candidate / llm_inferred

位置：014.php:45-61

014.php 的密码修改流程分为 step=1（校验 CAPTCHA）与 step=2（实际写库）。step=2 分支（第 45-73 行）只检查 $_POST['Change'] 与 $_POST['step']=='2'，随后直接读取 $_POST['password_new']/$_POST['password_conf']，两者相等即执行 UPDATE users SET password=md5(...) F-5 014.php 使用 MD5 存储口令（CWE-328 弱哈希）

medium weak_crypto / CWE-327 · 置信度 0.76 · candidate / rule_verified+llm

位置：014.php:56-57

014.php:57 执行 $pass_new = md5( $pass_new );，将用户新口令以无盐 MD5 形式写入 users.password（014.php:60-61 的 UPDATE）。该值随后用于口令校验，属于安全用途的弱哈希，而非加密算法误用。

影响：无盐 MD5 可被彩虹表/GPU 暴力快速还原，数据库泄露后用户口令近乎明文暴露；相同口令产生相同哈希，便于横向撞库。

CVE/CWE 论证：CWE-328（Use of Weak Hash），不是 CWE-327。证据为 014.php:57 的 md5() 调用原文；属实现型弱点，无需 HTTP 污点链即可成立。外部可达性体现在任意口令修改请求都会生成 MD5 摘要落库。

修复建议：改用 password_hash($pass_new, PASSWORD_DEFAULT)（bcrypt/Argon2id）存储，校验使用 password_verify()；对历史 MD5 记录在用户下次登录时透明升级；禁止在代码中直接调用 md5/sha1 处理口令。
